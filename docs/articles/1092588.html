Application

Our architecture looks like this.

The code was written over several iterations: code - test - fix - test - ... until testing yielded positive results. After completion, the entire project was reviewed using the same process. The stack turned out to be approximately: Python, FastAPI, SQLite, Caddy.

The application is configured to work specifically with Sber's GigaChat. My main goal was to verify its functionality. The essence is that upon registration, you receive a token. A request is sent with this token, and in response, you get an access token, which you can then use to send requests to the AI. This token is valid for 30 minutes. After it expires, we don't request a new one until an SMS arrives.

Configs

One SMS in Cyrillic has a maximum of 70 characters. But if it's, for example, 80 characters, the message is concatenated into one, but you pay for two. With an unlimited SMS tariff, this doesn't bother me much, but keep it in mind. I believe the maximum number of concatenated messages is 10. And then we get to the configs.

system_prompt - "Respond in Russian briefly, up to 200 characters, without emojis or markdown." This 200-character limit is a conditional one that the model might ignore and output slightly more.

max_reply_units = 201 This is a hard limit. The message is concatenated from parts of 67 characters, as the concatenation header consumes 3 characters.

max_tokens = 500 - GigaChat's response limit. Theoretically, there's no limit here, but this is to ensure it finishes its thought and stays within our 200 characters. By the way, our GigaChat has a context limit of about 8k.

max_sessions = 10 - limit of active sessions. This is built into our code. Each session lasts 24 hours without activity. There's not much point in detailing the advantages of different sessions. If we want to switch to another session, we just type "#2 " immediately followed by our request. When the 11th session appears, the least recently active one is overwritten, and so on.

history_messages = 10 - message limit per session. Here, as everywhere else, the model remembers nothing about our past messages. Therefore, we send it the last 10 messages (ours and the model's) to remind it of the context.

Next steps

GigaChat. Register for GigaChat API. Go to API settings, get your authorization key. Save it somewhere, you'll need it later.

Domain. We will need to set up 2 DNS records. If you already had a domain before, you can add to it. I did exactly that, and they were set up immediately, without waiting several hours. Mine is registered on Cloudflare. What's important is Type - A (A record maps a subdomain to the VPS's IPv4 address), Proxy status - DNS only (proxy interferes with Let's Encrypt and the phone's SSE connection), TTL - Auto. For the domain domain.ru, set up app.domain.ru and sms.domain.ru. And of course, the IP address of your VPS.

VPS. After purchase, log in to the server. Update the system, install Docker.

Next, configure the firewall.

ufw allow ssh && ufw default deny incoming  # Allow incoming SSH (22) and deny all other incoming by default. Only SSH, 80, and 443 will be accessible from outside.
ufw default allow outgoing        			# Allow outgoing (deny would break apt/docker pull/GigaChat)
ufw allow 80/tcp && ufw allow 443/tcp  		# We need 80 for issuing and renewing Let's Encrypt certificates, and 443 for everything else.
ufw --force enable						# Apply
timedatectl set-ntp true          			# Enable NTP. Each webhook is signed with a timestamp, the receiver only accepts within a ±5 minute window from the server's clock. If the drift is larger, all webhooks will be rejected with 401.

What were the difficulties

Actually, there weren't many significant ones.

The first one: I went out on business, sent an SMS, no reply. I don't know about other Android versions, but on mine, the sleep mode activates after 30 minutes - the maximum setting. After that, messages go into a buffer, and the app retries them with increasing intervals (14 attempts over 45 hours). It was solved easily and simply: in developer options, I checked the "don't turn off screen" box. A nuance: this only works while charging. That is, to leave the phone unattended, it must be left charging. If you leave it for a few hours, there are no problems. If you leave it for several days or weeks, it's unclear what will happen to the phone, especially the battery.

The second problem: I sent an SMS, it was received, the phone sent a reply, but I didn't receive it. I wrote to support, they said everything was fine on their end. I googled it, and there's a possibility that a new, "unwarmed" SIM card might do this due to the operator's anti-fraud filters, and the messages got stuck with the operator. But this is just a hypothesis, the exact reason remains a mystery. It hasn't happened again since.
