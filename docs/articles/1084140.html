It all started with the fact that my measurement logs show which URLs Perplexity uses as sources, but not what exactly from the page went into the answer—the entire text, a paragraph, or a single list item.

Perplexity shows which pages it used as sources, but not what text from them

For each source in the Search API response, there are five fields: title, url, date, last_updated, and snippet—'a short excerpt from the article related to the query'. There are no fields with the full page text that went into the model in the response. A separate note on naming: sources_cited, which appears later in the text, is a field in my log where I normalize the answer sources; in the Perplexity API itself, they come as search_results and citations. Confusing a convenient name from your own code with the schema of someone else's response is a good way to spend half an hour later searching for a non-existent field in the documentation.

Manually correlating two facts—that a source was cited and what exactly was taken from it—is unrealistic: 60 answers yield over a thousand numbered references.

Dataset: 60 Perplexity answers (20 prompts with 3 repetitions each), sonar-pro model, search enabled for all. They contain 583 lines in sources_cited, corresponding to 220 unique URLs, and 1407 numbered citations [N] in the answer texts. After filtering out short fragments like "see also" without a meaningful sentence nearby, 1355 citations were included in the analysis.

Perplexity API has a text limit per page, but how it's cut is not described

Working with a fragment of a page, not its full text, is directly built into the Perplexity Search API interface: the client has a setting for how many tokens to take from each found page. The search_context_size parameter with values low / medium / high controls the extraction depth. The max_tokens_per_page has a straightforward description in the documentation—maximum content tokens extracted from each result page—and next to it is max_tokens, the same limit for all results combined.

The documentation does not reveal how these settings relate to what actually reaches the answer: it doesn't describe how the snippet is selected, what size the page is cut into, or the cutting rule itself. I observed everything else externally by directly comparing the answer text with the source text.
