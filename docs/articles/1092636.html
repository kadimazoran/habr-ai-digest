I've broken down 12 signs of AI slop, i.e., text generated by a neural network and not proofread, into checks for my AI text detector. Five are caught by code. The remaining seven rely solely on editor rules.

Online detectors check texts, but often you just see percentages in response – it's unclear what exactly to fix. The percentage itself is also unreliable: in the work of Liang et al., seven detectors on average classified 61% of TOEFL essays written by non-native English speakers as machine-generated. OpenAI closed its classifier in the summer of 2023 due to low accuracy.

My check works differently: it names the phrase and the rule, and each trigger can be disputed separately. Wikipedia editors maintain an open list of AI text indicators and explicitly state that an indicator points to a potential problem and proves nothing on its own. My script operates on the same principle: it looks for traces of unedited text, it does not determine authorship. The overall score of this detector has already been discussed on Habr.

Which of the 12 Signs of AI Slop Can Be Caught

It's simple here. Code can catch AI slop where there is a stable phrasing or vocabulary:

  1. Announcement instead of content: sentence start and end templates plus length threshold.

  2. Empty introductory part before the main point: code catches partially.

  3. Identical paragraphs: sentence length variation, catches indirectly.

  4. Quotes on ordinary words: code regularly catches using quotation marks and exceptions.

  5. Calques and jargon: two replacement dictionaries.

However, code can hardly catch the lack of details, fabricated numbers, balanced arguments without a stance, antithesis with enumeration, tricolons, chopped paragraph endings, and dashes in every sentence.

How the Detector Catches Announcement Phrases and Why It Misses Those Not Starting with a Verb

The script splits paragraphs into sentences. Announcement templates only check sentences up to 12 words; it skips longer ones:

for sent in re.split(r'(?<=[.!?])
bsp+', para):
    clean = re.sub(r'[*_`]', '', sent).strip()
    if not clean:
        continue
    if any(rx.search(clean) for rx in SELF_TALK_RE):
        bad.append(clean[:70])
        continue
    if len(clean.split()) > 12:                  # a long sentence is not an announcement
        continue

A short sentence is compared against templates. One of them looks for a promise verb at the beginning of the phrase:

r'^(?:разберу|разберём|расскажу|расскажем|покажу|покажем|объясню|объясним|'
r'рассмотрим|приведу|приведём|опишу|опишем|перечислю|начн[уё]м|перейд[уё]м)'

A match is discarded if the sentence contains a factual anchor: a number, code in backticks, or a Latin word.

FACT_ANCHOR = re.compile(r'
|`[^`]+`|[A-Za-z]{2,}')

The miss lies in the ^ symbol. The phrase "In this article, we will consider the main signs" starts with an adverbial modifier, the verb is the fourth word, and the template doesn't see it.

Fixing this is not easy. If you remove ^, the condition on the tail after the verb remains, and the phrase still passes. If you remove that too, the template catches normal phrases: "Let's break it down step by step," "Write in, and we'll break it down specifically for your niche." Nine such false positives were found in my blog articles. A narrow template tied to the words "in this article" works; on the same articles, it has no false positives:

r'^в
bsp+(?:этой|данной)
bsp+(?:статье|заметке|части)
bsp+(?:мы
bsp+|я
bsp+)?(?:разберу|рассмотрим|покажу|опишу)'

How the Detector Catches Empty Introductory Phrases and Quotes on Ordinary Words

Empty introductory phrases are caught by a list of 36 regular expression checks. One hit gives 3 points, two already stop the text for editing:

LEADIN_PATTERNS = [
    # …
    r'вывод из этого прост',
    # …
    r'давайте (?:разберёмся|разберемся|начнём|начнем)',
    # …
]
score = 10 if n >= 3 else (5 if n == 2 else (3 if n == 1 else 0))

The dictionary only knows the phrases entered. It misses the phrase "The conclusion is simple:" with a colon because the list only contains the phrase with "из этого" (from this). Adding it to the dictionary is also not possible: in four other blog articles, the main point follows it, and the dictionary would flag a normal sentence.

With quotes, the regex for quotation marks is simple; all the work is in the exceptions:

def ordinary(s):
    s = s.strip()
    if len(s.split()) > 3:            # long ones are usually quotes/titles
        return False
    if re.search(r'[A-Za-z+0-9]', s):  # Latin/terms/labels are legitimate
        return False
    if s[:1].isupper():               # Capitalized is usually a name/title
        return False
    # … a question, a quote of a search query are also not flags
    return True

Anything else is considered an ordinary word in quotes, like model "knows" brand, and a flag is set for just one such pair.

How the Detector Notices Monotonous Rhythm and English Calques

The script indirectly detects identical paragraphs: it calculates the standard deviation of sentence length in words across the entire text. When sentences are of the same length, the variation is small, and the text sounds monotonous. It doesn't compare entire paragraphs, so a structure of a thesis, three points, and a conclusion with sentences of different lengths might pass.

Calques are caught by two dictionaries. The first contains slang Anglicisms with Russian replacements: "partiya" instead of a calque from "batch," "vyvod" instead of a calque from "insight." The second contains fifty replacements that I have already manually corrected in published texts. A semantic calque, where all words are Russian but the phrase is English, will not be found by the dictionary.

Seven Signs of AI Slop That the Detector Doesn't Catch

Three are semantic: the text contains no verifiable details, no numbers were calculated, everything is balanced without a stance. A string search doesn't find them. The phrase "growth of 37%" yielded zero points on a test run: the script doesn't know if anyone calculated these percentages. The phrase "On the one hand... on the other" is not in the dictionary.

Four are syntactic: the phrase "Not A, but B, C, and D," tricolons for rhythm, a chopped ending like "And this is not a metaphor.," and dashes in every sentence. These are forbidden by editor rules, there's no counter. Wikipedia's list on how to tell if text is AI-written also includes them. Dashes are the most noticeable: there's a limit of three dashes per thousand characters in the rules, but no check in the code.

The script is written in the standard Python library and does not access the internet. I am not publishing it in its entirety: the fragments in the article are enough to assemble your own version. You can check text with the AI detector with one command:

The exit code gives the verdict: zero means the text is fine, one requests revision, two indicates clear AI text. A normal text scores less than 20 points, but some categories stop it even with a low score.

I assembled a short test text from slop samples according to the list. The script gave it 18 out of 80 points: 15 for monotonous rhythm and 3 for one introductory phrase. The script found two announcements separately; they are not included in this sum. Therefore, 18 points are below the threshold, but the verdict still requires revision: an announcement stops the text on its own. The remaining samples passed.

How to Assemble Such a Check for Your Texts

  1. Each sign has its own function, and it returns the found phrase, not just a score. Without the phrase, the trigger cannot be verified.

  2. Run each new template on your old texts. Removing the anchor ^ leads to false positives; a narrow template for a specific miss is more reliable.

  3. Count dashes with a few lines:

def dash_rate(text):
    dashes = len(re.findall(r'
bsp—
bsp', text))
    return dashes / max(len(text), 1) * 1000   # dashes per 1000 characters

With a limit of three dashes per thousand characters, such a counter would flag from a fifth to half of my articles, depending on which dashes are considered acceptable, so the threshold is first determined based on your own texts.
