Why Machine Learning in PHP at All?

When a machine learning task arises in an existing PHP application, the common approach is to create a separate service in Python.

Such a solution has obvious advantages. Python has a vast ML ecosystem, numerous ready-made models and tools, and the computational part can be scaled independently.

However, a separate service comes at a cost: additional deployment, inter-application communication, monitoring, data exchange, and one more component to maintain.

Imagine a SaaS platform that collects statistics from social networks, publishes content, and analyzes user activity. At some point, there's a need to find anomalies in metrics, classify data, or segment accounts.

Is it mandatory to create a separate Python service for this?

Not always. For some tasks, you can use an ML library directly within the PHP application. Rubix ML provides algorithms for classification, regression, clustering, anomaly detection, and neural network models, as well as tools for data preparation and model quality evaluation.

Of course, this doesn'p mean PHP should replace Python for all machine learning tasks. But the ability to start with an already used language can be beneficial in itself.

What's New in Rubix ML 3.0?

1. Parallel Computing: Inference and Training

One of the most interesting changes is the ability to perform individual algorithm operations in parallel.

It's important to understand the terminology here. Training is the process of teaching a model. Inference is applying an already trained model to new data to obtain predictions or estimates.

For example, we've trained a model that detects anomalies in user activity. Now, the system needs to check thousands or millions of new observations every day.

If processing is done sequentially, inference time can become a bottleneck. Parallel computing allows distributing work across multiple processes to utilize available CPU cores more effectively.

In Rubix ML 3.0, parallel inference has been added for K-Nearest Neighbors and KNN Regressor. For Isolation Forest, both training and inference are parallelized.

How does it work?

Instead of creating a separate process for each observation, the developer can use the parallel execution mechanism supported by the algorithm. The library distributes the corresponding computational tasks through the selected backend.

For instance, with K-Nearest Neighbors, processing multiple observations can be distributed among worker processes. For Isolation Forest, the results of individual ensemble trees can be computed independently and their scores combined.

To actually enable parallel processing, you need to configure a supported backend. Rubix ML offers backends based on Amp and Swoole, among others. By default, a sequential backend is used, so simply updating to version 3.0 doesn't mean any model call will automatically become parallel.
