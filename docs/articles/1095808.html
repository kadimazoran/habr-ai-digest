Obscura: Your Own On-Prem Gateway That Prevents Secrets from Leaking to AI Without Breaking Model Responses

This summer, I wrote about what happens when you upload work data to ChatGPT: SOC logs, Cisco and FortiGate configs, internal IPs, employee emails. I then created an offline tool to clean configs manually before sending. It solves the problem for those who remember to use it. But a company cannot rely on everyone always remembering.

So I took the next step: a gateway that sits between a person and a neural network, checks every request, and decides what to do with it. It's called Obscura. It works on-prem, so data stays within the network.

Fig. 1. Main console screen

How it Works

The client interacts with the gateway as if it were a regular OpenAI-compatible API (/v1/chat/completions); for Anthropic, there's an adapter /v1/messages. For web interfaces like ChatGPT, there's a Chrome/Edge/Firefox extension, a separate inspector for files and images, plus a built-in corporate chat.

There are three operating modes:

•        Monitor: We only observe and log;

•        Warn: The user chooses whether to "mask" or "send as is";

•        Enforce: Mask or block before sending.

Fig. 2. Gateway Architecture

Stack: Python, FastAPI, SQLite in WAL, Redis, spaCy, Svelte 5 for the web console.

NER – RU/EN/AZ/TR

Most DLP solutions are designed for English. They handle Russian data less effectively: different document formats, Cyrillic context, declensions. Obscura has its own rules for Russian: INN (10 and 12 digits, with checksum verification), SNILS, bank cards, payment details, phone numbers, as well as API keys and tokens (sk-..., AWS, GitHub, JWT). Regex matches are confirmed by checksum, reducing the chance of a random number being mistaken for a "card number".

The Problem: [EMAIL_1] Breaks Model Responses

Typically, data is replaced with labels. This is fine for chat, but not for code and JSON: the model receives an incomprehensible label in the middle of a structure, which can break the format or lead to irrelevant reasoning. Therefore, Obscura has a synthetic surrogate mode:

The model sees normal data and responds naturally, while the gateway returns the actual values in the response. The generator is deterministic: one value within a request yields one surrogate. The speed is about 18,800 values per second, and all generated card numbers pass Luhn.

Streaming: The Most Annoying Part

With stream=True, the response comes in chunks of 1–2 characters. A token might arrive as "[", "EMA", "IL_1", "]", and substring search for each chunk doesn't work. The solution: a finite state machine with a sliding window. Regular text is sent to the client immediately, while the tail, which might be the beginning of a token, is held in a buffer until it's clear what it is. This is especially important for Russian text: each Cyrillic letter takes two bytes in UTF-8, and chunk boundaries can split them in half. I tested this with "chaotic" fragmentation: chunks of 1–3 bytes, broken brackets and UTF-8, false prefixes. Lost bytes: 0. At 100 parallel streams: P50 0.056 ms, P95 0.486 ms, P99 10.9 ms.

How the Gateway Decides What's a Secret

A single regex yields too many false positives, so each match has several indicators: format and checksum, contextual words nearby, Shannon entropy of the candidate string, and de-obfuscation traces. Before detection, the text is normalized: Base64 and Hex are decoded, invisible characters are removed, sparse digits and leetspeak are merged.

I calculate entropy for individual long strings without spaces, not for the entire text: regular prose also has an entropy of about 4 bits.

All of this is visible in the log as a "verdict": the security officer understands why the rule triggered and can adjust it. The log is linked by hashes; editing or deleting a line breaks the chain, which is detected by the "Verify chain integrity" button.

Browser Fleet

The extension registers each browser as a device. If the extension is disabled or removed, the device goes silent, which is immediately visible in the console, not after an incident.

Fig. 5. Devices with extension

Images

A screenshot with a passport or card is also a leak. The inspector extracts text via OCR and feeds it into the same pipeline. If a secret is found, the request is blocked (403), the original is encrypted and stored in the evidence locker, and SecOps receives an alert.

Evidence

Intercepted data cannot be stored in logs in plain text. Therefore, fragments are encrypted, and access follows a four-eyes principle: one officer submits a request with justification, another approves it, and a 15-minute token is issued. For the "right to be forgotten," there's crypto-deletion: the write key is erased, the ciphertext remains, and the log chain is not broken.

Agents, Budget, Policies

•        Injections and jailbreaks: heuristics plus risk assessment, system prompt protection.

•        Tool Guard: checks tool call arguments for shell injections and SSRF.

•        Token Limits: TPM and TPD per key or department, returns 429 before the request even goes to the paid model.

•        Policy Simulator: a new rule is run against logs from the past 7/14/30/90 days to see how many legitimate requests it would have blocked, even before enabling it.

•        SIEM: sending alerts (only metadata, not the values themselves) via webhook and integrations.

Limitations

Tests show that the code does what I intended, not the detection quality on real requests. The detector is rule-based and uses NER, not a trained classifier, so it misses non-standard formats, and sometimes incorrectly flags numbers that resemble phone numbers (order numbers). A secret rephrased in one's own words will not be caught by the gateway. There is no independent audit or production deployment yet. The project is evolving daily, with new features constantly appearing.

How I Made It With an AI Agent

I used Claude Code, ChatGPT, DeepSeek, and Antigravity in development. I particularly liked Claude Code (Opus, Sonnet) and ChatGPT (Astra) as they helped speed up development and testing.
