Let's Make Those Laptop Fans Spin

So, how do you set all this up locally and get the same benefits? First, let's figure out what hardware you'll need.

You need a laptop with more than 16 GB of unified memory or a discrete graphics card with 16 GB of VRAM. For a more comfortable experience, 32 GB of memory provides a noticeable advantage. Macs, especially MacBook Pros, also have higher GPU memory bandwidth, so they are usually faster than other laptops in these tasks.

I hadn't worked with local models before, but it only took me about an hour of trial and error to grasp the basics. Now you can skip that step and get everything running in minutes.

  1. Install DuckDB

  2. Install LM Studio

  3. Download a quantized, i.e., more compact, version of Qwen3.8 27B

    1. For MacBooks with 32 GB of memory, I recommend the 4-bit version, for example Qwen3.8-27B-MLX-4bit

    2. For MacBooks with 16 GB of memory, you'll need a 3-bit version. I like IQ3_XXS from the unsloth model family

  4. [Optional] Download MTP for multi-token prediction – in some cases, it speeds up generation

  5. Ask the agent to start a server in LM Studio with an OpenAI-compatible endpoint and the loaded model. The following settings worked well for this benchmark:

    1. Context of 16,384 tokens

    2. MTP, if you downloaded it

    3. Reasoning mode – low or off

  6. Connect your favorite agent wrapper to this server: OpenCode or another

    1. Or use your own wrapper, as in our benchmark repository

  7. Connect DuckDB to your data and ask a data question.

I ran a few more small tests to fine-tune the settings and get the most out of the machine. The following approach worked best: I asked the agent to create a design of experiments (DOE) and test different combinations of settings. This is important. Parameters strongly influence each other, so adjusting them one by one is not the best way to achieve the desired result. I also monitored memory load and swap usage – or rather, I asked Claude to measure them for me – and looked for ways to reduce memory consumption.

When running a local model, memory is the most scarce resource, so before running benchmarks, I would recommend simply restarting your laptop. Or at least close all your Chrome tabs…

On the MacBook Air with M5, I got about 5–7 tokens per second, calculated over the full execution time. This is quite close to the 8.8 tokens per second you might expect based on memory bandwidth.

On the older MacBook Pro with M1 Pro and 16 GB of memory, I used the 3-bit version. In this version, the model weights are rounded even more aggressively to save memory. Accuracy dropped slightly: 96.4% compared to 98.6% for the 4-bit version. But the model still worked – even on hardware almost five years old. Over the full execution time, I got about 5 tokens per second. The reason is that the memory bandwidth of the M1 Pro is actually higher than that of the regular M5 without the Pro designation in the MacBook Air, but the M5 has decent neural accelerators that give it an advantage.

What is MTP Anyway?

MTP, or multi-token prediction, is an interesting way to speed up generation: the model tries to guess the next few tokens in advance and then checks if those predictions were correct. The closest analogy is speculative execution in CPUs. A processor uses branch prediction to start computations on the most likely branch in advance – for example, the one that an if condition most often falls into. If the prediction turns out to be correct, everything executes faster. If not, the processor simply reverts to normal sequential execution.

Since the predicted tokens are later verified, accuracy is not compromised. I love acceleration without risk!

On the newer MacBook, MTP was useful with a draft prediction size of 3: the gain was about 30%.

On the older MacBook Pro, however, MTP slowed things down. The bottleneck was elsewhere in the system – the hardware simply wasn't designed for that kind of load. It took too much time to make additional predictions and then verify them.

How Did We Run the Benchmark?

All the details are in our GitHub repository.

Our own agent wrapper uses the DABStep benchmark to simulate how a data team should work with a context layer. First, general documentation, including several SQL snippets, is passed to Claude Fable 5, which converts it into MotherDuck Guides. Guides are regular Markdown documents stored alongside the data and linked to each other. If you want to work locally, you might find that Markdown files and a few links between them are sufficient.

So yes, at one stage we do use a large, cutting-edge model, but that's the fast and inexpensive part of the process. The main costs start when evaluating question-and-answer sets – and this is where local models come into play.

Once the initial context layer is ready, it's iteratively tested on a smaller AI model using 26 question-answer pairs as a training set. For each question, the model must produce a strictly defined text. If the smaller model answers a question incorrectly, the context layer is refined: missing assumptions and business rules are added. A larger model is used for this refinement to polish the central set of definitions as accurately as possible.

When the training and refinement cycle concludes with a result of 26 out of 26, the full test set of over 400 questions is run, and the final score is calculated. A smaller model is also used here because only then can this process be scaled in production.

No one should run Fable for large-scale eval tests – unless your company name rhymes with "gyroscopic." And Sol, perhaps, can be used if it rhymes with "orange banzai."

The Rest of the Story

I'm finally convinced that local models have reached a point where they are truly usable. I was particularly impressed by Qwen3.8 27B – it made me rethink what a 27 billion parameter model is capable of.

But there's still a noticeable difference in some areas. Let's start with speed:

On average, Qwen took 5–6 minutes to answer a question, while Gemini-3-Flash managed it in about 25 seconds, and GPT 5.6 Luna in 40. But there are a few caveats here. I think the settings can still be tweaked a bit to get an additional 20–30% performance. Plus, new quantization options are constantly appearing that allow you to squeeze even more out of Qwen.

Hardware also plays a huge role. A MacBook Pro with M5 Max has about four times the memory bandwidth of a MacBook Air. If this provides a fourfold performance increase – a reasonable assumption – then 90 seconds is much closer to the results of leading models from major AI labs.

But locally, I could only run one prompt at a time properly. In this benchmark, I regularly sent 15 questions at once via OpenRouter, and in the cloud, you can run as many prompts in parallel as your budget allows. Sub-agents are particularly useful here: they can be run simultaneously.

This approach is only suitable for those with sufficiently powerful hardware. According to Claude's rough estimate, about a third of laptops have more than 16 GB of RAM, meaning most users still won't be able to fully utilize this approach. If we only consider Macs with 16 GB of memory or more, where high memory bandwidth helps, the proportion drops to about one in thirty laptops.

But among the readers of this article, there are surely more than 3% like that, so if you have the power, definitely give it a try.

Furthermore, in this benchmark, the construction of the context layer was still handled by a large, cutting-edge model – in our case, Fable 5. Local models are unlikely to cover all scenarios yet, at least on mid-range consumer hardware.

And finally, so far we've only considered the cost of electricity, assuming you already have a laptop. If we add the depreciation of the laptop itself, a local model will cost about $6 per 1000 responses. Where does this figure come from? Suppose a laptop costs $2000 and lasts four years. Then six minutes of depreciation for each question amounts to about $5.70 in costs per thousand responses.

So, buying a MacBook Air solely for running Qwen isn't worth it. After all, a laptop should also be used as a laptop.
