It's hard to imagine development without AI anymore. It helps to test ideas faster, understand unfamiliar code, and handle routine tasks: from writing tests to preparing documentation.

We talked with Naumen developers Ilya and Dima about which tasks they already delegate to AI and how they verify its work.

What has changed in development with the advent of AI

It has become easier to test ideas and approaches

For me, AI is already a full-fledged development tool. AI helps to cope with routine tasks faster and test ideas and approaches. Previously, implementing them and experimenting with them took much more time.

Less time is spent on initial code drafts

I use AI almost daily: I discuss ideas, get code drafts. In a couple of minutes, you can sketch out the basis of a function or write a regular expression. It's possible to save tens of minutes on such tasks.

What tasks can be delegated to AI

Task implementation and refactoring

I use AI for task implementation and refactoring, analyzing existing code, finding errors, and writing tests. You can ask an agent to understand an unfamiliar part of the project, find the cause of a problem, and suggest a fix. Or delegate a routine task to it entirely.

Code analysis, tests, and documentation

With AI, I understand unfamiliar project code or libraries: I ask it to explain it and find errors. It's like a patient colleague who doesn't get tired of answering "stupid" questions.

I also ask it to write unit tests for ready code, add function descriptions, and fix README files. During debugging, I show logs, the error, and the code: sometimes your vision gets blurred, and AI helps you notice what you missed.

What needs to be checked

Project changes and agent actions

AI errors are not always obvious: the code looks normal, tests pass, but the solution doesn't account for project specifics, edge cases, or violates existing logic.

I am especially cautious about architectural changes and complex tasks with implicit dependencies. The agent doesn't always understand why something is done a certain way and might try to "improve" what shouldn't be touched.

Once, the agent needed to reproduce the behavior of a mobile application in a simulator for a test, but it couldn't perform the necessary gestures. It got stuck trying, spent a lot of tokens, reread large logs, and even started changing the code.

But the problem was in the limitations of the agent's interaction with the simulator, not in the application itself. It couldn't fix it by changing the code.

Library functions, security, and performance

I am cautious about unfamiliar libraries: AI can confidently suggest non-existent functions or outdated methods. A confident tone does not guarantee the correctness of the answer.

Security requires special attention. Generated code may contain vulnerabilities. It is important to check for protection against SQL injections, deserialization security, and the risk of secret leaks.

You also need to check if there are unnecessary database queries or redundant data copying. Ensuring the code works is not enough—especially when performance is critical or resources are limited.
