A Minimum About Jev's Structure

Jev does not generate text. It takes text (state) and a set of questions about it as input, and outputs an answer to each question with probability distribution. There are three types of questions: choice (select one option from a list), score (rate on a scale of levels), and noul (yes/no as a single probability). For choice, classes and their natural language descriptions are provided — this is the entire "setup".

curl https://api.typesafe.ai/v1/systemone 
  -H "Authorization: Bearer $TYPESAFE_API_KEY" 
  -H "Content-Type: application/json" 
  -d '{ 
    "model": "jev-1.13.0", 
    "state": "typed it wrong too many times at the atm and now its locked, how do i fix", 
    "questions": { 
      "intent": { 
        "type": "choice", 
        "instructions": "What is the customer asking about?", 
        "criteria": { 
          "pin": "Problems with the card PIN: forgotten, blocked, needs changing", 
          "transfer": "Sending money, a transfer that failed or is delayed", 
          "support": "Anything else that needs a human agent" 
        } 
      } 
    } 
  }'

The response for each question includes the selected option, confidence, and the distribution of probabilities across all options (structure is abbreviated, values are conditional):

{ 
  "answers": { 
    "intent": { 
      "choice": "pin", 
      "confidence": 0.98, 
      "probabilities": {"pin": 0.99, "transfer": 0.0, "support": 0.01} 
    } 
  }, 
  "usage": {"input_tokens": 212} 
}

Only input is charged: $0.042 per million input tokens, output is free.

TL;DR

  1. Jev's accuracy is on par with gpt-4.1-mini if both models are given only class descriptions. Jev is 2.4 times faster and 5 times cheaper.

  2. The main difference is calibration. The same confidence threshold for Jev filters out errors, while for GPT it barely filters anything: 83% of gpt-4.1-mini's errors are made with confidence above 0.9, while for Jev it's 29%. GPT doesn't rank answers by risk any worse; its threshold needs to be adjusted by traffic share, not by value.

  3. The threshold cannot be transferred between schemas. Adding more classes means the same threshold lets more errors through.

  4. Forty questions for one text take almost the time of one and are up to 86% cheaper than asking them individually.

  5. The quality of class descriptions has a comparable effect to model choice. With descriptions, the label name barely affects accuracy; without them, it determines everything.

  6. Jev tokens are not LLM tokens. The same request costs twice as many tokens as with GPT, and Russian text costs three times more than English.

  7. Extraneous text harms immediately, not at the context limit, and Jev is more sensitive to it than GPT.

  8. Noisy input is dangerous not due to volume but content: a quoted email pulls answers into the "email" class.

  9. For external input, an explicit other class is orders of magnitude better than a threshold.

  10. With a few hundred labeled examples (about 16 per class), a standard trained Jev classifier catches up.

How to Read the Numbers

The article relies on statistics, but almost all of it boils down to a few concepts:

  • Accuracy — the proportion of correct answers (accuracy): 90% means the model guessed the class correctly in 90 out of 100 examples.

  • p.p., percentage points — the difference between two percentages. It was 90%, now it's 87% — that's minus 3 p.p. (not minus 3%).

  • Interval in square brackets, e.g., −4.1 [−6.3; −2.0], — a 95% confidence interval: the range of values that the data are consistent with. If it's entirely on one side of zero, there is a difference. If it covers zero, the difference could not be shown.

  • p — how unusual such a difference would be if it were actually zero. The smaller the p, the stronger the evidence that the difference is real; p does not say whether it is practically significant. "After correction" — taking into account that many hypotheses were tested and some might have "hit" by chance.

  • "Not detected" does not mean "none". It means the data were insufficient to distinguish. Therefore, an interval is usually provided: what effect the data still allow.

  • Confidence — a number from 0 to 1 that the model returns with the answer. Threshold — the rule "answers with confidence above 0.9 are accepted automatically, others go for additional processing". Automatically accepted answers are further called autoflow.

  • Latency p50 / p95 — response time: half of the requests are faster than p50, 95% of requests are faster than p95.

Rules important for reading the numbers:

  • all models answer the same examples, comparison is paired (McNemar's test); for families of comparisons — Holm-Bonferroni correction;

  • "not significant" means "data were insufficient", and an interval is always provided: what effect the data still allow;

  • the unit of observation is an example: if one example appears in several lengths, positions, or runs, these answers are averaged within it, and intervals are calculated by bootstrapping over examples. Confidence is compared by paired Wilcoxon, Holm-Bonferroni correction — within the family of comparisons of one experiment;

  • the model has its own noise: two runs of the same request differ in 0.47% of labels. The proportion of changed answers is compared to this noise, not to zero;

  • GPT received the same list of classes with the same descriptions, structured output, temperature = 0; GPT confidence is the probability of the label token from top_logprobs = 20 at the position of the first token of the label value, normalized by schema classes (before normalization by classes, almost the entire probability mass was concentrated: below 0.99 — for 0.25% of gpt-4.1-nano answers and for none of gpt-4.1-mini answers). This is one way to estimate GPT's confidence, not the only one: I did not test asking the model to evaluate itself or the agreement of multiple answers.

    If you are building routing on GPT. With this method — by the first token of the label — class probabilities can only be obtained if the labels differ by the first token. The labels lightsoff, lightscolor, and lightson share the first token, and on such a schema, confidence by class cannot be separated. For calibration comparison on 30 classes, five labels had to be renamed; with descriptions, the label name does not affect the result (section 5).

1. Accuracy, Speed, Cost

Why these specific OpenAI models. Jev has confidence, and for comparison, I needed models with a confidence indicator — if not the same, then at least similar. Therefore, I chose non-reasoning models with available logprobs: they allow estimating class probabilities and using them as a confidence indicator. I started with gpt-4.1-nano and moved up the line until I saw a clear boundary. Starting from gpt-5-*, OpenAI models are reasoning models and do not return logprobs, and the calibration split appeared before gpt-5-mini. I took it as one of the control points for accuracy; there was no point in further iteration.

Where the models diverge is visible at the difficulty levels. For easy examples, all four give 100%. For difficult ones — with traps like "a word from another class that the text then negates" — Jev is 98%, gpt-4.1-mini is 96%, gpt-4.1-nano is 90%. A typical GPT error on such an example:

"My transfer was blocked pending checks. I’m not asking about the transfer — I’m asking how to pass the checks"

gpt-4.1-nano and gpt-4.1-mini answer transfer with confidence 1.0 (correct is identity). Jev answers correctly, and its few errors are made on truly ambiguous texts with low confidence (0.31, 0.36, 0.53).

On banking77, the answers of the three most accurate models matched on all 150 examples. All three made errors on the same three examples, which turned out to be debatable labels of the dataset itself upon analysis.

Latency is almost independent of input length for any model (Jev: 346 → 336 ms on long input). The expectation that Jev's advantage would increase with longer texts was not confirmed: it is constant.

Jev uses twice as many tokens (553 input tokens per request vs. 269 for GPT): the entire block of class descriptions goes into the input. And yet, it is the cheapest — the price per token outweighs the difference. More on tokens in section 7.

2. Calibration — The Main Difference

Accuracy isn't everything. In real projects, it's important to know if the model's answer can indicate that it's making a mistake: then confident answers go to autoflow, and doubtful ones to additional processing.

An ideally calibrated model behaves like this: out of 100 answers it gives with 0.9 confidence, about 90 are correct. Then a threshold of 0.9 means exactly what it says.
