Everything discussed works in cortiq — my open-source engine for local LLM inference (Rust; CUDA, Vulkan, Metal, CPU). A page with illustrations in three languages is available on Hugging Face.

Where It All Began

I wanted to "compile" a neural network for a specific task: take a general model and keep only what's necessary for the task, like a compiler discards unused code. A professor on a forum suggested a rigorous test – linear differential equations: the answer is either precisely correct or not at all, and "almost correct" is not accepted.

I placed a trainable gate on the neurons of the frozen model and trained only the gates on task examples. I expected the model to become smaller and slightly worse. Accuracy increased. The gates not only turned off the unnecessary parts but also re-weighted what was important for the task.

This effect became my second US patent application: № 19/452,464 "Dynamic Task-Guided Mask Activation (DTG-MA) Compression", filed January 19, 2026. Cortiq implements part of the method; the patent covers more than the open-source code.

The Idea in a Minute

  • The base model is frozen and quantized. Its weights do not change.

  • For a specific task, a gate σ(m) is trained for each output row of each projection (--mask-scope linear: GDN, attention, FFN) or for each FFN neuron (--mask-scope ffn). One number per row.

  • The skill file stores only these numbers: for Qwen3.5-0.8B, there are 399,936, which is 1.7MB. In the FFN-only variant, it's 0.38MB.

  • skill apply multiplies each base row by its coefficient and saves the row in the base's own codec (ours is q8_2f). The result has the size and speed of the base.

How this differs from LoRA. LoRA adds two low-rank matrices to each layer: this is 10.8 million parameters and 43MB for r=16, and during inference, it introduces extra matrix multiplications in each layer (or a full model copy if the adapter is merged into the weights). The DTG-MA skill adds nothing: it scales what's already in the model.

Five Ways to Apply a Skill

The skill file carries identity keys – a hash of the tensor directory of the base model it was pruned against. Therefore, skill apply will refuse to work with a different or re-quantized base, instead of silently creating a chimera (there's a --force option for those who know what they're doing).

1. Embed into the Model

cortiq skill apply base.cmf emo.skill.cmf -o emo.cmf 
cortiq run emo.cmf -p "Меня наконец взяли на работу!"

This results in a separate specialist model with the size and speed of the base. Suitable when the model is needed for a single task: a phone, an embedded device, a service with a single function.

2. Overlay: One Base and a Shelf of Skills

cortiq skill apply base.cmf emo.skill.cmf --overlay -o shelf.cmf 
cortiq run shelf.cmf --skill emo -p "..."
cortiq run shelf.cmf --skill none -p "..."      # clean base
cortiq skill list shelf.cmf

The base tensors remain byte-for-byte, and the skill is deployed alongside as skill.<id>.* — re-encoded copies of the projections it modifies. The runtime reads the skill tensor instead of the base tensor — substitution, not addition; a second model is not assembled in memory. Consider the size: a skill for all projections of Qwen3.5-0.8B in overlay occupies about 490MB alongside the 796MB base, although the skill file itself for storage and transfer is 1.7MB. A skill for FFN only expands to an overlay of about 80MB.

3. Server: Skill per Request

cortiq serve shelf.cmf --skill emo     # one skill for all requests
cortiq serve shelf.cmf                 # routing policy: file selects per request

serve launches an OpenAI-compatible API. With --skill, all requests go through a single skill. If the file contains a routing policy, the server selects a skill for each request based on the user's last message. Each skill has its own pipeline with its own KV cache, so switching doesn't reset the state of other dialogues. A skill is activated only if it outperforms the base by a margin specified by the policy; otherwise, the base responds.

4. Blending and Switching During Generation

cortiq run shelf.cmf --blend auto -p "..."               # soft blend of the two best skills
cortiq run shelf.cmf --route-dynamic --trace -p "..."    # switch skill mid-response

--blend auto blends the two best skills with weights determined by the router's evaluation. --route-dynamic switches the active skill during generation when the context changes: for example, the response starts with an SQL query, and then continues with an explanation in Russian. --trace prints each switch.

5. Hard Mask: Smaller and Faster Than the Base

cortiq skill bake base.cmf --files corpus.txt -o specialist.cmf

Without --soft-fold, baking closes neurons and defragments the file: closed neurons are not stored or computed. A Qwen3.5-0.8B specialist for Russian technical text resulted in 705MB compared to the base's 733MB, 89.7 tokens/sec vs 86.0, and perplexity on held-out text dropped by 14.7%. Works where the base model is weak in a domain; if it's already good, check its perplexity first.

How to Bake Your Own Skill

cargo install cortiq-cli --locked --features cuda
cortiq convert --model Qwen/Qwen3.5-0.8B --quant q8_2f --output base.cmf
export CMF_GPU=cuda
cortiq skill bake base.cmf --files train.txt --held-files held.txt 
  --record-start '<|im_start|>system' --length-buckets 
  --answer-after $'<think>

</think>

' --answer-end '<|im_end|>' --checkpoint-accuracy 
  --mask-scope linear --mask-init 2.0 --lr-a 0.1 --lin-l1 0.02 --through-attn 
  --steps-a 750 --batch 8 --steps-b 0 --soft-fold --no-defrag 
  --checkpoint-dir ckpt --output specialist.cmf
cortiq skill export specialist.cmf --base base.cmf --id emo --gains-from ckpt/phase-a-step-750.json -o emo.skill.cmf

train.txt contains chat records (system, user, assistant). The loss function and accuracy on the held-out set are calculated only on the response after --answer-after, so the model learns to respond, not repeat the question. --through-attn passes the mask gradient through the frozen attention, similar to how autograd works in original method notebooks. --checkpoint-accuracy selects a checkpoint based on accuracy on the held-out set, and skill export --gains-from saves it as row coefficients. Baking is done on an NVIDIA graphics card; one RTX 3060 is sufficient.

Accuracy Within Noise, Gains in Size and Speed

  • Accuracy: Any difference with LoRA lies within the noise of its test. On 2000 texts about emotions, the noise is about ±1.2 points, and the difference is 0.1 and 0.8; on 100 tasks with equations, the noise is about ±4 points, and the difference is 4. In terms of balanced accuracy, the skill is ahead: 91.5% vs 85.4%.

  • Size: 1.7MB and 0.38MB compared to 43.3MB – 25–115 times smaller.

  • Training: 12 and 16 minutes vs 18 and 21.5 minutes on the same card, with the skill's time already including its checks on the held-out set.

  • Inference: An applied skill runs at exactly the base speed. A LoRA adapter adds extra matrix multiplications to each layer, and when merged into weights, it requires a full model copy for each task.

Is a Skill Store Needed?

A skill is a 1-2MB file for a model you are already running. Dozens of skills can fit alongside a single base, each downloaded in seconds, and skill apply turns it into a specialist or overlay in seconds. For a phone or a small server, you only need to transfer the skill file, not a second model.
