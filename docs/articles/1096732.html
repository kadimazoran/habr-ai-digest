Good Model, Short Context

Closed loop, energy sector, live cybersecurity. Copilot and Cursor are not an option for us because the code goes to external servers. However, we have our own internal gateway with Qwen.

The model is good. A recent mid-sized Qwen handles short tasks excellently. The problem is the context, which for us is about 100,000 tokens. The agent reads five files, modifies two, checks test output, and there's no space left. The model forgets the beginning of the task and starts looping.

Popular agents are designed for cloud models with vast contexts and consume them as they please. I reviewed several open-source options: Cline, Kilo Code, Continue. I took a little from each, more from some, less from others, and started adapting them for my needs. This is how Skycode came to be.

I initially started with a fork of VS Code itself, like Cursor. For one person, this proved to be unmanageable. Every Microsoft update had to be merged manually, build fixed, installer signing issues resolved. Eventually, I switched to a regular extension, which turned out to be even better for corporate use. I'll explain why below.

The Main Goal: Conserve Context

This is where the bulk of the work went. The goal is for the agent to read what's necessary and complete the task within 100,000 tokens.

Read in Chunks. A file can be read line by line, not in its entirety. There's a separate tool, read_symbol, which extracts a single method or class from a file. Models usually need a method, not a two-thousand-line file. If the model reads a file for the second time without changes, it receives a short confirmation like "file is the same," without the full text.

Don't Repeat What the Model Has Already Seen. After a modification, it receives the chunk around the change; it doesn't need the entire file again. Long terminal output is truncated, showing only the beginning and end. Environment descriptions are sent only if something has changed.

Compress History. When the context limit is approached, the session is compressed into a brief summary: what has been done and what remains. Here, I encountered a surprise. In the part inherited from Cline, for non-top-tier models, half of the history was silently dropped instead of being compressed. The model simply forgot what it was doing. Fresh Cline also has significant changes in compression, but I focused more on preventing the context from filling up in the first place.

See Where It Went. The interface has a ring that shows how much space is used and for what: files, command output, history. If one log consumes half the space, it's immediately noticeable.

Along the way, I fixed several issues unrelated to the model's core intelligence but which caused problems. The model sometimes repeated a phrase hundreds of times. The culprit turned out to be a temperature of 0; with the recommended settings for Qwen, loops were almost eliminated. The model also liked to write "I'll start by reading the files." and then end the response without doing anything. Now, the agent prompts it to continue in such cases. And if a response is cut off due to the length limit in the middle of writing a file, the truncated file is no longer saved. The model receives a hint to break the work into parts.

I've used very few hard restrictions in the prompt. It's easier to provide a hint at the right moment to support a model's weak spot.

Multiple Tasks in Tabs

This is what I use the most myself. Tasks open in tabs, like files in an editor. In one, the agent analyzes a module; in another, it writes tests. They work in parallel.

While the agent is busy, you can continue typing; messages will queue up. If urgent, a second Enter press interrupts the agent and sends the message immediately.

The short context actually helps here: the model handles a couple of small tasks in different tabs better than one huge one. The agent can also draw relationship diagrams and tables directly in the chat, which can then be copied to Word or Excel. This is very helpful with existing legacy systems.

Voice Input Without Internet

Voice typing, where text appears as you speak, is available in many places. But almost everywhere, the audio is sent to a server, which is not allowed in a closed loop.

Initially, I used Whisper, but its small Russian versions have mediocre recognition. I switched to GigaAM v3 from Sber. It recognizes 17 seconds of speech in about a second on a standard processor, complete with punctuation, and the text appears in the input field as you speak. The model is downloaded once; no internet is needed afterward.

Terminal or Editor

I showed Skycode to colleagues. One said: cool, but I use OpenCode or Claude Code in the terminal. This is when I realized that developers with agents fall into roughly two camps. Some prefer the console, and good tools already exist for them. I'm in the latter group; I like visuals and control. I want to see the changes directly in the file and revert them with a single click if necessary. Skycode is for people like that.

In a closed loop, the difference between a standalone program and an extension proved decisive. GitBor is installed as a program, and the AI version was not approved for our loop, so I had to create a non-AI build. It will be the same with console agents; they are also separate programs. Skycode, however, is a VS Code extension. In our company, like many others, everyone has VS Code installed, and extensions are installed from the Marketplace without separate approval. If these are also restricted, it's easier to negotiate with information security: the extension only communicates with the internal gateway, there's no telemetry, and the code is open.

Honest About What's Not Right

  • I'm developing it alone, so I haven't had time to test everything thoroughly.

  • I primarily tested on Windows. I barely ran it on macOS and Linux.

  • The context is still short. All these tricks extend it, but it's better to break down large tasks and review the diff visually.

  • There's intentionally no telemetry, so I only learn about user issues from them directly.

Why This Article

Skycode is free, and the code is open-source. I believe that in the corporate environment, the coming years will be dominated by internally hosted models rather than top-tier cloud ones. The key factor will no longer be which model is smarter, but how the surrounding tool conserves its context.

If you are also working behind a gateway with Qwen, GigaChat, or a local model, please share in the comments what breaks for you. The most useful improvements to Skycode have come from such shared experiences.
