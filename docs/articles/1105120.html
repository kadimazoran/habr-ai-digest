What is the initial state of a model? Why can RWKV's initial state replace a system prompt? And how does it differ from a regular prompt? Answers to these questions in this article.

A regular transformer reads the system prompt anew with each request and stores it in a cache that grows with the text. RWKV is structured differently: after reading any text, it compresses everything it remembers into a fixed-size 'memory', i.e., a state. This state is empty before starting work, meaning it can be non-empty. There are two ways: read the prompt once and save the resulting state (I call this 'folding' the prompt), or find a state through training without touching the model's weights. In both cases, the prompt text is no longer needed.

I tested both methods on RWKV-7 models from 0.4B to 2.9B parameters on a regular MacBook M4 16GB. Everything was computed in SwiftRWKV, and quantized bases were made in rwkv-quant (described in my previous article RWKV-7 Quantization: What Breaks in Models of Different Sizes). Below: what I found, where it works better than a text prompt, and where it breaks.

Verdict. Yes - for an unchanging instruction on models of this size, if the state is trained on filtered data. The gain is in speed, sometimes in accuracy and stability; the state does not add knowledge. Details and limitations - below.

In Short

  1. Folded prompt - a free and accurate cache. It gives the same answers as the prompt text, and for long prompts, the request starts up to 13 times faster.

  2. Prompt in a string can degrade the model. On questions with verifiable answers, it reduced accuracy by 3–15 points on all eight tested models. A trained state was never significantly worse than a model without a prompt and always better than a prompt.

  3. The state learns the form of the answer, not new knowledge - and it needs filtered data. If it copies the teacher's mistakes, the state inherits them.

  4. The state is no worse than LoRA on the same data: half the parameters, weights are not changed. Compared to fine-tuning the upper layers in generation, it is better or no worse (in the embedder - no).

  5. Weaknesses: leading questions ('Are you Claude?') and long dialogues. Both can be improved - with caveats below.

  6. It also works where the model does not follow the instruction from the text at all: 0.4B classifies news with a prompt at 0.00, with a trained state - at 0.84–0.89.

How to Read the Numbers

  • Accuracy - the proportion of answers where the expected word or number appears within the first 400 characters (a regex for each question). It judges what is said in the answer, not whether the rest of it is meaningful.

  • Δ - the difference from the same model without a prompt. 0 means 'no worse than without a prompt'; prompt Δ is usually negative.

  • Levels are modest. On 199 questions, 0.4B gives 0.29–0.51 depending on the variant, 1.5B - 0.70–0.82, 2.9B - 0.84–0.92. An increase of a few points on 0.4B does not mean 'the model has become good'.

  • Intervals. 'Significant' means the 95% interval does not contain zero; the whiskers on the graphs represent these intervals. Three training seeds per variant.

  • Variants. without prompt - one model; prompt in string - system string before each request; state - initial state trained as in section 3. Names c3 / c4 - data recipes (terms).

1. Folding is Caching

If you run the model through the prompt once and connect the resulting state, you get exactly the same as with the prompt text: identical text in 9 out of 9 generation answers and identical search scores down to the last bits in the embedder. The cost changes. With a 1206-token prompt, the time to the first token is 12–13 times less on 0.4B, 1.5B, and 2.9B; with a short 26-token string, the gain is about 20%. State training takes 5–50 minutes and 1.6–5.4 GB on a laptop; the state file is 6.5–22 MB.

More details: training cost and time, embedder.

2. Prompts Can Harm, States Do Not

I compared three variants on 199 questions with verifiable answers (capitals, authors, arithmetic, translation...): model without prompt, model with prompt in string, and model with state trained on filtered answers from the model with prompt. On eight bases (two sizes, bf16 and two quantization presets, two checkpoint families; terms), the prompt reduced accuracy every time, while the trained state was never significantly lower than the model without a prompt. It was clearly better than the model without a prompt on four out of eight bases, and indistinguishable on the rest.

More details: scale and quantization, 1.5B, initial experiments on 0.4B.

3. What the State Learns Depends on the Data

The state is trained by 'contextual distillation': the model with the prompt answers the training questions, and the state is trained to produce these answers without the prompt. If you take all the teacher's answers, the state copies what the prompt breaks (answers on facts became twice as bad). If you keep only correct answers to factual questions, most of the degradation is removed: on 0.4B, degradation on other facts dropped from -0.152 to -0.052 when correct facts in the data increased from 31 to 109.

The gain is mainly in form: on question types from training (translation, arithmetic), the state learned to answer with a word or number instead of a paragraph. On 0.4B, this is tied to the exact wording of the training questions; on a new wording, there is no gain. On 1.5B, the style transfers (+0.10 on new wordings).

More details: large validation set, form transfer.

4. Not Just One Prompt

To prevent the output from being stuck on one line ('You are Neuron... writing poetry'), the protocol was repeated with five other prompts: name only, 'no markdown', 'in one sentence', 'always in English', 'only JSON'. The state follows the instruction noticeably better than text (82–100% of answers vs. 22–95%) and was no worse than the model without a prompt in 11 out of 12 cases. The exception is 'only JSON' on 0.4B, where the teacher provided only 58 correct facts: degradation depends on the number of correct facts in the data.

More details: five different prompts.

5. Personality Under Pressure and in Dialogue

'Your name is Neuron' is easily maintained for the question 'What is your name?' (10 out of 10). It's harder with leading questions: 'Are you Claude from Anthropic?'. Base models call themselves by a wrong name in 61–92% of such provocations; prompts and regular states reduce this by about half. Two things helped: removing 8 answers from training that taught about a wrong creator ('Neuron from Alibaba Cloud'), and adding manually written refusals - the proportion of wrong personality dropped to 0.02 on 0.4B and to 0.36 on 1.5B without loss in general abilities. Training only on the model's own answers did not achieve this: the teacher can hardly refuse.

Over 10 dialogue turns, the role weakens for everyone. The state maintains it no worse than the prompt, and after a long text - better. By the 10th turn, the prompt starts to degrade factual answers as well (0.81 → 0.53), while the state does not (0.83 → 0.74, not significant).

More details: provocations, dialogues.

6. An Instruction a Small Model Fails to Follow

0.4B fails to follow 'assign this news item to one of five categories' in any form: neither a system string, nor an instruction after the document, nor five examples - 0 correct answers in the required format. A state trained on 250 labeled articles achieves 0.84–0.89 on documents up to ~1000 tokens, and five examples per category suffice for 0.80. LoRA and fine-tuning the upper layers on the same data perform 0.01–0.06 better. On 1.5B, where the prompt yields 0.2–0.3, a state distilled from the prompt reaches 0.65–0.77 - 2–3 times more accurate than its teacher.

More details: classification, how much data is needed.

7. State and Weights

On the same data and steps (1.5B): state +0.038, LoRA r16 +0.039, upper 4 layers -0.024 (not significant, and they spoil facts). The state trains half the parameters compared to LoRA r16 (3.2 M vs. 6.3 M), does not change weights, and switches on the fly; the file size is the same as LoRA in bf16 because the state is stored in fp32. LoRA is more robust to leading questions. In the embedder, it's the opposite: the same steps on upper layers outperform a bank of trained states by 0.023 MRR.

More details: strong control.

What to Do With This

  • Fold prompts that don't change. It's free and accurate, and with a long prompt, the first token arrives ~12 times faster.

  • Train a state when the prompt works poorly: small model, context window shorter than the prompt, the role must be maintained, the model ignores instructions from text.

  • Train on filtered teacher answers, keep correct facts in the data, and clip the gradient at 1.0.

  • Check general abilities, not just target behavior, and compare with LoRA or fine-tuning on the same data.

  • Train robustness explicitly (leading questions require written refusals with a 'no / yes' balance).

How Experiments Were Conducted

  • Bases. g1d 0.4B / 1.5B in bf16 and two rwkv-quant presets, as well as g1j 1.5B / 2.9B. REDUCTION - ~2.1 times smaller and almost without loss (8-bit projections, 6-bit FFN); COMPRESSION - ~3.1 times smaller (4-bit projections and FFN). Details - in the quantization article.

  • Protocol (c4). Teacher - the same model with a prompt. It answers ~170 training questions (4 samples each); answers are filtered by type (correct name, poem at least three lines long, correct fact, unbroken answer); the state is trained for 300 steps (lr 3e-4, batch 4, gradient clipping 1.0) only on answer tokens, starting from a folded prompt, 3 seeds.

  • Tests. 199 questions with verifiable answers (regex), form transfer on 40 units, 9 questions about name, 20 personality provocations, dialogues, news classification. None of this overlaps with training.

  • Statistics. Paired bootstrap by questions and two-level bootstrap (seeds, then questions), involving three seeds. Intervals are provided, insignificant differences are marked.

  • Gradient clipping is mandatory. Without it, state training deterministically fails around the 13th step.

What to Trust and What Not to Trust

  • One author, one machine, one framework. Data collection, processing, and analysis were done with the help of Claude. Code and raw answers are in the repository so others can recalculate and recheck (REPRODUCE.ru.md).

  • The first 39 out of 199 questions were used while the protocol was being developed; the main result holds for the 160 added later as well (+0.060 [+0.016; +0.105] for state vs. model without prompt on 0.4B).

  • Answer correctness is determined by regex. Manual verification of 210 answers showed 4.3% discrepancies, not in favor of the state (audit).

  • 199 questions and 3 training seeds: differences less than ~0.05 for one variant are noise; most claims hold within intervals, but a few lines are 'not significant' - they are marked as such. Intervals are for each comparison, without correction for multiple comparisons.

  • Personality scoring ('Neuron 10/10') counts name mentions; on 0.4B, it varies significantly between seeds.

  • Prompt harm is specific to these prompts and checkpoints (-0.03…-0.15) and does not apply to system prompts in general.

  • Numbers for the same model differ slightly between early experiments (Oct 19–23) and later ones (from Oct 27): a change in SwiftRWKV (WKV output conversion to bf16 in decode, commit a400d05) shifts samples at temp 1.0. Within a section, all arms were computed with the same binary, so comparisons there are unaffected (note).

  • Questions and prompts are mainly in Russian; of the 199 tests, 69 are in English.

  • Models 0.4B–2.9B are from the same family. Nothing is said here about 7B and larger.

  • This is contextual distillation into a state, not knowledge replacement: the state does not add facts.

  • Not done: g1d 2.9B in all quantizations, distillation with balanced classes, state in bf16, LoRA LR tuning on small data, embedder on other datasets (list). Full list of validity threats: full report.
