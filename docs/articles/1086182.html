What happens when an AI system needs to answer not just "What do I remember?", but also show which historical source confirms the answer?

In SRX, I'm experimenting with a different approach to long history: instead of passing the entire accumulated context to the model, the system first finds the required data version, reconstructs it, and verifies it against the original source. Only then can the result be given to the LLM for interpretation.

Why Ordinary Search Is Not Enough

Imagine the parameter database.pool_size changed like this:

v1: 4
v2: 16
v3: decision made to switch to 32
v4: decision canceled, value reverted to 16

Semantic search or RAG can find all four entries. But the system still needs to understand which state corresponds to the required version, which decision was later canceled, and whether the original file on which the answer is based can be restored.

Therefore, in SRX, the chain looks like this:

storage
  ↓
retrieval
  ↓
state reconstruction
  ↓
verification
  ↓
answer

The LLM here should not "decide" for itself whether the data matches. Reconstruction, hash, and verification remain deterministic.

LLM never creates metrics; LLM only interprets measured evidence.

What Has Been Tested

To avoid being limited to synthetic data, SRX was tested on the real Git history of Vite. The system imports 50 first-parent commits, reconstructs selected historical states, and compares them with the original Git history.

Result:

Imported real commits: 50
Persistence reload: PASS

Verified evidence: 4/4
SRX verification: PASS
bit-perfect vs git show: PASS
source SHA match: PASS

This means the selected historical states were reconstructed byte-for-byte and passed the SHA-256 verification.

This is not yet proof of retrieval quality. But it confirms a fundamental point: a historical answer can be linked to a realistically reconstructed and verified source.

What Didn't Work

Initially, I also tested SRX as a way to represent changes between versions more compactly.

The results were much weaker than expected. On some real data, structural operators provided no advantage at all, and strong baselines like zstd + reference performed better.

Therefore, I consider the hypothesis "SRX as a new compressor" closed.

Now, another question is more interesting:

Can only the minimally necessary fragment of history be reconstructed, the correct answer obtained, and simultaneously a verifiable source be shown?

This is precisely the direction that seems most important to me now.

What's Next

The next stage is to measure selective reconstruction: how much history is actually needed to reconstruct for an answer, how accurately the required state is selected, and whether it can be confirmed by the original source.

I am also separately investigating whether it's possible to machine-describe the meaning of the change between versions, not just record the byte difference. But conclusions here will only come after a separate experiment.
