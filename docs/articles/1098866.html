Honestly, I didn't understand why SKILLs were needed for LLM agents. With MCP, it's clear: a useful tool to give LLM access to a database or Figma. The only drawback is that to avoid wasting tokens, it's best not to connect 30 MCP servers at once. And in general, it's better to disable unnecessary ones and connect only those that are truly needed for the task. In this light, SKILLs seemed like useless overhead that devours tokens like crazy. I often saw TikTok rants like: connect this SKILL or a whole bunch of them, and you'll be happy. I immediately thought: if I connect them all, subscription limits will run out not by lunch, but by morning.

So why are SKILLs useful and necessary after all? Well, firstly, compared to MCP, SKILLs don't bloat the context: each connected SKILL adds not tens of thousands of tokens, but 1-2 hundred. Since only the SKILL's name and description are initially included in the context, you can add 30 of your own SKILLs without significant consequences. When a SKILL needs to be used, the LLM agent will pull its description itself if it understands from the task context that it's necessary, or the user will tell it to use such a SKILL for the job.

Secondly, LLM models are trained on the most popular and well-known things. For example, it's obvious to everyone that an LLM can work with Git or write a Python program without issues. But if you've developed your own program or need to use an obscure tool or technology for your work, a SKILL is simply indispensable. You just need to create a SKILL.md file and describe how to work with this program or technology in it. This way, you make life easier for the LLM: when performing your tasks, it won't have to search for documentation online and browse websites to understand how to use it. Especially if there's nothing online because your program is not publicly accessible.

Thirdly, an LLM model usually doesn't know how your development process is structured. For example, an agent knows how to use Git, run tests, build a project, and create releases. It doesn't need to be taught this. But it doesn't know how releases are typically made in your company. A SKILL can describe a sequence of actions: check changes, run tests, update CHANGELOG.md, increment the version, build the package, create a Git tag, and publish the release. That is, a SKILL helps to master not a technology, but a specific business process.

Fourthly, a SKILL is not just an instruction, but a whole set of tools. Besides SKILL.md, you can include ready-made scripts, documentation, templates, and other files. And the most interesting part: all these files are not automatically loaded into the context. The agent reads them only when necessary, and it can simply run ready-made scripts without spending tokens on code generation. Thus, a SKILL allows you to combine instructions, documentation, and executable code into one package without bloating the LLM's context. For example, the structure might look like this: 

my-skill/
├── SKILL.md
├── scripts/
│   ├── generate.py
│   └── validate.py
├── references/
│   └── api.md
└── assets/
    └── template.html

The funniest thing is: I only appreciated SKILLs when I wrote my own program, blueprint4llm. The idea to create it arose after I asked an LLM agent to generate a plan.md file describing a task. Usually, it outputs a large block of text that is slow and tedious to read. I wanted to shorten the text and add more flowcharts, tables, diagrams, and user interface prototypes. As you know, in .md files (Markdown), only tables and Mermaid diagrams are available as visualization tools. They lack charts, graphs, histograms, full UML diagrams, and UI prototypes. As a result, with the help of blueprint4llm, I added support for formats like PlantUML, draw.io, Pencil, Balsamiq, Graphviz, Figma, OpenAPI, Excalidraw, Vega-Lite, ECharts, and D2 to .md.

By connecting the blueprint4llm SKILL, you will receive plan.md not as a kilometer-long text, but as flowcharts, prototypes, graphs, etc. By the way, blueprint4llm doesn't necessarily have to be used only for creating plan.md. For example, I used this SKILL to add an illustration to each paragraph of the article and make it more engaging to read. This SKILL is also convenient to use when you task an agent with compiling a comprehensive dossier on a company, technology, or person and ask it to format the final result.md file using blueprint4llm. It can then be converted to HTML or PDF, or you can ask the agent to display it directly in the browser with graphs.

Here's how you can install the blueprint4llm SKILL.

# Codex
npx skills add evgenyigumnov/blueprint4llm --skill blueprint4llm --agent codex

# Claude Code
npx skills add evgenyigumnov/blueprint4llm --skill blueprint4llm --agent claude-code
