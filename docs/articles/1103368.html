Immediately after Jev's release, everyone rushed to create analogs: Liquid AI, for example, showcased d1 just two weeks later. Why should we be any different? Well, in terms of quality, probably worse. But at least it's free.

Now, we'll break down what happens inside a language model when it "answers" with a single letter, and build a simple Jev analog on a T4 in Colab: a core of about 70 lines, probability calibration, and speed measurement. I'll preface this by saying: this is not Jev. We'll take a regular instruct model and read the solution from its logits without fine-tuning, so in terms of quality, it won't reach models specifically trained on solutions.

❯ What We're Replicating

Jev has a simple interface: input is the state (text) and a set of named questions, output is probabilities. Questions come in three types: yes/no, choice from options, and score on a scale. We'll do the same: Bool, Choice, and Score functions, and the output will be a dictionary of probabilities.

❯ How LLMs "Answer": From Tokens to Logits

To understand where a solution without a single word of text comes from, we need to peek inside the language model. There's nothing scary there: six steps will suffice.

What Happens in One Pass

  1. Tokenization. Text is cut into tokens (word pieces), and each corresponds to a number in the vocabulary. Modern models have vocabularies ranging from tens of thousands to hundreds of thousands of tokens.

  2. Embeddings. Each number is converted into a vector that the network layers can process.

  3. Transformer Layers. The attention mechanism allows each token to "look" at previous ones and incorporate relevant information. After all layers, each token has its own hidden state: a vector that already incorporates all the context to its left.

  4. Last Token. To predict the next token, only the hidden state of the last token of the prompt is needed: everything else has already been incorporated into it via attention.

  5. Logits. This state is multiplied by a "vocabulary size × dimensionality" matrix, resulting in one number for each token in the vocabulary. These numbers are called logits: the higher the logit, the more readily the model would choose that token next.

  6. Softmax. Logits are converted into probabilities using the formula p_i = exp(z_i) / Σ exp(z_j): all values are positive and sum to one.

Regular generation does one thing with this distribution: it selects a token (the most probable or a random one), appends it to the text, and restarts the process for the next token. To get a JSON like {"angry": true, "team": "billing", "urgency": 3}, this needs to be repeated dozens of times: brackets, quotes, keys, and values are also tokens. The exact number depends on the tokenizer, but it's around twenty to thirty steps, each waiting for the previous one.

Where the Solution Hides

Now for the interesting part. If the prompt says "answer with a single letter: A, B, or C," then at the very first step, the model already distributes probabilities among the tokens A, B, and C. There's no need to select or append anything: just look at these three numbers. We discard everything else from the vocabulary and recalculate softmax only on the option letters: p_A = exp(z_A) / (exp(z_A) + exp(z_B) + exp(z_C)).

It turns out that the solution is already present in the logits of the last position of the prompt. The prompt itself is processed in a single parallel pass (the GPU calculates all its tokens at once in a large matrix operation), and after it, there's no need to wait for any generated tokens. This is precisely why this approach should be faster than regular generation. We'll measure this below.

Why letters, not words? A word like "billing" might be split into several tokens, and then its probability would have to be pieced together from multiple steps. One letter is one token, and all options are fairly compared. The trade-off is positional bias: the model might favor options at certain list positions. We'll address this too.

What "Doesn't Hallucinate" Means

The answer won't go beyond the list of options: we only look at the letters from the list. But this is a format guarantee, not a truth guarantee: the model can be confidently wrong. Next, we'll check how much the probabilities can be trusted at all.

❯ Hardware and Model

Free Colab usually provides a T4 with 16 GB of memory (in practice, about 15 GB is available), sessions last up to 12 hours, and GPU availability is not guaranteed: it's a lottery, but a free one. The T4 lacks hardware support for bfloat16, so we work in float16.

We'll use Qwen/Qwen2.5-1.5B-Instruct: in fp16, this is about 3 GB, and such a model usually works fine in float16. If you need more precision, Qwen/Qwen2.5-3B-Instruct (about 6 GB) is suitable. Models trained in bf16 sometimes output NaN in fp16, so the code includes a check for finite logits.

❯ Step 1. Core

import torch from transformers import AutoTokenizer, AutoModelForCausalLM LETTERS = 'ABCDEFGHIJKLMNOPQRSTUVWXYZ' SYSTEM = ('You are a decision engine. Read the state, then answer the question ' 'with exactly one option letter and nothing else.') def Bool(text): return {'type': 'bool', 'instructions': text, 'options': ['Yes', 'No']} def Choice(text, options): return {'type': 'choice', 'instructions': text, 'options': list(options)} def Score(text, lo=1, hi=5): vals = list(range(lo, hi + 1)) return {'type': 'score', 'instructions': text, 'options': [str(v) for v in vals], 'values': vals} class MiniJev: def __init__(self, model_id, dtype=torch.float16, device='cuda'): self.tok = AutoTokenizer.from_pretrained(model_id, padding_side='left') if self.tok.pad_token is None: self.tok.pad_token = self.tok.eos_token self.model = AutoModelForCausalLM.from_pretrained(model_id, dtype=dtype).to(device).eval() self.device, self._ids = device, {} def _label_ids(self, label): if label not in self._ids: ids = set() for v in (label, ' ' + label): # 'A' and ' A', only if it's a single token t = self.tok.encode(v, add_special_tokens=False) if len(t) == 1: ids.add(t[0]) self._ids[label] = sorted(ids) return self._ids[label] def _prompt(self, state, instructions, options): lines = '
'.join(f'{LETTERS[i]}. {o}' for i, o in enumerate(options)) user = (f'State:
{state}

Question: {instructions}

' f'Options:
{lines}

Answer with the letter only.') msgs = [{'role': 'system', 'content': SYSTEM}, {'role': 'user', 'content': user}] return self.tok.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True) @torch.no_grad() def _option_logits(self, prompts, k): enc = self.tok(prompts, return_tensors='pt', padding=True, add_special_tokens=False).to(self.device) logits = self.model(**enc).logits[:, -1, :].float() # readout at the last position assert torch.isfinite(logits).all(), 'NaN/inf: try float32 or another model' return torch.stack([torch.stack([torch.logsumexp(logits[i, self._label_ids(LETTERS[j])], 0) for j in range(k)]) for i in range(len(prompts))]) def logprobs(self, state, q, debias=True): opts, k = q['options'], len(q['options']) shifts = range(k) if debias else [0] prompts = [self._prompt(state, q['instructions'], opts[r:] + opts[:r]) for r in shifts] lp = torch.log_softmax(self._option_logits(prompts, k), -1) # (shifts, k) out = torch.zeros(k, device=lp.device) for row, r in zip(lp, shifts): for j in range(k): out[(j + r) % k] += row[j] / len(shifts) return out # mean log-prob of each ORIGINAL option def decide(self, state, questions, T=1.0, debias=True): res = {} for name, q in questions.items(): p = torch.softmax(self.logprobs(state, q, debias) / T, -1).tolist() item = {'probs': dict(zip(q['options'], p))} if q['type'] == 'bool': item['p_yes'] = p[0] if q['type'] == 'score': item['value'] = sum(a * b for a, b in zip(p, q['values'])) res[name] = item return res

Usage:

jev = MiniJev('Qwen/Qwen2.5-1.5B-Instruct') state = 'I was charged twice this month, please refund one of them.' print(jev.decide(state, { 'angry': Bool('Is the customer angry?'), 'team': Choice('Which team should handle it?', ['billing', 'tech support', 'sales']), 'urgency': Score('How urgent is it?'), }))

The output for each question will be a dictionary with probabilities for the options, plus p_yes for yes/no and the expected value for the score.

How It Works Internally

  1. Prompt. _prompt assembles the message: instruction, state, question, and options A, B, C. The chat template adds "assistant's turn" at the end, so the next token is already the beginning of the response.

  2. Single Pass. _option_logits runs the entire batch of prompts through the model and takes logits[:, -1, :]: the distribution for the first response token, i.e., the last position.

  3. Option Labels. For each letter, we take the token IDs for A and ' A' (with a space): depending on the tokenizer, the response might start with either. We only take options that are encoded as a single token.

  4. Summation. If a letter has two tokens, their probabilities are summed. This is done using logsumexp: which is log(exp(a) + exp(b)), i.e., summing probabilities directly in logarithms, without loss of precision.

  5. Normalization Only on Options. The model might assign some probability to a word like "The." We discard this and normalize only among the option letters.

  6. Left Padding. Prompts of different lengths are aligned to the left, so the last position is the actual end of the prompt for all of them. For models with RoPE, the positional shift due to padding does not affect the result: on a tiny random model, batch and single requests matched to within 3·10⁻⁸.

Combating Positional Bias

Models tend to favor options at certain list positions. The debias=True parameter runs all cyclic shifts: for ['billing', 'tech support', 'sales'], this means three prompts where each option becomes letter A in turn. Then, the log-probabilities are averaged across the original options. For yes/no, this is two passes; for choosing from five, it's five. In a test with a "rigged" model that favors the first position, the incorrect option won without averaging, while the correct one won with averaging.

❯ Step 2. Calibration

Now for the million-dollar question: can these numbers be trusted? Not yet. The model was trained to predict the next token, not to output honest solution probabilities, so 0.9 from it doesn't actually mean "I'm right 90% of the time." A typical scenario: the model is overconfident or biased towards one label, e.g., "Yes.".

This can be fixed cheaply: it requires 100–300 labeled examples and a couple of lines of code.

Platt Scaling is suitable for yes/no. We take the difference in log-probabilities z = log P(yes) − log P(no): this is the model's "confidence" on a logarithmic scale. Then, we fit a logistic regression p = σ(a·z + b) with just two parameters: 'a' stretches or compresses the confidence, and 'b' shifts the threshold.

Temperature Scaling is suitable for choosing from multiple options. It has one parameter T: probabilities are calculated as softmax(s / T). With T > 1, the distribution smooths out; with T < 1, it becomes sharper.

We measure the quality of probabilities using ECE (Expected Calibration Error). All predictions are divided into ten bins based on confidence, and in each bin, the average confidence is compared to the actual proportion of correct answers. ECE is the weighted average difference. If ECE is 0.05, it means the model's confidence is off by 5 percentage points from the actual accuracy, on average.

import numpy as np from sklearn.linear_model import LogisticRegression from scipy.optimize import minimize_scalar def ece(probs, y, bins=10): probs, y = np.asarray(probs), np.asarray(y) conf, ok = probs.max(1), probs.argmax(1) == y edges = np.linspace(0, 1, bins + 1) total = 0.0 for lo, hi in zip(edges[:-1], edges[1:]): m = (conf > lo) & (conf <= hi) if m.any(): total += m.mean() * abs(ok[m].mean() - conf[m].mean()) return float(total) class Platt: def fit(self, z, y): self.lr = LogisticRegression(C=1e6).fit(np.asarray(z).reshape(-1, 1), y) return self def predict(self, z): return self.lr.predict_proba(np.asarray(z).reshape(-1, 1))[:, 1] def fit_temperature(S, y): # S: (n, k) log-probs, y: (n,) S, y = np.asarray(S), np.asarray(y) def nll(log_t): z = S / np.exp(log_t) z = z - z.max(1, keepdims=True) lp = z - np.log(np.exp(z).sum(1, keepdims=True)) return -lp[np.arange(len(y)), y].mean() return float(np.exp(minimize_scalar(nll, bounds=(-3, 3), method='bounded').x))

❯ Step 3. Measuring on SST-2

Let's take SST-2 from GLUE: binary sentiment of reviews. Out of 600 examples, 200 will be used for calibration, and 400 for testing.

from datasets import load_dataset ds = load_dataset('glue', 'sst2', split='validation').shuffle(seed=0) q = Bool('Is the sentiment of this movie review positive?') def margins(rows): out = [] for r in rows: lp = jev.logprobs(r['sentence'], q) # [log P(yes), log P(no)] out.append((lp[0] - lp[1]).item()) return np.array(out) z = margins(ds.select(range(600))) y = np.array(ds[:600]['label']) # 1 = positive = 'Yes' z_cal, y_cal, z_te, y_te = z[:200], y[:200], z[200:], y[200:] platt = Platt().fit(z_cal, y_cal) p_raw = 1 / (1 + np.exp(-z_te)) p_cal = platt.predict(z_te) def report(name, p): print(name, 'acc=%.3f' % ((p > .5) == y_te).mean(), 'ECE=%.3f' % ece(np.stack([1 - p, p], 1), y_te)) report('raw', p_raw) report('calibrated', p_cal)

The run was performed in Colab. Methodology:

  • Dataset: GLUE SST-2, validation split, shuffled with seed=0;

  • The first 600 examples were taken: the first 200 went into the calibration set for Platt scaling, the next 400 became the test set;

  • MiniJev calculated the difference in log-probabilities of Yes and No, and we evaluated the quality of probabilities before and after calibration.
