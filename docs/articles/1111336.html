How to make neural networks smarter without inflating them to gigantic sizes? The answer was presented on November 23 by the Chinese laboratory Z.ai, previously known as Zhipu AI. 28 layers, two passes, and not a single new parameter. This is how the new GLM is structured, according to TNW.

GLM-5.4 has become the company's first flagship model based on the Loop Transformer architecture, where the same layers are applied to a token repeatedly. What this is and how it affects model inference is discussed below.

How Loop Transformer is structured

In conventional neural networks, a query passes through layers strictly in sequence—from the first to the last, like on a conveyor belt. In Loop Transformer, some layers are looped. Instead of building a huge model from hundreds of unique blocks, the neural network takes one section and processes the data through it multiple times in a row. This is analogous to re-reading. The model, as it were, re-checks its thoughts before responding, without increasing its own size.

In the new model, 28 layers of the base GLM-5 are processed twice. This increases processing depth while the size of the neural network itself remains the same. It was not trained from scratch—Z.ai simply fine-tuned an existing base. The developers themselves admit that with equal computational costs, such looped models currently underperform conventional architectures if trained from scratch.

To prevent the repeated pass from increasing costs, Z.ai employed three techniques at the 750 billion parameter scale:

  • smart gates that decide for each token what to write into the main data stream;

  • a hybrid KV cache with a single sliding window for the additional loop;

  • reusing sparse attention indices from the first pass.

Experiments were conducted on models of various scales—1, 4, 30, and 750 billion parameters. For the 30 billion parameter version, adding the loop required about 10% additional resources during training. The biggest improvements in quality were seen in mathematics, scientific reasoning, and handling long contexts. At the same time, responses in complex tests like GPQA-Diamond and MMLU-Pro became 10–14% shorter on average.

A week earlier, Thinking Machines demonstrated a similar technique. In Inkling 2 Mini, intermediate blocks are also processed three times. Two labs released Loop models within seven days, and this seems to be the start of a trend.

What it costs in production

There is no data yet, as the announcement was literally made yesterday. Based on the architecture, the repeated blocks incur twice the computation per token with the same weights. Memory for weights does not increase, and the hybrid cache should curb the growth of memory for context. Z.ai claims speeds of up to 200 tokens per second during off-peak hours and 70–80 during peak hours.

There is already an independent analysis by AlphaSignal. It notes that there is no technical report or service data, the number of passes in production is not disclosed, and a fair comparison requires an equal computational budget. Z.ai itself mentions the model's tendency to go into overly long "marathon" reasoning as a limitation.

What can be used today

Subscribers to the Coding Plan have already gained access to the new model—their weekly quota has been increased by 50% compared to GLM-5.3. The model works in ZCode and Z.ai Chat. To connect it in Claude Code, you need to specify the identifier glm-5.4[1m], and for other tools, the regular glm-5.4 will suffice.

The context window is 1 million tokens. The main new feature for developers is built-in image processing, but it only works for input; the model cannot generate images.

Others will have to wait. The paid API will only be launched after a security check, and the weights will be released publicly after additional safety hardening. Z.ai has not yet provided specific timelines, prices, or license types.

Can we believe "like 2–3 trillion"

So far, this is a claim without numbers. Z.ai's blog includes an internal graph comparing the base and Loop versions on AIME25, GPQA-Diamond, AA-LCR, MMLU-Pro, and IFBench benchmarks, but there are no specific scores in the text. The only external assessment is a review by an early tester for TestingCatalog, who stated that the new model is no weaker than Qwen4-max. But this is just one informal run.

There is also confusion about the model size. TNW reports 750 billion parameters, and AlphaSignal's newsletter mentions approximately 700 billion, clarifying that Z.ai itself has not disclosed the figures. However, since no new parameters were added, the size should match the base model. On Z.ai's Hugging Face page, GLM-5.3 is listed as 753B, so 750 billion seems more plausible.

If the weights are released publicly, with FP8 quantization (one byte per parameter), they will occupy about 750 GB. To simply run such a model, a server with at least eight H200 accelerators would be needed.

Moving forward, it's worth watching two things: whether a technical report with comparisons on an equal computational budget will be released, and what the "significantly larger" next model will show.
