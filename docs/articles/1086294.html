There was a popular Chinese extension Dadda Translate (达达划词翻译): you highlight a word, get a translation, save it to a vocabulary list, and the word later pops up as a notification until you memorize it. It stopped working: the Sogou and Shanbay APIs, which powered the translation, changed or disappeared. Moreover, it was only for Chrome and only for English → Chinese.

I rewrote it from scratch. The result is WordToast for Firefox, Chrome, and Edge (GitHub). It translates to the browser's language, can work entirely on-device, and explains words in context using your own AI key. In the article, I will discuss three technical parts:

  1. Chrome's built-in Translator API: useful, but with non-obvious limitations;

  2. calling LLMs directly from the extension, without your own server;

  3. pop-up cards over any site that don't break from external CSS and CSP.

Multiple Engines and Fallback

There are five translation engines:

  • Google (public endpoint translate.googleapis.com);

  • MyMemory;

  • DeepL with your key;

  • Chrome's built-in translator;

  • any LLM.

The engines are chained: if the first one returns an error, limit, or empty response, the next one is used. For single English words, the card is supplemented by the dictionaryapi.dev dictionary: parts of speech, definitions, examples, pronunciation.

A couple of practical observations:

  • Free APIs can have slow responses. dictionaryapi.dev sometimes takes 10 seconds to respond or returns 5xx. Therefore, each request has its own timeout: the card first shows the translation, and the dictionary part loads afterward.

  • DeepL has two addresses. A free key is identified by the suffix :fx and goes to api-free.deepl.com, a paid one goes to api.deepl.com. It's easy to forget this and get a mysterious 403.

  • The original did something dangerous. Dadda downloaded a script from the translator's website and executed it using eval to get a token. This is forbidden in MV3, and it was a bad idea even before. WordToast does not use any external code.

On-Device Translation: Chrome's Translator API

Starting with Chrome 138, the browser has built-in translation and language detection models: Translator and LanguageDetector. Text doesn't go anywhere; everything is processed locally. For an extension that sees everything you highlight on pages, this is a strong argument for privacy.
