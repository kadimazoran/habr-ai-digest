I have two Claude accounts. The first is corporate. The second is personal, I pay for it myself and use it in my projects. Both run on the same machine, and it quickly became clear that they should be kept separate.

There are several reasons. Work code should go through the work account because the company has its own rules for this. Conversely, I don't want to run my own projects at the employer's expense and leave them in the corporate history. You can switch manually via /logout and /login, but "is this life?".

I wanted the account to be selected automatically, depending on which project I opened. It turned out to be very easy to do. Below I will explain how to set this up on Linux. For Windows, it's done analogously - I think you'll figure it out.

Where Claude Code stores its files

Everything related to the user, Claude Code keeps in one folder. By default, this is ~/.claude (user's home directory on Windows). Next to it is the file ~/.claude.json.

What

Where (Linux)

Authorization token

~/.claude/.credentials.json

Global settings

~/.claude/settings.json

Global instructions

~/.claude/CLAUDE.md

Agents, skills, plugins

~/.claude/agents/, ~/.claude/skills/, ~/.claude/plugins/

Session history

~/.claude/projects/

State, MCP servers

~/.claude.json

The location of this folder can be changed by the environment variable CLAUDE_CONFIG_DIR (environment variables). If it is set, Claude Code looks for everything in the specified location, and .claude.json also moves inside. Two folders give two independent Claude Codes, each with its own account, settings, and history.

I left my personal account in the old (default) location, and for work, I created ~/.claude-work:

~/.claude        personal account
~/.claude-work   work account
CLAUDE_CONFIG_DIR=~/.claude-work

Now we need to make sure the variable is set automatically and only where needed. Let's start with the terminal.

Divide and conquer

Linux / macOS

First, run Claude once with the new directory and log in with your work account:

CLAUDE_CONFIG_DIR=“$HOME/.claude-work” claude

The directory is empty, so Claude Code will go through the initial setup and prompt for authorization. If it doesn't prompt, you can force it with /login. Log in with your work account.

Then, add a short command (in this case, for the bash / zsh shell, add the line to ~/.bashrc or ~/.zshrc):

alias claude-work='CLAUDE_CONFIG_DIR="$HOME/.claude-work" claude'

Let's check in any terminal now:

  • claude launches the personal account

  • claude-work launches the work account

A good start, half the job is done. But what about VS Code?

Using VSCODE profiles

We've sorted out the terminal. It's more complicated with VS Code because the Claude Code extension itself launches the claude process and is completely unaware of our alias.

The first thing that comes to mind is configuring claudeCode.environmentVariables: a list of environment variables with which it launches Claude. The first thing that comes to mind is to put it in .vscode/settings.json of the work project. But alas, this won't work.

Why .vscode/settings.json doesn't work

In the extension's package.json, this setting has "scope": "machine". For VS Code, this means:

  • the property cannot be set at the workspace level (.vscode/settings.json): VS Code simply ignores it. This is logical: otherwise, any cloned repository could substitute the process environment.

  • the setting can be set in user settings, and each VS Code profile has its own. Only settings with application scope apply to all profiles at once, while machine is stored separately in each profile.

Hence the solution: a separate VS Code profile for work.

And here VS Code profiles come to our aid.

Create a new profile:

Ctrl+Shift+P → Profiles: New Profile... (or File → Preferences → Profile → Profiles).

  • Name: e.g. Work

  • Copy from: Default. This way, the new profile will inherit all your settings from the Default profile (well, unless you used profiles before. Or copy from the one you use from your desired profile).

Next, switch VS Code to the new profile (File → Preferences → Profile → Profile (Work)).

And open VS Code settings for your user (but for the new profile - File → Preferences → Settings):

Click to edit the setting and add to the opened JSON file (note that claudeCode.environmentVariables is an array, add to it):

{
  "claudeCode.environmentVariables": [
    { "name": "CLAUDE_CONFIG_DIR", "value": "/home/<user>/.claude-work" }
  ],
  "terminal.integrated.env.linux": {
    "CLAUDE_CONFIG_DIR": "/home/<user>/.claude-work"
  }
}

Also, pay attention to <user> - obviously, you need to replace it with your username.

Two important points:

  1. The path must be absolute. The extension does not recognize ~, $HOME, and %USERPROFILE%: the string is passed as is, and Claude will look for the config anywhere but where we need it. Unfortunately.

  2. The second setting (terminal.integrated.env.*) is needed for the integrated terminal. claudeCode.environmentVariables only affects the extension panel. Without the second setting, the command claude, typed in the integrated terminal of the work window, will run under the personal account. This is exactly the error we are protecting against.

For macOS, it will be terminal.integrated.env.osx, and for Windows, terminal.integrated.env.windows, respectively.

Linking work folders to the profile

Of course, switching profiles manually is much easier than switching Claude accounts. But VS Code allows you to automate even this.

Go back to the profile settings, select our Work profile.
In the `Folders & Workspaces` section, add our work folders with projects.

That's it. Now, when VS Code opens any project, it will automatically switch to the work profile, and thus - launch claude-work instead of the standard claude (meaning it will log in with our work account).
All that's left is to restart the IDE and check that everything works as we've configured.

Checking

Open any work project in the editor.

  • In the work VS Code window, open the Claude panel and execute /status. We should see our work account.

  • In the integrated terminal, you can run echo $CLAUDE_CONFIG_DIR

  • In the regular OS terminal, you can also check /status in claude and claude-code.

Result

  • One variable CLAUDE_CONFIG_DIR gives two (or more) completely independent Claude Codes.

  • In the terminal, these are different cli commands: claude , claude-work, etc.

  • In VS Code, it's the Work profile with claudeCode.environmentVariables and terminal.integrated.env.*.

  • Work folders are linked to the profile, so the account is selected based on the project we opened.

  • /status helps to quickly verify if anything has gone wrong and which account the current session is running under. Just in case.
