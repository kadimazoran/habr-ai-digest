Project Architecture: Two Operating Modes

The project has two independent modes that use the same codebase and common tools but are launched differently and pursue different goals:

  • Interactive Agent (LangGraph). User → Streamlit WebUI → LangGraph graph → 32 tools → external systems (Platform V Pangolin DB, TaskTracker, Prometheus, Pipeliner, LLM).

  • Autonomous Agent (cron). Cron → Ticket Scanner → Handlers (Statistics / DiskSpace / PlannedMaintenance) → external systems (TaskTracker, DB, LLM).

The interactive agent is designed for manual diagnostics and chat operations, while the autonomous agent is for automatic ticket resolution on a schedule.

Where LLM is Used in the Entire Project

LLM (GigaChat) is used in four different scenarios. Below is a brief description of each (instead of a complex diagram):

  • Interactive Agent (LangGraph) — LLM is called repeatedly in a loop: it understands the request, selects a tool, enriches arguments, requests confirmation, and forms a response.

  • Autonomous Agent (cron) — LLM is called once to extract structured data from the ticket text (host, mountpoint, date and time, action). After that, hard logic is executed (SSH, SQL).

  • analyze_pangolin_ai collects metrics from Prometheus and error logs, and passes them to the LLM to generate conclusions and recommendations in Russian.

  • get_db_log_errors analyzes database logs, identifies critical errors (FATAL, PANIC, deadlock), and can pass them to the LLM for analysis (extension point).

Event Feed — A Window into the Agent's Inner World

The agent logs every significant action to a JSONL log file (logs/agent_events.jsonl). The WebUI has an "Event Feed" page that allows you to:

  • filter events by importance level (INFO, WARNING, ERROR, DEBUG);

  • search by ticket number, handler (StatisticsHandler, DiskSpaceHandler), or message fragment;

  • view details — which step was executed, what parameters were passed, the result;

  • monitor the processing progress in real-time (with auto-refresh).
