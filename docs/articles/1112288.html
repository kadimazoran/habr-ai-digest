I'm teaching a course on AI usage to final-year IT students.

I've observed an interesting phenomenon: with an AI agent on a small local Qwen 4B model, I achieve better results than students using agents on top-tier models.

The reason isn't so much about AI usage skills as it is about engineering competence.

An expert understands the task, narrows down the solution space, manages complexity, detects errors, and provides quality feedback.

A novice delegates all this to the model, including decision-making, the correctness of which they cannot assess themselves.

Personal expertise is one of the most powerful leverage points for amplifying AI.

This raises the question: how should we train developers if a significant portion of coding can now be delegated to agents?

1. AI Agents — From the First Year

Traditionally, developer training is built from the ground up. First, language syntax, then algorithms, data structures, databases, application development, and only then system design.

This is a logical sequence when a person writes code independently.

Today, a student can start creating applications almost immediately. This capability should be leveraged in the educational process.

As early as the first semester, students need to be introduced to the fundamental tools of agent development:

  • AI agents and the principles of their operation;

  • prompting and context management;

  • tools and tool calling;

  • skills and MCP servers;

  • working with the file system and terminal;

  • Git;

  • security and agent permission limitations.

The goal is to quickly master the tool to a level sufficient for further learning.

After this, fundamental disciplines are studied in the context of available machine intelligence.

Instead of studying programming for four years and then learning AI, or offering an elective course on neural network architecture, we should use AI from the very beginning and consistently build engineering competence.

2. Change the Goal of Education

Why do we teach students programming? So they can write a program, or so they can solve a problem using a computational system?

Until recently, the former was a necessary condition for the latter. Now, a significant part of the implementation can be delegated.

Other competencies come to the forefront:

  • understanding and formalizing the task;

  • designing the solution;

  • decomposition;

  • managing complexity;

  • monitoring execution;

  • verifying the result.

Fundamental disciplines do not lose their relevance. The way acquired knowledge is applied changes.

Algorithms need to be known to select and evaluate algorithmic solutions. Databases — to design data models and control their implementation. Architecture — to define system structure and limit complexity.

Writing code remains a necessary element of learning, but the ability to write a large volume of code independently ceases to be its primary goal.

3. Teach Code Reading

In traditional education, the main focus is on writing code. Reading and analyzing existing code often remains secondary.

In agent development, priorities shift.

Students should be able to:

  • trace program execution flow;

  • understand system state changes;

  • analyze dependencies;

  • find logical errors;

  • localize defect causes;

  • evaluate algorithm complexity;

  • perform code reviews.

This requires independent programming, debugging, and understanding program principles.

However, assignments should not be limited to writing programs from scratch. Students should be given existing codebases, including those generated by agents, and be required to understand them, identify problems, and organize modifications.

4. Teach Decomposition and Design

Decomposition is one of the most effective ways to improve the performance of AI agents.

When presented with a large, poorly formalized task, the model is forced to make many interconnected decisions independently. An early error can devalue all subsequent work.

An engineer must be able to break down a task into components, define their boundaries, interfaces, dependencies, and completion criteria.

After this, the agent receives local, well-defined tasks whose complexity matches its capabilities.

Simultaneously, students must be taught software design:

  • domain modeling;

  • separation of component responsibilities;

  • interface design;

  • dependency management;

  • architecture selection;

  • KISS and YAGNI principles.

It is especially important to teach complexity management.

Previously, the growth in system complexity was limited, partly by the cost of writing code. AI has significantly weakened this constraint. Now, creating ten thousand lines of unnecessary code is almost effortless.

Therefore, an engineer's ability to determine not only what needs to be implemented but also what should *not* be implemented becomes particularly valuable.

5. Restructure Teaching of Fundamental Disciplines

Let's consider databases as an example.

Traditional lab work: create tables, write SQL queries, implement several data operations.

In the agent-based approach, students should design the data model, define entities and relationships, integrity constraints, transactional boundaries, indexes, and access rules.

The agent can implement the schema, migrations, queries, and tests.

The student verifies the implementation, analyzes query execution plans, detects integrity violations, and corrects design decisions.

At the same time, they must be able to write an SQL query independently and understand its semantics.

Similarly, the teaching of algorithms, networks, operating systems, information security, and other disciplines can be restructured.

An agent allows for a faster transition from mastering individual technical operations to solving meaningful engineering problems. However, fundamental knowledge and skills must be verified independently of the agent.

6. Teach Specification Writing

When writing code independently, some requirements and design decisions can remain in the developer's head.

When delegating work to an agent, these decisions must be explicitly formulated.

Students should be able to describe:

  • functional and non-functional requirements;

  • business rules;

  • constraints;

  • component contracts;

  • edge cases;

  • acceptance criteria.

It is important to distinguish prompting from specification.

Prompting is a method of interacting with the model. Specification is a description of what should be implemented and what requirements the result must meet.

Specification-Driven Development should be taught as a full-fledged engineering approach, not just another prompt writing technique.

7. Teach Testing and Verification

If a significant portion of the code is written by AI, the ability to verify the result becomes one of the developer's key competencies.

It is insufficient to ask an agent to write code and then ask it to write tests. The model can misunderstand the requirements equally in both implementation and testing.

Students must independently define the verifiable properties of the system and understand methods for their verification:

  • unit, integration, and contract testing;

  • functional testing;

  • edge case testing;

  • property-based testing;

  • static analysis;

  • load testing.

A good educational practice is to first formulate acceptance criteria and test scenarios, and then delegate the implementation to the agent.

The agent should not determine if the task is solved correctly. Correctness criteria must be defined independently of the implementation.
