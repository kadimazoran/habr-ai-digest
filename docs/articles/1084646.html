## 1. Anatomy of the Problem: Why Regular Expressions Fail

Most custom scripts and commercial parser bots operate on a primitive logic:

```python

# Naive approach from 2018

KEYWORDS = [r"ищу\s+разработчик\w*", r"нужен\s+бот\w*", r"требуется\s+дизайн\w*"]

pattern = re.compile("|".join(KEYWORDS), re.IGNORECASE)

if pattern.search(message.text):

send_alert_to_crm(message)

```

This looks functional in synthetic tests. But when a script connects to a live stream of open professional chats with a total volume of 15,000+ messages per day, the system instantly encounters two fundamental NLP problems:

### Problem 1. False Positive Deluge (False Positives)

Contractors, web studios, and freelancers use the exact same keywords in their offers:

> "Hello! *Looking for** development projects. Our team builds complex Telegram bots and turnkey web services. Case studies in the pinned message @agency_dev"*

The regex sees the pattern looking for + development and happily reports to the CRM: "Hot lead!". In reality, a sales manager spends 15 minutes contacting a competitor. In our dataset, 60.3% of all pure regex matches turned out to be outgoing offers from contractors.

### Problem 2. Catastrophic Intent Miss (False Negatives)

Real, solvent clients (especially founders and C-level executives) rarely use textbook SEO phrases. They formulate their needs through business context:

> "Colleagues, can anyone advise who can quickly connect amoCRM with a custom Go backend? The previous contractor disappeared, the project is burning, payment via bank transfer from a legal entity."

This message contains not a single trigger word ("looking for a contractor", "integrator required"). However, from a commercial standpoint, it's a maximally hot lead: there's a burning pain ("project is burning"), willingness to pay ("bank transfer, legal entity"), and a specific tech stack. The regex missed it.

## 4. Solution Architecture: Three-Level Cascading Pipeline

To process the Telegram stream in real-time (SLA < 1 sec) with zero budget overruns, we built a three-stage filtering system.

```mermaid

flowchart TD

A["Incoming Telegram Message"] --> B["LEVEL 1: Heuristic Filter (CPU, <2 ms)"]

B -- "Junk / Spam Lists / <20 chars" --> Trash1["🗑️ Drop (84.2% of stream)"]

B -- "Potential Candidate" --> C["LEVEL 2: Vector Intent Router (~15 ms)"]

C -- "Cosine sim < 0.42 to Purchase cluster" --> Trash2["🗑️ Filter Out (12.1% of stream)"]

C -- "Cosine sim >= 0.42" --> D["LEVEL 3: LLM Decision Logic with Schema (~450 ms)"]

D -- "Score < 7.0 / False flag" --> Trash3["🗑️ Filter Out Non-Liquids"]

D -- "Score >= 7.0 (Target Lead)" --> E["🚀 Ready Lead Card in Telegram / CRM"]

```

### Level 1: Deterministic Heuristics (Latency: ~1.8 ms)

The goal of the first level is to eliminate obvious junk with zero computational cost:

* Text Length: filtering out messages shorter than 25 characters ("ok", "thanks", emoji reactions, links without descriptions).

* Telegram Entity Specifics: analysis of MTProto service headers - forwards from channels with the broadcast tag, system messages about entry/exit.

* Blacklist of Explicit Noise Triggers: patterns of "infobusiness" funnels, crypto bots, and lotteries.

Result of the first level: 84.2% of the incoming volume is filtered out. Only coherent messages with meaningful text remain in memory.

### Level 2: Semantic Vector Router (Latency: ~14 ms)

Messages that pass the basic filter go to a local embedder.

We use an optimized embedding model (multilingual encoder with distillation) that translates the message text into a fixed-dimension vector and calculates cosine similarity with the core target and anti-target centroids:

* "Commercial Demand" Centroid: vectors of phrases like "looking for a contractor", "need staff augmentation", "how much does implementation cost", "turnkey development required".

* "Commercial Offer" Centroid: vectors of offers like "we provide services", "our team of specialists", "discounts on development".

If the cosine similarity with the demand vector is below the cutoff threshold ($ ext{threshold} = 0.42$), the message is discarded without invoking heavy models.

Result of the second level: another 12.1% of the stream is filtered out. Only about ~3.7% of messages, truly containing signs of a business offer, reach the final evaluation.

### Level 3: LLM Decision Logic with JSON Validation (Latency: ~450 ms)

The final arbiter is a compact LLM operating in Structured Outputs mode (guaranteed schema validation at the sampling grammar level).

The system prompt doesn't just ask "is it a lead or not", but forces the model to break down the message into predicates:

```json

{

"name": "b2b_intent_verdict",

"strict": true,

"schema": {

"type": "object",

"properties": {

"is_commercial_lead": { "type": "boolean" },

"role": { "type": "string", "enum": ["buyer", "seller", "job_seeker", "other"] },

"intent_score": { "type": "number", "description": "Score from 0.0 to 10.0" },

"detected_budget": { "type": ["string", "null"] },

"tech_stack": { "type": "array", "items": { "type": "string" } },

"urgency_level": { "type": "string", "enum": ["high", "medium", "low", "none"] },

"explainable_verdict": { "type": "string", "description": "Why it is a lead or why it was filtered out" }

},

"required": ["is_commercial_lead", "role", "intent_score", "detected_budget", "tech_stack", "urgency_level", "explainable_verdict"],

"additionalProperties": false

}

}

```

The model is required to clearly classify the author's role (buyer vs seller). If the author is selling, the is_commercial_lead flag is forcibly set to false, no matter how professional the text may seem.

## 6. Reaction Speed: The Speed-to-Lead Factor

Scoring accuracy is only half the equation. The other half is delivery delay.

In open Telegram chats, a strict first-come, first-served rule applies:

If you contact the client within the *first 10–15 minutes** after the message is posted, the conversion to a meaningful dialogue is 38–45%.

After *2 hours**, the client has already received 15–20 responses in direct messages, chosen the top 3 interlocutors, and closed the dialogues. Conversion drops below 7%.

After *24 hours**, conversion tends to zero.

Thanks to the cascade, the total time from a user sending a message in a chat to a lead card appearing for a sales manager in Telegram is less than 2.5 seconds (including MTProto network latency).

## 7. Conclusions

1. Regular expressions in 2026 are economically harmful. Losing 80% of hot leads costs businesses far more than renting an intelligent pipeline.

2. Processing all traffic through raw LLMs is a path to burning money. The only viable architecture for processing large volumes is a multi-level cascade (heuristics $ o$ embeddings $ o$ LLM with a strict schema).
