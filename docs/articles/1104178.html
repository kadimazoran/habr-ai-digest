For this article, I created a small training vault with 16 fictional notes: exam tickets, tasks, and preparation notes. The screenshots were taken in Obsidian 1.13.7 with Veynrel 2.3.1. My old tickets are not included. I actually prepared for exams in a similar way.

It Started with an Icon

I stumbled upon Obsidian by chance. I'm not sure where I downloaded it from anymore, but I remember the first thing I liked was the icon. I opened the app and started writing down my exam tickets. Most often, I used the LaTeX plugin: it made formatting formulas in exam answers easier. I didn't have any complex life organization system back then — subjects, notes, questions, and a few links.

If you're not familiar with Obsidian yet, its foundation is quite simple. A vault is a folder on your computer, and the notes within it are regular Markdown files. To link notes, I write [[Note Title]] directly in the text. In reading mode, it's a standard link: from a note about derivatives, I go to the explanation of extrema, and then return to the task.

A few years later, I saw a video about someone using Obsidian to organize their studies and daily thoughts. I wanted to use the app again. I started saving fragments of articles I read, sometimes entire articles, and jotting down my own ideas. Soon, I had accumulated text that I wanted to process directly in the editor, without constantly copying it back and forth to another chat.

I tried Copilot, got acquainted with OpenRouter. I had wanted to build something out of personal interest for a long time, so I decided to write my own plugin and learn TypeScript along the way, which I had hardly used before.

The first versions of Veynrel processed selected fragments, appended answers to the end of the note, and worked through files in a single folder. After the first article on Habr and the discussion below it, ideas for vault checking and working with links began to emerge. Several times I thought the functionality was complete. After adding semantic search, that feeling disappeared.

Ask the Way You Remember

The built-in search helps when I remember the exact word from a note. Over time, I tend to remember the content more, and the file name slips my mind. Then I have to sift through notes and guess where I saved the explanation.

Before the screenshots, I prepared three questions for the training set. The first was: "I can't explain the topic without notes. How can I test myself?" Veynrel ranked the note "Rehearsing an oral answer" first. The snippet of text was visible in the search results, so I opened the result directly from there.

Semantic search compares the query with the note content through a pre-built index. For this, embeddings are used — numerical representations of text. During my first test, I built an index of the training folder, entered the question, and opened a relevant snippet from the results.

Found a Note — Checked the Rest

After several edits to notes, unfinished links start to remain. One ticket has a link to an explanation I intended to finish; another has a complete copy of an old note. For this part of Veynrel, there's Health — a local check for broken links, exact duplicates, and other file structure issues.

In the training set, I intentionally left two defects: a link [[Second Derivative]] in the "Extremum Check" ticket without a target file, and an exact copy of the note about the zero derivative. I ran Health — the actual check found both cases.

Duplicate search doesn't have to end in deletion either: two similar notes are sometimes needed for different purposes. The check itself runs locally, without a language model or API key.

When You've Already Read the Notes

With tickets, there's another familiar problem: I read the answer — everything seems clear. I try to explain it out loud and suddenly forget the condition or the sign. That's why Veynrel has Recall — flashcards for review. The question and answer are written in Markdown, the plugin finds them and creates a schedule.

For the demo folder, I used four pre-prepared flashcards. One has the question about what a positive derivative means. I revealed the answer and chose "Good" after the screenshot. The next review was indeed recorded in the plugin's data, and the other cards remained unchanged.

Revealed answer and rating options. The frame was taken before one card received "Good."

If I can't recall the question, I go back to the notes and work through an example. Short questions help check which parts of the material I can already explain from memory. Recall also works locally in this mode.

What Else is in Veynrel

The initial text manipulation commands evolved into Studio over time. It saves processing scenarios: formatting a note, creating a training log, or structuring long text into a clear format. There's also the creation of editable diagrams for Excalidraw. These tools require a configured model; the result is reviewed separately before saving. I've already written in detail about working with LLMs and their errors in the article "How I Format Workouts and Nutrition in Obsidian Using LLM and What It Loses Along the Way".

After Studio was introduced, I also added the Community Library: users share their processing scenarios.

Discussions have already influenced development: in the comments on the first article, I was suggested to connect via MCP — a way to give an AI agent access to notes. Integration via Veynrel Companion is already in release 1.8.0: the agent reads synchronized note copies and suggests changes that I confirm in Obsidian. In version 2.3.1, connection and viewing suggestions are in the Connect section; a running Companion server is required for it to work.

For those who need details: models, Rerank, and cost

In the MiniLM screenshot, paraphrase-multilingual-MiniLM-L12-v2 was used via ONNX CPU and an OpenAI-compatible server on the same computer. It was specifically a local server, not OpenRouter. In the cloud series, baai/bge-m3 via OpenRouter was tested. For it, Veynrel built a new index; it ranked the three correct files at positions 1 / 1 / 1, while MiniLM ranked them 1 / 4 / 1. Proximity values between models are not directly comparable.

Veynrel has Rerank — the "Refine Results" button. For the second query using mongodb/rerank-3-lite, it reordered the 16 candidates, but the correct ticket was already first after BGE-M3 and remained first. In the previous benchmark on 24 questions with answers, the nDCG@10 metric improved in 11 cases, remained unchanged in 11, and worsened in 2. This is a different dataset and a different test.

Six paid requests in the cloud series cost 0.02 per million input tokens, and BGE-M3 — $0.01 per million input tokens. This is the cost for a small synthetic corpus; the price for a large vault will be different. OpenRouter rates.

In the local series on Ollama, Ollama 0.40.14 and bge-m3:latest in GGUF F16, digest 790764642607…, ran on CPU. Veynrel's standard Ollama provider created a separate index of 19 vectors with 1024 components. The ranks of the correct files are 1 / 1 / 1, without Rerank. During indexing and search, notes did not leave the computer; there were no cloud requests in this series. Local and cloud configurations are not declared identical: OpenRouter responses do not report the format and precision of weights, and three-rank matches for such output are few.

The methodology and raw files are saved in the original demonstration archive. Three questions and 16 specially prepared notes do not prove the superiority of one model in all tasks.

How to Try It

If you don't have Obsidian yet, download it from the official website and create a folder with a few notes on a single topic. Link a couple of files together. Veynrel is then installed via Settings → Community plugins → Browse. Search for Veynrel, install, and enable it. Starting with the local Health check is the easiest: it works without a model.

For semantic search, there's a tested local option without an API key:

  1. Install and run Ollama, then execute ollama pull bge-m3. The model takes about 1.2 GB of disk space; check available space and memory before downloading.

  2. In Veynrel's embedding settings, select Ollama, the model bge-m3, and the address http://127.0.0.1:11434, without /v1. No API key is needed.

  3. Test the connection, build a new index for a small folder, and ask a question in your own words. A new configuration requires its own index, even if you previously used cloud-based BGE-M3.

The tested cloud option remains a separate configuration: OpenRouter and baai/bge-m3. It requires a key, balance, and a new index. With this connection, note fragments are sent to an external provider, so it's best to use non-critical notes for your first experience. Step-by-step Veynrel documentation.
