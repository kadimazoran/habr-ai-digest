What to write about: Season Themes

Last year, the article season launched by the GitVerse team was dedicated to open source and generated significant community interest, featuring 80 strong submissions. We decided to repeat this experience but focus primarily on AI. We won't forget the topic of open source either, as many AI products and models wouldn't exist without it. So, this season will feature three interconnected themes:

1. AI-Disrupt PDLC — Rebuilding the Development Lifecycle

Simply embedding a neural network into existing processes is like putting an airplane turbine on a cart: the structure will fall apart, and there will be no benefit. To achieve results, the entire product development lifecycle (PDLC) needs to be changed.

AI-Disrupt PDLC is a rethinking of the classic development lifecycle, considering AI capabilities. It's not about just adding an AI assistant to a couple of stages, but about how to build the entire process around human-AI agent interaction.

Within this theme, we expect practical case studies of AI integration into processes: planning, code writing, review, testing, and monitoring. Tell us how you are building your AI-Disrupt PDLC, where AI measurably speeds up work, and where it only creates an illusion of productivity. Share how team roles are changing and what pitfalls you've already encountered on the path of AI transformation.

Sber has created a whole line of tools supporting this concept:

  • GitVerse — an AI-centric platform for code work that ensures the complete software development cycle. It includes hosting for open and private projects, a code editor, and tools for analytics and vulnerability scanning. GitVerse currently has over 250,000 users and hosts over 230,000 projects.

GitVerse integrates AI tools that accelerate development: GigaCode, GigaIDE, GigaStudio.

  • GigaCode — an AI assistant with an agent mode that comprehensively solves tasks, from analyzing a codebase to providing a ready solution with technical documentation. It understands project context and supports over 35 programming languages and major IDEs. The GigaCode CLI AI developer assistant provides access to over 30 AI models for code generation and verification, testing, and refactoring.

  • GigaIDE — an IDE where AI agents help write, edit, and debug code in a local environment. It integrates with Git and includes tools for working with databases, big data, and ML. GigaIDE allows connections to external application marketplaces, and the pro version of the environment features a local application marketplace.

  • GigaStudio — a multi-agent AI system for creating web applications that generates working products based on natural language requests. An ensemble of agents develops the UI, business logic, and connects databases. GigaStudio allows launching projects of any complexity, from landing pages to SaaS platforms.

All these solutions are not isolated; they work together, forming a unified agent ecosystem.

2. Open Source for AI and AI for Open Source

This theme serves as a bridge from traditional open-source development to the new, AI-native reality. Here, two major directions can be explored:

  • Using open-source-based tools in AI/ML development: successful integration cases, examples of building pipelines based on open-source solutions, comparisons of benchmarks for open and closed AI models (which is faster, cheaper, and more effective), and nuances of choosing the optimal model for a specific task.

  • Developing open-source tools that improve the modern process of creating secure software with AI agents, making it faster and more reliable. Share your own projects: libraries, frameworks, utilities, models, autonomous programs that work with open source. If you develop a tool that simplifies the lives of other engineers, this is your track.

Open source and AI are interdependent. Open models democratize access to AI, and AI, in turn, makes supporting open-source projects faster and better. Show through your examples how this works.

3. Secure Development in the AI Era

Traditionally, the primary method for ensuring secure development was creating an air-gapped perimeter, meaning installing everything on the company's on-premise infrastructure. However, hybrid approaches are now needed. Agents require access to the external world (previously a human prerogative), connection to third-party LLMs alongside neural networks hosted within the company's environment, and some are already using A2A (agent-to-agent) interactions with third-party agents... Now, cybersecurity specialists are building gateway and guardrail systems, developing "do" and "don't" rules for agents and external access.

Another challenge is the volume of code generated without human involvement. With AI, developers can create hundreds of commits per day, often shifting focus to specifications while code is reviewed as a secondary priority. Traditional code review approaches are breaking down: the speed of changes exceeds verification capabilities, and CI, CD, DevSecOps practices are too slow for AI pipelines with thousands of changes per day.

Sensational stories about AI agents finding thousands of vulnerabilities in systems previously considered fully protected require a reassessment of response times and the closure of cybersecurity defects—from days to hours.

Share your experiences and ideas on how to adapt DevSecOps approaches and practices to the realities of the agent era: verifying AI-generated code, protecting the software development pipeline from new types of risks, and building a secure environment for AI agents to operate within the corporate network.
