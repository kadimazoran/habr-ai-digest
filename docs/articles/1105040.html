I once asked Claude Code which CMS it would recommend. I wanted to see where it was leaning. It answered: Drupal. No way. I asked why, and it explained that it saw my custom Drupal skill and decided that I work with Drupal and would be comfortable with it.

Fair enough. My instructions, skills, and settings make the agent biased. But for this question, I needed an unbiased one. A regular chatbot would have sufficed, but we don't take the easy way, do we? 😁

I started looking for how to run Claude Code without my own config and found the flag --safe-mode. According to the description, it's just what I needed: no CLAUDE.md, skills, plugins, hooks, or MCP servers, and my subscription as usual. Pure default Claude Code ✨

I asked again. Drupal again.

/ccu: Claude Code, Unbiased by me

This is how /ccu came about — a skill that runs a prompt in a clean Claude Code instance.

I could have created a shell command that opens a full unbiased Claude Code session. But I don't usually need to work in that format; I only need a quick check from time to time. That's why it's a skill: my main agent writes the prompt, copies the necessary files for the task into an empty folder, launches a clean instance there, and brings back its response.

I use it in various ways. One option is as reviewer personas for my blog, for example, an editor or a colleague.

What does a clean instance know about me? Nothing. Out of the box, it only sees the OS, the shell, the path in the temporary folder, and today's date.

How the instance is isolated

Each run gets a fresh temporary directory with two subfolders: work — the instance's working directory with task files, and home — an empty home directory. Then, roughly like this:

cd <run dir>/work 
 env -i HOME=<run dir>/home PATH=$PATH CLAUDE_CODE_OAUTH_TOKEN=<token> 
  claude -p --model <model> < prompt

env -i starts with an empty environment, so nothing leaks from my shell. The home directory is empty: no config, no skills, no memory, no history. The token is the same as my current session's; /ccu gets it from macOS Keychain. The subscription is the same, but the email is not: Claude Code's account profile is stored in .claude.json, which is written upon login, but here the home is clean.

Permissions must be granted in advance

claude -p rejects any tool that requires confirmation: there's no one to confirm. Therefore, the main agent lists the tools needed for the task in work/.claude/settings.json, for example, for a web task:

{"permissions": {"allow": ["WebFetch", "WebSearch", "Bash(curl:*)"]}}

In a folder that Claude Code doesn't trust, these settings are ignored, so /ccu also marks work as trusted in .claude.json inside home:

{"projects": {"<run dir>/work": {"hasTrustDialogAccepted": true}}}

The transcript remains mine

After running, /ccu converts the raw session log into a readable transcript.md. The main agent forwards the instance's response, but I never read the transcript. I can read it myself whenever I want.

What about the CMS?

Through /ccu, Claude Code recommended Payload.
