How it Looks

I was editing my listings. Open, re-read the description, fix the title. I thought an AI assistant, like in Word, would be suitable here. I sit nearby and watch as it suggests an edit and makes it.

For this, Anthropic has the Claude in Chrome extension. It opens pages, reads them, and clicks on the site on your behalf. Usually, one "always allow" is enough. Here, the page opened, the text was read, but when clicking "Edit," a window popped up.

{
  "url": "https://www.classifieds-example.com/profile/items/active",
  "domain": "www.classifieds-example.com",
  "category": "category3",
  "org_policy": null,
  "policy_source": null
}

I replaced the website address, the rest is as it was. The "always allow" button is completely missing, and it doesn't appear in the settings. At first, I thought I had clicked something wrong myself. It turned out, no.

What's Inside

In the Anthropic help section, it says exactly that. There are sites where Claude asks before every action, even before a simple navigation. According to the documentation for organizations, the extension checks the address against Anthropic's "website security list." The server responds that the site is regular, blocked, or requires confirmation. The criteria for a site being added to the list are not described. The list itself is not published. In the security help section, there's only a hint. Adult and pirated sites are blocked, and Claude asks before financial sites.

The extension's code is on your disk and can be read. Before an action, the extension sends the page address to the Anthropic server and receives a category. The names are internal; they are not in the documentation.

category4

organization ban

site blocked by your company administrator

The checking process is as follows. Before an action, the extension sends the page address to the Anthropic server (POST api.anthropic.com/api/web/url_hash_check/browser_extension). The server returns a category: for category0, "always allow" is available; for category1, a blocked page is shown; for category3, a prompt appears for every click. The response is cached for 5 minutes. There is no website list on the computer; the server maintains it.

How the extension decides whether to ask for every click. The category is sent by the server; there is no list on the computer.

The category is assigned to the entire domain, not the page. On other sites on the same computer, one "always allow" was sufficient.

Settings Don't Help

The extension panel has three confirmation modes. I tried all three, and the window remained the same. The "Your approved sites" section, according to the help section, only shows granted permissions; you cannot add a site there. The "auto mode" in Claude Code according to the documentation should bypass site verification. I tried it once. Reading passed, but clicking "Edit" again hit the same window.

There is only one described working method. This is the list of trusted sites in the organization settings. It's only available in Team and Enterprise plans. A personal account doesn't have this, and there's no description of how to request a site be removed from the list.

What This Means

Anthropic's main risk is prompt injection. These are hidden instructions for the AI on a page, in an email, or document, which the model mistakes for your command. Hence the caution. But the criteria are closed, the list is closed, there are no notifications. You only find out when you hit a wall. Your work site, or a site you're developing for clients, could be on this list.

How to Check Your Site in Chrome

Open the site and type in the Claude panel: "Open this page and click any safe link in the menu. Do not enter or submit anything." Observe the first window.

You can see the server's response with your own eyes in five steps. I've verified it myself.

  1. Open chrome://extensions in Chrome and enable "Developer mode" in the top right corner.

  2. In the Claude card, click the small "service worker" link below the description. This will open the developer tools.

  3. Go to the Network tab at the top and type url_hash into the filter.

  4. Ask Claude to open the desired site.

  5. Click on the browser_extension line and open the Response tab. There you will find the category field.

In the Headers tab nearby, you can see your login token. Only look at the Response and do not show screenshots of the Headers to anyone. If the line is not there, the response is in the cache for 5 minutes; open another page on the same site.

I am collecting the verification results in an open registry on GitHub. It's a table of sites with categories, dates, and verification methods. You can add your site via the form or an issue.

What I'm Doing Now

If the window says "Site-level permissions are disabled for this site," I don't touch the settings and don't reinstall the extension. The assistant prepares texts in a file, and I insert them into the dashboard myself. Once a month, I re-read the documentation pages for chrome.md and desktop.md.
