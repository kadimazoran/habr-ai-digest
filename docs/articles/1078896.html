 Chat: POST /v1/chat/completions

After registration, the service credited 100 million tokens. Initially, they are on the account balance, after which they need to be manually allocated to an API key via the Allocate button.

At the time of checking, /v1/models returned two models:

Model ID

MiniMaxAI/MiniMax-M2.7

deepseek-ai/DeepSeek-V4-Flash-0731

Dahl has an unusual billing scheme: for example, if the request and response together used 63 tokens, exactly 63 will be deducted from the balance. In the test, MiniMax used 43 input + 20 output = 63 tokens, and the balance decreased by exactly 63. DeepSeek used 9 + 2 = 11 tokens, and exactly 11 were deducted.

MiniMax M2.7 responded in approximately 0.56s. DeepSeek V4 Flash was noticeably slower: one request resulted in an HTTP 524, a repeat request completed successfully in approximately 37 seconds.

Limits

No separate RPM is indicated in the API headers, so I tested the load on MiniMax M2.7.

Result: 60 requests in 60.86 seconds, 60/60 successful, exactly 2700 tokens deducted.

This means that at the time of checking, the service consistently handled at least 60 RPM.

Limits

The API itself provides rate limits in the headers:

x-ratelimit-limit: 30 
 x-ratelimit-remaining: ... 
 x-ratelimit-reset: ...

Five consecutive requests to different models resulted in the remaining limit decreasing from 29 → 28 → 27 → 26 → 25 with the same reset time. This means it is a shared limit of 30 requests per minute per account, not separate 30 RPM for each model.

TokenForge

Website: https://tokenforge.ai.studio/
API: OpenAI‑compatible
Base URL: https://tokenforge.ai.studio/v1
Chat: POST /v1/chat/completions
Models: GET /v1/models

After registration, the service credits $50, plus you can get $20 every day via Check in. After the first bonus, the balance was $70.

/v1/models returned only: claude-opus-5

Limits

I could not detect a specific RPM limit: even when testing with 60 requests, the API did not return any HTTP 429. However, the model itself worked unstably — only 17 out of 60 requests were successful. This means there is no strict RPM from TokenForge, but the model's stability is low.

Conclusion

If choosing based on test results, Dahl is the most generous in volume with 100 million tokens. APInex is one of the clearest options with completely free models and a 30 RPM limit, and VyceAI offers a good starting balance and 60 RPM. ModelRouter is interesting for its daily limit, but its 150,000 internal tokens are consumed with a coefficient depending on the model. TokenForge, despite the large bonus, turned out to be the most unstable: in the load test, only 17 out of 60 requests were successful.

The terms of free tariffs and model availability may change, so all figures in the article are relevant only at the time of testing.
