On November 19th, Docker rebranded. The whale was redrawn, the corporate blue became a different blue, and the homepage now sports the slogan "Trust Docker for the agents you don’t." Loosely translated: you don't trust agents, so trust them to us.

I read the marketing director's post, browsed the product menu and documentation, and initially intended to write that Docker had rolled out a bunch of new features for AI agents. Then I looked at the release dates.

What the Post Says

Docker's Marketing Director, Tery Avnaim, explains the rebranding using AI agents as an example. If you give an agent a terminal, it will decide for itself which command to execute, which file to rewrite, and which service to access. Docker wants to sell an environment where you can pre-emptively restrict the agent's access to files and networks. Hence the new slogan, Run on Trust.

The word "trust" appears more than twenty times in the text. A separate paragraph is dedicated to containers: Docker promises to continue developing them. On the homepage, two words have been added to the familiar build, ship, run: "build, ship, and run on trust."

How Sandboxes Work

A sandbox is an isolated environment where an agent can execute commands with limited access to your computer. Suppose you've tasked Claude Code with updating dependencies, and it decides to delete a folder and rebuild everything. If the agent runs directly on your laptop, its commands can affect anything it has access to. In a sandbox, you can give it a separate copy of the project. It can delete the folder there, and your working copy will remain untouched.

You can install the sandbox for free. According to the FAQ, the CLI and local sandboxes are free, including for commercial use.

Each sandbox runs in a separate microVM with its own kernel and Docker Engine. A regular container shares the kernel with the host, but here, a hypervisor sits between the agent and your machine: KVM on Linux or Windows Hypervisor Platform on Windows. To run it, you only need the separate CLI command sbx.

The launch looks like this:

sbx login          # or codex, copilot, cursor, opencode...          sbx run claude          sbx run claude ~/project-a ~/shared-libs:ro          sbx run --clone claude .

By default, the current folder is mounted into the sandbox for writing. With the --clone flag, the agent operates in a separate clone of the repository. If the experiment goes wrong, you won't have to clean up the working copy on your laptop.

Claude Code starts with --dangerously-skip-permissions by default. It doesn't ask, "Can I delete this folder?" or "Allow me to run the test?" Therefore, it's important which folders you give the sandbox write access to: the agent can modify them directly on the host.

Keys work similarly to frontend requests: the browser sends a request to the backend, and the backend inserts the key. In the sandbox, the agent sees a placeholder proxy-managed. The token is stored on the host, and the proxy inserts it into the request header.

External access depends on the network policy. If the required domain is not in the allowed list, you can add it:

sbx policy allow network registry.npmjs.org

On macOS, you need Apple silicon and Sonoma 14+; on Linux, Docker specifies Ubuntu 24.04+. You need to log in via sbx login to run. In the Hacker News thread, there was a debate about account linking and the placeholder instead of a key. The agent cannot read the token. It can send requests where the proxy will insert this token. Where the request goes is determined by network rules.

What Else is in the Table

We've already covered Sandboxes. There are three more products in the table worth mentioning: AI Governance, MCP Enterprise Gateway, and Hardened Images.

  • AI Governance is a console where the platform team distributes policies to agents across the entire company: which domains are open, which folders can be mounted, and which MCP tools are allowed to be called. Audit events are sent to Splunk, Datadog, or Grafana. The price field shows "Custom," and if the organization enables centralized management, the developer's local permissions cease to apply.

  • MCP Enterprise Gateway is a gateway that authenticates users via corporate SSO, determines which MCP servers they are entitled to, and automatically inserts credentials when calling a tool. Again, there's no price tag, only a "Talk to sales" button. For personal use, the open-source MCP Gateway under an MIT license, already integrated into Docker Desktop, is sufficient.

  • Hardened Images have long been free in their basic version: over a thousand stripped-down images based on Debian and Alpine under Apache 2.0. Paid versions add FIPS-compliant images, guarantees on vulnerability fix timelines, and extended support.

Paid tools become useful when hundreds of employees are running agents, and someone needs to report on it to the security department.

Why Docker is Doing This

Since 2025, the company has been led by Don Johnson, who previously built Oracle's cloud. After his arrival, analysts began discussing a potential sale of the business; Docker has not commented on this.

Anyone can run containers today: Podman, containerd, OrbStack, any cloud provider. It's hard to imagine the company growing significantly on just docker run alone. However, security departments now have a new question: "How do we give an agent a terminal without losing production?" Docker has been selling code isolation tools for over a decade, so this move is understandable.

In the Hacker News thread about the rebranding, I saw eight upvotes and one comment: "vacuous." On Lemmy, people asked where containers had gone from the homepage. Meanwhile, a summer thread about Sandboxes themselves garnered nearly 700 upvotes and 400 comments. People are interested in sandboxes, but apparently not the new logo.

What's Next

The engine, images, and docker compose up are not going anywhere. But there's almost nothing about containers on the docker.com homepage anymore; the first screen is entirely about agents.

Docker used to feel like a foundation. It wasn't chosen; it was just there in every README and every CI. We thought the company would remain a container company, but it has followed where the money and attention have gone – into AI. If even Docker is rewriting its primary message about itself, it's strange to expect familiar tools to remain unchanged.
