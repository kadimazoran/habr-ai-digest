I've been meaning to write about this for a long time. Yes, it's a bit late, but I'll still jump into the "MCP vs. CLI" debate. There's a thought that might be interesting to some.

How is an MCP server actually different from a regular CLI with the --help flag? In my opinion, not at all. A CLI designed with agents in mind covers the same tasks, and there's no need to invent anything new for it. Or am I missing something? (By the way, here's Adam Wathan's tweet on the topic.)

Companies that make developer tools are of two kinds: S-tier and F-tier. The first win, the second lose. And which tier you fall into is entirely decided by model weights.

An S-tier company is already in the weights. Let's take GitHub. You can criticize it all you want, but models know how to work with it because this ability is hardcoded directly into the weights. They don't need any skills or MCP; the regular CLI is enough.

It's easy to check. If a prompt like this works, you're in the S-tier:

Use the GH cli to create a repository, commit the changes, push to origin, set the reposistory to public and update the repository description.

("Use the GH cli to create a repository, commit the changes, push to origin, make the repository public, and update the repository description.")

And if you're a young company and not yet in the weights, you have few options. First, you'll have to persuade users to download some kind of skills package, or even install the CLI itself. This is extra hassle that S-tier companies don't have at all.

So what should you do? Nothing tricky.

First, make a truly good CLI and polish its --help. See if the model reaches the result just by reading the --help for all subcommands. Then tweak the wording and keep the versions that require a minimum of tool calls for it. All this can be automated, whether by a simple loop or an auto-exploration loop.

When the foundation is ready, make your CLI documentation publicly available and focus on ASEO (Agentic Search Engine Optimization, i.e., SEO for agents) for their web_search_tool. The task is the same. See how the agent navigates, and ensure it finds everything it needs in one web search call. If it has to wander through your documentation, it means there's still something to refine.

Next, you'll need a commercial deal with the labs. Perhaps you already have an inference contract with them. Then, push to have your CLI documentation included in the next training run.

If all goes well, you'll be on your way to S-tier. And the best part is that users won't have to download and install skill packages, configure an MCP server, or mess with all that nonsense.
