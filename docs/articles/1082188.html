The friend's question is, in miniature, the same debate that has been quite active lately in the feed about LLM and Obsidian, only framed differently by different people.

Andrej Karpathy, in his gist llm-wiki, describes the structure of a storage for an LLM agent — raw material, compiled wiki, global index, schema file. The AI Impact channel, in the video "Don’t Use Karpathy’s Second Brain (I BUILT SOMETHING BETTER)", goes even further and shows Infinite Brain: 16 node types, 10 typed edges, atomic files, and a graph on which the agent reasons, saving tokens. Sounds like a closed topic. You take the recommended structure, connect Claude Code, and get your Second Brain.

Only in this narrative, all three voices answer the same question — how to make your base convenient for LLM. And none answer the other — what about your own mind. In recent months, my personal knowledge base (over six thousand notes) has significantly shifted towards structures convenient for an agent — I had a separate project for *enriching the knowledge base for agent interaction*, and it's now closed. In parallel, I started noticing a symptom: I increasingly remember that there's something about it in the base, but I don't remember what. Knowledge has moved from my head to the index.

Karpathy's LLM-wiki: How to Make Your Base Easier for an Agent to Read

Karpathy proposes three layers and two utility files, all designed for an LLM agent to navigate:

CLAUDE.md    ← schema (or AGENTS.md): how the wiki is structured, conventions, workflow. raw/         ← immutable raw material: articles, papers, images, data. wiki/        ← markdown pages written and maintained by the LLM. index.md     ← catalog: link to page, description line, optional metadata. log.md       ← append-only log: ingest, queries, lint runs.

The agent's query flow: index.md → selected pages → answer with citations, and a successful answer can be added back to the wiki as a separate page.

One caveat immediately: this is an idea file, not a specification. Karpathy explicitly states that the document is intentionally abstract, and the specific directory structure and page formats depend on your domain. Even the names raw/ and wiki/ in the schema above are mine; for him, they are simply the "raw sources" and "the wiki" layers. Therefore, all the "canonical" layouts with master_index.md and nested wiki/<topic>/index.md that circulate in retellings are someone else's implementations, not his requirements.

In Chase AI's hierarchy for Claude Code memory (from AutoMemory to Agentic RAG), this is level 4 out of 7. No embedding pipeline, no vector store, no orchestration: markdown files and Obsidian.

And here's the second misdirection. Chase AI's quote about the "99% solution" refers to level 4 as a whole, i.e., an Obsidian markdown base instead of AutoMemory or RAG. He directly names Karpathy's schema as the benchmark for this level, and shows the nested master index with folders for articles, the very one from retellings, as his implementation. This is an argument for Obsidian as a level. He doesn't vote for a specific directory layout, nor for Infinite Brain's ten edges, and when the "99% solution" is used to justify a taxonomy choice, it's a stretch.

And now, a line that gets lost in retellings, though the entire scheme rests on it:

You never (or rarely) write the wiki yourself — the LLM writes and maintains all of it. You’re in charge of sourcing, exploration, and asking the right questions.

You never (or almost never) write the wiki yourself: the LLM writes and maintains all of it. Your task is to find sources, explore, and ask the right questions.

This means the agent here is not so much reading the base as writing it. Karpathy calls the grunt work (retelling, cross-linking, page layout, accounting) exactly that, grunt work, and gives it to the LLM. The human is left with sources, direction of analysis, questions, and reflection: thinking about what it all means. Remember this point; I'll return to it when we get to the "scar."

Infinite Brain: Same Camp, More Radical

AI Impact, in the video "Don’t Use Karpathy’s Second Brain," continues the same line. The description directly states: "I improved Andrej Karpathy’s famous second brain system." The authors named their version Infinite Brain, supported by StarMynd. It's a knowledge graph with two layers on top of regular Obsidian.

Sixteen node types instead of PARA's four categories: decisions, concepts, facts, questions, hypotheses, sources, and so on. And ten types of semantic edges instead of untyped wikilinks. The most important ones:

  • supports / contradicts — an argument confirms or logically contradicts another thesis.

  • depends_on — for the truth of one statement, another must be true.

  • derived_from — an idea/solution is derived from a specific document.

  • related_to — an implicit association without precise semantics.

  • authored_by — who created it: human, Claude, human with Claude, ChatGPT.

The logic: based on the edge type and a one-line summary, the agent decides whether to open the file body at all and doesn't read everything. The video mentions a specific number: for the same question, 600 tokens were used instead of 9,000, "the same data, just structured differently." The community implementation obsidian-infinite-brain repeats this in the README for the /query-vault skill: "~600 tokens, not ~9000." Both are claims, not measurements: no methodology, no storage size, no reproducible run. So don't count the fifteen-fold saving as a measurement. The direction is plausible, the magnitude is based on faith.

The strong point of the approach, which I'm incorporating into my setup: with typing, you get semantic queries that cannot be asked cheaply without it. "Find contradictions in my base on topic X" via an untyped wikilink is O(body of all related notes): the agent has to read each one and decide if it contradicts. Via the contradicts edge, it's O(metadata): a single query by a frontmatter field. The same applies to depends_on (build a learning path), derived_from (trace the origin of an idea), authored_by (what I wrote, what the agent assembled). Calling this convenience is an understatement. Without typing, such a query cannot be asked at all, only read.

This cannot be called an alternative to Karpathy, regardless of what the video title promises: it's the same optimization for LLM as the primary consumer, only more radical. In both cases, the base is built for the agent.

What Karpathy and Infinite Brain Don't Solve

Both systems solve one task — agent access to notes. They don't address the other — integrating new knowledge into the author's worldview.

Agent access is limited by tokens, indexing, search speed, and retrieval accuracy. Knowledge integration is checked differently: after reading an article, you can explain the new idea in your own words, connect it to three already known ideas, and notice that one of them now looks different.

Karpathy's method is closer to indexing, Infinite Brain to a semantic database. In both cases, the result is a neatly organized storage that the agent can navigate easily, but the author's worldview doesn't change: all new information is stored in files and the connections between them, not in understanding.

The symptom is simple. I have a separate note *about the proportion of my own notes as an indicator of PKM health*, and I can refer to it, open it, and show it at any time. If the same question is asked without a laptop, the wording becomes vague. *I remember the note exists. I remember roughly which corner of the base it's in.* But *thinking* with this idea in the moment becomes harder with each year of maintaining the base — because the more convenient it is for the agent to find something, the less the brain considers it necessary to keep in active memory. This is the Google effect: in Sparrow, Liu, and Wegner's experiments, people remembered facts less well that they were told a computer would save, and when everything was sorted into folders, people remembered the folder name more often than the fact itself.

Caveat: the work is debatable. Its first experiment, where difficult trivia questions were supposed to prompt thoughts about computers and slow down color naming for words like Google, was not replicated by two independent groups. First, in the Social Sciences Replication Project (Camerer et al., 2018), where samples were on average five times larger than the originals; Sparrow replied that the procedure differed from the original. Then, in Hesselmann (2020), who redid the procedure according to her remarks, and the result was again negative.

I rely on another part of the work. "Saved items are remembered worse" by Schooler and Storm in 2021, although only when people had time to be convinced that saving was reliable, and a trusted base is exactly that case. The authors themselves called "address instead of content" a preliminary result; I haven't found a direct replication, so I support it with my own observation, not just a quote.

The agent knows. I know there is an agent.

On top of this, there's an illusion of understanding: the feeling "I know this" is generated by the brain regardless of whether you actually know it. You see an idea in your storage and feel like you know it. If the storage is also optimized for an agent ready to retrieve everything on demand, the illusion only strengthens. For a base built for an agent from day one, this is the default mode.

The "scar" from the epigraph is about the same thing. It's a trace in consciousness left when you yourself have marked a fragment, argued with the author in the margins, connected the new to the already known. If an agent did it for you, the scar remains with the agent, and you only have a record.

Now, that very line from Karpathy: "You never (or rarely) write the wiki yourself" — the condition for the entire scheme. He honestly leaves reflection to the human; no complaints there. But retelling and cross-linking, precisely what leaves a scar, are classified as grunt work by him and handed over to the agent. I argue further precisely with this division of labor; directories and indexes are secondary here.

The counterargument is obvious: "What if my memory is bad — I need indexing, and Karpathy and Infinite Brain solve my problem?" Reasonable, but only under one condition — your base's task is truly referential. Team documentation, project wikis, sets of guides you refer to, not "study" — there, optimization for the agent and search win. A personal knowledge base, into which you invest ideas from read books and your own reflections, is a different case. If you maintain it to understand the world a little better than now in a year, then "I have a bad memory" is no longer an argument for indexing, but a symptom itself that cannot be cured by indexing. It's cured by training: you have to hold ideas in your head yourself, and this is a separate discipline. Rustam Agamaliev offers a trainer for it.

Agamaliev's Alternative: AI as a Trainer

Rustam Agamaliev, author of the channel on note-taking, in the video "Novak's Map in 15 Minutes: Obsidian + Claude as a Trainer", proposes a different principle. The machine doesn't read for the human. The machine works with what the human has already read and marked.

Specifically, two skills in conjunction with Obsidian: Highlighter and Mapper. In the demo, they are run by Claude Code, but according to the author, any agent will do.

Highlighter performs three operations on raw highlights from a book (more accurately, "excerpts," but that sounds medical). In the demo, they come from Zotero via the Zotero Integration Plugin, though their origin doesn't matter:

  1. It titles each fragment. Here, Rustam refers to old methodologists: a title is "the door through which our thinking knocks."

  2. It highlights keywords.

  3. It places empty slots «» — markers for "the reader's thought should appear here."

The trainer is built on these empty slots. The machine doesn't replace thinking; it shows where it should kick in. The title and highlighted words act as road signs: they show how the fragment is structured. The slots are where you yourself add your reaction.

Mapper takes a file marked by Highlighter and builds a concept map: the central main idea, blocks of quotes united by a single thought, problems that still need to be thought about, and arrows with labeled logical connections. This is Novak's map from the title: a concept map that educator Joseph Novak invented back in the 1970s.

The tool's goal is not to relieve the human of work but to train them to see the structure independently. Agamaliev claims that after working through at least three to five books with both skills, the reader begins to see the pattern the machine works with and can then manage on their own, without an agent. A tool that works well makes itself unnecessary.

This is where the line between the camps is drawn. Karpathy's LLM-wiki and Infinite Brain make themselves more necessary with each new note — without an agent, your base loses its usefulness. Highlighter and Mapper make themselves less necessary with each new book — after a few, you can manage without them.

My Setup: Optimization for Myself with Concessions to the Agent

If the choice were binary ("only Karpathy" or "only Agamaliev"), I would choose Agamaliev. But it's not binary. I have no religious prohibition against typed edges — I have a pragmatic criterion: what really works in my base, and what is over-engineering.

The basic principle is optimization for myself. I maintain the base, I read it, the thoughts in my head should be mine. But with targeted concessions to the agent where it genuinely helps and doesn't think for me. Not "let's do it like in Infinite Brain because everyone does," but "does this close a specific gap in my practice?"

Of Infinite Brain's ten edges, only one has stuck with me — contradicts. It closes a real gap: the query "find contradictions on topic X" without reading the bodies of all related notes. The field is bidirectional (if A contradicts B, the link is in both notes) and complements the callout > [!warning] Contradiction: ... in the body — a fact in frontmatter, an explanation in the text of what exactly it is.

Next, a number that I caught myself on during fact-checking. The key contradicts: exists in 529 notes, but almost everywhere it's an empty contradicts: [] from the template, a placeholder, not an edge. The field is filled in 36 notes, and this is after almost four months since it appeared in the templates. It won't get faster. The edge appears only when, while processing a source or revising the base, I actually encounter a contradiction with what's already recorded, and there's no point in inventing contradictions for a nice number. Queries by field already work, and the "contradiction graph" itself is built up gradually, one point at a time.

I tried a second edge and discarded it. depends_on was intended as a "prerequisite knowledge" relationship: concept X only makes sense after Y has been mastered. When I got around to marking it up, it turned out that "prerequisite knowledge" was already *expressed by existing fields* in my previous article. I look at my own concept of Error Budget: a link to SLO is already in up, because an error budget without SLO is literally undefined. It's its parent, not a separate "dependency." The new field didn't add a relationship but duplicated an existing one and required synchronizing two lists instead of one. Typing pays off only where the relationship is truly new, not where it's just prettily named.

Two more fields are not about edges. ai_generated is a minimal analog of authored_by from Infinite Brain: one field instead of a list of "human / Claude / human with Claude / ChatGPT." After a year, I won't remember which note was written by me from scratch and which was assembled by a skill when processing a source. No field — written by me, true — written by the agent, false — written by the agent, but I read it, reworked it, and acknowledged it as mine. A side rule emerged: a note with ai_generated: true must have a non-empty sources field, otherwise it's a hallucination with frontmatter.

And summary — one to three sentences with the essence of the note. Here the gain is direct: the agent reads the summary of neighbors and already understands which body to delve into and which not. The only thing that truly spread throughout the base — almost three thousand notes. It spread not because the format was successful and caught on by itself: summary fields were populated in batches, according to a separate checklist and with manual verification, over dozens of sessions, if not hundreds.

None of these fields are about the agent reading for me.

What I'm Not Adopting

  • 16 node types from Infinite Brain — my PARA + tags + templates already cover this.

  • The remaining edges. supports, derived_from, related_to, and company are covered by up/down/other/sources/links fields without additional typing.

  • Global index.md. Karpathy himself writes that an index file is sufficient when the wiki is small, and beyond that, a normal search is needed, recommending a hybrid BM25/vector search. With over six thousand notes, I'm long past that: the agent collects a selection for a specific query via hybrid MCP search, and I don't need a catalog that needs to be kept in sync with the base. The same applies to log.md: git handles my operation log.

  • Forced atomization of everything. The rule "better under-segment than over-segment" from my own skill on knowledge structures weighs more than cheap traversal for the agent.

  • Complete replacement of embeddings with typing. Semantic similarity ("find similar in meaning") is handled by hybrid embedding search via MCP, and typing is not needed here. Named relationships like contradicts are a different task and are justified only where embeddings don't solve it.

  • Most importantly: I don't adopt the condition "the wiki is written by the agent." The notes in the base are mainly written by me; agent notes are about a tenth, and they are marked with a flag. Skills assemble frontmatter and links. This is the boundary beyond which someone else's scar begins.

Without Which This Setup Becomes the First Camp

Optimizing the base for an agent needs to be balanced with rituals where the agent works against me, not instead of me. What I plan to implement:

  • Random Walk Review — the agent randomly selects 3–5 notes from the base and asks what I remember about them without the laptop open. The goal is to measure the delta between "in the base" and "in my head."

  • Socratic Dialogues on concepts from the base instead of queries like "tell me about X." I ask Claude a question, it asks me back — and so on until the concept is built within myself.

  • Highlighter mode on new books — so that highlights and thoughts in empty slots remain mine, and the agent only highlights the structure.

Without them, a base optimized for an agent drifts towards where knowledge lives in the index, not in the head. And then all the work above is in vain.

What I Ultimately Told My Friend

All of the above is about a base that already exists and is already large. The original question was about a base that doesn't exist yet, and the answer there is shorter.

From day one, anything that isn't thinking can be safely handed over to the agent: find where you've already written about it; fix typos; set the date and tags; add links between notes that you've already connected semantically. Transport and cleaning. No scar is left here by anyone, and shouldn't be.

Three things are not handed over, and they are the entire essence of the activity: reading the source, marking what's important in it, retelling it in your own words. As soon as the agent does this, the base starts growing faster than you. After six months, you'll have hundreds of notes you didn't write, and a stable feeling that you're on top of the subject. It's checked the same way as in the previous article: close the text and retell it in your own words.

And when do you return to the question? When the base no longer fits in your head. You remember writing about X somewhere, but you don't remember where, and a keyword search no longer helps. That's when the agent truly solves the task, and that task is navigation, not understanding. My friend, with her three sentences a day, is far from this point, and that's good news, not a delay.

Mirror

If you're currently considering which direction to move your base in, I have a diagnostic test.

Ask your LLM agent about any topic for which you have several notes in your base. You'll likely get a coherent answer that looks like you knew it yourself. Now ask yourself the same question: without the agent, without the laptop open. Only what's in your head.

The difference between the two answers is how much thinking you have delegated. Small — you are in Agamaliev's camp. Large — in Karpathy's camp, consciously or not.
