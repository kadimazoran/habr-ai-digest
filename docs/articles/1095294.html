Part 1. Paradigm Shift: Not Masking, but a Passport

It doesn't matter to a website whether you are human or not. It needs to answer three questions:

1. Who is making the request?

2. Can this "who" be trusted (reputation, limits, agreements)?

3. Did the request actually come from them, and not from someone who stole their User-Agent?

The string User-Agent: MyBot/1.0 answers the first question, but can be faked with a single line of code. IP checks (reverse DNS, ASN lists) answer the third, but tie identity to infrastructure. Changed cloud provider – lost reputation.

The correct answer is signing the request with an asymmetric key. This is precisely what RFC 9421 — HTTP Message Signatures (IETF, February 2024) standardizes. Building on top of this is the Web Bot Auth direction, which introduces the Signature-Agent header: it indicates where the agent's public key directory is located.

The result – three headers instead of a browser:

No JS runtime, no canvas fingerprint, no mouse movements. 64 bytes of signature and one verification operation at the network edge.

Part 4. How the Server (WAF / Edge) Verifies

On the server side, verification takes a few milliseconds:

1. Retrieve the Signature-Agent header and request the public key from the trusted directory (with caching in KV/Redis).

2. Construct the canonical signature string according to RFC 9421 rules.

3. Verify the Ed25519 signature (one fast cryptographic operation).

4. Check the created and expires timestamps (protection against replay attacks).

5. Allow the request to the API, bypassing Cloudflare's draconian captchas and blocks!
