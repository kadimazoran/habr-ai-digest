The team at the research organization Answer.AI has released the SolveIt platform as open source. The tool was primarily created for internal research tasks and code work. It has now moved to public access after two years of closed beta testing, which involved three thousand users united in a Discord community. Registration on the platform is free, and billing is based on the model of paying for actually consumed computing resources. The developers have opened access to the platform on the website solve.it.com.

Dialogue Architecture

Unlike standard chatbot interfaces where messages are sequentially added to the end of the conversation feed, SolveIt combines code with Markdown notes and other documents in a single interactive space for working with a language model. The workflow is organized in the form of dialogues, where text blocks and mathematical formulas in LaTeX markup coexist with executable code and artificial intelligence responses.

The user retains full control over the document structure: blocks can be freely edited and moved, and deleted if necessary. A prompt for the neural network can be embedded anywhere in the dialogue, with the model considering only the information located directly above the request itself. AI responses are also available for direct editing, which prevents context pollution with unwanted remarks. The language model itself performs calculations in the same software interpreter that the human uses.

Infrastructure

Each work session in SolveIt is deployed on a persistent server with its own file system and terminal, where the git version control system is pre-installed. Users can create an unlimited number of such instances for independent tasks or collaborative research. Within the work environment, it is convenient to clone repositories and commit changes.

The platform also functions as a web application hosting service without the need for a separate deployment stage. Any program launched within an instance immediately becomes accessible via a public network address or a user's own domain. When moving a dialogue to a special directory, AUTORUN scripts automatically start with the server and maintain continuous operation. The project authors state that they themselves use this mechanism for their own services, including SolveIt's server infrastructure and a chatbot for students.

Extension Tools and Collaboration

The system's capabilities are extended directly from the work environment. Any function written in Python is converted into a user tool that the AI can access. The language model can read and correct the current working document, as well as initiate generation in adjacent dialogues. Furthermore, through a special Chrome browser extension, it can be granted access to control actions in web interfaces.

For in-depth project configuration, there is a CRAFT configuration file. Placing such a file in a folder allows all nested documents to receive common instructions for the artificial intelligence and starting executable code. Additionally, through CRAFT, individual CSS styles and JavaScript scripts can be defined. Multiple participants can simultaneously edit the same dialogue in real-time, and upon completion, convert it into a Markdown document with support for templates and cross-references.

Practical Application of the Platform

The Answer.AI team uses the tool for data analysis, reading scientific literature, dissecting mathematical models, legal contract review, and programming. The developers create some of SolveIt's functionality within the service itself. In particular, the law firm Virgil uses the built-in editor for preparing contracts.

The effectiveness of step-by-step logic fixation is illustrated by the example of researcher Jack Hogan, who was designing a color palette generator for a graphical interface.

An initial attempt was made to solve the problem using Claude Code. After a series of experiments involving millions of tokens, the assistant produced a working but overly complicated tool, and Hogan himself could not justify the choice of approach. In a new session, the researcher tried to organize the documentation and build the logic of the solutions but quickly realized he was just inventing explanations for randomly generated code.

While working in SolveIt, Hogan justified the logic of the solution, prepared auxiliary functions, calculated color gamut boundaries, built and optimized color scales, and then generated CSS. Initially, he had only a rough plan, and the final project structure took shape during the experiments. While testing hypotheses, the researcher tried several approaches, including applying Fourier transforms.

He worked iteratively, in small, sequential steps. He documented the requirements for the palette and the generator itself in Markdown notes, and performed all necessary calculations directly in the code. Formulas (e.g., for relative brightness) were written in LaTeX markup. The researcher separately noted the ability to justify each methodological decision made, which significantly increased his confidence in the final result.

Another practical example was provided by Jeremy Howard, who, while analyzing a paper on recursive language models, wrote his own implementation of the algorithm directly from the publication's text.

Development Context and Training Materials

The creators of SolveIt were inspired by the ideas of scientists Bret Victor, Donald Knuth, Ivan Sutherland, and Kenneth Iverson regarding the need to combine program code with data and documentation in a single interactive environment. The development continues the principles of the educational project fast.ai, created in 2016 to expand access to deep learning technologies. When creating SolveIt, the authors abandoned the idea of full automation of human work, focusing instead on deepening the understanding of the problems being solved.

To familiarize themselves with the system's capabilities, developers are invited to start with an open introductory lesson from the practical course “How to Solve It with Code.”
