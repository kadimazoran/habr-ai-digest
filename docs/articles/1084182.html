Hello, Habr!

Over the last few months, I've been studying modern AI tools and testing them on my own projects. It was important for me not just to generate code, but to rethink the entire development cycle: from task formulation to testing, review, and security checks.

Planning — The Clearest Win

I used to often start coding "off the cuff." Now, I first formulate my intention: goal, constraints, edge cases, and security requirements. Then, an agent helps prepare the specification, acceptance criteria, decomposition, draft architecture, and a list of risks.

After manual review, such a plan takes 30–60 minutes instead of one or two evenings. Here, the acceleration has been stable: agents are good at finding contradictions and overlooked scenarios.

Code Generation: Fast, But Not Free

In my work, I used Cursor with Claude, GPT-4o, and GigaCode, local Qwen2.5-Coder and DeepSeek-Coder via Ollama, as well as LangGraph and OpenHands for more autonomous tasks.

For typical tasks — CRUD, API integrations, migrations, tests, and refactoring — the acceleration was approximately 2.5–4 times. For new business logic and architectural decisions — 1.3–1.8 times. Sometimes AI even slowed down the work.

The main illusion is the feeling that the agent wrote 70–80% of the ready code. After review, corrections, integration, and quality checks, a significant portion of the time was still spent understanding the result. I was simply checking and correcting instead of typing characters.

Most often encountered:

  • non-existent methods and APIs;

  • code that doesn't fit well into the project architecture;

  • missed checks and vulnerabilities;

  • overly confident but erroneous explanations.

Review and Testing

In solo development, there's no full code review, so I used a separate AI reviewer with project rules, static analysis, autotests, and property-based testing.

Agents write unit tests reasonably well, but complex scenarios and e2e tests require significant human involvement. Critical areas — security, architecture, and complex business logic — I always review manually.

Security Became the Main Bottleneck

Even in pet projects, agents regularly suggested insecure solutions: SQL injections, XSS, hard-coded secrets, and incorrect data handling. New specific risks also emerged: prompt injection through input data, leaks through agent logs, and supply-chain risks from tools and dependencies.

I added a security checklist to the agents' skills, introduced a separate security review, and started describing security requirements at the specification stage. For sensitive code, I use local models.

This reduced the number of obvious errors but did not eliminate manual checks. The speed of code generation easily outpaces the speed of its verification.

What Worked and What Was an Illusion

Worked:

  • preparing specifications and planning;

  • typical code and unit tests;

  • exploring implementation options;

  • analyzing and documenting existing code.

Illusion:

  • a several-fold increase in speed without accounting for review;

  • almost error-free agent performance;

  • no need to worry about security in personal projects.

AI is indeed changing the role of the tester and developer: I write less code manually and act more as an orchestrator of agents, a quality and security owner.

The metric should not be generation speed, but time to a working, maintainable, and secure result. The best effect comes not from individual prompts, but from the process: intention → specification → implementation → testing → review.

Open-source models already cover a significant portion of daily tasks, especially with good context and tools. However, for complex tasks, closed models often still win in quality.

The most important skill now is not the ability to get code from an agent, but the ability to set the task correctly and rigorously verify the result.
