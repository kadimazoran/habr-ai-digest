Before it hit the fan

I inherited a B2B SaaS project at a stage any tech lead dreams of: "It's almost done. Release in two weeks." Two out of three API calls were returning HTTP 500.

The code had accumulated several generations of agentic fixes. When a new bug was found, we'd ask an agent to figure it out and fix it. The agent would insert a workaround as another conditional. The object's state was determined by indirect signs. In 21 places, a handler identified its type through negation: not A and not B, so it must be mine. The agents saw these approaches and continued the pattern, adding more tangled logic to the existing mess.

Claude dove headfirst into this substance. I provided the keys from the outside. When Claude surfaced, he looked like a cat after valerian. Never before had I encountered so many hallucinations from it on such a small context. It couldn't answer half the questions coherently.

After two days of this shit-diving, I decided fixing symptoms was pointless. We rewrote the module entirely, reconstructing the authors' intent from the sparse documentation and existing code. We, Claude and I, called the environment where the agent writes new code without seeing the old code the "clean room." Three days were spent on the migration contract: algorithms and snapshots of inputs and outputs. Another two on the new implementation. The algorithms described what needed to be done in prose, not how.

Migration Mechanism

I divided the work between two agents. The Analyst studied the old code, ran the system, and took snapshots of inputs, outputs, and database changes. It recorded the results in scenario cards, one per operation. These cards formed the migration contract. Each card contained:

  • input

  • expected result

  • artifacts and states

  • codes

  • what is included in the snapshot

  • what confirmed it

Each line had a tag: [measurement], [code], or [gap].

The Implementer wrote new code based on the cards. It did not see the old code: a prohibition in the task, a separate session, two linter prohibitions (new code does not call old, old does not call new), and a plagiarism checker that compared the abstract syntax trees of the old and new code, highlighting only matching parts.

Defects in working functions were migrated as-is and fixed in the clean room. Unused functions were not migrated.

We took the entire user scenario: from the input request to the result. After successful verification, we switched the calling code to the new implementation. The old path was deleted after acceptance.
