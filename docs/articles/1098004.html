I gave Claude Code (Opus 5.5) a test assignment:

Draw a scene from the movie Blade Runner 2049 using SVG graphics, where Ryan Gosling’s character is looking at a hologram of an AI girl in purple light. Don’t use external SVG generators.

The task seems simple, but in reality, it's almost impossible. The prohibition on external generators removes the possibility of cheating: the model draws with code roughly like a person would paint, dictating coordinates.

All the agents I tried failed it in the same way: none looked at the actual reference, or even tried to – at most, they'd look at a Wikipedia article. The agents drew from memory and reported that it was done. When asked to "make it better," they'd fix something in one place and break something else in another.

Questions the Agent Doesn't Ask Itself

At some point, I stopped hoping for the best and started prompting the agent with questions:

  • Is there documentation?

  • Has anyone solved something similar?

  • What tools do I have? If the necessary one doesn't exist, can it be created?

  • What should the result be compared against? Where is the reference?

  • What does "good" mean? By what criteria should the work be accepted?

  • How do I not forget what has already been done?

  • Is the new result better than the old one? When should I stop?

With these questions, the picture improved. However, I had to ask them anew each time, and after a couple of steps, the agent would forget them. I decided to delegate everything to a skill, and that's how AutoHarness was born.

I used to work in aviation. No one builds an airplane head-on there: first, they study each discipline, documentation, and if the necessary document doesn't exist, they write it. I wanted the same from the agent, without being tied to the test task.

How It Works in Practice

Before starting work, the agent breaks down the task into areas of knowledge. For the movie frame, these are the figure of the person, the lighting, and the composition. For each area, it searches for a ready-made skill or MCP server from sources I trust, such as the Anthropic marketplace. The agent installs skills itself. Installing skills from a public catalog is risky, so each candidate receives a trust score, the skill is first downloaded to a temporary folder and checked for dangerous things like reading ~/.ssh or curl | sh. Anything that cannot be fully trusted is installed only after my "yes." If a suitable one isn't found, the agent writes the skill itself. The answer "I already know this" is not accepted; such knowledge must also be recorded in a skill. At the end of the task, the agent deletes everything it installed.

Then the agent retrieves the reference. In this case, it's the movie frame itself. Before the first attempt, the agent measures proportions, figure placement, color – everything by which it will later judge the result.

Next, the agent writes a short brief for itself. It contains three things: what a good result should be (for the frame – the same proportions, purple light, hologram in place), my conditions verbatim ("without external generators"), and how it will check the work. For the movie frame, this looks like this:

  • Look at its work. SVG is code, and the agent doesn't "see" it. Therefore, it opens the file in a browser and takes a screenshot, turning the code into an image.

  • Place it next to the original. The screenshot is placed side-by-side with the actual movie frame.

  • Compare against measurements. Before starting work, the agent measured the frame: where the character is positioned, their height relative to the frame, where the hologram is, what the color is. Now it compares its drawing against these numbers.

  • Provide critique. A separate agent, one that didn't do the drawing, compares the images and gives an assessment. Without a brief, the agent in Claude Code simply cannot create or modify files: a hook prevents it.

The Agent Doesn't Evaluate Its Own Work

The most telling case wasn't with the picture. I was fixing several security issues in AutoHarness itself. The agent writing the fixes rated its own work as "minor" five times in a row. A separate critic agent, which didn't write the code, found two ways to bypass the hook in the very first round and called it a blocker. Then it found three more serious problems.

Therefore, the work is always checked by a second agent that did not do it. It compares images blindly: it sees two versions labeled A and B and doesn't know which is new. The feedback always ends with a single word: blocker, major, minor, or none. The first agent doesn't rephrase the feedback, otherwise, a blocker could easily turn into a minor. Instead, the program assigns a one-time ID to each check. The second agent writes this ID as the first line of feedback, and the first agent saves the feedback to a file entirely, and the program matches the IDs and reads the assessment itself, so the critic's old feedback won't be accepted as new.

If the critic finds a serious problem, the agent first looks for how it should be according to the rules and adds it to the skill. It can only fix it after that. If the same problem persists for three rounds, the agent must change its approach.

Who Enforces the Rules

Agents skip prompt rules; I've seen this many times. Therefore, AutoHarness has two parts. The first is instructions for the agent. The second is the autoharness script, which the agent runs itself in the terminal. The agent records each step in the task log and verifies it. For example, if the brief states that a skill was found via a certain query, the script will cross-reference this with the search log. If a step is not completed, it refuses, and the agent cannot proceed.

Skills Also Need Verification

A skill written by an agent might point in the wrong direction. Therefore, it can be run on test tasks: each is done by two agents, one with the skill and one without, and a judge compares the work without knowing which is which.

What's the Result

On my tasks, Opus 5.5 with AutoHarness worked noticeably better than without it, especially on visual tasks. I don't have a proper benchmark yet. A normal run is expensive and time-consuming. In my opinion, the predictability of task completion results has improved.

Preparation consumes time and tokens, so for minor things like typos, there's a light mode without searching and briefing.

Works with Claude Code, Codex CLI, Gemini CLI, Antigravity CLI, Qwen Code, GigaCode.
