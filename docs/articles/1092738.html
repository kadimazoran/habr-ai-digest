What solves it: expensive and lengthy fine-tuning of a narrow model, or a good wrapper around a standard cloud one?

At first glance, it seems obvious that a model from a vendor with privileged and unlimited access to materials will leave no stone unturned by competitors. But perhaps we have reached a point where the difference in the quality of answers from general and specialized models does not justify the costs of fine-tuning?

Let's try to compare our interactive assistant on an open-source stack and Partner on common questions that 1C users and developers face daily.

What the agent is made of

We will leave the choice of a specific LLM out of scope. All top models work well with tool calls and have a decent context window. Tested on models like deepseek-v4-flash, gpt-6.1-sol, glm-5.3-flash.

  • Agent wrapper — Deep Agents based on LangGraph. Out-of-the-box, we get task planning, delegation to sub-agents with isolated context, and context window management through history summarization.

  • The foundation of everything is a well-structured knowledge base index tree on RAG indexes. We use hybrid search. The full-text branch is built on FTS PostgreSQL with a Russian dictionary, and the vector branch is on the pgvector extension with an HNSW index. We merge the results of both branches using Reciprocal Rank Fusion — candidates with high rankings in each output are boosted in the final list.

  • For the source code of standard configurations, we use fast search. Five dumps of standard configurations contain about 236 thousand files and 193 thousand directories. With good algorithms and modern hardware, this volume is not a problem. To navigate thousands of modules, we wrote a configuration metadata parser that collects objects, attributes, and relationships between them.

  • For internet search, we use the Yandex API, which provides much more relevant results for Russia than the search engines built into LLM chats. We aggregate and summarize information from all found sources.
