The Original Winamp on Mac: How I Made My Childhood Player with AI Agents in SwiftUI and AppKit

I've long been looking for a simple player for Mac in the spirit of the old Winamp and couldn't find one: modern players are either bloated into all-in-one solutions with streaming and media libraries, or they're written in Electron and wastefully load the CPU. Three or four years ago, I started writing such a player myself, but it didn't get past the first screen and basic playback. The project lay dormant, and whenever I stumbled upon that folder, I'd remember it and think that someday I'd finish it. With the advent of neural networks, I finally succeeded.

The result is MacAmp: an open-source reproduction of Winamp 2.95 for macOS using Swift, SwiftUI, and AppKit. There's no Electron or web views in the interface, the build is universal (Apple Silicon and Intel), and it requires macOS 14 or newer.

Functionality

The windows, menus, settings, dialogs, and hotkeys in MacAmp are the same as in Winamp 2.95. All modern features are hidden inside or moved to a separate group at the end of the settings page.

  • The main window, equalizer, and playlist magnetically dock with each other. There's a Shade mode and Double Size (2x) mode.

  • Any Winamp 2.x skins (.wsz or folder) are compatible and read on the fly. The basic 2.91 skin is included.

  • Plays MP3, AAC/M4A, FLAC, WAV/AIFF, Ogg Vorbis/Opus, MP2, AU, and MIDI. It has crossfade, and when you switch headphones or speakers, the sound automatically goes to the new device.

  • A ten-band equalizer with a pre-amp, presets, and auto-loading by genre, plus pitch/tempo and reverb.

  • M3U, PLS, XSPF, and CUE playlists, bookmarks, Jump to File.

  • SHOUTcast and Icecast internet radio; the station catalog is taken from radio-browser.info.

  • Audio CDs can be listened to and copied to FLAC, ALAC, AAC, WAV, or AIFF.

  • Media library, Minibrowser, video window, Track Info with ID3 editor, spectrum analyzer, and oscilloscope.

  • The hotkeys from 2.95 work with the Russian keyboard layout as well (this required special effort).

  • An optional FFmpeg plugin adds support for MKV, WebM, AVI, WMV, WMA, APE, and WavPack.

The media library in the default skin displays Cyrillic in tags without any issues.

Classic Outside, Modern Inside

I've strived to make everything from Winamp 2.95 look and work the same way. Screenshots of the original are kept next to the code, and I refer to them. New features either work invisibly in the background, like support for modern formats and output device switching, or are moved to a separate settings group. There will be no cloud media libraries or subscriptions.

Track Info: ID3v1 and ID3v2 editor, just like in the original.

The second goal is for the player to sit quietly in the corner without draining the battery. On an M1, it uses about 0.01% of the CPU at idle, and 2–3% when playing with the spectrum analyzer active. When nothing is playing, the engine stops, and the analyzer stops sending frames after two seconds of silence. These two seconds are enough for the spectrum bars and peaks to fall.

A Few Technical Details

Windows Move as One Unit

The main window, equalizer, and playlist are three separate borderless NSWindows, and there's no built-in way to group windows in macOS. When you drag the leading window, the others should move with it and not drift apart. Therefore, I recalculate the position of each window from where it was at the start of the drag, adding the total shift. If you were to add small increments for each mouse movement to the current position, rounding errors would accumulate. Magnetic snapping to screen edges and adjacent windows is calculated once based on the projected frames, and only then is the result applied to the entire group:

let totalShiftX = roundedDeltaX + bestSnapX
let totalShiftY = roundedDeltaY + bestSnapY

for (gid, startOrigin) in startOrigins {
    guard let win = windows[gid], win.isVisible else { continue }
    win.setFrameOrigin(NSPoint(
        x: round(startOrigin.x + totalShiftX),
        y: round(startOrigin.y + totalShiftY)
    ))
}

Coordinates are rounded because in a pixel-based interface, window edges should not shift even by half a pixel, especially in 2x mode.

Pixels Without Smoothing

Winamp skins are raster BMPs drawn for old screen densities (MAIN.BMP, EQMAIN.BMP, PLEDIT.BMP, TEXT.BMP). If displayed using standard methods, fonts and timer digits would blur on Retina displays. Therefore, the windows draw themselves with interpolation turned off:

public override func draw(_ dirtyRect: NSRect) {
    guard let context = NSGraphicsContext.current?.cgContext else { return }
    context.interpolationQuality = .none
    // ...
}

Sprites are cut out precisely according to the original pixels, and coordinates are stored in SpriteCatalog. I verified them against the Webamp source code.

Equalizer

The ten bands with frequencies like in Winamp (from 60 Hz to 16 kHz) and the pre-amp are handled by a standard AVAudioUnitEQ: the bands are parametric filters, and the pre-amp is its globalGain. The audio goes through AVAudioEngine, so the player automatically follows the system's output device.

How It Was Written with AI

The majority of the code was written by AI agents. I came up with the ideas, assigned tasks, reviewed the results, and decided what to release. This approach worked: I understand what needs to be achieved and notice when the architecture drifts off course, while the agent knows the specific AppKit calls.

Three things helped me. First, the project includes documentation: vision, a phased plan, a checklist, and a reference guide for Winamp 2.x sizes and behavior, along with screenshots of the original. The agent reads all of this before working, so I don't have to explain every time that "like in Winamp" means literally. Second, the rules in AGENTS.md and several skills about the project structure and how to safely modify the equalizer and playlist: thanks to these, the agent doesn't break what's already working. And finally, all tests can be run with a single command: ./build.sh test.

One thing I couldn't delegate to the agents was the feel. How it feels to drag and drop, whether the field shakes, if the color is right, how the crossfade sounds on actual tracks – these can only be checked by hand and ear. Some of this testing is still on my to-do list, mentioned below.

What's Missing So Far

Milkdrop visualizations via projectM are not yet available, nor is an MP3 or Ogg encoder for CD ripping (Winamp 2.95 had Ogg Vorbis). Tracker modules MOD, XM, S3M, and IT also don't play: they require libopenmpt, and I'm still considering whether to pull in such a dependency. There's also no Last.fm scrobbler, and if it's added, it will be as a separate option and disabled by default.

Why No Apple Developer ID Signature

I intentionally did not sign the application. In Winamp, on the File types page, you can select which formats the player opens, and at the same time, change the icons for files and playlists. These changes were made on the fly. On Mac, Finder gets document icons from the application itself, so MacAmp replaces the icon inside MacAmp.app and re-signs itself with a local (ad-hoc) signature. This wouldn't have been possible with a Developer ID signature: the modified bundle would break it, and the icons couldn't be changed.

The price for this is the Gatekeeper warning upon first launch. You can open the application via System Settings › Privacy & Security › Allow Anyway or by running:

xattr -dr com.apple.quarantine /Applications/MacAmp.app

Preferences › File types: the same associations and icon changes as in Winamp.

Help Needed with Testing

I use the player every day, but on a single computer and with a single music library, so much is still not manually tested, and I would appreciate your reports. The most interesting aspects for me are: crossfade on real tracks (with pauses and seeking in the middle of them), albums in a single FLAC with .cue files, radio stations with reconnection after network interruptions, Bluetooth headphones during playback, and Mac sleep/wake cycles. I also haven't tested playlists with thousands of tracks (scrolling, searching, sorting, CPU load with windows open), old skins from the Winamp Skin Museum with non-standard graphics, and Intel Macs running macOS 14.
