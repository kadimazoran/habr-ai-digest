So, How Do We Search Regulatory Documents with Agents?

An analyst at a webinar asked about hierarchical indexes for regulatory documents: a tree of 'document → article → clause', where the model descends from the root and selects a branch, like a person browsing a table of contents. Then, about costs: indexing involves processing the entire corpus. I compared such an index to a B-tree. Then I sat down to calculate, and the comparison held up. In a B-tree on disk, a node is fitted to a block to reduce head movements. Here, the block is the effective window of a small model, and head movement is a call to it. Let's estimate. Six acts of ~200 pages — depth 2. 2M tokens — depth 3. The navigator reads 8–12 thousand tokens instead of the entire corpus. And the tree itself already exists in the laws: chapters, articles, parts, clauses. It's built with regexps based on numbering, without a model. Costs are one-time, only for a brief description of internal nodes. The navigator only needs to choose one of fifty branches based on a short description. This is closer to classification than reasoning. Someone in the audience asked if a 1.5–3 billion parameter model could handle this. Intriguing. On September 1st, I hosted a webinar on how to teach an agent to read documentation for an internal framework. The demo was about code: a niche Java framework, a library without source code, AGENTS.md next to the project.

But the first question from the audience wasn't about code. A system analyst is building a system that answers based on a corpus of internal security orders, GOST standards, and specifications. He needs an answer with a reference to a specific clause. The document structure cannot be altered: the document is legally significant.

Objections were raised in the chat. By the end of the broadcast, a discussion had developed.

In code, the agent has an arbiter – the compiler. Invent a method, and the build fails. Not everything is caught: at the same webinar, a participant's build passed, but the screen crashed at runtime. But there is an arbiter.

Regulatory documents have no arbiter. A retelling of a non-existent clause looks the same as a correct answer. How can one build such an arbiter and a search for it?

Example about editions. State information systems were protected for many years under FSTEC Order No. 17. From March 1, 2026, it was replaced by FSTEC of Russia Order No. 117 dated April 11, 2025, registered by the Ministry of Justice on June 16, 2025, under No. 82619 — official publication. It repealed five items: Orders No. 17, No. 27, No. 106, No. 61, and clause 1 of the amendments from Order No. 159. Certificates issued before March 1, 2026, "remain valid" — as stated in clause 3. From September 1, 2026, the Requirements are in effect under the edition of Order No. 137 dated May 8, 2026. The chain of editions does not end. The index must track it.

Now about retellings. There are common misconceptions circulating in reviews: a certificate is valid "until its expiration date" and "provided the configuration remains unchanged." These are not in the text of the order; they come from secondary sources. The real limitation lies in another document: FSTEC Information Message No. 240/22/1492 dated March 12, 2026, requires additional certification tests after system modernization.

A model trained on texts up to 2025 would answer "according to Order No. 17." Factually correct, but the document is outdated.

This article will be about that.

Three Solution Variants from the Webinar

Mine. Static documentation consists of files. The agent searches with grep and reads them itself. MCP for a static corpus is an unnecessary gear, another call in the chain. For a weak model, the corpus should be pre-processed into an index for its window.

Participant in the chat. grep is old-fashioned. A local search index is needed, like Windows Search, and it should be given to the agent via MCP. He clarified RAG: the first stages of the pipeline return documents, and only the last, generative one, retells them. Remove it, and the originals remain.

Analyst from the audience. RAG is heavy: database, vector storage, data preparation. The main issue is that during preparation, the model might rephrase a clause, and the original gets lost. He compared it to undefined behavior in C++: something was optimized under the hood, but what is unknown. He is interested in a hierarchical index: navigation through a tree with links to clauses. Costs: indexing requires processing the entire corpus.

What is clear:

  • The generative final step will have to be disabled or covered by quote verification.

  • MCP does not affect search quality: it's a transport mechanism.

Everything else is open. We will measure whether it is cheaper to preserve the original than to reconstruct it from a retelling. And how complex the search itself should be, if a model will read everything anyway — here, the chat participant and I did not agree.

What's Already Available

When writing the article, I looked for ready-made solutions.

Legal Databases with AI. ConsultantPlus has an AI assistant, and from July 2026, an experimental "Link Checker." It verifies if the acts cited by the neural network are still in effect. It's unclear from the description whether it compares the quote with the text of the clause. Garant has the assistant ISKRA and the Garant Connect API; Yandex's NeuroJurist runs on Garant's platform. Kodeks launched KodeksNeuro: answers on GOST standards and other technical regulations with references to clauses.

The strong point of all these is the handling of editions. They have been managed for decades, and there's no need to repeat this work in your own system: it's easier to get the current text via API. NeuroJurist also accepts custom documents, and its business tariffs include "operation within the company's environment." However, the answer is always generated by a model. This is variant D below, but the analyst needs the original.

Lexis+ AI and Westlaw AI are also built on RAG with generation and were marketed as "hallucination-free." In 2024, Stanford tested them: hallucinations were found in 17–33% of answers.

MCP Servers for Russian Law. garant-mcp provides the verbatim text of an article and its edition for a given date, but it accesses Garant through a browser session with your subscription. russian-law-mcp keeps federal laws in a local SQLite database with full-text search. Both are under Apache 2.0.

Search, original retrieval, and quote verification will have to be assembled within your own system. The question is how to do it with minimal components.

Five Approaches

A. Files and grep

The corpus is stored in markdown files in a repository, and the agent searches using ripgrep and reads the found content. Preparation: preserve clause numbering during conversion. The agent receives the original, without intermediate steps.

We run into morphology issues. The string "personal data operator" does not contain the string "operator of personal data." Part of this can be fixed with stemming directly in the regex:
