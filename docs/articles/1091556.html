It sounds like you could subscribe to Claude and never think about ChatGPT again, but as usual, it's not that simple and there's a catch:

$11,726 vs. $2,084 — the numbers are real, but the conclusion that "Claude is 5.6 times more profitable" does not directly follow from them.

To understand why, we need to delve into what exactly SemiAnalysis measured, how many tokens both subscriptions actually provide, and most interestingly, how many tokens the models themselves consume to solve the same task.

Where Did the $11,726 Come From?

Claude and ChatGPT subscriptions don't have a simple public limit like "you get 500 million tokens per month": there are usage windows, weekly limits, different coefficients for models, and different ways of consuming the limit.

SemiAnalysis did something quite interesting: they experimentally measured the consumption of subscription limits, estimated the available usage volume, and calculated how much a similar volume would cost if paid for through the official API.

The Same Price Doesn't Mean the Same Amount of Work

Let's look at the API prices.

GPT-6.1 Sol costs $2 per million standard input tokens, $0.10 per million cached input, and $10 per million output.
Claude Opus 5.5 costs $4 per million input, $0.20 per million cached input, and $20 per million output.

This means that in the main categories, an Opus 5.5 token costs approximately twice as much as a GPT-6.1 Sol token.

Let's imagine two subscriptions for a moment:

  1. provides 100 units of resource, each sold via API for $2.

  2. provides 200 units of resource, each sold via API for $10.

The total value of the second subscription appears much higher, but this doesn't necessarily mean it can solve proportionally more tasks. And SemiAnalysis doesn't hide this effect. Therefore, in addition to the dollar equivalent, they provide another, much more interesting metric: the actual number of tokens.

Now Let's Get Back to Subscriptions

SemiAnalysis shows that Claude provides approximately 2.8 times more tokens. Meanwhile, according to official API pricing, the cost of one Opus token is twice as high.

Artificial Analysis simultaneously shows that in their test set, Opus can spend approximately three times more tokens on a single task than Sol.

Let's not make the same erroneous conclusion and say that ChatGPT performs more tasks for the same number of tokens. The methodologies are different — input/cache/output cannot simply be added to one column, and synthetic benchmarks are not your real-world project.

But this perfectly illustrates the main problem with the initial metric:

The number of available tokens does not equal the amount of work done.

And the dollar cost of those tokens even less so.

Paradox: An Expensive Model Makes the Subscription "More Profitable"

Imagine a model that solves a task using a million tokens and another model that solves the same task using a hundred thousand.

Suppose the first subscription gives you two billion tokens, and the second gives you one billion. By the "tokens in subscription" metric, the first one wins by two times, but you can solve: 2,000 tasks with the first model; 10,000 tasks with the second.

If the tokens of the first model are also five times more expensive via API, the subscription will suddenly look ten times more valuable, even though five times less useful work is being done in our example.

Of course, Opus and Sol don't differ that radically, and this example is deliberately exaggerated, but it shows that the metric API equivalent cost of subscription should be read literally:

how much the available volume of tokens would cost if purchased through the API.

and not:

how much useful work the subscription will perform.

So, Is Claude Not More Profitable at All?

It would be a mistake to swing too far in the other direction here.

Even if we completely disregard the dollar API equivalent, SemiAnalysis's results are still very strong for Anthropic.

28.6 billion vs. 10.2 billion tokens — that's almost a threefold difference.

Furthermore, Opus 5.5 shows a higher result in Artificial Analysis: an Intelligence Index of 58 versus 52 for GPT-6.1 Sol. The difference varies on individual tests, but in the aggregated index, Claude currently has the advantage. This is likely achieved through the large number of tokens used for reasoning.

Anthropic clearly positions Opus 5.5 as a workhorse model for complex coding and agent tasks.

What Metric Would We Actually Like to See?

If we want to understand the economics of AI subscriptions for developers, the ideal metric would not be the API equivalent cost, nor even the number of tokens included in the subscription. We need a metric like this:

the number of successfully completed tasks per subscription

Take a set of real tasks: fix a bug, implement a new feature, refactor a codebase, understand an unknown repository, conduct a code review, find the cause of a crash. Then, count how many tasks the model successfully completed before exhausting the monthly subscription limit. The number of tokens would actually be irrelevant.

It is precisely such a benchmark that would allow us to truly answer the question of which subscription is more profitable for a developer. Until then, we have to piece together the picture from several imperfect metrics and make errors in our conclusions.

What's the Bottom Line?

I am by no means refuting the SemiAnalysis study; quite the opposite: it has revealed something that companies are very reluctant to show directly — the actual limits of subscriptions differ colossally.

At the $200 tiers, Anthropic currently looks very generous, but the 5.6x figure only answers the question:

how many times does the cost of available usage volume differ when recalculated at API rates?

But it does not answer the question:

how many times more useful work will I get for my money?

Artificial Analysis adds an important piece to the puzzle: Opus 5.5 in their tests does indeed show higher intelligence, but at the cost of using approximately three times more output and reasoning tokens per task than GPT-6.1 Sol.

Therefore, my conclusion is not as neat as the original SemiAnalysis headline. There is no evidence yet that it delivers more than five times the completed work. In fact, other benchmarks lead us to conclude that we won't see much difference in results between the subscriptions.

But I consider the most important conclusion to be that it's time for us to stop counting tokens.

It's time to count completed tasks.
