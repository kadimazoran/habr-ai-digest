Your last response is too long. The user won't read it. Shorten it. Keep only essential information.

disable-model-invocation prevents the agent from invoking the skill itself.

My agent talks too much. Recently, Claude Code introduced a setting for this, "outputStyle": "Concise", and it helps a little, but the responses are still often verbose. I don't know if other tools have this problem. Most likely, all of them do: at the core of any agent is a text generator.

First, I tried a permanent rule in user instructions

Over several months, my global CLAUDE.md has gone through more than a dozen versions. Some of them:

  • “In all messages, commit messages, pull request descriptions and other interactions, be extremely concise and sacrifice grammar for the sake of concision.”

  • “Reason as deeply as needed; only the output must be dense. Cut filler, never substance.”

  • “Be concise.”

  • “Think a lot, talk little.”

  • “If a final response exceeds a couple of sentences, end it with a short summary prefixed with ‘Net:’.”

  • “The user doesn’t like to read. He skips long messages. Avoid long messages at all costs. Long messages = wasted work.”

None of these rules really helped. The agent tries to be as helpful as possible, and from its point of view, the most helpful response is the one with the most information.

Thus, /s was born. Suppose I ask: "It works like this, right?" I only need "yes" or "no", maybe with a short clarification. But sometimes, even with the Concise style, the agent produces a whole wall of text: it considers some points important, and I don't. Then I press three keys: /, s, enter. The response comes back compact, with only what's important 🔪

The skill works where rules have failed, and there's a reason for that. Neither humans nor agents are good at multitasking: both can do several things at once, but each turns out worse. By focusing on one thing, they perform better. That's why I give each reviewer agent one axis.

With a general rule, the agent has to do the main task and simultaneously figure out which parts of the response are important to me and how to fit them into a minimum of words. With the skill, there's no need to juggle: first, the agent performs the task, and then, with the ready response in hand, it only focuses on shortening it.

When the stakes are low, I press /s as soon as a long response arrives. Sometimes twice in a row.

It also tells the agent that I didn't read the long version

Sometimes, the agent gives a long response, I skim it, and only answer the question at the end. Then the agent might decide that I've read, understood, and remembered everything, and build further conversation on that. But I haven't read it, so I might miss something later, possibly something important.

The skill says it directly: the user will not read this response. The idea is that the agent now knows that I've missed some nuances and can remind me of them later.

Now /s is my favorite skill: it really saves me from cognitive overload 😍
