How working with the plugin looks

I asked it to analyze active advertising campaigns and load conversions from Metric. In response, ChatGPT showed expenses, clicks, and goal achievements for the campaigns.

The MCP server gets data from Yandex API, and ChatGPT explains the result. The model's conclusions and selected goals need to be verified: achieving a goal in Metric by itself does not yet confirm a sale.

How we published the MCP in Sites

  1. Assembled the server in the company's repository. In the code, we defined available commands and checks for parameters, accounts, and counters. Arbitrary methods or API addresses cannot be passed.

  2. Configured Yandex keys. Direct and Metric tokens, Wordstat key were saved in the Site's server variables. Secrets are not passed to the chat, source code, or tool arguments.

  3. Published the Site with MCP. The server accepts requests at /mcp; the owner receives a linked plugin upon publication. We did not need a separate OAuth server for login from ChatGPT.

On November 17, 2026, we checked the connection via check_connection: reading Direct and Metric was successful. For Wordstat, we only checked the free region directory — this check does not confirm the freshness of frequencies.

Who has access to the plugin and data

The settings below are as of November 17, 2026.

Site Access

The owner chooses the audience: invited users, workspace, or access by link. We chose Infostart participants.

For a marketer to work, view access is sufficient. An editor can refine the Site; we did not add additional editors.

Plugin Access

In our workspace, the plugin can be distributed by invitation, by link, or through the catalog. We chose the Infostart catalog.

An employee needs access to the Site. After that, they find the plugin in the catalog, click "Install" and "Connect," then select it in the chat. They do not need local programs or their own Yandex keys.

For our plugin, it is set to Use my default: it inherits the general setting Allow low-risk actions. This determines when ChatGPT requests confirmation and does not add commands to the server.

Access to Yandex Data

Access to the Site opens up a common set of integration data to the employee. The server accesses Yandex using general tokens; the employee's personal Yandex rights are not checked here. For different departments with different accounts, separate Sites or code-based differentiation are needed.

Our MCP lacks commands to change advertising. If they are needed, a separate MCP can be created and opened only to employees authorized to make changes. Yandex token rights are configured separately from ChatGPT permissions.

When is an interface to other services needed?

An account will be needed if the numbers don't add up, the integration fails, or it lacks a required function. In our example, the model, the working interface, and MCP hosting depend on a single provider.

If company data and tools are accessible from ChatGPT, it begins to act as a working operating system.
