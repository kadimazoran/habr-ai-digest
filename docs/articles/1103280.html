Kodacode 1.3: The agent can now interact with applications and has its own browser

Kodacode 1.3 has been released, enabling interaction with computer applications. The Desktop version now includes a built-in browser for viewing web pages alongside the chat and easily sharing content with the agent. Additionally, the update introduces change previews without Git, interactive prototypes, AI agent automation flows, and an improved CLI for CI integration. This article details these new features, including a look at the new pet.

Until now, Kodacode only worked with code and the terminal, for example, reading files, executing commands, and parsing their output. In version 1.3, it has expanded beyond the editor. The agent can now control applications on your computer, and the Desktop version features a built-in browser.

Computer Use

Kodacode can find the necessary window or launch an application, observe its state, click on UI elements, scroll, and input text. It interacts with applications just like a human user: by seeing the screen and interacting with UI elements.

Computer Use is available in the Desktop version and in IDE plugins, in Agent mode.

Built-in Browser

Previously, a link from the chat would open in an external browser, requiring you to switch back to Kodacode, which was inconvenient. Now, pages open directly within the Desktop application, next to the chat.

The browser includes navigation, text search on the page, element selection, and screenshots. Selected text can be sent to the agent with a single click.

What else is new in Desktop

Change Previews

An agent can modify a dozen files in a single chat session, making it difficult to track exactly what was changed. Now, in Koda Desktop, all modifications are visible as a familiar diff view. Deleted lines are highlighted in red, and added lines in green.

Changes can be viewed at two levels:

  • For the entire chat: all agent modifications from the beginning of the conversation in one place. This is useful for checking for extraneous additions before committing.

  • For a single message: only the changes made by the agent in response to a specific request. This is helpful for pinpointing when something broke in a long dialogue.

And what's great is that diffs work even in projects without Git. Kodacode tracks the agent's changes internally, so reviews are available even in script folders, draft prototypes, and any project where a repository hasn't been initialized yet.

Screen Splitting and File Viewing

The first thing you want to do after agent modifications is to open the file and see what it did. Now, you can do this without leaving the agent. The Desktop window can be split into two parts: the chat on the left and the workspace on the right, where the file opens directly. It includes syntax highlighting, line numbering, and more. You can also attach a specific part as content for the next message. Additionally, you can display a tree of all files in the selected directory next to it.

Interactive Visualizations

The agent generates interface diagrams and prototypes directly within the Kodacode workspace. On the board, you can compare mobile and desktop versions side-by-side and click through interactive screens. Prototypes are built from your project's components and styles, making them resemble the actual product.

Flows (beta)

Flows are a visual automation builder within Koda Desktop. If you've used n8n or Zapier, the concept will be familiar: a scenario is assembled from blocks on a canvas and connected by arrows. The difference is that any step can be performed by an AI agent. The agent doesn't just pass data along; it reads, analyzes, writes, and makes decisions.

Flows can be triggered manually, on a schedule, via a webhook from an external service, or from another flow. Inside, you'll find everything needed for true automation:

  • agents that can return responses strictly in JSON according to a specified schema;

  • HTTP requests and MCP tools for interacting with external services;

  • conditions, branching, and loops;

  • file and list operations: reading, writing, filtering, sorting;

  • manual approval: the flow pauses and waits for human verification of the result.

For example, every morning a flow can fetch the latest AI news, select the most discussed ones, the agent writes a draft post about them, and you only need to approve it before saving. There are ready-made templates to get started, such as processing incoming events, scheduled reports, extracting data from documents into a table, and research with edits and reviews.

This feature is currently in beta. Enable it in Settings → General → "Flows (β)".

CLI: Kodacode in CI

The headless mode in Kodacode CLI has been significantly expanded, allowing it to be integrated into pipelines.

  • JSON output and streaming JSON;

  • usage metrics;

  • exit codes;

  • control over launch parameters.

Multiple requests can be submitted consecutively via stdin with the --input-format stream-json flag. Slash commands also work without a TUI.

Previously, in non-interactive mode, Kodacode CLI only returned the final text, making it impossible to know what the agent did along the way. Now, you can enable streaming JSON: the CLI will output events as the agent works, with one JSON object per line.

Let's ask the agent to explain what a file with payment logic does:

You can see each step: first, an init event with the session ID and model, then a tool_request where the agent decides to read the file, followed by a tool_result with the reading outcome. The response then arrives in chunks via content events, and finally, a result event with the overall outcome, number of turns, and token consumption.

This format is useful if you're integrating the agent into your own tool, such as a bot, an internal dashboard, or an IDE plugin. You can display the response to the user as it's generated, log every tool call, and immediately see where the agent made a mistake.

When the agent runs in a pipeline, the output isn't read by a human, so the script needs to understand how the run concluded. For this purpose, Kodacode CLI now has exit codes: 0 indicates success, and a non-zero code means the task could not be completed.

You can also limit the agent with the --max-turns flag to prevent infinite loops and token waste. Let's see what happens if we give it too few turns. We'll ask it to describe all project files but allow only one step.

The agent hit the limit: the JSON response shows "stop_reason": "limit", and the CLI exited with code 2. In GitHub Actions, GitLab CI, or any other pipeline, the build will stop at this stage, and you'll immediately see that the agent did not complete the task.

Additionally, the CLI shell now works without PTY (which is often missing in containers and on runners). Tool selection and token counting have also been improved.

Plugins

In IDE plugins:

  • Computer Use in Agent mode;

  • each chat displays creation and last modification dates;

  • history can be sorted by last activity: newest or oldest first. Sub-agent activity is considered, while they remain nested under the main chat.

Agent Adheres More Closely to Task Boundaries

We have refined the task boundaries in the agent's instructions:

  • a question or request for explanation does not grant permission to modify files;

  • search must be related to the query;

  • work is considered complete when a result is obtained and necessary checks are passed.

System instructions for different models have been unified, and general rules have been localized into Russian and English. User model validation and context evaluation have been improved.
