1. Motion Graphics in After Effects and HyperFrames

I've loved After Effects for a long time, so Kris Kashtanova's experiment with Astra immediately caught my attention. She asked the neural network to create special effects and animated graphics directly within the program.

Miguel Angel also showed a video made in HyperFrames using Astra. According to him, he used a ready-made reference video as a basis.

My feelings were about the same as with Blender: ideas for motion design for various brands and commercials immediately came to mind.

After Effects can run scripts that handle routine tasks in a project. HyperFrames works differently: video is assembled from HTML, CSS, and JavaScript. For an AI agent that can write code, this is another way to generate animation.

A good first experiment would be branded promotional animation. I would provide the logo, fonts, and color scheme, as well as an example of the animation style. Then I would ask Astra to create a short intro animation and make necessary adjustments along with it.

Motion design involves minor edits. The title disappears too quickly, the transition is abrupt, and the product appears before the viewer has finished reading the text. It would be good to simply describe what's wrong and get a corrected version.

I would also check how Astra handles adapting the video for different screen formats. For vertical video, you usually have to rebuild the composition, and I'd want the model to rebuild the frame rather than just scale down the original video.

It would be so cool to try this in practice. I already have websites that could use better promo videos, and a short animation would be a convenient project for me to start with.

2. Interactive 3D Websites


User ashe created an anatomy website in 3D using Astra, where you can view individual parts and organs of the male body model.

If you're tired of generating ordinary landing pages, here's a rather ambitious alternative.

I've always liked striking design and animated websites, so I'd gladly take on creating such a project. The visitor is given an object that can be studied, and they choose how to view it.

This example with an interactive website also shows how 3D can be useful for a website. When a model can be disassembled, it becomes clear how everything inside works. A similar approach can be used for a product whose internal components are difficult to show in a photograph.

Imagine a website with speakers where you can look behind the protective grille, or a camera website where the lens disassembles into its components, and selecting any part would bring up a short description.

A few years ago, creating such a website would have required a separate budget and a developer. Now, I would first try to create a prototype myself. The costs in this case depend only on the tools used and the scope of work, but it's already possible to implement almost any idea.

I would also add parallax and animated transitions. I like this design, although it's hard to resist making every element dynamic.

The website must be optimized for mobile loading, and visitors should find information rather than wait for the animation to finish loading. I would start with one interactive 3D section and add the rest after checking if it works correctly.

3. Explaining a Topic with Cinematic 3D Reconstruction

User Haider asked Astra to explain the incident between OpenAI and Hugging Face in the format of a cinematic 3D reconstruction.

I would love to try this format in a technical article. Some topics are difficult to explain with screenshots, and a short animation would help readers better understand the topic or individual concepts.

A 3D scene can show how components are related or illustrate a sequence of events. The camera can zoom in on the relevant part while a voiceover explains what's happening, and then linger long enough for viewers to understand everything.

If it were about a software incident, I would start by presenting the facts and use labeled objects to denote the systems involved. Using animation, I would show the interaction between them, as well as what happens next.

I would immediately make it clear that the scene is an illustration. Especially when it comes to a real event: the video should help clarify the facts, not create the impression that one is watching actual footage.

There are many other topics I'd like to try. It would be good to create a video on assembling a mechanism—disassemble it, explain why each part is needed, and reassemble it. A building is also easier to show if the camera moves through its layout.

Of course, I'd want the video to be beautiful. But I would also make the camera stop occasionally, because when there's too much animation, it's harder to follow the explanation.

Even a short video within the text would be useful for my articles. Detailed information would be in the text, and the video would show a process that's difficult to describe. I enjoy working on such a video much more than searching for a generic image only vaguely related to the topic.

4. Jelly with Three.js

X user Scott asked Astra to create bouncy jelly with Three.js and WebGPU—it turned out pretty cool. You can read about how the Claude Opus 5.5 model handled a similar task in my article.

I've seen many 3D objects generated by GPT and Claude models. But when I saw something like this that you can actually interact with, I thought: how much easier will it be to experiment with games.

The same idea can be used to create a small game based on it. Imagine a jelly character squeezing through obstacles. Or dropping different objects onto a surface and watching them bounce.

I can imagine spending a lot of time playing such a game.

Three.js is a JavaScript library for creating 3D scenes in a browser. The code controls objects, materials, and animation, so the appearance and behavior of the result can be changed as much as desired.

There are plenty of materials for experimentation. You can ask to make the material softer, the movement stronger, or change the shape altogether. You can go through several versions before deciding which one will become an interesting game mechanic.

You'll also have to work with the movement. The jelly should deform and gradually return to its original shape. If the object just bounces up and down, the effect won't be the same.

I like these small experiments because you don't need to think through the entire game beforehand. You start with one interaction, see if it's fun, and build something around it. Even a silly jelly demo can be enough to start working.

5. Astra Will Draw You in Paint or Canva

Astra will open a drawing application itself and draw you. User Alex shared an example from Microsoft Paint, and user Zachi shared one from Canva.

At first glance, this is a simple request, and I was surprised by how confidently the model handles the drawing process.

Drawing a person requires precision. You need to analyze the reference, choose tools, and apply lines correctly. After all, even if the model makes mistakes when drawing the eyes or the shape of the face, a different person will look from the portrait.

The entire process takes place in the program you use yourself. Watching the portrait appear, you can see how many individual actions the model performs.

In terms of speed and clumsiness, the process looks much better compared to demos with computer control from a couple of months ago. According to OpenAI's information, Astra has become more efficient at working with computers. However, videos from social media are not a verified comparison.

I would start by trying to create a simple drawn avatar with a limited palette and in a style that would look good even at a small size. Then I would ask to change the facial expression and see what remains of the original drawing.

This capability would be useful for anyone who draws sets of avatars or character illustrations. Getting one liked drawing is great, but the ability to refine it without starting from scratch would make this feature something I'd use more often.

And yes, it's just funny to me: we give a powerful model access to a computer and ask it to draw us in Paint.

6. Creating 3D Environments and Assets in Blender

User Anshu showed a 3D game project created by Astra. According to him, Codex is connected to Blender via MCP.

MCP allows an agent to access the tools provided by another application. In this case, it gives Astra the ability to work with Blender within the project.

I've seen examples like this in various forms. Some generate individual 3D assets, some generate characters, and some assemble entire scenes. The quality of some works is honestly impressive.

I keep coming back to the thought of how much time this will save a 3D artist or animator, especially when there are many background objects in a scene. You can assign the agent the task of creating variations of props and distributing them, and dedicate more time to the details that people will actually notice.

Blender has a Python API, so agent developers can programmatically create and modify scene elements. The available operations depend on the specific integration, but much can already be controlled via code.

I would start my experiments with a small environment: different lighting options, different camera angles. Even without adding characters and animation, this would be a useful template for video planning.

It's more complicated with characters. The model might look great in a render but still need refinement to move correctly, especially around the joints.

Still, the ability to describe a scene and get an editable starting version would make me more willing to try working with 3D. I wouldn't have to study every detail of Blender before finding out if an idea is good.

7. UGC Videos and Product Advertising

Jerrod Lew showed an advertisement for shoes that he created using Astra and other tools. According to him, he generated the initial shoe images in GPT Images 2.0, and then generated the video itself.

I know this isn't anything new. AI videos with product ads and user-generated content (UGC) style ads have been around for a long time. But this example is much more realistic than many videos I've seen before.

I think if I were scrolling through my feed, I wouldn't immediately realize it was a generated video.

You can imagine a workflow where you define the product's appearance, develop a storyboard, and create frames according to it. Astra helps plan and coordinate all of this, and image and video creation tools do their part.

In UGC videos, the presentation is as casual as that of content creators. This is another direction you can try alongside more traditional product advertising.

In the case of shoes, I would compare a video with a close-up of the product to one where the shoes are shown as part of an everyday outfit. The same product in different settings and with different presentation feels completely different.

If it's a real brand, I would start with actual product photos and check the details throughout the video. The sole, stitching, and logo should remain consistent. Even a very realistic video is a problem if a different sneaker appears in the frame halfway through.

I like the idea of refining several concepts to the point where they can be visually compared. When you have examples of frames and a storyboard, it's much easier to decide which advertisement to develop.

8. Turning a Painting into an Explorable World

Using Astra, X user Pietro Schirano transforms the paintings of artist Hiroshi Nagai into explorable worlds.

Of all the methods I found, this is one of the most unusual examples of use, and perhaps the one I would spend the most time with.

You can take a scene that exists only as a two-dimensional image and move within its interpretation. I immediately wanted to know what would happen if I went beyond what is depicted on the canvas.

The model will have to invent part of this space. The painting doesn't show what a building looks like from other sides or what's at the end of the road, so there's plenty of room for interpretation.

I would want the result to retain the mood of the original. Colors and proportions are half the reason people love a painting. If everything is made more realistic, walking through its world might become less interesting.

All of this led me to the idea of an application where you can upload a painting, and Astra, using Blender, will generate an environment that can then be explored in a browser. I would start with my own image or a famous painting, and make the first scene small.

A huge world isn't necessary for enjoyment. A few interconnected areas are quite enough for a stroll. I would also add the ability to return to the original viewpoint so that it can be compared with the painting.

This approach can be useful for game designers to turn concept art into an early version of a game world. After walking through it, you can decide what to change, and only then spend time on full scene assembly.

I would probably just keep trying different paintings to see what Astra does with them.
