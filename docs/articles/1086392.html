Practice (Without Measurements)

Let's move on to practice!

I decided to tackle a rather complex task right away - it's called "Multi-hop branching".

Regular multi-hop is like "a = b = c, what is a?" and the model, in theory, should output "c", but as it turned out, this was a simple task for my network.

And branching multi-hop is like "a = b, and also a = c. What was the initial 'a', and what is the final 'a'?"

In general, I had two inference scenarios after training:

  1. Simple test ("a = b, a = c"), without any modifications.

  2. Test, but for (how is it pompously called) length extrapolation - meaning the test length is increased. So here it was like this: "a = b = c, a = c = b".

My network always failed on the second test.

Initially, I thought the problem was in the LWM layer.

I tried to "solve" it like this: first, I tried replacing the division by with LayerNorm (the quality was better, but it still failed), then I decided to pass H through three matrices first - Q, K, V - without changes.

In short, I tried all the reasonable options in my opinion, and I realized that LWM wouldn't help me at all.

Then I thought and thought - and realized - I forgot to add the output gate (well, yes...).

So, after an hour of fiddling with the output gate (sometimes turning it into a regular linear layer, sometimes using instead of the normal ), I arrived at the conclusion of how the output gate should be. Well, I arrived at this option in the "Theory" section.

And suddenly, my network started passing these multi-hops.

import torch
import torch.nn as nn
import torch.optim as optim
import numpy as np

device = torch.device("cuda")

class LSWM(nn.Module):
    def __init__(self, vocab_size, d_model):
        super().__init__()

        self.d = d_model
        self.sd = d_model ** 0.5

        self.vocab_size = vocab_size
        self.embedding = nn.Embedding(vocab_size, d_model).to(device)

        self.W_f = nn.Linear(d_model, d_model).to(device)
        self.W_ix = nn.Linear(d_model, d_model).to(device)
        self.W_ih = nn.Linear(d_model, d_model).to(device)
        self.W_o = nn.Linear(d_model, d_model).to(device)
        self.a = nn.Parameter(torch.scalar_tensor(2)).to(device)

        self.norm = nn.LayerNorm(d_model).to(device)

    def softsign(self, x):
        return x / (1.0 + torch.abs(x))

    def softsign_scaled(self, x):
        return (1.0 + self.softsign(x)) / 2.0

    def forward(self, token_seq):
        batch_size, seq_len = token_seq.size()

        x_seq = self.embedding(token_seq)

        h_t = torch.zeros(batch_size, self.d).to(device)
        h = []

        for t in range(seq_len):
            x_t = x_seq[:, t, :]

            x_normed = (self.softsign(x_t + h_t)) * self.a

            f_t = self.softsign_scaled(self.W_f(x_normed + h_t))
            i_t = self.softsign_scaled(self.W_ix(x_t) + self.W_ih(h_t))
            o_t = self.softsign(self.W_o(x_normed + h_t))

            c = self.softsign_scaled(f_t * h_t + i_t * x_normed)

            h_t = o_t * c

            h.append(h_t)

        h = torch.stack(h, dim=1)
        res = torch.bmm(h, torch.bmm(h.transpose(-2, -1), h))
        h = res / self.sd

        res = self.softsign(h.sum(dim=1))

        return self.norm(res)

VOCAB_SIZE = 21
TOKEN_ARROW = 15
TOKEN_Q_1 = 16
TOKEN_Q_2 = 17

def generate_branching_batch(batch_size, epoch):
    x = np.zeros((batch_size, 7), dtype=np.int64)
    y = np.zeros(batch_size, dtype=np.int64)

    for i in range(batch_size):
        a, b, c = np.random.choice(15, 3, replace=False)

        ask_live = epoch % 2 == 0

        if ask_live:
            x[i] = [a, TOKEN_ARROW, b, a, TOKEN_ARROW, c,  TOKEN_Q_1]
            y[i] = b
        else:
            x[i] = [a, TOKEN_ARROW, b, a, TOKEN_ARROW, c,  TOKEN_Q_2]
            y[i] = c

    return torch.tensor(x).to(device), torch.tensor(y).to(device)

Pros and Cons of My Network

Pros of LSWM (original):

  1. "Larger" tails of softsign.

  2. Simplicity of operations (0 exponents).

  3. Relatively few parameters (no W_c).

  4. "Self-Attention" in the LWM layer.

Cons of the original LSWM:

  1. Sometimes the "large" tails of softsign can be detrimental.

  2. is actually a poor calculation that makes too strong, causing the network to be more sensitive to random seeds.

  3. Absence of CEC - the carousel of constant error is still important.

The modified LSWM (with the carousel of constant error described in the "Benchmarking" section and other modifications) has one disadvantage and loses one advantage.

This disadvantage is the softsign tails.

The advantage lost is the small number of parameters.

Conclusion

I'll make a quick conclusion.

Constant Error Carousel is a very important thing, you can't do without it.

Don't make too strong, even if you normalize it with softsign later.

Softsign and its scaled version (for the range 0 to 1) as a replacement for tanh and sigmoid is a working idea.

Replacing concat with summation is also a working idea.

The LWM layer is also a working idea (because the quality didn't drop due to it, the model still responds well).
