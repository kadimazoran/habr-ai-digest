To answer the question "has it gotten better?" without guesswork, let's first agree on what an eval is.

1. What is an Eval and Where is it Run

1.1. Eval Components

An eval includes three key components:

  • Cases: a dataset of input data for testing.

  • Checks: criteria for evaluating the result.

  • Evaluation: metrics that show how successfully the task was performed.

Choose the simplest check that will help you detect an error.

End-to-End Example from a Project

Let's take the Job Hunt project (Job Radar bot). It started as a pet project and later became a full-fledged service. The service collects IT vacancies from Telegram channels and distributes them by professional fields.

The Problem

One of the service's main features is classifying vacancies by professional fields (backend, HR, QA, etc.). If the model makes a mistake, the vacancy ends up in the wrong category, and subscribers won't see it. These errors go unnoticed: without exceptions or log entries.

Eval Components for This Feature

  1. Cases:

    • Input data: vacancy text.

    • Success criterion: correct field label plus an explanation of why it fits.

  2. Check:

    • Code that retrieves the response from the feature and the reference label.

    • Comparison of the label with the reference: a case is considered passed if the response matches the reference.

  3. Result:

    • Analysis of results: how many cases passed, how many failed.

    • Comparison of results for different versions of the prompt or model.

    • It's important to run the case dataset with the same configuration as in production, with identical parameters, so the results will be comparable.

Storing Cases

Cases are conveniently stored in jsonl (JSON Lines) format: each JSON object describes a separate case.
