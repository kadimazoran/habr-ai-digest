Glafira for Apache Kafka: An Open-Source Rust Desktop Client That Lets LLMs Read Your Cluster, But Not Touch It

Glafira for Apache Kafka is a free desktop client for Kafka on macOS, Windows, and Linux, built with Tauri 2, Rust, and librdkafka, with open-source code under Apache 2.0. It offers message viewing with filters and JSONPath, a Producer with templates, consumer sessions, topic and group management, offset resets, and built-in cluster checks. Its most interesting feature is the MCP gateway for LLMs. Claude, GigaCode, Cursor, or any other MCP-compatible client can connect to Glafira to read cluster metadata, identify issues, and suggest changes, but cannot make any modifications. Why Another GUI for Kafka

If you work with Kafka not as an administrator but as a developer or tester, your typical day looks like this: kafka-console-consumer with five flags, kcat with another five flags, a custom script to "find a message by substring in value," and another one to "reset group offsets before running autotests." Every time, you have to recall the syntax, and every time, you copy SASL settings into yet another config.

GUI tools exist, but each has its compromise: some are proprietary and paid, some require a JVM, some are deployed as server applications, which is overkill for "just looking at a topic on a dev environment." I wanted something simple: a regular application that installs in a minute, stores passwords in the system's secret store, and handles the six daily tasks I need.

Dreaming is not harmful, and I thought I couldn't bring this to reality. Then I met a smart fellow named Claude, who helped me out like a brother.

Here are those six things, which also served as criteria for my MVP:

  1. Connect to a cluster with the required authentication faster than a minute, including importing certificates.

  2. Find a message in a topic by a substring in the key, value, or headers, limiting the search by time or offset.

  3. Send a message with a key and headers, including a batch of generated ones.

  4. Read a topic as a consumer group member and commit offsets manually.

  5. Create a topic, change configurations, add partitions, clear, or delete it.

  6. View consumer groups, their lag per partition, and reset offsets.

Why the name Glafira? I just liked the name ) I also like to call her affectionately—Glasha ) I plan to create a whole family of tools for my work; currently, I'm working on Glafira for PostgreSQL, a similar tool for PostgreSQL and Patroni clusters, so Glafira for Kafka is just the first of them.

What It Can Do

Briefly, without marketing fluff.

Connections. PLAINTEXT, SSL, SASL PLAIN and SCRAM-SHA-256/512, mTLS with client certificates in PEM, PKCS#12, or JKS. Trusted CA—also PEM, PKCS#12, or JKS, or system root certificates. Connections are organized into nested folders, exported to a file without passwords, and imported on another machine with a preview. Passwords and key passwords are stored in Keychain, Credential Manager, or Secret Service, not in a JSON file nearby.

Message Viewing. Reading without group.id via assign, so the cluster doesn't notice the observer. Initial position: last N, from the beginning, from offset, from timestamp, "last X minutes." Filters are applied in Rust before sending to the interface: substring or regex on key, value, and headers, JSONPath condition like $.order.status == "FAILED", time range. Live tail with a circular buffer, limit up to 100,000 messages. Formats: auto, string, json, hex, base64.

Producer. Key, value, headers, partition selection, acks, compression, idempotence. Templates with placeholders {{uuid}}, {{now}}, {{seq}}, {{randomInt 1 100}}, {{env NAME}}. Batch sending: N copies of the form or a JSON Lines / CSV file. "Resend" from the message table copies the key, value, and headers byte-for-byte, and the templating engine doesn't touch existing text.

Consumer Sessions. Honest group joining with rebalancing, partition assignments, manual commit via buttons. Autocommit is off by default.

Topics and Groups. Creation, config editor with "before → after" diff, adding partitions, clearing via DeleteRecords, deletion. For groups: lag per partition, members with hosts and group.instance.id, offset reset with mandatory preview, only for groups in the Empty state.

Cluster Check. A set of built-in rules: no controller, under-replicated and offline partitions, replication factor of 1, min.insync.replicas greater than RF, unclean leader election, auto-topic creation, divergence of important settings between brokers, empty groups with lag, perpetual rebalancing, lag increased since the last check. Strictness depends on the connection environment: RF=1 is critical in prod, a warning on stage, and not shown on dev at all.

Small things that turned out to be important. In this fast-paced world, there are fast people who don't have time to navigate links and search for information among "lots of text" in a not-so-clear language. Therefore, the interface is available in 12 languages. Built-in help with F1 search. "?" tooltips for every field and every topic configuration parameter. Everything in one place—right before your eyes. Corporate policy via MDM, GPO, or /etc: disable auto-updates, specify a mirror, fix the language, disable MCP. Paranoia is not an illness these days, but a useful skill.
