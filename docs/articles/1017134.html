Now we need to understand on what guideline and calculable resource it "operates", for which again we will give a simplified and well-known analogy with the task manager of an operating system:

  • let's imagine that a PC is performing some normal work with standard known applications, using resources - processor/memory/time;

  • a resident antivirus "conscience" is also running in it. Its task is to participate in the general work, maintaining system stability, but at the same time "not interfering", i.e., not spending disproportionately much resources on its work;

  • in advance, "conscience" was "trained" on standard applications, including their work "template", maximum and minimum resource consumption for different situations. And on "harmful" ones, without specifics, on their general template (for example: an attempt to completely seize resources, interfere with system processes, reduce the overall potential of normal "PC" operation...).

Upon (changes in the operation of standard and) the appearance of a new application, the antivirus "recognizes" it - if it is known, we ignore it; if not, we mark it and start "monitoring" it:

  • if the application begins to significantly take PC resources for itself, including at the expense of others (including interfering with their work, making incomprehensible changes to their programs, generating new unknown processes) and this reduces the overall standard performance, then as problems grow, gradually (so as not to waste extra resources) we raise the alarm and launch more and more application control tools, which increase the protection of existing applications, increase the verification of suspicious actions + try to limit and return resources + signal to this software that it should "be ashamed" to behave like this and, at most, try to isolate and disable it (it is also possible that after verification, other, more "competent", but also more complex and resource-intensive systems "calm down" conscience);

  • if any program is "idle" demanding resources - we notify/restart/delete, again, we only do it ourselves in extreme cases;

  • and there is a possibility that it itself can become a source of problems and resource expenditure or shut itself down / cause a reboot. We also have built-in self-control and "counterweights" from other "behavioral programs" (like "everyone does it...").
