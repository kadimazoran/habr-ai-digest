1. How to Transfer Data from 1C to a Neural Network Without Revealing Real Details

One of the problems with corporate use of neural networks arises even before the first request is sent.

Suppose you need to send a table to a model for analysis. It may contain full names, bank details, addresses, phone numbers, amounts, or other data that you wouldn't want to send to an external service.

"Anonymizer PRO" acts as an intermediate layer between the source data and the LLM: real values are replaced with pseudonyms, after which the anonymized set can be sent to ChatGPT, Claude, or YandexGPT. The received response can then be converted back, restoring the original values.

The processing can recognize, in particular:

  • Full names and organization names;

  • INN, KPP, OGRN, and OGRNIP;

  • IIN and BIN of Kazakhstan;

  • Bank accounts, BIC, and IBAN;

  • Card numbers;

  • Passport data and SNILS;

  • Phone numbers and email addresses;

  • Addresses;

  • Dates of birth;

  • Car license plates.

The handling of numerical indicators is more sophisticated. If financial values are simply replaced with random numbers, the neural network will lose the connection between them. For example, the proportions of expenses between departments or revenue dynamics will change. Therefore, amounts are multiplied by a single coefficient within the current session. This allows preserving proportions, shares, and outliers, and after the analysis is complete, the real values can be restored.

At the same time, the processing intentionally does not change data whose substitution could disrupt the meaning of the analysis: document dates, platform versions, article numbers, quantities, percentages, contract numbers, and accounting accounts.

The substitution dictionary is stored in the information base and is accessible to a specific user. Therefore, it is not necessary to complete the entire cycle in one session: you can return to the result later and restore the original values.

This approach can be useful, for example, when analyzing financial tables, customer requests, or large exports from 1C using external LLMs.

2. AI Assistant Directly Inside 1C

Another approach is to reduce the number of switches between 1C and the browser altogether.

"Digital Employee in 1C" integrates the neural network interaction interface directly into the accounting system.

A chat with dialogue history is available inside. The user can create separate sessions, attach files and images, and export correspondence. Responses are generated through background jobs, so waiting for the LLM does not block the user's work in 1C.

But the most interesting scenario is related to corporate knowledge.

The system can upload:

  • Regulations;

  • Instructions;

  • Internal policies;

  • Price lists;

  • Other corporate documents.

Separate datasets for assistants are formed from these. For example, you can create a separate assistant for an accountant, HR specialist, support specialist, or sales manager.

Additionally, the assistant can access the information base data via OData.

Different operating modes are provided: only with database data, with training materials, a combined mode, working with a report, or automatic source selection.

Support for OpenAI, DeepSeek, Qwen, and the local TsA-32M model is declared for connection. When using a local LLM server, the solution can operate within the corporate network.

Image analysis is also supported: for example, you can send a photo or scan of a document to the chat and ask a question about its content.

The result is not just a "chat in 1C," but a potential access point to several information sources at once: a corporate knowledge base, information system data, and an external or local LLM.

3. Financial Contour Instead of a Set of Excel Files

AI is not the only focus of the August selection.

As a company grows, financial accounting often turns into a combination of several information bases, Excel files, correspondence, and separate approval processes.

CorpFinance offers to consolidate these processes into a single contour.

The system includes:

  • Treasury;

  • Budgeting;

  • Contract management;

  • Project budgeting;

  • Consolidation;

  • Management accounting.

The treasury module includes requests for funds, approvals, limit control, and a payment calendar.

The budgeting block includes cash flow budgets, profit and loss budgets, management balance sheets, departmental and cost center budgets, and plan-vs-actual control.

For corporate groups, data consolidation and elimination of intercompany transactions are provided.

A broader financial contour can include management accounting, IFRS reporting, cost accounting, procurement management, and project budgeting.

A separate block is dedicated to contracts: you can register and approve contracts, and track performance and payment schedules.

However, the transition from spreadsheets is not necessarily a one-time event. Excel import is supported, and the system itself is modular: you can start, for example, with treasury and then connect new areas.

This is particularly relevant for companies that have already "outgrown Excel" but are not yet ready to rebuild their entire financial structure in one project.

4. When Automation is One Correctly Modified Print Form

Not every task requires a large subsystem.

Sometimes, it's enough for the user to make one operation, which they perform several times a day, more convenient.

An example is the external print form M-15 with extended filling for "1C:Complex Automation 2".

It supplements the standard form without altering the main configuration. The user can choose how to fill the "Account, Subaccount" field:

  • Determine the account based on the accounting settings of each line;

  • Use one account for all items;

  • Disable additional filling.

The print form additionally displays:

  • Price excluding VAT;

  • Amount excluding VAT;

  • VAT amount;

  • Amount including VAT;

  • Total VAT amount.

All calculations are performed only for the printed representation and do not change the original document.

There is also saving of user settings and batch generation of multi-page M-15 forms for several documents at once.

Interestingly, the processing itself does not have its own layout: it takes the current standard form of the installed configuration and supplements the already generated tabular document.

Thanks to this, the structure of the standard form is preserved.

A good example of how the effect of automation does not always depend on the scale of development. Sometimes, a few correctly automated actions can save users more time than a large new subsystem.

5. Signing HR Documents via "Goskluch" Directly from 1C

Another scenario becomes particularly noticeable in companies with branch networks and remote employees.

If an employee is in another city, a simple order for leave or business trip can go through several emails, printouts, scans, and repeated requests.

The "Goskluch" integration module allows sending HR documents for electronic signature directly from 1C.

Two basic scenarios are supported:

  • Sending one document to one or more employees;

  • Mass sending of several similar documents to a group of employees.

For individuals, work with enhanced non-qualified and enhanced qualified electronic signatures is declared.

For authorized representatives of legal entities, a qualified electronic signature in the "Goskluch" mobile application is provided.

The signing route is configurable: you can define the sequence of participants and the set of signatories.

In addition to standard documents, custom HR print forms can be connected for exchange through standard 1C mechanisms.

The signing status is also tracked within 1C. You can see completed and rejected documents, find documents with expired deadlines, and resend them to the employee.

Signed documents are saved in an archive.

The module can also be used in conjunction with the "1C:Employee Portal" service, integrating "Goskluch" signing into the existing HR electronic document management system.

What These Five Solutions Show

These tools solve very different tasks, from preparing data for LLMs to printing a single specific invoice. But together, they clearly illustrate several directions in which automation around 1C is currently developing.

First: AI is gradually moving from a separate browser tool directly into the company's operational workflow. This creates demand for LLM integration with 1C, corporate knowledge bases, and data anonymization tools.

Second: The movement from individual spreadsheets and manual approvals towards end-to-end processes within the information system continues. This is evident in both financial accounting and HR electronic document management.

And third: Automation still doesn't necessarily mean a large project. Sometimes, it's quite enough to eliminate one repetitive manual scenario: supplement a print form, automate document sending, or eliminate data transfer between windows.

It is precisely in such small but regularly repeated operations that the most significant savings in working time are often found.
