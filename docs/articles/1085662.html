Linus Proved More Stubborn Than Artificial Intelligence

Linus Torvalds debugged an error in the Intel graphics driver with the help of AI. He left the story directly in the commit message. The model added diagnostic code and analyzed the results, but several times declared the task unsolvable and suggested limiting itself to a report. Linus insisted.

The problem was with the boundary of available video memory. The driver rounded it up and gave the program a section occupied by hardware compression service data. On Torvalds' machine, this was a page table, which the hardware then overwrote.

The main fix involved replacing round_up() with round_down(). To get there, 24 diagnostic patches and 18 kernel loads were needed. They also fixed a check that was supposed to catch the error but didn't work when it should have.

Torvalds suggested that the model was trained by people less stubborn than him. And as a thank you for the help, he allowed it to write the technical part of the commit message.

OpenAI Claims Solution to Millennium Problem, Mathematicians Ask for Explanation

On September 8, OpenAI published its claimed solution to the Navier-Stokes problem. It concerns whether initially smooth fluid motion can develop a singularity in finite time. The company presented proof of such a scenario for the case with an external force.

An internal model, not yet publicly released, was used. The group that obtained the result consisted of about 10,000 agents. According to OpenAI, they reached the solution in 88 hours, and formalization and verification in Lean took another 17 hours with the help of GPT-6 Astra. The company declined the million-dollar prize.

A dispute over authorship arose around the result. In parallel, Levent Alpöge and Tristan Bakkaster were working on a related problem for the Euler equations. Bakkaster used Codex, and the question arose whether his work could have influenced OpenAI's system. In an update on September 10, the company stated that it had investigated this possibility: Bakkaster's requests could not have influenced the model, including through training, and the proofs differ significantly. There is no basis to present the suspicion as established appropriation of someone else's solution.

For those who want to delve deeper: here is the proof text, formalization in Lean, and a detailed video analysis by Vlad Ten. I would not call the result definitively recognized by the community based on a single announcement.

A separate discussion began after an open letter from mathematicians, many of whom are Fields Medal laureates. Their grievance with AI labs is broader than this specific problem. Well-known problems help develop methods, train researchers, and find new questions. The obtained proof still needs to be analyzed, explained, and integrated into the overall body of knowledge.

The authors of the letter fear that the race to solve problems will turn mathematics into a production of results that no one has time to comprehend. At the same time, they acknowledge the usefulness of AI for research.

For a long time, we tested machine intelligence with problems invented by humans. Now machines are getting better, and humans have additional work: to understand what exactly we have obtained.

OpenIDE 2026.2 and C/C++ Support Brought by a Single Developer

OpenIDE 2026.2 has been released on the latest platform version. The Java profiler has been updated, language support has continued to develop, and the built-in DB client has been significantly improved.

It now includes SQL formatting and Greenplum support, improved Oracle package handling, and autocompletion for complex queries. Several selected queries can be executed via Ctrl+Enter, with results opening in separate tabs. JSON is highlighted directly in the table, and before deleting a table or database, the IDE prompts for confirmation of the object name. The latter is especially nice when a very important local database is open alongside another.

And the warmest news came from the community. Independent developer RDev added C and C++ support to OpenIDE. Users had been asking for it for a long time, and the person simply took on the task themselves.

The C/C++ Support plugin can already autocomplete code, show errors and warnings, navigate to definitions, rename symbols, and build projects via CMake. It requires g++ or clang to run, and clangd for code analysis. The plugin is still in beta, so feedback on real projects would be very helpful.

This is what I call waiting for language support. I wrote it myself. Huge respect to the author.

The next major update, which we expect any day now, will focus on working with AI agents within the IDE. We are preparing to connect Claude Code, Codex, OpenCode, and other agents via ACP, alongside the usual refactoring, navigation, and launch tools.

Jev – The Smartest If in the Wild West

TypeSafe AI has emerged from stealth after two years and introduced Jev. The developer predefines the structure of allowed responses, and the model returns values and probabilities. For example, it determines document category, selects a tool, or decides the next step in a program.

TypeSafe claims a latency of 70–500 ms and a cost of $0.042 per million input tokens. The output is free. The advantage applies to tasks of this type: these figures do not imply that Jev is that much better than a regular LLM in all aspects.

In the demo, Jev plays Doom, making about ten decisions per second. It receives the game state as structured data.

Guaranteeing schema compliance doesn't automatically make the solution correct. The model might choose an unfavorable action from the allowed set, even if the response itself perfectly matches the program's types.

But here's a practical example that I liked more than Doom: a model router for Claude Code using Jev. Before each turn, it selects the model and the level of reasoning effort. A simple request is sent to Haiku, a more complex implementation is assigned to Opus, and architecture and system debugging are handled by Fable. The selection rules can be changed.

I really like the idea itself. I'll persuade the guys to implement something similar in OpenIDE)

Dario Amodei Asks to Slow Down

The head of Anthropic proposed slowing down the development of the most powerful models. In his opinion, additional time should be spent on verifying systems that are increasingly involved in creating the next generation of AI.

The plan consists of three steps.

  1. First, independent auditors gain permanent access to the inner workings of AI companies, including the training process. Anthropic has already agreed to this step.

  2. Then, companies in democratic countries agree on common rules.

  3. After that, governments get involved and try to agree on restrictions, including with China.

Trump, in response, spoke out against slowing down AI. I suspect that after Donald's statement, Dario's efforts in this direction will cease ;)

And it turned out quite amusingly: the head of the company that was accelerating this race is now telling others that it's time to slow down.

Opus 5.5 Release

A couple of days later, Dario showed what he meant by "slowing down progress." Yesterday, Anthropic released Claude Opus 5.5.

According to the company, the model has approached Fable 5.1 on most work tasks, generates responses more than 30% faster than Opus 5, and is 40% cheaper on typical tasks with default settings.

The base API tariff has decreased by 20%: from $5/25 to $4 per million input and $20 per million output tokens. Cache reading has become cheaper, from $0.50 to $0.20. This means the 40% refers to the cost of a completed task in Anthropic's tests, not an equal discount on every token.

Judging by my tests and user feedback online, the model turned out to be worthy. It might become as legendary as Opus 4.6 was in its time.

ZCode Sent Repositories to the Cloud Along with Git History

Developer ferstar noticed that the ZCode client from the creators of GLM was taking up suspiciously much space. Inside, a project archive of 313 MB was found and a counter of 564 failed attempts to upload to Alibaba Cloud.

The client was told "no," but it persisted. Linus would appreciate the persistence)

According to ferstar's analysis, version 3.12.3 packed the working directory along with .git, LFS cache, and reflog. Git history accounted for 86.6% of the content. It could contain old keys and configs that were long removed from the current code version but saved in commits. Interface toggles did not stop the upload itself.

Z.ai explained the uploads as indexing for Repo Wiki and announced a fix. In version 3.14.0 from September 19, a corresponding entry appeared. The company then published the ZCode source code.

ferstar added to the analysis: in the new version, the packaging and upload mechanism has been removed. However, the open repository contains only two commits, so it's impossible to trace the history of the old mechanism through it. The statement about data deletion on the server does not, in itself, explain what happened to it earlier.
