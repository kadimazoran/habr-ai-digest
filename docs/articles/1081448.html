Manticore Search 29.9.0: chunked auto-embeddings and mmap access to columnar attributes

Manticore Search 29.9.0 adds chunked and multi-vector auto-embeddings, input limiting for embedding models, UTF-8 identifiers, default mmap access to columnar attributes, and fixes for hybrid search, KNN, bulk ingestion, and grouping.

The [Manticore Search 29.9.0](https://mnt.cr/go/6d9yh8) release is out. The main change relates to auto-embeddings: long documents can now be split into chunks, and a single document can store multiple vectors instead of compressing all content into one. In the release, mmap also became the default access mode for columnar attributes, more secure settings for embedding workloads appeared, along with UTF-8 identifiers, backup improvements, and fixes in hybrid search, KNN, bulk ingestion, grouped search, and schema changes.

This post covers everything released after 29.0.2, from 29.0.3 to 29.9.0.

Thanks to [@tudorvasinca](https://mnt.cr/go/TIds5B) for work on [PR #4857](https://mnt.cr/go/B1SXr5), [PR #4859](https://mnt.cr/go/O0eEjC), and [PR #4873](https://mnt.cr/go/drbfcB).

What to consider when upgrading

There is no mandatory data migration for the entire release. Existing tables and configurations can be upgraded as usual, but some fixes require additional actions if the old behavior has already affected the data:

  • Normalization of the German sharp-s is enabled explicitly. If you switch an existing table to lemmatize_de_v2 or lemmatize_de_v2_all, the indexed terms will change, so the plain table needs to be rebuilt, and documents in the RT table need to be replayed.

  • For authenticated BACKUP, the backup authorization action has been added. Before downgrading to 29.3.12 or an earlier version, you need to remove all backup grants.

  • Columnar attributes now use mmap by default instead of buffered file reads. If you need the previous access mode, explicitly set access_columnar_attrs='file'.

Long documents can store more than one embedding

The old auto-embedding path created one vector per document and truncated text that didn't fit into the model's input window. This works for titles and short descriptions, but a relevant paragraph near the end of a long article might not have been indexed at all.

Manticore Search now supports five [chunking strategies](https://mnt.cr/go/fCxeBG).

  • truncate preserves the old behavior and remains the default strategy.

  • mean builds an embedding for each chunk and averages the results into one vector.

  • fixed splits text into fixed-size windows in tokens.

  • recursive prefers paragraph, line, sentence, and space boundaries in that order.

  • sentence groups complete sentences up to a specified limit.

Multi-vector strategies use [float_vector_array](https://mnt.cr/go/UuFwcw). Each chunk participates in KNN search independently, but Manticore returns the document once and uses the nearest chunk for knn_dist():

CREATE TABLE articles ( title text, content text, chunks float_vector_array knn_type='hnsw' hnsw_similarity='cosine' model_name='Xenova/all-MiniLM-L6-v2' from='title,content' chunk_strategy='sentence' max_tokens='256' overlap_tokens='32' ); INSERT INTO articles (id, title, content) VALUES (1, 'Rotating certificates', 'A long guide with many sections ...'); SELECT id, knn_dist() FROM articles WHERE knn(chunks, 5, 'how do I rotate a certificate');

MAX_TOKENS, OVERLAP_TOKENS, and MAX_CHUNKS control chunk size, overall context at boundaries, and the maximum number of vectors. Model-backed float_vector_array must be declared when creating the table; it cannot be added later via ALTER TABLE ... ADD COLUMN and have embeddings rebuilt.

Limiting local embedding workload

Models with long contexts can make a single large input unexpectedly expensive, especially on CPU. The new column option [MAX_INPUT_TOKENS](https://mnt.cr/go/zZvLPe) limits the size of each input sent to a local embedding model:

ALTER TABLE articles MODIFY COLUMN chunks MAX_INPUT_TOKENS='512';

The change applies to embeddings created after this; existing vectors remain as they are. The option can be set during CREATE TABLE or changed later without re-embedding the table. A value of 0 or omitting the option uses the model's own limit.

Two less noticeable issues were fixed in the same direction: models no longer remain in the cache after an embedding column is changed, and configurations with different API_TIMEOUT or MAX_INPUT_TOKENS no longer conflict and reuse the wrong cached model.

UTF-8 identifiers and better German word matching

Table, field, and attribute names now use a unified [safe UTF-8 identifier syntax](https://mnt.cr/go/6un5co). RT, percolate, distributed, template, and plain tables can use localized names, such as Chinese or Cyrillic identifiers, in DDL, expressions, field selectors, and inferred source schemas.

German AOT morphology has received optional sharp-s normalization. With charset_table=non_cont,german and morphology=lemmatize_de_v2 or lemmatize_de_v2_all, forms like Straße, Strasse, and STRAẞE match in ordinary whole-word searches. If index_exact_words=1 is enabled, exact-word queries can still distinguish between ß and ss forms.

Load testing and backup improvements

[manticore-load](https://mnt.cr/go/sdBXEJ) can now run benchmarks via the HTTP JSON API with --http. Inserts use /bulk, searches use /search, and --table selects the target table. Reports now include local searchd RSS during runtime, as well as peak RSS, disk, and CPU statistics at the end, including aggregate monitoring for multi-command workloads.

[Manticore Backup](https://mnt.cr/go/2yXrq7) now works with authenticated Manticore Search installations via username/password or bearer-token credentials. SQL [BACKUP](https://mnt.cr/go/eqvadg) has a separate authorization action and checks read access to the selected tables.

S3 backups and restores can also use the AWS SDK credential provider chain when static keys are not specified. This includes IRSA, shared credentials, ECS task roles, and EC2 instance profiles. Temporary credentials can specify AWS_SESSION_TOKEN.

Columnar attributes use mmap by default

Manticore Search now defaults [access_columnar_attrs](https://mnt.cr/go/6A7EpL) to mmap. The operating system maps and caches columnar attribute files (*.spc) on demand, without pre-reading the entire file at startup. The previous buffered path is still available via access_columnar_attrs='file'.

ALTER TABLE also reopens the replaced columnar storage with the configured access mode, so a modified table no longer reverts to a different reader than requested.

Vector and grouped search fixes

Several fixes address queries that were valid but might have returned incomplete results or crashed with specific table structures:

  • Distributed and sharded KNN queries with a local shard no longer recompute merged 1-bit-quantized results twice, which could lead to a coordinator crash or an incorrect nearest neighbor. ([Issue #4791](https://mnt.cr/go/iuOi6U))

  • KNN queries with additional filters avoid an unnecessary knn_dist prefilter when HNSW already excludes documents without vectors. ([PR #4861](https://mnt.cr/go/UTI8PT))

  • LENGTH() for float_vector_array now returns the number of vectors, not the internal storage word count. ([PR #4879](https://mnt.cr/go/he0eBc))

  • Hybrid search with GROUP BY preserves all buckets, including MVA groups, and respects final and within-group ordering. ([Issue #4639](https://mnt.cr/go/W77QRM))

  • Hybrid filters on weight() and expressions or aliases derived from it are now executed after fusion on the final text weight, rather than being ignored. Weight-dependent filters within OR trees remain unsupported and return an explicit error. ([Issue #4889](https://mnt.cr/go/VOf6Qq))

  • Multi-chunk RT grouping no longer risks duplicate groups, incorrect split counts, or hangs when ordering COUNT(DISTINCT ...) results. ([Issue #4856](https://mnt.cr/go/fwDLRA))

  • Filters on document IDs whose signed representation is negative now follow unsigned ordering lookup index. ([Issue #4774](https://mnt.cr/go/VPvgyV))

Crash scenarios have also been fixed: a second hybrid search statement in a multi-statement request ([PR #4864](https://mnt.cr/go/i5Kymv)), distributed JSON aggregation with sorting by a string attribute ([Issue #4822](https://mnt.cr/go/NCIurP)), and dropping a table during auto-embedding precommit ([Issue #4860](https://mnt.cr/go/D22E3f)).

Bulk ingestion is more predictable

Elasticsearch-compatible /_bulk requests now return HTTP 200 after processing a batch, while individual errors remain visible via errors: true and per-item statuses. Duplicate create actions return a per-item 409 version_conflict_engine_exception, including duplicates within the same batch. This prevents clients like Fluent Bit from retrying records that have already succeeded.

Fixed-length gzip-compressed /bulk bodies are now correctly decoded, even if they arrive through multiple socket reads. And if native bulk processing fails due to a missing target table, the request can again reach Manticore's auto-schema fallback with valid NDJSON and preserve the expected bulk response envelope.

More reliability fixes

The rest of the release addresses a wide range of operational and compatibility issues:

  • searchd --stopwait no longer hangs while a sharded table is rebalanced after a node returns. ([Issue #3905](https://mnt.cr/go/jopxPb))

  • Compatible old binlogs are safely replayed during upgrade, and completed RT chunks are flushed before a clean shutdown. ([Issue #4808](https://mnt.cr/go/y6w4GH)) Fatal replay diagnostics also name the correct recovery flag. ([Issue #4811](https://mnt.cr/go/9w6uNo))

  • indexer creates missing parent directories for plain-table paths if the nearest existing parent is writable. ([Issue #4793](https://mnt.cr/go/2AyJ8K))

  • UUID document IDs no longer lead to empty stored text fields. ([Issue #4833](https://mnt.cr/go/hErEYm))

  • ALTER TABLE ... RENAME preserves hidden remote embedding API keys, not showing them in SHOW CREATE TABLE. ([Issue #4842](https://mnt.cr/go/YuCTPF))

  • Compatibility probes for Sequel Ace 5.3.1+ now work again. ([Issue #4828](https://mnt.cr/go/bVXFrw))

  • JSON /search preserves distances for negated NEAR and proximity operators. ([Issue #4784](https://mnt.cr/go/tsDLTu))

  • Internal string-sort helper columns no longer leak from LEFT JOIN results. ([Issue #4788](https://mnt.cr/go/wS6uNG))

  • Malformed binary API SEARCH element counts are now rejected instead of terminating searchd. ([PR #4790](https://mnt.cr/go/8l9q4g))

The full list is in the [29.9.0 version changelog](https://mnt.cr/go/Zf4B8X).
