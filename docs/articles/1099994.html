In the Beginning, There Was a Thought

It all started with the desire to create a database of tests. The website has protection: if you switch to other tabs or windows, the results are not counted. This means simply copying questions and saving them to a notepad is not an option. Recording the screen is too much effort. I needed a tool that could read and save text in the background without my intervention. I decided to create a system using a Tampermonkey script that would parse the page and send data to a local server. Since I'm currently gradually exploring the world of AI, the next logical thought was: "Why not integrate a neural network and automate this a bit?" This led to a fairly simple scheme:

So, the next step was to create a local server. I went to Google for advice: "My light, Gemini! Tell me, tell me the whole truth: who in the IT world is the fairest, most convenient, and fastest?" And I heard in response: "It's Python, no doubt about it." The fairy tale is a lie, but there's a hint in it – arguing with AI is futile, so I tied the code into a knot and whipped up a server.

The first version had two functions: it could save the entire HTML page and the test texts separately to files. Then I added the ability to work with AI models through LM Studio to pester them with tricky questions from test creators.

In the code, I wrote a system prompt:

Prompt

Explanation

Testing on Git: 1 question and several answers are given.

I specified the subject area just in case, to make it easier for the AI to understand the testing context.

Do not recheck yourself more than once.

I set a condition so that the model doesn't recheck itself too thoroughly, otherwise it might get stuck in self-checks, which wastes precious minutes.

Do not ask clarifying questions.

The work must be done in the background and completely autonomously, so it was necessary to get rid of clarifying questions (although I'm not sure if an AI model in API chat mode would even ask them).

Respond with a short message containing only the text of the selected answer and its number. Do not explain the answer.

I specified to truncate the answer to the suggested options to get rid of extra junk in the output.

Determine the correct answer. If there are multiple correct options, choose the most optimal one.

During the tests, I noticed that the model sometimes chooses a suboptimal option. I tried to improve this through the prompt, but the effect was 50/50.

Another Python script was generated for testing. It took files with previously parsed tests and sent them to my local server. This way, I could test the main server, fine-tune the prompts, and see how different models handle the tasks.

After all the improvements, the final process looked like this: two windows on the screen – the browser with tests on the left, the terminal with the running server on the right. As soon as a question appears in the browser, it goes to the server to the AI, I wait for the answer, and manually select the correct option. And so on.

Testing AI Models

The basic scheme worked well, but I wanted to see how different models handle similar tasks. I chose the Qwen family of models for comparison. I was interested in evaluating the performance of recent, relatively large models with 27–35 billion parameters compared to smaller models with 7–9 billion parameters, testing older versions (Qwen 2.5), and also finding out how the test difficulty level affects the final score.

In the header of the final table, "questions" and "time" refer to the total number of questions and the maximum time allotted for one test. The body of the table shows the number of errors made and the time spent. Models took the tests 3 times each; the time indicated is the average, and the errors are the minimum and maximum.

For basic level tests (10–11 questions), it's acceptable to make 2 mistakes. For the advanced level, it's likely 3–4 mistakes are allowed (I don't know the exact threshold; I either got 2 mistakes or failed the test miserably). Obvious failures are highlighted in red in the table, and borderline results are highlighted in yellow.

The Qwen3.8–27B model on my PC outputs no more than 6 tokens/sec. This is too slow for reasoning mode, but I wanted to test the possibility of using models at this speed, so it was tested without reasoning. At the very end, I added the Qwen3.8–9B CPU model – it was fully loaded into RAM and ran on the processor, simulating very Spartan conditions.

As we can see, almost all models successfully passed the tests, only the old Qwen2.5 faltered in some tasks. Test difficulty can be critical for weaker models, although all participants successfully passed even the advanced level on the OOP topic.

Among the disadvantages of small models: the answer format is extremely unstable. I asked to output only the full answer text and nothing else (the texts themselves always started with numbers), but the models still outputted:

  • text, with the number removed;

  • only the number;

  • text, followed by the number;

  • the number of one answer and the text of another (the most unpleasant part);

  • "extra" information – the question text or a detailed explanation of their choice.

Conclusions

I am not claiming to be the ultimate authority; this section is merely my assessment and personal opinion.

Essentially, the HeadHunter theoretical testing system today is a sham. It uses a simple protection mechanism developed in the pre-AI era. Now, anyone who wants to can bypass it, even those who are not very knowledgeable in the field. Consequently, the presence of these certificates for a candidate guarantees nothing at all.

Moreover, to bypass the protection, free software, the web version of Gemini, a weak PC, and a minimum of time are sufficient. But even if local AIs are not an option for you, you can always open Gemini in a second browser window and use it instead of a local LLM. Or you can go even further and do without automation altogether: just take pictures of the questions with your smartphone and send them to an AI chat with built-in vision – the model will instantly recognize the text from the PC screen and provide the correct answer, while the HeadHunter's protection system will piously believe that you haven't switched anywhere. But this is a completely different, boring story, not suitable for a curious IT mind.
