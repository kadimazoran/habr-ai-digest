A message arrives in the chat: "How can I enable notifications only for new orders?" The application needs to determine its type: question, advertisement, or other. The subsequent action depends on the selected category.

Jev from TypeSafe AI accepts data and questions of a specific type, returning values for code: a label, a score on a scale, or the probability of a "yes" answer. Universal LLMs also support structured outputs, and a similar process can be built with their help. Jev is worth considering when you need a ready-made contract for decisions: distribution into predefined options when choosing a category and independent questions about the same data per call. The application receives both the result and scores, based on which it can choose the next action.

This is an analysis of the API documentation as of October 26, 2026, without service calls. The advantages of Jev in probability calibration, quality, and speed were not tested here.

Category, Scale, or Yes/No Question

Three types of questions are useful for text tasks. Choice selects one option from a set: for example, "question," "advertisement," or "other" for a chat message. The same method can be used to determine the topic of a support request and select a handler: payment, delivery, return. There is no order between categories.

Score evaluates text on an ordered scale. For a queue of requests, you can describe urgency: "can wait," "disrupts work but has a workaround," "work stopped." Three levels occupy positions from 0 to 2, and the final score can be fractional, between levels. This is a position on the scale you described.

Noul returns the probability of a "yes" answer as a number from 0 to 1. For example, whether a comment contains personal data or if a client asks to speak to a human. Such a signal is useful for moderation and transferring to an operator; the threshold for action is set by the application.

In a single call, you can determine the message type using Choice and separately ask via Noul if it contains personal data. This way, the application gets a category and an additional signal for verification. Questions are evaluated independently: the second does not receive the answer to the first. Dependencies between decisions must be organized in the code.

First Request: Determine Message Type

Let's use Choice with categories "question," "advertisement," and "other." In the instructions, we'll set a rule for a mixed case: if an advertisement contains a question, choose advertisement.

According to the quickstart, you need Python 3.10 or newer and the official package typesafe-sdk. Get a key from the TypeSafe console and pass it via the environment variable TYPESAFE_API_KEY. For example, in PowerShell:

python -m pip install typesafe-sdk
$env:TYPESAFE_API_KEY = "your-key-from-the-console"

Save the code in classify_message.py. The client will read the key from the environment. jev-latest selects the current model based on the documentation example, without fixing the version.

from typesafe_sdk import Choice, TypeSafeClient

message = "Подскажите, как подключить уведомления только для новых заказов?"

with TypeSafeClient(model="jev-latest") as client:
    response = client.system_one(
        state=message,
        questions={
            "message_type": Choice(
                instructions=(
                    "Определи тип сообщения в чате. "
                    "Если реклама содержит вопрос, выбери рекламу."
                ),
                criteria={
                    "question": "Просьба о помощи или информации без рекламы",
                    "advertising": "Продвижение товара, услуги или внешнего канала",
                    "other": "Сообщение без рекламы и без просьбы о помощи или информации",
                },
            ),
        },
    )

answer = response.choices["message_type"]
print("Метка:", answer.choice)
print("Вероятности:", answer.probabilities)
print("Confidence:", answer.confidence)

In the same PowerShell session, run python classify_message.py.

state contains the text being evaluated; instead of a string, structured data is allowed, for example, a message along with chat rules. In questions, the identifier message_type links the question to the answer, instructions sets the task, and criteria describes the categories. In the Python SDK, Choice answers are available via response.choices.

The .choice field contains the label with the highest probability, and .probabilities contains the distribution across options. If the scores for "question" and "advertisement" are close, the application can send the message for analysis even when one label formally wins. The distribution allows accounting for such ambiguity when choosing an action.

Confidence for Choice is calculated from the highest probability, adjusted for the number of options: 0 corresponds to uniform choice, and 1 corresponds to complete focus on one option. This is a separate indicator, not the probability of the chosen label itself. Even a high value does not guarantee that the model correctly understood the message.

Jev is suitable for a part of the application where a predetermined decision needs to be made based on text content: selecting a handler, setting priorities, or flagging a message for moderation. After classification, the question can be passed to a bot to prepare a response. Generating detailed text and tasks requiring long reasoning require a separate stage; Jev occupies the space between input data and the next code action.
