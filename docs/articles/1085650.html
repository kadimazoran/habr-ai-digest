I wanted my own system that I could change at any time, so I made three desktop AI applications

Hello, Habr! This is my first article, and it's about Zeqou: a small ecosystem of desktop applications for working with language models. Two applications are ready, and the third will be released very soon. I'll tell you what they can do, how they are structured, and what unexpected problems I encountered.

In short. Zeqou consists of three applications: a chat, a workspace for agents, and a model fine-tuning studio. They are free and work on Windows, macOS, and Linux. The chat and Harness are ready, xtraining will be released very soon.

Why all this

I've always wanted to have my own system: my own applications where I can change anything at any time. Not something external, where you don't know what will happen to it tomorrow: they might change the terms, remove a feature, shut down the service. This is how Zeqou came about.

ZeqouXChat: desktop AI chat

ZeqouXChat is a chat with language models built on Tauri 2 and React 19. It works with both cloud models using your API key and local models via Ollama.

Supported providers: OpenAI, Anthropic, Google, OpenRouter, Ollama, and any custom endpoints.

What's inside:

  • streaming responses;

  • code highlighting (highlight.js), Markdown, and KaTeX formulas;

  • built-in Zeqou datasets for the trainer: the main v2 (EN→RU translation with reasoning), as well as parts with dialogues, code, science and technology, and language packs;

  • installers for Windows, macOS, and Linux.

Zeqou Harness: workspace for models and agents

Zeqou Harness is designed for more serious work than a regular chat. It's a desktop application built with Electron, which brings together models and agents, and stores project context in one place. The providers are the same as in the chat.

What it includes:

  • Memory. This is the context that the AI remembers, so it doesn't have to explain everything again in each session.

  • Agent's task list. When the work is multi-step, the agent plans the steps using the todo tool, and the Tasks panel displays this plan in real-time with statuses like "pending," "in progress," and "done." You can also edit statuses manually. The idea is to see what the agent is about to do and correct its course in time.

  • Tools and MCP. MCP is not included out of the box, but it can be connected.

  • Installers for Windows, macOS, and Linux.

ZeqouXTraining: model fine-tuning studio (release soon)

ZeqouXTraining is a desktop studio for fine-tuning small language models locally, without the cloud: a real pipeline on GPU or CPU.

How it's structured

The application consists of three layers:

┌───────────────────────────────────────────────┐
│  React interface (Vite, TypeScript, Tailwind) │
│  pages, wizard, charts, playground        │
├───────────────────────────────────────────────┤
│  Electron main (Node)                         │
│  preload bridge, IPC, tasks, registry, storage │
├───────────────────────────────────────────────┤
│  Python engine                                │
│  datasets, backends, trainer, inference          │
└───────────────────────────────────────────────┘
      Node ⇄ Python: line-by-line JSON in stdout

Node and Python communicate via a line-by-line JSON protocol. This way, the Node part remains a thin supervisor, and all ML logic is tested as regular Python without an interface.

You select a base model and dataset, and the application automatically selects batch size, precision, context length, optimizer, and rank based on your hardware, explaining each choice. Simple and Advanced modes

JSON, JSONL, CSV, TXT, Parquet, a folder of shards, or IDs from Hugging Face Hub. Files are not copied but used in place

Shows what the model will actually learn: field matching, duplicates, overly long entries, role statistics

Interpreter selection, one-click ML environment setup in an isolated venv, Hugging Face token in system key storage

Training methods: LoRA, 4-bit QLoRA, full fine-tune, SFT, and training a small GPT from scratch.

Thinking mode

In the playground, you can enable Thinking mode. Then, the model's reasoning between <think> and </think> is displayed in a separate collapsible panel before the response, and temperature, top-p, and repetition penalty can be changed on the fly. Models that were not trained to reason will simply return an empty block, so the switch is safe.

How it's tested

  • 206 tests for the Python engine.

  • 54 end-to-end smoke tests.

Smoke tests don't simulate reality: they launch a real Electron and a real Python backend, import real dataset fixtures, check for corrupted files, and export a real folder with artifacts. All of this happens in a temporary directory, so your library is not affected.

The stack didn't go as planned

To be honest: the different stacks (Tauri in the chat, Electron in Harness and xtraining) were not the result of a long-term strategy. It just happened, and partly it was just for variety. Tauri is good where small size and a native feel are important, while Electron is convenient when you need a Node layer and a familiar ecosystem. There's no secret here.

The most unpleasant part turned out to be the installers. On Windows, I have NSIS with a choice of installation folder, where the license is shown before copying files, plus a portable build without installation. For macOS and Linux, different formats are needed (.dmg, .AppImage, .deb), and setting everything up so that builds for three operating systems are released together turned out to be more difficult than expected.

Why the license is closed

All three projects are under PolyForm Strict 1.0.0. This is source-available, not open source.

Why I decided this:

  1. Reputation. I don't want my system to be called viruses: if someone builds and distributes a modified version, the reputation of the original will suffer.

  2. A year of work. This is a project I've been working on for a whole year, and I don't want it to be simply taken and completely redone for someone else's needs.

If the project doesn't take off, I might open the source code later.
