Previously, we talked about FAIRouter, our library for request routing. To briefly remind you, here's what it does. There are several language models, each with different costs, speeds, and strengths. FAIRouter itself selects the model for the task, verifies the generated response, and learns from feedback. The overall workflow is shown in Figure 1.

The C# version is now published on NuGet, so you no longer need to build it from source. In this article, I'll show you how to install the package and what you can do with it. All examples below were created with package version 0.1.0.

Installation

You'll need .NET 10. Let's create a console project and add the package:

dotnet new console -f net10.0 -n RouterDemo
cd RouterDemo
dotnet add package FAI.Router

You also need a model provider key. We'll use OpenRouter in the examples; put the key in an environment variable:

$env:OPENROUTER_API_KEY = "your key"

First Request

Let's replace the contents of Program.cs with the following code:

using FAI.Router;

FaiRouter router = await FaiRouter.FromOpenRouterAsync(
    apiKey: Environment.GetEnvironmentVariable("OPENROUTER_API_KEY")!,
    modelIds:
    [
        "google/gemini-2.5-flash",
        "openai/gpt-4.1-mini",
        "anthropic/claude-haiku-4.5"
    ],
    databasePath: "fai-router.db");

RouterAnswer answer = await router.AskAsync(
    "Write a review of clustering methods in 1500 characters");

Console.WriteLine($"{answer.Winner.Name}: {answer.Score}");
Console.WriteLine(answer.Text);
Console.WriteLine(answer.Critic);

Here, modelIds specifies the list of candidates, and the fai-router.db file stores weights and the turn log. If the file doesn't exist, it will be created. In the response, we are interested in four fields:

  • Winner shows which model was chosen;

  • Text contains the model's response;

  • Score contains the judge's score from 0 to 1;

  • Critic shows, point by point, how the response differs from the request.

The judge automatically verifies the response. For example, if the request specified four sections and a table, but the response has only one section without a table, this will be reflected in Critic.

You don't have to specify the list of models at all. In that case, the choice will be made from 54 popular models included in the package:

FaiRouter router = await FaiRouter.FromOpenRouterAsync(
    apiKey: Environment.GetEnvironmentVariable("OPENROUTER_API_KEY")!,
    databasePath: "fai-router.db");

Training on Feedback

The most interesting part begins when the router receives feedback. Feedback is given as a number from 0 to 1, where 1 means an excellent response and 0.2 means a weak one:

router.Feedback(answer.RoundId!.Value, score: 1.0);
router.Train(epochs: 10);
router.Save();

After this, the weights are saved to the database, and the router will consider the acquired experience for similar tasks. You can accumulate feedback and train the router less frequently, for example, once a day. It's worth noting that the request texts are stored in the log.

What's More Important, Cost or Quality?

The library has three predefined profiles: Quality, Balance, and Price. The default is Balance. You can change the profile for each request:

RouterAnswer cheap = await router.AskAsync(
    prompt, weights: RouteWeights.Price);

RouterAnswer strong = await router.AskAsync(
    prompt, weights: RouteWeights.Quality);

Another rule is often more convenient: find those who can handle the task, and among them, choose the cheapest and fastest. For this, there's a sufficiency threshold, i.e., the minimum probability that a human will like the response:

RouterAnswer enough = await router.AskAsync(prompt, bar: 0.7);
Console.WriteLine(enough.Reached);

The Reached field indicates whether any model met the threshold. The threshold starts working when at least three human feedbacks have been collected.

Dialogue Instead of a Single Request

You can pass an entire dialogue to AskAsync. The task is recognized by the last user utterance, and the model sees the entire history:

using AI.LLM.Core.Models.Common.Messages;

LLMMessage[] dialog =
[
    new(LLMMessage.UserRole, "What is clustering?"),
    new(LLMMessage.AssistantRole, "It's the process of grouping objects."),
    new(LLMMessage.UserRole, "Now explain it to a school student")
];

RouterAnswer replied = await router.AskAsync(dialog);

Other Providers

The package works not only with OpenRouter. There are three connection methods in total:

Method

Connects to

FromOpenRouterAsync

OpenRouter

FromFractalRouterAsync

FractalRouter

FromOpenAiCompatibleAsync

any server with the OpenAI chat completions protocol

The last option is suitable for your own model. You need to specify the cost of such a model yourself:

FaiRouter local = await FaiRouter.FromOpenAiCompatibleAsync(
    baseUrl: "http://localhost:8000/v1",
    apiKey: "local",
    modelIds: ["my-model"],
    prices: new Dictionary<string, Price>
    {
        ["my-model"] = new Price(0, 0)
    },
    judgeModel: "my-model");

The judge works through the same provider, by default using the openai/gpt-4o-mini model. If your server doesn't have this model, specify another one in the judgeModel parameter, as shown in the example above.

Not Just Models

You can choose not only models but also tools and agents. To do this, pass your own candidates and a function that runs them to the constructor. Let's consider an example with two search options:

using AI.LLM.Core.Models.Common.Messages;
using AI.LLM.Services.LLM;
using FAI.Router;
using FAI.Router.LLM;
using FAI.Router.RoutedElements;

BaseRoutedElement deepSearch = new()
{
    Name = "deep-search",
    DPMTInp = 5,
    DPMTOutp = 20,
    TPS = 30
};

BaseRoutedElement fastSearch = new()
{
    Name = "fast-search",
    DPMTInp = 1,
    DPMTOutp = 2,
    TPS = 200
};

LLMBase judge = new OpenAiCompatibleLlm(
    Providers.OpenRouter,
    "your key",
    "openai/gpt-4o-mini");

FaiRouter tools = new(
    [deepSearch, fastSearch],
    (candidate, messages, token) =
        RunSearchAsync(candidate.Name!, messages, token),
    "tools.db",
    llm: judge);

Here, DPMTInp and DPMTOutp define the cost per million tokens, and TPS is the speed in tokens per second. For a tool, these numbers are relative; only their ratio matters. You write the RunSearchAsync function yourself; it launches the required search and returns text. Such candidates start with random weights, so they need your feedback initially.
