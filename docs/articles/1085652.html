Over the past few years, the wrapper around LLM models has evolved from a chat interface and a rules file in an editor to a self-sufficient technological layer – the harness – with its own protocols, standards, and foundation. Client lock-in has shifted from the specific LLM model level to this harness level.

Definitions:

1. Model – an LLM, a neural network that generates text on demand. It is stateless (doesn't remember previous calls), has no access to the external world, and is incapable of action – only generating the next token or a probable set of phrases based on the input context.

2. Harness – the software and infrastructure wrapper around the model, transforming it from a text generator into a system capable of performing "meaningful" actions. The harness provides the model with functionality: tools (access to the external world), context management (memory, sessions, compaction), rules/instructions (behavior), permissions and rights (security), and optionally enhancements – hooks, skills, orchestration. The harness is the "body," the model is the "semantic brain."

3. AI Agent – a model placed within a harness, thus capable of acting, i.e., perceiving the environment's state through tools, maintaining context between steps, planning, and executing multi-step tasks. An agent is not a component but the result of combining a model and a harness.

Below is an approximate account of the development of harness ideas and its current state.

1. Rules and Prompt (2023 – February 2025). Beginnings in editors (.cursorrules, ~2024), systemically – with the release of Claude Code and CLAUDE.md (February 2025), then the open standard AGENTS.md (OpenAI, August 2025). In December 2025, OpenAI transferred it to the AAIF foundation; by September 2026, it was adopted in over 60,000 open-source repositories, supported by Amp, Codex, Cursor, Gemini CLI, and others.

2. MCP (November 2024). Standardized connection of external tools to an AI agent.
In December 2025, Anthropic transferred MCP to the neutral Agentic AI Foundation (Linux Foundation) along with AGENTS.md and goose – with support from Google, Microsoft, AWS, and Cloudflare.
Specification update from 07/28/2026: stateless core (server – a regular HTTP service without sticky sessions), Extensions framework (enterprise authentication, interactive applications, long-running tasks).

3. Context and Sessions (First half of 2025). Compaction/summarization of long context, checkpoints in short-term memory (model cache), and step rollback, forking (cloning) dialogues (~Spring-Summer 2025). Sub-agents – July 2025; in 2026, they gained asynchronicity, persistent YAML configs, file prompts, and their own hooks that launch with the sub-agent. Session compaction evolved into session memory compaction with background threads and prompt caching.

4. Hooks (insertion/correction points, triggers, or anchors) (~June 2025). Scripts on lifecycle events (before/after any inference). The essence: deterministic logic for deciding what to say/remind the agent; the signal reaches the agent without interrupting the current task. This approach is the path from giant markdown files to loading/reminding only relevant instructions at the right moment.
In OpenCode, the equivalent is plugins (TS modules with hooks); a native hook layer was still being discussed as a feature request there as of February 2026.

5. Skills (October 2025). A lightweight alternative to MCP: markdown instructions loaded as needed. Evolved into "markdown + executable scripts"; the ideal is to be covered by scripts as much as possible, not prose.
Anthropic published Agent Skills as an open cross-platform standard in December 2025; by mid-2026, there were about 40 compatible platforms and millions of skills. The focus shifted from portability to trust infrastructure (security scanning, quality control).
Microsoft added the APM package manager (April 2026) – an npm/pip-like declaration of skills, prompts, and MCP servers in a single apm.yml.

6. Orchestration (2025). Multi-agent wrappers on top of agent management protocols (ACP and others): different agents under a single management point; based on this, benchmark frameworks for comparing models and tools.
ACP (Zed, August 2025; JetBrains joined in October 2025) merged with A2A (August 2025, under LF AI & Data); by April 2026, A2A was a production-ready standard, with 150+ organizations.
2026 Stack: MCP – agent + tools, A2A – agent + agent.
Based on orchestration layers (ACP/A2A), benchmark frameworks are used for comparing models and tools.

Nuances:

Portability problem. A harness cannot be transferred by copy-pasting: hook capabilities and folder structures differ between tools. Partially solved at the skills level (open standard, ~40 platforms) and rules level (AGENTS.md as a de facto universal format), but not for hooks/plugins. A unified standard is still missing.
Working workaround: a unified harness in a separate repository + an input instruction that allows the agent to adapt it to its environment; on top of this, a package manager for declarative dependency installation.

A harness is a product with a role. Universal ones do not exist yet. Typical patterns established by the end of 2025: conversational interfaces, "talking to the database" (natural language → SQL → readable response), code base analyzers, personal assistants.

Models in 2025 became practically interchangeable: quality differences are leveled out within months, and retaining clients at this level is no longer possible. Therefore, vendor client lock-in shifted to the harness – the wrapper environment where rules, skills, hooks, MCP configuration, and agent memory reside. Changing a model takes minutes, changing a harness means migrating accumulated engineering effort.

Development patterns: open source develops ideas faster and sometimes leaps ahead of vendor capabilities, adopting ideas (OpenCode's hooks/plugins are richer than Claude's), but what becomes the de facto standard is what a major player solidifies. In 2025–2026, the "fixer" was not a single major player but a "neutral" consortium – agreements began, but under the auspices of a foundation, not a single winning vendor.

Three Levels of Harness Application.

a) per project;
b) per personality;
c) per team.

The team variant is the most problematic: there are almost no successful implementations because a team that has tightly integrated agents into its tasks ceases to be a team – each developer becomes a micro-manager of an agent pool when the task volume is that of a small team.
Team harness as a layer is still being formed. Anthropic, for example, only added Shared Skills and usage reports to Team/Enterprise tools in 2026.

Levels of Software Hierarchy:
┌─ Interface Layer: ACP (IDE ↔ agent), AG‑UI (frontend ↔ agent)
├─ Orchestration: A2A (agent ↔ agent) external, sub-agents – internal (within one harness)
├─ AI Agent: <Model> + harness
└─ Harness: MCP (tools) + rules + context + permissions


Status (as of September 2026).

The harness development chain (2023–2026) is as follows: rules → MCP → context management/sessions → permissions/sub-agents → hooks → skills → plugins → orchestration.
Within a single tool, everything is usually well-established. Between tools, a neutral management layer (stewardship) has emerged – Linux Foundation/AAIF: MCP, AGENTS.md, goose, A2A. However, a unified harness standard has not yet formed.
