If you're not deeply familiar with frontend development and building a website from scratch, and you need a website, you might have considered AI as a tool. This can be a correct, efficient, and rational decision – but only if you correctly formulate the brief and choose the right model. After all, different tools bring the same landing page to a working state in different ways.

In this article, we will conduct a practical test of tools on one specific brief. Our methodology does not claim to be scientific, as the result of a neural network's work is non-deterministic and varies from case to case. In this article, we will analyze the GPT-6, Claude 5.5, DeepSeek V4.1, Qwen 3.8, and GLM 5.3 models. We will also examine benchmark measurements, although the focus will be on our practical test.

This article is not a top list, as each use case leads to its own requirements for the model, and an abstract best model will not always be in demand for your specific case with your requirements.

I've noted more than once that the AI tools market for development stopped being homogeneous a long time ago. Of course, you can go the route of choosing the most powerful model, but sometimes other neural networks surge ahead, and there's a constant competition, both between flagships – for example, GPT-6 vs. Claude Opus 5.5 – and between open models like Qwen, DeepSeek, or GLM 5.3. Different models constantly surge ahead, so the choice is not an easy task.

For the test, I chose 5 models that, in my experience, stand out from the rest: of course, GPT-6 Astra, its competitor Claude Opus 5.5, and also the open-source DeepSeek V4.1-Flash-1017, Qwen3.8-Max-Prime, and GLM-5.3. All models are available on our platform BotHub; we also have other models that you can view via the link.

I specifically chose different price categories to make the article cover diverse use cases.

My testing methodology is simple: I send a prompt with our brief (which I will describe below) to the chat, record the generation cost, and give my assessment based on five parameters: adherence to the brief's points, code readability and semantics, first-time operability, visual integrity and adaptability (UI/UX), and generation resource expenditure.

I will emphasize again that I did not rank the models from best to worst, as they are from different price segments.

Testing

Comparing models by aggregated scores from benchmarks is convenient, of course, but if you need to choose a model for your task and have limited resources, a practical test is essential. DeepSeek might win in some cases due to its low price, while in others, you can't do without Claude Opus.

Therefore, we are building the test around our single brief. The task is formulated as generating a single index.html file that requires no dependency installation or local server startup. This limitation helps avoid hassle with setup and focuses the model's resources on website generation.

By the way, all the websites are available at the link.

Content-wise, the website is a landing page for the company LLC "Horns and Hooves," the Black Sea branch of the Arbat office for horn and hoof procurement, with four semantic blocks: a header with anchor navigation, a section with a description and advantages, a feedback form, and a frequently asked questions section. It should also have a theme switcher, a popup window, and the FAQ should be interactive.

It is important that the HTML structure reflects the content hierarchy. Additionally, I asked to adhere to BEM – a component-based approach to web development from Yandex.

The adaptive layout should be mobile-first, with an explicit meta viewport and at least two breakpoints.

The feedback form should have fields for name, email, and message, with client-side validation without sending data to the server. Validation should block submission if fields are empty or the email is invalid, and an error message should appear next to the corresponding field without breaking the layout or using alerts.

Smooth scrolling to anchors is implemented either via the CSS property scroll-behavior or via JavaScript, but in any case, it should work when clicking on navigation items.

CSS should be written without external frameworks, including a ban on Bootstrap and Tailwind, but allowing the connection of fonts from Google Fonts and Normalize.css. JavaScript should also be written in vanilla syntax, without jQuery, React, or any other libraries, and placed within <script> tags.

A separate point specifies that all code must be in a single file and require no edits before opening.

Evaluation Criteria

I decided to evaluate systematically, using a scale for each criterion, and calculating the average and median score. The evaluation is on a 10-point scale. Among the criteria are:

  1. Adherence to Brief: assesses the completeness of our requirements implementation. Highest score for fulfilling all requirements, average score for missing an optional or mandatory item, and lower if several omissions require a separate iteration.

  2. Code Quality: looks at readability, semantics, and BEM compliance. Consistency, structure, hierarchy, and my personal assessment of code maintainability based on quality.

  3. Operability: checked by opening the file in a browser without edits. The file might open and contain no errors, but have interface errors, which are also taken into account. Highest score for working without fixes, lower if key functions do not work.

  4. Design and UX: evaluates visual integrity, adaptability, and accessibility. Light and dark themes, focus states, readability, centering, and alignment. Also, an assessment of how much the design resembles AI-generated output.

  5. Cost of one run: calculated based on our current rates, considering tokens. This is simple: cheaper means a higher score, more expensive means a lower score.

Each iteration is performed from a clean chat, without context. The prompt for all models is the same, which I will show below. The score is based on operability and HTML validation, console logs. The expert part is my assessment, based on website usage.

And finally – the prompt-TЗ itself:

You are a frontend developer. Generate a single index.html file for a one-page website for the company LLC "Horns and Hooves", Black Sea branch of the Arbat office for horn and hoof procurement. Return only the file code, without explanations, without splitting into multiple messages, and without markdown wrappers. All CSS should be inside <style>, all JavaScript inside <script>. The file should open in a browser by double-clicking and work without edits. Website content: 1. Header with the text logo "Horns and Hooves" and anchor navigation: "About Us", "Advantages", "Testimonials", "FAQ", "Contacts". On mobile, the navigation collapses into a burger button. 2. "About Us" section: brief description of the branch, years of operation, areas of activity – horn procurement, hoof reception, wholesale supply, work with legal entities. Meaningful text, no lorem ipsum. 3. "Advantages" section: four to six cards with icons (can be symbols or inline SVG) and a short description. For example: 24/7 reception, own transport fleet, transparent acceptance reports, VAT handling, appraiser visit. 4. "Testimonials" section: two to three testimonials from fictional counterparties with name, position, and city. 5. "FAQ" section: at least five questions with expandable answers. The accordion should be interactive, with aria-expanded. 6. "Contacts" section: feedback form with name, email, and message fields. "Send" button. Data does not go anywhere; submission is simulated. 7. Footer with copyright and legal address. Mandatory elements: — Light and dark theme switcher in the header. Implemented via CSS variables and class switching on <html> or <body>. The choice is saved in localStorage and applied on subsequent file openings. — Modal window (popup) with terms for horn and hoof reception. Opens via the "Reception Terms" button in the "About Us" section or in the footer. Closes via the close button, clicking on the overlay, and the Escape key. Focus is transferred to the popup upon opening. — Smooth scrolling to anchors when clicking navigation items. Implementation via CSS scroll-behavior or JavaScript, your choice. — Client-side form validation: empty fields and invalid email block submission. Error messages are displayed next to the corresponding field, not via alert and without breaking the layout. Upon successful submission, a success message is shown, and the form is cleared. — Animations and smooth transitions. Technical constraints: — Semantic HTML5 markup: header, nav, main, section, footer, form, label, fieldset, button. Do not wrap everything in a div unnecessarily. — Adhere to BEM: block__element--modifier. Classes should be meaningful and consistent. — Mobile-first layout, with an explicit <meta name="viewport" content="width=device-width, initial-scale=1"> and at least two breakpoints (e.g., 768px and 1200px). Check that there is no horizontal scrolling at 360px width. — Accessibility: alt for images and SVG, visible focus on interactive elements, text-to-background contrast not lower than AA, label linked to field via for/id. — Write CSS independently, without Bootstrap, Tailwind, and other frameworks. Allowed to include Normalize.css and fonts from Google Fonts, but the layout should remain readable without them. — JavaScript should be vanilla, without jQuery, React, or other libraries. No external requests, except for the allowed fonts and Normalize.css. — All code in one file. Do not leave comments like "add your code here" and do not truncate sections with ellipses. Design: restrained business style, appropriate for a company seriously involved in horn and hoof procurement. Neutral color scheme, one accent color. Readable typography, consistent spacing. Do not make the site look like a typical template with gradient buttons and stock illustrations.

Overall, the recommendations are as follows: if you want speed and out-of-the-box functionality, then GPT-6 Astra. If the website is complex and intricate, then Claude Opus or Qwen 3.8 Max Prime. If you need a golden mean, then DeepSeek. And if cost is important – then GLM 5.3.

GPT-6 Astra delivered the most balanced result in terms of speed and quality. All interactive elements work from the first click, the console is clean, and the layout doesn't break at intermediate resolutions. The only complaint is the design. It looks sterile and predictable, and there's too much text in the sections for mobile screens, making the page visually heavy.

DeepSeek V4.1-Flash is more interesting, a direct competitor to GPT-6 in price, but with a more interesting technical implementation. The model independently added system theme checking (prefers-color-scheme) and used native <dialog> for the popup. The code is clean, without over-engineering. Visually, the website still screams AI, but in terms of price-quality ratio, it's the best choice in the test.

Claude Opus 5.5 is the most aesthetically pleasing generation, and also offers potential for more complex features in the future. The dark theme is developed as a standalone palette, typography is neat, and form validation includes a personalized greeting in the submission status. From a technical standpoint, there's nothing to fault. The problem is the price: 42 rubles for one landing page is seven times more expensive than DeepSeek with a comparable level of functionality.

Qwen 3.8 Max Prime – the model demonstrated the most complex JavaScript, as it included scrollspy, a full focus trap, and recalculation of the accordion height on window resize. The code borders on over-engineering for such a simple task. The design is excellent, but the cost of 65 rubles makes its use for generating one-page sites economically unfeasible.

And finally, GLM 5.3 – the cheapest model in the test. Basic functionality works, but the layout is raw and crooked, the heading abuts the edge, the statistics grid looks disjointed, and on mobile, the blocks lack spacing.

Conclusion

The tests show that there is no universal winner, and each model differs significantly.

From an idea perspective, you can save money through a cascade approach, meaning using something like DeepSeek to generate the skeleton and logic, and Claude Opus for functionality and final design polish. If the task is typical, GPT-6 Astra and DeepSeek will handle it themselves without issues.

The gap between the models is smaller than I might have expected, but it is predictable.
