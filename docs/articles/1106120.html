The llama-modchip project has been released under Apache 2.0. It is a set of patches for the ggml/llama.cpp kernels, quantization tools, and scripts that allow running sparse MoE models directly on the processor. The author claims that DeepSeek-V4-Flash (284 billion parameters, of which 13 billion are active) runs on a machine with 64 GB of RAM: without a graphics card and without swap. I will analyze what has been achieved below.

What was achieved

Peak memory consumption is around 58 GB with a context of 256,000 tokens. Prefill, i.e., "reading" the prompt, proceeds at a speed of 44 tokens per second, and generation yields 9 to 15 tokens per second. All of this was tested on a 16-core RyzenTM 9 9955HX. For comparison, this is approximately the pace at which text is still convenient to read as it appears on the screen.

Why this is even possible

Two techniques converged here. The first is embedded in the model itself. MoE (mixture of experts) is like a large library where only the relevant expert books are opened for each question. DeepSeek-V4-Flash has 284 billion parameters, but only 13 billion are active per token, so in terms of computation, it's closer to medium-sized models. The problem is different: all 284 billion must be stored, and it's usually memory that hits the ceiling.

The second technique is employed by the project author: aggressive quantization of routed experts, down to 1.56 bits per weight using the IQ1_S scheme, plus a custom file format. 284 billion weights at just over one and a half bits each result in slightly over 50 GB, which fits within 64 GB.

Where's the catch

The word "lossless" in the author's README only means that the logits match the unpatched build with the same quantized weights. There has been no comparison with a full-precision model, and at 1.56 bits per weight, a loss in quality is almost certain; the only question is its magnitude. All figures were obtained by the author himself; there have been no independent replications yet. The quantized files do not open in standard llama.cpp, Ollama, and LM Studio: a build from the project is specifically required.

Why this is noteworthy

Demand for HBM and DRAM is growing, while the memory and graphics card market is going through a difficult period. If such builds are confirmed, inference of last year's frontier-level models locally could move from expensive GPUs to home PCs and servers.
