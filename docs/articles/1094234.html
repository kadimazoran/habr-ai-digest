While one person pays for five AI subscriptions, another builds a personal agent on a small machine and controls it via Telegram. The second option is interesting not because of its attractive price tag. It allows you to check what routine tasks can actually be offloaded from a person.

I am Pavel Venzovsky, an AI Ambassador at Yandex. I am interested in the gap between "let's implement AI" and "it works and brings value." Below is an adapted version of my material about a personal agent: its structure, scenarios, and limitations. This is not an instruction for guaranteed free operation, nor a statement on behalf of the company.

What Constitutes a Personal Agent

Let's take Hermes Agent, an open-source project by Nous Research. It connects to models, has tools, memory, skills, scheduled tasks, and an interface via messengers, including Telegram. It also handles voice processing; the specific recognition method and its cost depend on the configuration.

The scheme, without technical details, looks like this:

  1. A small computer or server runs the agent program.

  2. The agent accesses the chosen model via a suitable API or its own model service.

  3. Tools allow it to work with files and perform permitted actions.

  4. Skills describe repetitive operations, and memory helps retain useful context.

  5. The user sets tasks from Telegram; some tasks can be run on a schedule.

The messenger here is the control panel. The agent is the process executor. The model is the component that helps interpret the task and choose actions. If you mix these roles, you can easily start expecting a chatbot to perform the work of an entire department.

An agent application requires an authorized way to access the model. Having a paid chat subscription does not automatically mean it can be used as an API for a round-the-clock agent. The terms of a specific service must be checked separately.

Where is the "Free" Part, and Where Does the Cost Begin

For prototyping, you can consider model APIs from the NVIDIA catalog. In their official FAQ, free access via the Developer Program is described for prototyping, research, development, and testing. This is not a promise of a perpetual production service with support and guaranteed availability. Production use and specific NIM variant terms are checked separately.

Therefore, "without a paid subscription" and "for 0 rubles per month" are different statements. Even with free model access, the following costs remain:

  • computer or server rental;

  • electricity and communication;

  • setup, updates, and troubleshooting;

  • potential fees for search, speech recognition, and other external tools;

  • human time for result verification.

A free software license does not eliminate these expenses. And the agent does not become a full-fledged employee just because it can respond promptly in Telegram. As a good first approximation, it's a junior assistant given a clear task, limited permissions, and result verification.

What Small Businesses Should Consider Testing

You can start with a small, repetitive process:

  • collecting summaries from permitted open sources;

  • preparing drafts of documents and presentations;

  • structuring notes and turning them into action plans;

  • generating regular reports in a consistent format;

  • preparing responses that a human checks before sending.

These are examples of possible scenarios, not a promise that any of them will work immediately after installation. You will need to define the document format, access rights, sources, and quality criteria. External actions, such as sending an email to a client, are best separated from draft preparation and explicitly agreed upon.

Round-the-clock operation is useful for scheduling: the result can be available by the start of the workday. However, a computer that doesn't sleep does not guarantee that the model, internet, and all external services are available.

How to Determine if the Agent is Helping

I wouldn't start with the number of messages in the chat. For the first test, it's enough to choose one task and record:

  1. What constitutes a finished result and who accepts it.

  2. How the task is currently performed and how much time it takes.

  3. How much time is spent on setting up and verifying the agent's work.

  4. How often the result needs to be redone.

  5. What are the costs for the entire scenario, not just the model.

For example, if the agent creates a draft report, it's useful to compare the entire path to an accepted report. A quick draft that then requires an hour of correction might be more expensive than the usual process. This is a proposed evaluation method, not figures from my implementation.

I wouldn't project savings without such observations. A cheap agent can also have an expensive manager – a person who spends all day explaining what exactly went wrong.

A Local Machine Does Not Mean Local Data

If Hermes runs on your mini-PC and sends requests to an external API, the data leaves that computer. This is a fundamental difference from a configuration where the model is also deployed within a controlled environment.

Different services have different terms for storing requests and using data. The statement "all free models learn from your requests" is too general. For a trial scenario, it's reasonable to use open or synthetic data; do not send confidential, personal, or client data to an external service without a justified basis and verification of terms.

When the usefulness of a process is confirmed, the next step is to choose suitable models, hosting, access rights, and maintenance. Simply moving the program to another server does not solve these issues.

What Remains of the Idea of a Personal AI Employee

I like the ability to inexpensively test a hypothesis: what repetitive actions will the agent offload from a person and what results will it yield. There's no need to start by buying a set of subscriptions or promising to replace a profession.

An agent empowers those who understand their process. If there is no process, you can get very convincing noise – now also on a schedule.
