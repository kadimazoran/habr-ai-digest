I Wrote 61 Tests for an AI Mentor. Then I Found Out Tests Can't Be Trusted Either

You don't hire a tutor based on their resume. You give them a real student's notebook and see not whether they know the answer, but where they'll get stuck. Will they point out the line with the error, or rewrite the problem for the student? Will they say 'I don't know, let's check,' or confidently make something up? What the Environment Checks

Each question in the environment consists of a student's message and a set of checks for the answer. The checks are intentionally primitive: substrings, tool calls, length, language.

Here are the terms: Question – a test case: a student's message and expectations for the answer. Run – one pass of the entire set or a part of it through one model. PASS/FAIL – the result of automated checks for one question, not a human evaluation of the answer.

type Question struct { 
	ID string 
	Group string 
	Messages []domain.Message 

	ExpectTools []string 
	ForbidTools []string 
	ExpectAny []string 
	ExpectEach [][]string 
	Forbid []string 
	Lang string 
	MaxLen int 
}

The mentor has three tools: lesson search, student progress, and their latest task attempt. In the environment, the latter two are simulated with fixtures, while the search uses the actual 272 course lessons. The student's fixture includes a function Reverse that reverses the original slice in place, although the task requires returning a new one. The model receives the code and the auto-check output only if it calls get_last_submission.
