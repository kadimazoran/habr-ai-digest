Life after Claude Code: How I moved to Codex and preserved project history

In late October, I unexpectedly found myself without working Claude Code. After a request for identity verification, Anthropic suspended access to my paid organization. The Claude Max 20x subscription was subsequently canceled, and a refund was denied. I filed an appeal, but I didn't want to indefinitely halt project development.

The problem wasn't so much choosing another neural network.

Over time working with Claude Code, dozens of projects and dialogues accumulated. They contained architectural decisions, feature discussions, experiment results, bug fixes, development plans, and many small details that didn't always make it into the documentation.

The source code is still there. Git repositories too. But how do you explain to a new agent why the project is structured this way, what options we've already rejected, and what we stopped at yesterday?

I decided to switch to OpenAI Codex. First, I considered my own tool for transferring history, then I tried Codex's built-in import, but I wasn't satisfied with the result.

Finally, I discovered Hansard – a tool that not only allows restoring work history across different AI agents but also offers additional capabilities for storing, searching, and reusing accumulated context.

I'll share what worked, what didn't, and how to replicate this migration.

In my opinion, these recommendations are valid not only for businesses.

A developer who has been working with an AI agent for months can also become dependent on the service. Especially if they manage multiple projects simultaneously and a significant portion of technical discussions remains in the agent's history.

The reasons for each specific block may vary. In my case, support cited a violation of terms of use, but I didn't receive a detailed explanation. Therefore, I won't draw conclusions about why the block was triggered.

I was more interested in the other side of the problem.

Most recommendations boil down to exporting data, saving documents, and switching to another neural network. For regular chats, this is sometimes enough.

But I used Claude Code for software development, not the web chat Claude.ai.

Here, the chat history is not just a set of questions and answers. It's effectively a development log that may contain information not even present in Git.

And I wanted to retain the ability not only to continue working in Codex but also to return to Claude Code someday if access was restored. Or to try other agents without starting from scratch each time.

First attempt: built-in import from Claude Code to Codex

Initially, it seemed like a relatively simple task.

Claude Code stores the history of local sessions, specifically in JSONL files in the ~/.claude/projects/ directory. Codex also uses local storage for dialogues and projects.

Why not transfer the history of one agent to another?

Especially since Codex already has a built-in import mechanism.

In Codex CLI, it's enough to open a session that isn't currently running a task and type:

/import

Then, select Claude Code or Cursor and mark the data to be transferred: settings, instructions, skills, projects, and recent dialogues.

A similar option is available in the desktop ChatGPT application: Settings → Import. In some versions, the item is located under General → Import other agent setup.

Details are described in the official OpenAI instructions.

There's an important limitation: the built-in Codex CLI import supports up to 50 chats from the last 30 days. For someone who has been working with Claude Code for a long time and manages many projects, this might not be enough.

I tried this mechanism with my own history.

During inventory, I managed to find 25 projects and 53 Claude Code dialogues. About 50 sessions were imported, but I wasn't satisfied with the result.

Some imported sessions were incorrectly mapped to projects. Some dialogues required manual linking, the history was inconvenient to view, and some service messages and incomplete data were just a hindrance.

Moreover, the mere appearance of an old dialogue in Codex didn't mean that the new agent actually understood the decision-making history.

I had to figure out which projects the imported sessions belonged to, which ones were actually needed, and how to delete incorrect mappings.

But even if I had managed to fix everything manually, there was still another problem.

What about the next migration? Back to Claude Code? To OpenCode? To Cursor or Kimi Code?

Convert formats and transfer dialogues again?

It turned out that we were only solving one specific task – migrating from Claude Code to Codex.

Almost started writing our own solution

After experimenting with the built-in import, the idea of a separate tool for exchanging context between AI agents seemed increasingly interesting.

I wanted it to be able to collect history from various sources, map dialogues to projects, consider instruction files, store agreements, and transfer them to a new agent.

Not only when switching tools but also during the parallel work of several agents on the same project.

As usual, I started designing the architecture for such a solution. However, during the research process, I looked for existing solutions and what could be built from other implementations.

Among the found options was Hansard.

And here, the approach turned out to be more interesting than the initial import.

Hansard: development history separate from the AI agent

Official website: hansard.dev

Documentation: Hansard Docs

Hansard is a tool for archiving, searching, analyzing, and reusing work history with AI agents.

The main difference from our initial idea: it doesn't require converting all Claude Code sessions into native Codex sessions.

Instead, a separate archive is created, from which different agents can retrieve the necessary context.
