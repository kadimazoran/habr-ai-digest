A page opens in a browser, but does a search AI bot receive it? To check site access for neural network bots, you need crawl rules, logs, and the HTML itself. Otherwise, you might be editing robots.txt while the bot is being checked as a visitor.

How Yandex discovers new pages for search

The Yandex robot can discover a site via an external link. You can report a new page through Page Re-crawling in Webmaster: this signals the URL to be visited. An external link does not guarantee that all pages will be crawled, and submitting an address does not confirm its download.

For Alice AI, page availability in Search is directly relevant: according to Yandex documentation, it queries Search with refined requests and uses its results.

How to distinguish ChatGPT and Perplexity bots by purpose

OAI-SearchBot is intended for ChatGPT search, GPTBot collects content for potential training of OpenAI AI models. User-initiated fetches are considered separately. The purposes of the agents are described in the OpenAI documentation and Perplexity.

How to identify a search AI bot request from site logs and IP

Match the bot name in the User-Agent string—the request string by which the sender identifies itself to the site—with the sender's IP according to the specific service's rules. The name alone in the log is insufficient.

  1. Find the request to the desired URL. Record the time, IP, User-Agent, response code, and size. In the Nginx text log, you can start the search like this:

sh rg -i -e OAI-SearchBot -e PerplexityBot /var/log/nginx/access.log

If your site uses a CDN—an intermediate service for content delivery and protection—request its logs from the developer: the request might have been stopped by the protection without reaching the server.

  1. Verify the sender. Match the OAI-SearchBot IP with the ranges from the OpenAI documentation. Perplexity assigns a unique IP list to each agent. For Yandex, after performing a reverse DNS lookup, perform a forward one: according to the robot verification rules, it should return the original IP.

  2. Check robots.txt for neural networks: the rules for the desired agent and the page path. Also, check the accessibility of the robots.txt file itself. According to RFC 9309, if robots.txt is inaccessible due to a server or network error, the robot must consider crawling completely forbidden. This rule applies to robots.txt.

  3. Record the HTTP response. If the server returned a 403 (forbidden), 429 (too many requests), or 5xx (server error) code, find the corresponding event in your CDN, Web Application Firewall (WAF), or anti-bot protection logs. If there's a redirect, save the chain of addresses and the final URL. For a 200 response, check the content.

  4. Align crawl permissions and protection. OpenAI recommends allowing OAI-SearchBot in both robots.txt and via published IP ranges. Changes to robots.txt for search may take about 24 hours to take effect.

How to check server response content using curl

curl is a program for making requests to websites; it can be used to save headers and HTML of a test response. The commands below are executed in the terminal of the computer where the necessary programs are installed. The request originates from your IP: substituting the User-Agent does not confirm access by a real bot.

Replace the domain and page path. Instead of ControlWord, substitute a rare word from its main text:

sh curl -sS -L -A OAI-SearchBot 
 -D robots.headers -o robots.txt https://example.org/robots.txt

curl -sS -L -A OAI-SearchBot 
 -D page.headers -o page.html https://example.org/new-page/

rg -ni -e HTTP/ -e location: -e content-type: 
 robots.headers page.headers

rg -ni -F -e КонтрольноеСлово -e captcha -e challenge page.html

The files will contain robots.txt, the final page HTML, and response headers with redirects. Matches for captcha or challenge are a reason to examine the HTML: these words alone do not prove a block.

A 200 response here can be easily misinterpreted: it might contain a visitor check instead of the page text. Perplexity documents a troublesome Cloudflare trap: Bot Fight Mode can continue to challenge bots even with a permissive WAF rule. The Skip rule should be placed above blocking rules: it only allows subsequent rules to be processed.

If the text is present in the browser but not in the saved HTML, check if it's loaded via JavaScript. curl does not execute JavaScript. The developer's task is to ensure the main page text is present in the HTML that the server returns without executing JavaScript.

Yandex leaves JavaScript execution to the robot's discretion by default. Deferred loading can lead to incomplete indexing. You can select a mobile or desktop version to check the page in Webmaster.

What data to provide to a developer if a search AI bot doesn't receive page text

Provide the developer with the URL, time, sender verification details, HTTP responses, and HTML. Include the blocking event from the protection logs or specify which text is missing from the HTML.

A hypothetical task example: the server responds with 200, but instead of text, it returns a visitor check. The task is to eliminate this for a confirmed search bot and repeat the fetch. Acceptance criteria: the bot receives the main page text.

Indexing a site by neural networks requires separate verification. Submitting a URL to Yandex's Page Re-crawling only confirms the signal to the robot. The log records the bot's request, and curl saves the response to a test request. In Yandex, check the indexed version of the page in Webmaster.

In Yandex, also check the robots meta tag with noindex or none: it allows excluding a page from search while keeping it accessible to visitors.

Technical page accessibility must be checked against crawl rules, server logs, and the actual content received. Successful HTML loading confirms page access but does not, by itself, prove its indexing.
