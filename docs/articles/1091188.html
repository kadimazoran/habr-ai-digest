On September 15, TypeSafe released Jev, calling it the first System One-class model. Jev receives the system state and a set of typed questions, returning a probability distribution over valid answers. The entire response is considered a single forward pass, without token generation.

In 16 days, five more implementations of the same idea were released: Clef and Clef-flash from Cloudflare, pplx-decider-v1-27b from Perplexity, Strands Decider 2B from AWS, Laya from Convai Innovations, and GLiDE from Fastino. They share a nearly common interface, but internally feature five different solutions: a frozen LLM with a trainable output layer, an LLM with a replaced LM head, a pointer mechanism, a 322 million parameter encoder, and on-demand reasoning.

Below is an analysis of the architectures, independent benchmarks, and what to check before launching such a model into production.

Why Agents Need a Separate Model

In many agent systems, an LLM is called at every step, even though text generation is unnecessary for most steps. The agent selects a tool, checks if the task is complete, or decides if a command can be executed. Full generation at such steps is more expensive and slower than required for selection, and the response still needs parsing and format validation.

TypeSafe proposed a separate, fast path for these steps, naming it System One, analogous to the fast, intuitive thinking Kahneman called System 1. The name Jev refers to Jevons paradox: the cheaper a resource, the more it is consumed. Jev itself costs $0.042 per million input tokens, with TypeSafe claiming a latency of 70–500 ms and a context window of 32K tokens.

Scenarios where such models have been tested:

  • Command validation before execution. An agent is about to execute rm -rf /data/tmp, and the model classifies the command into one of these categories: read-only, reversible change, or destructive action. LangChain integrated such a check into the middleware of its Jev integration.

  • Model selection based on query. Simple queries go to a cheap LLM, complex ones to an expensive one.

  • Agent evaluation. LangChain compared Jev with three LLMs acting as judges on 500 agent response evaluations. The results are in the table below. The test is narrow: one agent and five queries repeated 100 times each.

  • Pentesting. A preprint on arXiv proposes placing Jev and Laya at four points in an autonomous pentest agent: confirming found vulnerabilities, re-evaluating their criticality, pruning redundant agents, and confirmation loops.

Interface: State and Typed Questions

A request consists of two parts. The state is text or JSON: a ticket, a page, an agent trace, or conversation history. Questions about it can be of three types:

  • noul: probability of a "yes" answer;

  • choice: one option from a list; Jev supports up to 255 options;

  • score: a level on an ordered scale.
