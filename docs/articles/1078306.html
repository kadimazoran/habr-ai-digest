Imagine a sad school student who has to solve thousands of math problems. The textbook is generally good, but in about one percent of cases, it has incorrect answers printed. The student still studies from this textbook and eventually starts solving more and more new problems.

Intuitively, it seems that the result should be worse than learning from a perfect textbook. And usually, that's what happens: incorrect data really harms learning. But there's a curious nuance: under certain conditions, a small number of errors in the training data can not only be harmless but even lead to better quality on new data.

It sounds paradoxical: if you learn from incorrect answers, how can improvement arise? Let's talk about it.

A neural network doesn't learn like a student

To properly understand the impact of a dataset on model training, let's first talk a little about how neural networks learn in principle. If you already know this, feel free to skip ahead.

When people say a model is trained on data, it's easy to imagine the process like this: it's shown a picture of a cat and told "cat," then shown another picture and told the correct answer again. This results in a huge collection of "example-answer" pairs that the model gradually memorizes and then gives correct answers to new incoming data. In practice, things are a bit different.

To put it simply, AI has a large number of parameters – numbers that determine its behavior. During training, the model receives an example, makes a prediction, compares it with the answer from the dataset, and slightly adjusts the parameters to reduce the error. Then it receives the next example, and the process repeats over and over.

As a result, the parameters begin to reflect patterns that appear in many examples. If we are training a model to distinguish cats from dogs, it might discover that certain shapes of ears, muzzles, and bodies are more common in one class than the other. No one tells it in advance: "look at the ears," but it finds features itself that help reduce the error value.

And here lies an important distinction between learning and memorization. A model can memorize a specific example, but it's much more interesting when it finds a pattern that allows it to correctly classify examples it hasn't seen before. This is precisely what is called generalization. Now, let's imagine that one of the training answers is incorrect.

What one error does

Suppose we show the model 1,000 photos of dogs and cats. In 990 cases, the labeling is correct, and in ten, it's accidentally mixed up. For the model, this doesn't necessarily mean a catastrophe.

If 500 photos tell it one thing, and another 490 confirm the same pattern, while ten contradict it, the model has the opportunity to learn the general rule and not adjust itself completely to every exception.

This can be illustrated with a simple example of apartments. If almost all data shows that price increases with area, one strange entry like "70 m² - 3 million rubles" won't necessarily make the model conclude that larger apartments are suddenly cheaper than smaller ones.

Of course, a real neural network is much more complex. But the principle is the same: a single noisy example can be weaker than a stable pattern present in many other data points.

The problem begins when the model has the opportunity not only to find general patterns but also to memorize individual exceptions.

Overfitting: when a model learns too well

Let's imagine a photo of a cat against a room background. If in our dataset almost all cats are photographed at home, and dogs are outdoors, the model might find a very simple way to solve the task: consider the room as a feature for a cat and the outdoors as a feature for a dog.

This approach will be quite successful on the training data. But if you show a dog at home on the couch, the model will get confused. We wanted to teach it to distinguish animals, but it learned to distinguish the background.

This is one form of overfitting: the model adjusts too strongly to the specifics of the training set and uses features that happened to be useful specifically within it.

Therefore, in machine learning, we are interested not only in how well the model performs on data it has already seen. It's more important what happens with a new example. And here, one of the reasons why noise can sometimes unexpectedly help becomes clear.

Sometimes an error prevents the model from choosing too easy a path

Let's go back to cats and dogs. Suppose the model discovers a simple rule: "dogs are usually outdoors." It works perfectly as long as the data is structured this way. But what if photos of dogs indoors and cats outdoors appear in the training set? These examples break the simple rule.

The model can no longer reliably solve the task based on the background alone. It has to look for other features that remain consistent across different conditions. As a result, it might start considering the appearance of the animal itself.

This is an important idea: additional diversity in the data sometimes forces the model to abandon a random hint and search for a more stable pattern.

Moreover, errors in answers don't necessarily have to be present here. The same effect can occur due to augmentations – changes to training images, random noise at the input, and other regularization methods. Therefore, some types of noise can alter the training process in such a way that the model generalizes data better.

There's a big difference between random and systematic error

Now, another case: all black cats are marked as dogs for some reason. This is a completely different situation for the model. It might discover a pattern: black fur color is associated with the "dog" class. If such a dependency is strong enough, the model will start using it for classification.

This is precisely why systematic errors are usually more dangerous than random noise. Random noise can simply degrade the signal, while a systematic error can turn into a new signal.

This is one of the main problems in machine learning: the model doesn't know which pattern we considered correct. It only sees the data. If the data persistently asserts something incorrect, the model might well learn it.

Why a model can ignore noise at all

Here, I'll allow myself a slightly more technical part, as the paradox cannot be fully explained without it. It's no secret that modern neural networks have a huge number of parameters. In some modes, a model can memorize the training set almost entirely, including incorrect labels. However, the ability to memorize data doesn't mean the model does it immediately.

During training, it gradually adjusts parameters. In the early stages, it might be easier for it to learn patterns that appear in many examples. Later, if training continues long enough, the model gains the ability to adjust to individual complex or incorrectly labeled examples.

This is precisely why an interesting effect has been observed in deep learning research: models can first learn general patterns and then gradually memorize label noise.

This results in a kind of confrontation between two processes. On one hand, the model extracts structure from the data. On the other hand, it gains the ability to memorize specific examples.

Which process will be stronger depends on many factors: architecture, model and dataset size, optimizer, learning rate, regularization, and the nature of the noise itself. Therefore, a universal rule like "1% of errors is beneficial" or "errors are always harmful" cannot be formulated. It all depends on the specific task.

What does "the model has improved" mean then?

If, after adding some noise, the model's accuracy on the test set has increased, it doesn't mean the model has gained useful knowledge from incorrect answers; rather, the path it took to reach its solution has changed.

Noise might have made some overly simple strategies less advantageous. It might have forced the model to rely on more stable features. As a result, the found solution turned out to be better not on the training examples, but on new data.

And this is a fundamental difference. We evaluate precisely how well the model performs on tasks it hasn't seen in the textbook.

An ideal dataset is not necessarily a dataset without noise

Here, a disclaimer is in order. In real-world machine learning, no one aims to deliberately add errors to data. High-quality labeling remains extremely important, but "good data" is not just data without typos.

Let's return to the old example, but add one detail: all cat photos in the dataset are taken at home with one camera, and all dog photos are taken outdoors with another camera. The labels are absolutely correct, there are no errors at all.

Nevertheless, the dataset can lead to a bad model because there is a strong hidden dependency between the class and the shooting conditions. The model might learn to recognize the camera or background instead of the animal.

This leads to an important conclusion: the problem in machine learning often lies in the structure of the entire dataset.

And still: can noise make a neural network smarter?

Let's put it this way: a neural network doesn't gain knowledge from errors and doesn't become wiser from incorrect answers. But in a technical sense, the situation is indeed interesting. Under certain conditions, noise in the training data can alter the learning dynamics and lead the model to a solution that generalizes better to new examples.

Moreover, the same principle underlies many regularization methods: preventing the model from too easily memorizing random features of the training set and forcing it to seek more stable patterns.

A neural network doesn't know what we specifically intended to instill in it. It sees the data and tries to find patterns that minimize the error. If there is a strong, stable signal and a little random noise in the data, the model can sometimes separate the two.

But if the noise becomes too large or systematic, everything changes: the model begins to lose the useful signal or learns the error itself. Therefore, training a neural network is a story about teaching it to distinguish patterns from randomness.

And perhaps it is at this point that machine learning becomes particularly interesting. Because the same question, in a different form, arises far beyond neural networks: how to obtain reliable knowledge from imperfect observations at all? And there is no universal answer yet, but it is precisely the attempts to find this answer that largely define the development of modern machine learning.
