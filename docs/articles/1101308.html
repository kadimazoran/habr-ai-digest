If you've built an AI feature in Vue, you've likely encountered the same issue: most LLM interface tools are designed for React, requiring adaptation for Vue or manual implementation of streaming, tool calling, and chat state. I created vue-llm — an open-source library that addresses this for Vue 3, Nuxt, and even Vue 2.7.


Here are the links to try it out:

  • Playground without an API key (model downloads and runs directly in the browser on WebGPU): https://vue-llm.js.org/ru/playground

  • Russian documentation: https://vue-llm.js.org/ru/

  • GitHub: https://github.com/dadashi44/vue-llm

  • npm: npm i vue-llm

Below is what the library can do and how it looks in code.

Chat in ten lines

The core is the useChat composable. It streams the model's response token by token into reactive state: messages, status, error, cancellation, regeneration.

<script setup lang="ts">import { useChat } from 'vue-llm'import { createProxyProvider } from 'vue-llm/server'const { messages, input, handleSubmit, status, stop } = useChat({provider: createProxyProvider('/api/chat'),model: 'gpt-4o',})</script><template><div v-for="m in messages" :key="m.id"><b>{{ m.role }}:</b><template v-for="(part, i) in m.parts" :key="i"><span v-if="part.type === 'text'">{{ part.text }}</span></template></div><form @submit.prevent="handleSubmit"><input v-model="input"><button v-if="status === 'streaming'" type="button" @click="stop">Stop</button></form></template>

Messages consist of 'parts' (parts): text, model reasoning, tool calls, files, sources. Therefore, the same template displays both a regular response, reasoning from Claude or Qwen3, and a tool call.

The API key remains on the server. The server part is a standard Web Request → Response handler that works in Nuxt/Nitro, Node, Bun, Deno, and edge runtimes:

// server/api/chat.post.ts (Nuxt)import { createLLMHandler } from 'vue-llm/server'import { createAnthropic } from 'vue-llm/providers'const handler = createLLMHandler({provider: createAnthropic({ apiKey: process.env.ANTHROPIC_API_KEY! }),model: 'claude-sonnet-4-5',rateLimit: { maxRequests: 30, interval: 60_000 },})export default defineEventHandler(event => handler(toWebRequest(event)))

Out-of-the-box providers include: OpenAI (and any OpenAI-compatible API), Anthropic, Google Gemini, Ollama. If you already have your own backend with streaming, createSSEProvider connects useChat to it: you describe how your SSE events are converted into response chunks, and everything else works as is.

Generative UI: the model responds with components

The most interesting part for me. When the model calls a tool, you can display your Vue component instead of text. Arguments are streamed to the component as they are generated, meaning the card starts populating even before the model finishes the call.

import { defineTool } from 'vue-llm'export const getWeather = defineTool<{ city: string }, Weather>({name: 'get_weather',description: 'Weather in the city',parameters: { type: 'object', properties: { city: { type: 'string' } }, required: ['city'] },execute: ({ city }) => fetch(`/api/weather?city=${city}`).then(r => r.json()),})
<MessagePartsv-for="m in messages" :key="m.id" :message="m" :components="{ get_weather: WeatherCard }" @tool-result="addToolResult"/>

A tool with execute runs itself. A tool without execute pauses the chat and waits for a response from the interface — this is how human-in-the-loop is done: the model suggests booking a table, the user clicks
