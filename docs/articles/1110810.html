In previous articles, I discussed local image generation, models working with Russian text, and compared their speed on a home video card. Now I've added the missing functionality – training LoRA on real shots. I'll clarify here: in my other tool – Partcaster (a neuro-track generator) – I held a categorical opinion that LoRA was not needed there. The tool is designed to perfect neuro-tracks so that the final sound resembles the real thing: replacing guitars and drums, adding fills and guitar drops. And I saw the use of LoRA there as simple copying of others' work. Here, in my opinion, LoRA is appropriate. I wanted to add functionality to the application for generating photoshoots, selecting clothes and looks with a stylist, and trying on real clothes from marketplaces or even from regular photos taken on a smartphone.

To do this, I added LoRA training for a person and face swapping to Imagecaster, and the stylist, which previously only worked through MCP, now also works within the application itself, without connecting a third-party AI client.

For the article, I created Ada (Adelaida) – a fictional character, which is convenient for demonstrating the application's capabilities without publishing real people. I personally tested this setup on myself and my wife. I have a lot of photos of my wife, taken with my Nikon D5600 DSLR (more on this below).

How it Works

LoRA is additional trained weights for a chosen model (each base model requires its own LoRA). Unlike simply replacing a face in a finished image, here a new frame is created first: with the desired scene, clothing, pose, and angle. However, in my experiments, the LoRA itself sometimes created only a "slightly" similar person, so I had to separately enable face swapping.

For LoRA training, the server uses ai-toolkit; generation is done via stable-diffusion.cpp. In the examples in this article, I use the fast Z-Image, but training is not tied only to it: the model is selected from those supported by the application. The LoRA is trained for a specific model.

If you need to try on an item from an image, after generating the frame, Klein is connected: it transfers the clothing from the image. If face swapping is enabled, it's done after this try-on. These are separate stages:

  • LoRA creates a person in a new scene,

  • Klein handles the item from the photo,

  • and face swapping ensures facial resemblance.

The stylist in the application allows you to select a person, model, style, or workflow, choose clothing (if needed – this is optional), hairstyle, makeup, background, and poses, create a plan, and start the shoot. MCP offers another way to control the same system: an agent can suggest several looks and send the frames to the application's queue. I paid special attention to privacy: even when using a "smart" AI (via Claude or Codex or similar), the original photos do not enter the history: the description of the original photos is done by a local vision model, and MCP returns text and result numbers.

How to Train LoRA: Three Methods

1. Specify a Folder with Photos

The most direct way is to gather photos of one person into a separate folder. On the "People" page, select this folder, the model for training, specify the LoRA name and the person's name under which they will be available in the application, and start training. JPEG, PNG, and WebP are supported; 10 to 100 photos are needed for training.

It's best to collect diverse shots: different angles, facial expressions, lighting conditions, and clothing. A dozen almost identical frames don't provide the same variety as ten different photos. This method requires selecting photos of one person in advance; group photos are easier to add via a set, which I'll discuss below. The training duration depends on the selected mode and model.

2. Gradually Assemble a Set in "My Images"

The application has a photo viewer from the file system – "My Images." There, you can select photos and add them to "Training Set," specifying the person. Sets are visible on the "People" page – there you can view the contents, remove unsuccessful shots, and start training.

Group photos can also be added to this set. The application searches for faces and compares them with the already selected person. If it can identify the correct one, it selects it and prepares a crop around the person; if the choice is ambiguous, it prompts you to specify the face manually. If a face is not found, is too small, or is blurry, you will receive a message. If the person doesn't resemble those whose photos are already in the set, the application will ask for confirmation.

The main convenience is that you don't need to gather a large set of photos right away. You can start with ten suitable photos and a quick training, see the result, and then gradually add new shots and click "Retrain." This is a continuation of training an existing LoRA on the accumulated set: old photos remain, and new ones are used more frequently. If needed, you can retrain the LoRA from scratch or revert to a previous version.

3. Assign Training Initiation to an Agent via MCP

The same process can be initiated from the MCP client. For example: "Train Ada's LoRA using photos from this folder on Z-Image." You need to specify the folder on the machine where the MCP server is running and select a supported model. The agent can get a list of available models, create a training job, and start it – or postpone the start to avoid overloading the GPU immediately.

Photos That Are Too Perfect – and What to Do About It

One of the criticisms of AI-generated photos is that they turn out too "perfect," while reality is "messier." Smooth skin, regular facial features, beautiful lighting. This is partly true for Ada: I didn't try to make her appearance special or unusual, so the result is a fairly typical look with regular features. Ada is a fictional character, and she shouldn't be used to judge how well the model renders the appearance of real people.

For myself, I trained LoRA on my photos and my wife's photos. I like these results better: a real person has their own peculiarities, and seeing them in new looks is more interesting than generating a fictional model. In my opinion, the recognizability is good. The LoRA itself can change the face from frame to frame, and face swapping helps maintain resemblance.

At the same time, "beautiful" photos that are not too realistic have existed long before generative AI. I have a Nikon D5600 and a Samyang 135mm f/2.0. I initially bought the lens for astrophotography – to shoot the night sky from a tripod. But it turned out that it also shoots people wonderfully. However, the lens has no autofocus, and you have to step back more than 10 meters :)

Below are two of my shots taken with this setup. Both were shot at 135mm, f/2, and ISO 100: the autumn one with a shutter speed of 1/1000, the forest one at 1/1600. After shooting, I did the usual photo preparation in Photoshop: processing the NEF file into JPEG, adjusting brightness, color, and geometry. I use Photoshop and don't consider such processing to make a photo unreal.

The point is: these frames attempt to achieve a beautiful photograph that is slightly different from reality. Exactly what is, for some reason, held against AI.

However, anatomical errors and loss of detail are quite specific drawbacks. In the selection, I've included noticeable examples and labeled them. In one frame, the model made Ada look heavier and didn't show her face, so face swapping was skipped. In another, there were four fingers on one foot, and in yet another, three hands. Also, when the stylist was creating one look via MCP, they themselves realized the jacket was missing and "reshot" the frames. These are real results, not just the best pictures chosen to hide problems.

You can generate many variations and discard the unsuccessful ones immediately. This doesn't mean the photos are entirely free: equipment, electricity, and time also cost money. But an unsuccessful attempt doesn't write off paid credits, unlike cloud services with pay-per-generation models. For such a home photo studio, the ability to experiment freely and choose the result is more important to me than the promise of a flawless first shot.
