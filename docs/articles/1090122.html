Aquilum — a fast Obsidian alternative in Rust that consumes about 27MB of RAM

Aquilum is a fast, local-first note-taking app written in Rust for Windows, consuming around 27MB of RAM with an 11MB installer. It features a knowledge graph, backlinks, live Markdown preview, multiple knowledge bases, advanced tables, books and a reader, Dataview-like data analysis, fast search, change history, and integration with MCP agents. The note-taking app supports backlinks and a knowledge graph, file tree, live preview, working with multiple knowledge bases, data analysis using a Dataview analog, instant search for related and similar notes, change history within each note, and much more, which I will cover in the article.

I've attached the project description on Github and the release page with an installer for Windows. Yes, you can only test it on Windows for now.

Aquilum is not trying to replace Obsidian in all scenarios yet. It is an actively developing Windows prototype of a local-first note-taking app.

Why was the Aquilum note-taking app created?

I'm a big fan of Obsidian, but I got incredibly tired of how much RAM it consumes. This is especially problematic when several heavy applications are open, and memory is particularly valuable.

On my computer, Obsidian noticeably increases the load upon startup and works particularly heavily with large vaults and several demanding applications.

Below, I've included a screenshot comparing the resource consumption of Obsidian and Aquilum. I implemented analogs of Obsidian's familiar features in Rust: Dataview-like queries, graph, backlinks, history, tasks, and other functions, so the conditions in my case are as similar as possible.

You can see that Obsidian can consume over a gigabyte of memory, while Aquilum only uses 27 megabytes! So, I even understated the figures in the article's title...

The difference is that Obsidian pulls in a separate browser engine, which loads the system. I decided to do things differently and write the note-taking app using Tauri, so that resource consumption would be minimal. This allowed me to limit RAM usage to 27MB and pack the installer into 11MB of disk space.

Also, I don't like that all plugins in Obsidian have a disjointed visual design. I'm a designer myself, so this nuance constantly bothers me. I want a unified design system and control over tokens (indentations, sizes, and colors). Plus, developing a substantial product has been good practice for me, as I currently work in a design systems team.

And I also wanted openness and portability, so that all my data is always with me! In Obsidian, some plugins don't always store data obviously (this is typical for table plugins). In Aquilum, however, all data is stored in notes, which means complete portability of the knowledge base.

Aquilum uses CodeMirror 6 — the same editing engine used in Obsidian. Therefore, the basic experience of editing Markdown will be familiar to Obsidian users.

Knowledge Base Search

It was important for me that the search works instantly, even with a database of a million notes. This is the central part of the entire application, which must be reliable and lightning-fast. As a result, a thousand full notes are processed in 1-2 ms on my machine, and the search moment is completely unnoticeable to the eye. The search also supports hotkeys for quickly opening or creating notes.

At the same time, matches are highlighted, and the total number of matches is displayed in the upper right corner of the source card.

Metadata, Frontmatter, and Templates

The note-taking app also has a frontmatter block, where you can place various information.

For example, you can specify the creation date and time, display the cover of a page or book, tags, and book rating. There are also technical fields, such as reading progress, linked to the book's file size. This means you can open the book through Aquilum on any device, and reading will start exactly where you left off! Everything is done to ensure all data is with you!

Settings, Trash, and Vault Switching

There are also application settings that allow you to customize the app flexibly.

Currently, basic settings for appearance, language, fonts, and the start page are available; an advanced theme system is under development.

There is also a trash bin where deleted files go. In Obsidian, I sometimes accidentally deleted very important notes, and they disappeared completely! In Aquilum, this problem is fixed - notes always go to the trash!

If you need to work with multiple vaults, you can add them and switch between them through a convenient modal window. Via MCP, there is a command to switch knowledge bases so that the model opens the desired note for you.

MCP Server and Working with AI Models

It was important for me to be able to automate work with notes through MCP, because sometimes you need to, for example, change the date format in all notes or move notes between knowledge bases, which automation greatly helps with, especially when there are many tasks at work.

The application supports connections to Claude Code, Codex CLI, and Gemini Antigravity. Agents can search for information through instant BM25F search, view connections between notes, and even edit notes in multiple knowledge bases simultaneously!

This greatly speeds up work with project knowledge bases because all tools work out of the box and do not require additional setup or custom script writing.

Note Change History

Another advantage is the built-in versioning, which allows you to revert your edits and view the evolution of your thoughts. The same applies to edits made by AI agents, which might delete important information. Now you can always recover what was lost!

Knowledge Graph

I wanted to make the graph not just a decorative visualization but a working tool for navigating and analyzing the knowledge base.

It works with any number of notes instantly and also allows displaying a heatmap of note changes and creation within the knowledge base. This means you can now see which sections haven't been updated in a while and which ones you are currently working on.

Plus, you can filter notes by creation date, which can be useful for analysis.

Task Management

Task management is still in its early stages but already supports basic Markdown checkboxes and queries based on their status.

Dataview and Data Handling

The application supports writing custom scripts directly within the note body to work with data. The syntax is very similar to what's in the Dataview plugin in Obsidian, but it has been redesigned for simplicity, extended for my tasks, and rewritten in Rust for instant responsiveness to system changes.

Here's an example of all three blocks from the screenshot above:

Latest Notes

```dataview 
TABLE WITHOUT ID 
    link(file.link, title) AS "Latest Notes", 
    dateformat(file.ctime, "d MMM") AS "Date" 
WHERE file.ctime >= (date(today) - dur(1 week)) 
SORT file.ctime DESC 
LIMIT 10 
```

Note Stats

```dataview 
TABLE WITHOUT ID 
    item.name AS "Note Stats", 
    count(rows.file.ctime, item.span) AS "Total", 
    delta(count(rows.file.ctime, item.span), 
          count(rows.file.ctime, previous(item.span))) AS "Dynamics" 
FROM "" 
GROUP BY "" 
FLATTEN list( 
    object("name", "Today", "span", span(today, now)), 
    object("name", "Week", "span", span(today - dur(1 week), now)), 
    object("name", "Month", "span", span(today - dur(1 month), now)), 
    object("name", "Year", "span", span(today - dur(1 year), now)), 
    object("name", "All Time", "span", ever) 
) AS item 
```

Uncompleted Tasks

```dataview 
TASK TITLE "Uncompleted Tasks" 
WHERE !completed 
SORT file.mtime DESC 
LIMIT 10 
```

Live Preview and Ease of Use

To be honest, I haven't launched Obsidian in a long time and genuinely enjoy working in my dream note-taking app. It's not perfect, but it already supports the functions I need, and live preview allows seamless work with script blocks and quick formatting edits in Markdown.

Where you place the caret (cursor), the formatting will be displayed, and you can edit bullet points, bold text symbols, code, heading levels, and anything that affects the text's appearance.

Technical Details

  • Rust + Tauri 2;

  • React + TypeScript;

  • CodeMirror 6;

  • Markdown as the primary storage format;

  • Yjs for the local document model;

  • SQLite for application state;

  • BM25F for full-text search;

  • Windows as the current platform.
