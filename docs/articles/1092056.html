FRIDA Decisions is an open-source fast-thinking model for the Russian language. It selects an option from a list, assigns a score on a scale, answers 'yes' or 'no', and ranks candidates in a single encoder pass, without text generation, in tens of milliseconds on an RTX 5060 Ti. It can be used wherever LLMs currently function as classifiers or judges: ticket routing, moderation, data labeling, RAG ranking. On our razvilka benchmark, the model scores 0.893, on par with the commercial TypeSafe Jev API (0.897) and the LLM Qwen3.5-35B-A3B, which is 40 times larger.

In short, what's inside:

  • Speed. 28-34 ms per request on an RTX 5060 Ti. According to independent measurements, a commercial API responds in approximately 430 ms, including network latency.

  • Cost. Nearly 20 times cheaper than a commercial API per request when using a rented card at full load.

  • Hundreds of options in one request. All response options go into a single sequence; the text is encoded once. For a typical request with three questions, this uses 6 times fewer tokens than a naive approach, and a catalog of 243 intents is processed in 0.44s instead of 4.65s.

  • Openness. Weights and inference code under MIT, razvilka benchmark (each task has its own license), ONNX version for CPU, Mac execution via MLX, vLLM server.

We will explain how the model works under the hood and show you how to run it yourself.

Why a model that doesn't generate anything?

Any LLM product involves dozens of small decisions that don't require text output:

  • LLM Routing: deciding which model, index, or agent to send a request to.

  • Guardrails: is it toxic, does it look like fraud, does it violate policy?

  • Tool Calling: which of the hundreds of functions to invoke.

  • Ticket Parsing: topic, urgency, tone — all at once.

  • RAG: is the answer in the context, which passages are relevant (reranking).

Typically, these decisions are offloaded to LLMs: prompt, generation, JSON parsing. This is expensive and slow, and a separate class of fast reasoning (decision) models has emerged for such tasks: input is text and a closed list of N options, output is the best option and probabilities for all N. For example, the commercial TypeSafe Jev API: according to TypeSafe's own estimates, it is 40-200 times faster and about 400 times cheaper than frontier LLMs for such tasks. TypeSafe calls these models "System 1" according to Kahneman: a fast, non-reasoning response, unlike the slow "System 2" of LLMs, which reasons and generates.

However, such a service is an external API: network latency, per-token costs, request limits, and data leaving your system. We have created such a model for the Russian language based on our own encoder and are releasing it as open-source; you can run it yourself. The model requires about 2 GB of VRAM, and it also works on CPU without a graphics card: the int8 ONNX version responds in about 0.9s on six threads.
