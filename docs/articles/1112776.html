Skills over MCP: The MCP server now sends skills with it

On November 24th, Anthropic launched the public beta of Skills over MCP (announcement) in Claude and Claude Code. It's enabled by default on Pro, Max, and Ultra plans, administrators can enable it on Team, and it's promised for Enterprise later. The MCP server can now publish a skill itself, which is a SKILL.md file containing instructions for the agent: when to call which tool and what to ask the user first. Claude Code adds it to the model's skill list and displays it as a command /<server>:<skill>. The extension is called io.modelcontextprotocol/skills (SEP-2640), and the specification is available on GitHub.

What it was like before

Servers could already provide skills to agents in two ways:

  • As an MCP prompt. In Claude Code, this becomes a command like /mcp__aimyear__aim, but it can only be triggered manually: the model doesn't see prompts in its skill list and doesn't pick them up automatically;

  • As a resource. An agent reads it if the server's instructions say "read before starting work." Agents don't always do this.

Only a skill copied to ~/.claude/skills worked without issues: the model sees these skills immediately along with their descriptions. However, each user had to install it manually, and copies would become outdated after the first change on the server. My local copy fell two rules behind the server's in a month.

How it works now

Upon connection, Claude Code sends server/discover to the server, detects the extension, and calls skills/list. It receives only the skill name and description; the full text remains on the server. When a user selects a command or the model decides a skill is appropriate, Claude Code reads skill://<name>/SKILL.md via resources/read, verifies the sha256 from the list, and inserts the text into the dialogue. No code is run on the user's machine.

What needs to be changed on the server

  • Support protocol revision 2026-07-28. It is stateless, and the conversation with the server begins with server/discover instead of initialize.

  • The TypeScript SDK 1.x (up to 1.32.2) does not have this revision. It is supported by the @modelcontextprotocol/server package version 2.4, which also includes the extension for skills. Both SDKs can be kept on the same endpoint: the isLegacyRequest() function from v2 forwards old requests to the 1.x handler, so older clients remain unaffected. For servers without an SDK (like my Python on Lambda), a small module is sufficient: server/discover, skills/list, skills/get, and a file via resources/read.

  • server/discover, skills/list, skills/get, and resources/read must respond without authorization. tools/call remains protected.

  • You need Claude Code 2.1.331 or newer. Its limits are: 100 skills per server, 100 KB per text file, 400 KB per skill.

Note that after responding to server/discover, Claude Code switches all subsequent calls to this server, including tools, to the new revision.

Numbers from my servers

I migrated two of my servers to the new scheme: the AimYear goal tracker (TypeScript) and worklore (Python). Before the update, I analyzed server/discover requests from November 1st to 26th in the logs. AimYear received about 2,400 such requests, and worklore received about 2,000. Neither responded to any of them: AimYear returned 401, and worklore returned "method not found."

The majority of requests came from MCP server directories and crawlers. However, there were also genuine clients: Claude Code starting November 16th (version 2.1.323, a week before the announcement), Devin CLI, and the MCP client from OpenAI. Seven minutes after deployment, my Claude Code 2.1.332 called server/discover, then skills/list, and successfully received a skill. Crawlers currently only check the protocol version: after deployment, only one Claude Code requested skills/list from the server.

How to check your server

curl -s -X POST https://YOUR-SERVER/mcp 
  -H 'content-type: application/json' -H 'accept: application/json, text/event-stream' 
  -H 'mcp-protocol-version: 2026-07-28' -H 'mcp-method: server/discover' 
  -d '{"jsonrpc":"2.0","id":1,"method":"server/discover","params":{"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientCapabilities":{},"io.modelcontextprotocol/clientInfo":{"name":"check","version":"1"}}}}'

If the server responded with 401 or "method not found," Claude Code users will not see your skill. If the response includes 2026-07-28 in supportedVersions and io.modelcontextprotocol/skills in capabilities.extensions, you are all set.

You can give your agent instructions from worklore to apply the update in your project.
