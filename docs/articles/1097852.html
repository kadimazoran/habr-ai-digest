I'll start with the conclusion: if I do the same boring operation manually for the second time, an AI agent somewhere in the world gets sad. And if it's the third time, it's probably already a Python script.

For a long time, I perceived AI mainly as another interface to a language model: ask a question, get an answer, ask to rewrite something, explain code, or help with a formula. Then I started using AI agents and quickly realized that the difference between them and a regular chat is much less magical than it sometimes seems.

A regular chat mainly tells you what can be done. An agent can open a file itself, write a small script, run it, check the result, fix an error, and put the finished file where it's needed. After that, some habitual tasks suddenly start to feel like manually copying files to a USB drive. Technically possible. But somehow awkward now.

Below are five types of tasks that, after getting acquainted with agents, I particularly don't want to do manually again.

1. Parsing Large Excel and CSV Files

One of the most typical tasks looks like this: a data export of several tens of thousands of rows arrives, and first, you need to understand what's going on in it at all. Previously, a significant portion of the time was spent even before the actual analysis. I would open Excel, study the sheets, look for key identifiers, check for missing values and duplicates, create pivot tables, write formulas, and only then get to the conclusions.

The most unpleasant thing happened when, after half an hour, it turned out that the calculation was not done at the correct entity level, the denominator was chosen incorrectly, or the same object appeared in multiple rows. At that moment, analytics temporarily turned into an exercise in accepting the inevitable.

With an agent, I usually start differently:

Examine the file structure, identify key identifiers, check for missing values and duplicates, and then propose an analysis plan.

Then the agent can use Python, pandas, openpyxl, DuckDB, and other common tools. And here, one principle is important to me: the model should not calculate numbers "in its head". The normal scenario is when the AI understands the task, formulates the logic, writes the code, and the calculations themselves are performed in a standard deterministic way.

That is, instead of "I think it's about 18% here," you get a much more boring but useful option: here's the filter, here's the denominator, here's the code, here's the result. Mathematics still works best when calculated by mathematics, not by a confident text generator.

There's another bonus – reproducibility. If a new export of the same format arrives tomorrow, you don't have to go through the whole process manually again. You can repeat the already prepared sequence and focus on what has actually changed in the data.

2. Moving Information from One Format to Another

There's a separate class of tasks that require almost no complex solutions but are excellent time-eaters. For example, you need to convert PDF to a table, assemble a Word document from several sources, transform Markdown to HTML, bring a chaotic document to a unified structure, or generate a final Excel file from intermediate files.

Essentially, a person at this moment acts as an expensive format converter. Such an enterprise converter with coffee, meeting calendars, and periodic attempts to understand why a table has shifted again in one document.

An AI agent is useful in such tasks not because it "understands documents better than a human," but because it has access to common tools: pandoc, python-docx, PyMuPDF, openpyxl, pypdf, and other libraries. It can not only suggest how to solve the problem but actually perform the conversion.

For example, instead of the answer "you can use Pandoc for this," the agent can actually run:

pandoc input.md -o output.docx

look at the result, notice that part of the structure is lost, correct the source or parameters, and repeat the operation.

For me, this is one of the most underestimated capabilities of agents. Not magical intelligence or another chat with beautiful phrasing, but the absence of the need to be the glue between ten formats and tools myself.

3. Writing One-Off Utilities

This is where, perhaps, the most significant shift occurred for me. Previously, if a small program was needed for a task, I would first assess how much I actually wanted to open an IDE and write code for it. Very often, the answer was: not that much.

Now the threshold has significantly lowered. If you need to compare two exports, rename a thousand files, build a simple interface over Excel, perform a local search across documents, automatically generate a report, or validate a dataset against rules, I first think not "is it worth the development?" but "can it be quickly handed over to an agent?"

It writes code, runs it, catches errors, fixes them, and runs it again. Sometimes it resembles a very fast intern who doesn't need sleep but needs a good task setter. If a simple interface is needed, you can add Streamlit, HTML, or a small local web service to it.

As a result, a utility that was previously too much hassle to create for a task that takes a couple of hours a month suddenly becomes quite justified. AI reduces the cost not only of creating complex products but also of small automations that previously simply didn't pay off in terms of time.

4. Troubleshooting Unfamiliar Environments Through Trial and Error

Anyone who has ever set up anything in Linux knows the wonderful cycle:

command → error → search → article → another command → another error → yet another article → command from 2019 → it got worse

It's especially fun when the problem lies somewhere between PATH, certificates, SSH, Python environments, permissions, dependencies, and the corporate network. At some point, you're no longer fixing the problem but completing a side quest that accidentally appeared within your workday.

With an agent, this turns more into collaborative diagnostics. Instead of chaotically trying commands, you can first check which Python is being used:

which python which pip

then check the environment:

pip list

and then study logs, directory structures, environment variables, and gradually localize the problem.

This doesn't mean the agent never makes mistakes. It makes them, believe me. Sometimes it confidently suggests the very command that makes you want to close the terminal and pretend nothing happened.

But the value for me is elsewhere: I no longer need to keep the syntax of twenty tools in my head simultaneously. I can maintain a higher level – what exactly do I want to achieve – and then unravel the technical details together with the agent.

5. Repeating the Same Process a Second Time

Perhaps this is the main effect. If I've done a task manually with an agent once, the question almost automatically arises the second time: why am I even doing this again?

Suppose every month you need to put a new export into a folder, check its structure, calculate metrics, find anomalies, generate a final Excel, and write a short summary. After the first run, it becomes clear where checks are needed, which fields are mandatory, what constitutes an error, and what the result should be.

At this point, the process can be formalized as a command, script, or separate scenario. For example:

/analyze-report

and hide the entire sequence behind it.

Then AI becomes not only an executor of individual tasks but also a way to document a workflow. Moreover, automation no longer has to start with full-fledged development. Previously, the first question often sounded like "should we assign this task to developers?" Now you can start much cheaper: first, automate the process locally, check if it's truly useful, and only then decide whether to turn it into a proper service.

Where's the Catch

Of course, an agent is not a magic button. Although sometimes it tries very hard to look like one. I wouldn't entrust it without supervision with financial calculations, modification or deletion of important data, actions in production systems, or any decisions where the cost of an error is significantly higher than the cost of saved ten minutes.

Sensitive information is a separate story. If an agent gains access to internal documents, client data, or corporate systems, you need to understand where the data goes, what rights the agent has, and what exactly it can do on behalf of the user.

And the closer the task is to a real business process, the more important non-AI issues become: access rights, logging, security, infrastructure, monitoring, and responsibility for errors. It has indeed become very easy to assemble a useful tool locally today. Turning it into a reliable service for hundreds of people is still a separate engineering task.

Kubernetes hasn't disappeared just because we've learned to talk nicely to a model.

Instead of a Conclusion

Although the conclusion was already in the first paragraph – optimization has reached even the structure of the article.

The most useful thought I've gained from working with AI agents is quite boring: you don't necessarily have to look for a task where AI will do something incredible. It's much more practical to look at your regular workday and notice operations that are repetitive, require a lot of mechanical actions, and follow roughly the same scenario every time.

I increasingly ask myself a simple question:

What stupid repetitive operation have I already done for the second time today?

Very often, that's exactly where the best first use case for an agent lies.

And if, after that, it takes over another Excel file, PDF conversion, or environment setup from me – I'm absolutely fine with that.
