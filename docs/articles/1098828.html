This is the story of how a small widget for Claude limits grew over a month to include a pixel crab, weather, chat, and a whole wardrobe of skins. And about what happens when Claude writes all the code, and you only explain what you want.

How It All Began

I started using Claude not too long ago: in March, I got a $20 trial subscription to check out this "vibecoding" and what the popular LLM was really capable of. It wasn't that it hooked me much back then. I barely used it for almost the entire month. I mostly asked it to generate short code snippets, which I then corrected to fit my style.

Nevertheless, in April, I subscribed for $100. I didn't even exceed the limits of the previous plan, but it was psychologically uncomfortable when they filled up to half or more within a few requests. By then, I realized that the tool was generally useful and I might need more limits someday, and the price for such an assistant wasn't that high.

Gradually, I started getting used to it and offloaded more and more tasks, especially log analysis, problem diagnostics, and other uninteresting admin routines. For research, I already asked it to run multiple agents simultaneously.

Along with this, I found myself checking my limits more and more often, mainly by visiting the website or using the terminal. But all this was inconvenient and I got tired of constantly checking.

Then the idea struck me – I needed a small widget on my screen that would show my limits in real-time. By that time, the new Opus model had just been released, which was clearly better at coding than I was, and I had to correct it less and less often.

Thus, the first version of the widget appeared: a couple of hundred lines in a single PowerShell file without any third-party dependencies. The limits no longer bothered me; I had fully satisfied my need.

Too Much Empty Space

The story could have ended here, but one evening, glancing at the widget again, I thought there was too much empty space above the five-hour limit bar. The next thought was that I needed to put an animated mascot there.

Claude Code already has its own mascot – the pixel crab Clawd from the welcome screen. I asked to port him to the widget using the same block characters and animations as in the terminal.

He got bored just sitting there, so very soon he started reacting to what was happening. When nothing is running, he sleeps; while a session is active, he scurries back and forth; and when the session is waiting for my response, he waves his paw. He starts sweating near the limit, and when the limit runs out, he lies on his back.

New Ideas

Once the crab started living in its own space, I immediately wanted to add a background for it. Naturally, the idea came to add the real weather outside the window. And at night, a moon in the correct phase, if it wasn't hidden by clouds.

Then I wanted Clawd to be more than just decoration. So he got his own chat panel. Once every half hour, he can check the system and report that the disk is full or something new has appeared in the startup programs. Next came reminders, to-do lists, and recurring scheduled tasks. The tasks politely wait if the limit is almost exhausted, after all, the widget is about limits. Along the way, a weekly usage graph, top projects, and sessions from other machines were added.

I posted the widget on GitHub and wrote about it on Reddit. It turned out that people liked it and actually started using it. And someone wrote that they installed it for their entire office. That's when I realized that personalization was urgently needed, because a whole office of identical crabs is somehow not right.

Thus, widget themes and crab skins appeared.

As a result, in a month, a couple of hundred lines turned into over 10,000 lines and 36 modules, and it's still pure PowerShell without a single third-party dependency.

All the Code is Written by Claude

I didn't write a single line by hand, but only explained in detail what I wanted and how it should work, reviewed the result, and sent it back for revision if something was wrong. It's like working with a team, only the team doesn't get tired and doesn't argue why the crab needs a ushanka hat.

It's funny that in the end, Claude Code created a widget that monitors the limits of Claude Code itself.

What Came Out of It

Now it's a small window on top of the desktop plus an icon in the system tray. All you need is Windows and Claude Code itself: no Node, npm, or installers.

  • Limits. Percentage of the five-hour session, weekly, time until reset. The numbers are official: provided by claude -p "/usage", and this command does not interact with the model and does not consume tokens.

  • Sessions. How many Claude Code sessions are running, which ones are active, and which ones are waiting for a response. It's convenient for catching a forgotten agent that is quietly draining the limit.

  • History. A 7-day limit usage graph and top projects.

  • Service Status from status.claude.com and Claude Code version.

  • Clawd and the Sky. Moods based on sessions and limits, weather and moon phase, eight themes, and over twenty skins.

  • Clawd Panel. Chat, computer tips, reminders, lists, and scheduled tasks.

  • Self-Updating. The widget installs new versions itself, and if a new version doesn't work, it rolls back.

  • English, Russian, and French interface.

Response

In a couple of days, the repository was viewed by over 200 people, and the project has almost 60 stars. People started creating ports for other systems: macOS, Linux, Android, and iPhone; links to them can be found in the README.

How to Install

You need Windows 10/11 and Claude Code installed with a logged-in session. Clone the repository (or download the ZIP) and run start-widget.vbs:

git clone https://github.com/Enhed/clawd-usage-winwidget.git
