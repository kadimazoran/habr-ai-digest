Background:

The IBM PC was my first computer. More precisely, it was my parents' first personal computer, which I got to use at a very young age.

By the time I grew old enough to start using it, it was already obsolete. But at five years old, it was a magical device for me: all you had to do was enter the right command, and the computer would start performing various tasks.

I learned to type and work in DOS to run educational games — for example, those that helped teach the alphabet (my mom bought them for me). I even learned a bit of BASIC, although it didn't go beyond simple games like "guess the number" and other small projects.

Many years have passed since then, but I still have some parts of that very computer. Now I have a whole collection of vintage equipment that is dear to me, and the centerpiece is a fully equipped IBM PC 5160. Its 20 MB hard drive is still functional, but it's currently disconnected: instead, I use a PicoMEM module, which allows emulating a hard drive using an SD card — it's much more convenient for experiments and gaming.

Old meets new, and new meets old: I really enjoy it when technologies from different eras intersect. And what could be better than creating an AI code-writing agent that runs in DOS on original hardware?

And, of course, who better to create such an agent than the AI itself?

I (or rather, Claude) created this for my own enjoyment. I was curious to see what an AI agent could do if placed in conditions far from modern standards. And another question: could the product it creates, in turn, create something else? All the code in this repository was written by the Claude neural network — except for the text you are reading right now.

The project's test environment runs on the native operating system and hardware, and it uses an intermediate computer (a "bridge") to handle the TLS protocol — a task that the 8088 processor simply couldn't handle.

Type CLAWDOS at the C:\> command prompt, and you can chat with Claude. It can read and edit files on your disk, write programs, compile them using Turbo C, run them, and analyze their screen output. The system maintains context between chat sessions, allowing you to resume work where you left off.

This entire complex runs directly on the PC. The HARNESS.EXE program (176 KB in size) interacts with Claude's message API: it forms requests, parses incoming responses, launches necessary tools, and saves the history of each dialogue to disk. The 8088 processor performs all tasks except for handling the TLS protocol.

One command: "Write PRIMES.C: output prime numbers less than 100. Compile with Turbo C and run." ClawDOS accesses its reference guide for the compilers installed on the machine, creates the source code, and then — in a single tool call — performs compilation, linking, and execution. 64 seconds after pressing Enter, the result appears on the screen; 26 seconds of this time were spent compiling, linking, and running the program.

During the build process, the compiler is given full control of all machine resources. ClawDOS saves its current state and unloads from memory, providing Turbo C with about 450 KB of free space, and upon program completion, ClawDOS returns to its original context, now with the obtained result.

WarGames, written on an XT

ClawDOS wrote this tribute to the 1983 film on the PC itself: a vector world map, missiles flying over the pole, a tic-tac-toe endgame, and a score for the PC speaker or AdLib card. Five Turbo C files, 15 KB of source code, WG.EXE under 10 KB.

To run the project, you will need a computer (Mac or Windows) with Python 3 installed, as well as an Anthropic API key. No key? Run python3 tunnel/mockapi.py to emulate the API offline: enter CLAWDOS 10.0.2.2:18023 and send the !help command.

In mid-November, developer WollyMonjac used neural networks (Fable 5.2 and Opus 5.5) to create the open-source project TINY 2.1 — a transformer for DOS. This is a small language model in Turbo C 2.0 that runs under DOS on an old Pentium or 486DX and fits on a single floppy disk.

Earlier, developer Benj Edwards introduced the local model project ChatGPT for SNES for the 16-bit Super Nintendo Entertainment System console, released in 1990. The project is based on a small language model with approximately 2.2 million parameters, which runs on the Super FX 2 coprocessor of a flash cartridge. ChatGPT for SNES has no relation to OpenAI.
