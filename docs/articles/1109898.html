Jatoba DBMS now uses AI to automatically detect personal data

We have introduced a new feature for our cyber-secure domestic general-purpose DBMS "Yatoba". The system has replaced manual labor in searching for personal data with artificial intelligence scanning. Thanks to the automatic detection of personal data (PDn), it will be easier to comply with the requirements of 152-FZ and reduce the risks of leaks when transferring data to test environments or to technical support. The function solves a relevant problem for the DBMS market - searching and classifying PDn, as well as any other confidential data that the database administrator needs to find for subsequent masking. The manual approach scales poorly: studying a large and constantly changing database takes a lot of time, and the human factor inevitably leads to errors. The new function uses a combined approach, analyzing not only the structure but also the data itself. The process begins with scanning, during which the component lists all tables and columns in the database. Then, a data sample is taken from each column (sampling). During the analysis, regular expressions, dictionary checks, and a machine learning model are applied to the samples. In the final stage, classification, the system makes a verdict for each column: whether the data is personal, and if so, to which domain it belongs (e.g., full name or email address). The key advantage is the automation of the full cycle. The detection component works in conjunction with the anonymization component: the first creates a report on the found PDn and security labels, and the second automatically performs masking based on them. We have introduced a new feature for our cyber-secure domestic general-purpose DBMS "Yatoba". The system has replaced manual labor in searching for personal data with artificial intelligence scanning.

Thanks to the automatic detection of personal data (PDn), it will be easier to comply with the requirements of 152-FZ and reduce the risks of leaks when transferring data to test environments or to technical support.

The function solves a relevant problem for the DBMS market - searching and classifying PDn, as well as any other confidential data that the database administrator needs to find for subsequent masking. The manual approach scales poorly: studying a large and constantly changing database takes a lot of time, and the human factor inevitably leads to errors. The new function uses a combined approach, analyzing not only the structure but also the data itself.

The process begins with scanning, during which the component lists all tables and columns in the database. Then, a data sample is taken from each column (sampling). During the analysis, regular expressions, dictionary checks, and a machine learning model are applied to the samples. In the final stage, classification, the system makes a verdict for each column: whether the data is personal, and if so, to which domain it belongs (e.g., full name or email address).

The key advantage is the automation of the full cycle. The detection component works in conjunction with the anonymization component: the first creates a report on the found PDn and security labels, and the second automatically performs masking based on them. Each domain corresponds to its own masking algorithm, but the administrator can also set their own functions.
