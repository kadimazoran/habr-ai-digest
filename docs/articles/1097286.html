Previously, the main workflow looked like this: a user connects an AI to an information base, asks a question, and receives an answer based on its data. In recent versions, capabilities for maintenance and development tasks have emerged: finding the cause of a document's behavior, checking method intercepts, or preparing an extension modification.

The solution "ChatGPT, Codex + Claude for 1C" now offers tools for analyzing program code, creating and modifying extensions, as well as verifying customizations after updating the standard configuration. Direct connection from ChatGPT and anonymization of supported personal data before transferring to the model have been added.

Analyzing Configuration and Extension Code

The assistant can now search for procedures and functions, navigate call chains, and correlate program logic with the actual data of the information base.

For example, a developer can ask:

Why does the project change when this document is posted?

For such analysis, the program creates a local index of the modules in the main configuration and active extensions. This allows finding the necessary code snippets without constantly exporting the entire configuration to files.

The AI receives the code fragments necessary for the task. Indexing is performed in read-only mode and does not alter the working configuration.

Creating and Modifying Extensions

Through Codex and Claude, you can create extensions and modify the code of existing ones. The program applies the prepared changes in the database and restarts 1C. Extension versions are saved, so you can revert to a previous state.

In normal mode, checks are performed before applying changes. If an error is detected, the changes are not applied, and information about the problem is sent to the model for correction. This check does not replace the testing of application logic.

The ability to modify extensions is enabled separately for each database and is only available for the MCPFullAccess role.

For development on database copies, an accelerated mode has been added: changes are loaded in a single configurator launch, processing only modified modules. Additional preliminary checks are disabled in this mode; they can be run separately by clicking "Check" if needed.

Verifying Customizations After Updating the Standard Configuration

A separate area of updates concerns working with method intercepts in extensions.

The "Intercepts" report helps detect:

  • methods that have disappeared or changed in the standard configuration;

  • intercepts that are overridden by another extension;

  • outdated copies of standard code;

  • potential issues with re-recording documents and register movements.

In the latest update, the report can now show changes made by the provider and the extension author, and prepare updated code while preserving customizations. You can also generate a task to fix an intercept and send it to the Codex or Claude chat.

For example, if a standard method was previously copied into an extension and several parts were modified, the assistant can retrieve the current version of the method, transfer the customizations, and check for conflicting areas. The result of such a transfer should be verified on a database copy.

Problems in the report are presented as cards with filtering by extension, importance, and intercept type. After fixing the code, the check can be performed directly in the working folder without rebuilding the index.

Connecting Directly from ChatGPT

In addition to Codex, Claude Desktop, and Claude Code, the ability to work with the information base directly from ChatGPT has been added.

After setting up the connection, the user can ask questions about 1C data, search for documents, compare metrics, analyze code, and generate reports. The initial setup is done according to the instructions, after which the program maintains the connection automatically.

Diagnostics have also been improved: if OpenAI rejects the connection tunnel, the program shows the reason.

Access to the selected AI service is purchased separately and is not included in the solution's cost. Capabilities and limitations depend on the service and account used.

Anonymizing Data Before Transferring to the Model

The settings now include an "Anonymize Data" function. When enabled, supported personal information is replaced with pseudonyms before being sent to Codex or Claude.

Full names, phone numbers, addresses, passport data, SNILS, individual taxpayer identification numbers (INN), bank details, and dates of birth are processed. A persistent pseudonym is assigned to each person, allowing for the correlation of information across different query results.

However, organization names, product names, and amounts are not changed. Transferring attachments to the model is disabled in anonymization mode. This function should be considered when selecting data for analysis: it does not mean that the entire transmitted context becomes anonymized.

Multiple Employees Working on a Terminal Server

Support has been added for scenarios where multiple employees work on the same server via RDP. Each connects their 1C instance to their own program instance. Codex and Claude see the respective employee's databases and work within their permissions.

Recent versions also reduce disk space usage: the program deletes outdated code indexes and retains only the latest reports and extension versions. The results folder can be opened by clicking "Reports."
