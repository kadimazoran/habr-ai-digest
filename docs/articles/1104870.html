If a link from a neural network's response does not open, does that mean it was invented?

Not in this check: I did not find any invented addresses among the ones that did not open, although I expected more. An invented link is a hallucination: an AI model creates a plausible page address that never existed. A neural network invents sources when it doesn't search the internet: in the Walters and Wilder study, 55% of scientific links for GPT-3.5 and 18% for GPT-4 were invented without searching.

I took the addresses from a single visibility measurement in the AI models' responses and opened each one with a request. Among those that did not open, there are two groups that should not be confused. About three dozen addresses did not return a page to the bot: this is site protection. There are very few dead ones: collections on vc.ru and DTF, and a blog on Tilda. These are ordinary materials from live platforms, not a random set of characters, so most likely they are deleted articles. I don't know when the pages disappeared. No single service stood out noticeably: the proportion of live links across services is similar, from 88% to 94%.

What response code means a page is gone, and which means the site didn't let the bot in?

A page is gone when the server responds with 404 or 410. Codes 401, 403, 429, and 503 indicate something else: the server did not return the page to the bot, although it may exist itself.

According to MDN, 410 means the content has been permanently deleted and there is no redirect address. 403 means the client does not have permission to access and the server refuses. 429 is a rate limiting, the page itself may be intact. 503 is a temporary state, the server may indicate the recovery time in the Retry-After header. 401 can be a standard response to a Cloudflare security check: no visitor is blocked. A script that considers any page with an error code as dead would incorrectly mark an additional thirty addresses as dead.

How to check links from a neural network response with a Python script

The script categorizes addresses the same way as the code table, plus two auxiliary categories: no response and needs manual review. Save the code to a file named check.py, the addresses to a file named urls.txt, one per line, install the requests library, and run it in the terminal from that folder: python3 check.py urls.txt.

import sys
import requests

s = requests.Session()
s.max_redirects = 10
s.headers["User-Agent"] = "link-check/1.0 (checking links from AI answers)"

def check(url):
    try:
        r = s.get(url, timeout=(5, 15), allow_redirects=True, stream=True)
        r.close()
    except requests.exceptions.RequestException as e:
        return "no response", type(e).__name__, url
    code = r.status_code
    if 200 <= code < 300:
        return "live", code, r.url
    if code in (404, 410):
        return "deleted", code, r.url
    if code in (401, 403, 429, 503):
        return "closed to bot", code, r.url
    return "manual review", code, r.url

for url in open(sys.argv[1]).read().split():
    print(url, *check(url), sep="\t")

  • GET instead of HEAD. HEAD returns only headers without the body, so the script won't see the page content. GET allows for adding content verification later; in the script above, I don't read the body.

  • Up to 10 redirects. A link that leads to an article through redirection is live for the reader. The number 10 is taken from Google crawlers: they follow a chain of up to 10 redirects by default. If you switch to HEAD, you'll need to explicitly enable redirects in Requests with the allow_redirects parameter.

  • Timeout of 5 seconds for connection and 15 for reading. Without it, Requests might wait indefinitely for a response. The library reports timeouts and excessively long redirect chains with exceptions, which have no response code, so the script catches them separately and writes: no response. The numbers themselves are mine and can be debated.

  • Custom User-Agent. The script identifies itself as a link checker and does not impersonate a browser. It will not pass Cloudflare's security check: it works with JavaScript, and instead of a page, the script will receive the check itself. Addresses categorized as closed to bots should be opened in a browser.

  • Final address in the last column. If it differs from the original, the page has been moved or redirected to the homepage, and the script will mark it as live in both cases. Such lines should be read manually.

Why does a neural network with search link to a deleted article?

Most likely, because the neural network's search database lags behind websites: the article has already been deleted, and the crawler has not yet reached it. Pages are constantly being deleted. According to Pew Research Center, a quarter of pages that existed in 2013–2023 became unavailable by October 2023, and most often, a single page on a working site was deleted. Perplexity states that it's often impossible to re-index every address, and the machine learning model decides what to crawl and when. Therefore, a deleted page may remain in its database until the crawler reaches it. OpenAI publishes a timeframe only for robots.txt changes, about 24 hours, but does not specify a timeframe for deleting pages from ChatGPT's search.

Regular search engines at least describe what they do with deleted pages. Google, for 4xx responses (except 429), reports that the content is gone, and previously indexed addresses are eventually removed from use. Yandex removes a page with a 404, 403, or 410 response from its search database within a week after the bot detects it, but it can take time for crawling. Yandex's list also includes 403: it removes pages closed to bots from its database as well.

What to do with your page before deleting it: set up a redirect to a page on the same topic

A link to a deleted page may remain in neural network responses, so before deleting, it's advisable to set up a redirect from it to a current page on the same topic. Instruct the website administrator to configure a permanent redirect from the old address to the chosen new one and check in a browser that the old link opens the new page. This way, a person clicking on the old link from a response will land on live content. A redirect to the homepage will also be shown as live by the script, but the reader from the neural network's response won't find what was promised there. If there's no replacement, return 410: according to MDN, this is an explicit signal that the content has been permanently deleted.

In my check, there were about six hundred addresses from a single measurement, and none of them were invented. The fear that neural networks invent links is outdated for services with search: they link to real pages that once existed. The real problem is an outdated index: a deleted page continues to serve as a source. Therefore, it's necessary to check not whether the address exists, but whether it's live and whether the page says the same thing that the neural network summarized.

Limitations: one measurement and checking only if the page opens

This is one measurement: about six hundred addresses from the responses of five neural networks, checked a month later. It doesn't distinguish when dead articles were deleted, before the neural network's response or within this month. The picture can be worse with other data: Tow Center found invented or broken addresses in more than half of the responses from Gemini and Grok when citing news. I did not check whether the opened page says the same thing as the neural network summarized, and a live source can turn out to be unreliable: in a preprint on arXiv, a fabricated concept appeared in the citations of 8 out of 10 AI search engines within a week on easily accessible platforms.
