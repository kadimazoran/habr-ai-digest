Researchers from UC Berkeley and Arena compared seven models within Claude Code, Codex CLI, and the minimalist Pi. On two benchmarks, the choice of harness barely changed the average success rate but increased the cost of the same model by up to five times. The result explains why comparing coding agents by model name alone is already meaningless.

What Exactly Was Measured?

As a reminder, a harness is a software wrapper around a model. It forms system instructions, connects tools, decides which files and command results to put into context, launches the terminal, and repeats the cycle until the task is solved. The model remains the same, but the path to the answer changes.

The authors of HarnessTax collected 21 combinations of seven models and three harnesses. The study included Claude Fable 5, Opus 4.8, Sonnet 4.6, Haiku 4.5, GPT-5.6 Sol, GPT-5.6 Luna, and Kimi K3. Each combination was tested on 30 random SWE-bench Lite tasks and 30 Terminal-Bench 2.0 tasks. Each task was run three times, with one run limited to 100 agent steps.

On SWE-bench Lite, Claude Fable 5 solved 97.8% of attempts in Claude Code and 96.7% in Pi. The difference in success rate was 1.1 percentage points. The average cost per attempt reached $1.33 in Claude Code and $0.67 in Pi.

The most significant gap appeared with GPT-5.6 Luna. In Claude Code, an attempt cost an average of $0.152, while in Pi it was around $0.030. The success rate was 55.6% and 53.3% respectively. Almost the same result cost about five times more.

On average across all models, Claude Code was twice as expensive as Pi and 1.6 times more expensive than Codex CLI on SWE-bench Lite. On Terminal-Bench 2.0, the difference with Pi was 1.5 times. The authors called this overpayment "harness tax" or a tax for the agent wrapper.

Where Does the Extra Cost Come From?

Pi provides models with only four tools: read, write, edit, and bash. Despite its minimalism, it landed on the Pareto frontier for price and success on both benchmarks.

  1. This doesn't mean that four tools are always better than forty.

  2. It means that every tool, rule, and piece of context must pay for itself.

The same Fable 5 provided a good example. In Pi, it completed the task in an average of 15.4 steps; in Claude Code, it took 15.3 steps. The number of steps was almost the same, but Claude Code was about twice as expensive. One factor is visible in the very first model call. The average initial context contained 1,972 tokens for Pi, 11,308 for Codex, and 27,011 for Claude Code. The difference between Pi and Claude Code reached 13.7 times. The tool schemas differed even more, 2,873 vs. 76,995 characters. Long instructions and tool descriptions are charged again on subsequent calls if they are not covered by caching.

There is another inconvenient result. In nine out of twelve comparisons of Anthropic and OpenAI models, the native harness of the provider did not show the maximum observed success rate. For example, GPT-5.6 Sol on Terminal-Bench 2.0 scored 83.3% in Pi and 78.9% in Codex CLI. An attempt in Pi cost $0.42 versus $0.76 in Codex.

Let me clarify immediately. The study uses only two public benchmarks that might have been included in the training data. 30 tasks were taken for each benchmark, so the confidence intervals are wide. The cost is calculated based on API rates as of September 1, 2026, and does not include subscriptions. Furthermore, a short and minimalist harness might perform well in a limited run but lag in long-term work over multiple sessions. The study's conclusion is not that Pi won. It is that the combination of model, harness, and your specific task type needs to be tested.

What This Means for KodaCode

We at HarnessTax find the conclusion particularly interesting because we independently verified the same principle on a different set of tasks. In our harness comparison, the same DeepSeek V4 Flash Max with the same reasoning level achieved 52.2% in Koda, 49.5% in KiloCode, 48.2% in Claude Code, and 47.6% in OpenCode.

In a separate comparison of models within Koda, the new Koda Pro achieved 54.3%, and Koda Base achieved 49.5% with an average calculated cost of about 11.9 rubles per task. These figures do not isolate the harness's contribution but show the correct unit of measurement. It is primarily the quality and price of the entire agent trajectory, not the rate per million tokens.

And yes, I am not directly comparing with HarnessTax. Of course, the task sets, models, and methodologies are different. For example, our Koda Index includes 261 tasks. Among them are 125 fixes in existing repositories, 45 software design and implementation tasks, and 91 data analysis tasks. The agent operates in an isolated environment without a network, does not see hidden tests, and cannot peek at the fix in Git history. Infrastructure failure or exceeding limits is considered an unsolved task. Therefore, the results show not universal Koda leadership, but the specific effect of the harness on a fixed model and a reproducible run.

The harness's influence arises within the agent cycle. It decides which instructions and tool schemas to send to the model, how much terminal output to keep in context, how to pass an error, when to retry, and when to stop. For us, two things are important here: controllable context and a predictable "change, run, verify" cycle. These are what can reduce unnecessary calls and prevent a long session from drowning in its own logs. However, claiming exact savings without a separate cost measurement would be dishonest.

Therefore, our conclusion aligns with HarnessTax:

One should evaluate not the model or the harness separately, but their combination. The accepted changes, the total expenditure for the trajectory, and the number of attempts to reach a working result are important.

This leads to a practical hypothesis. Kodacode may be cheaper than another client even when working with the same model. Not because the tokens within it cost differently, but because the harness can send less extraneous context, repeat failed actions less often, and bring a change to verification faster.

Our DeepSeek V4 Flash run already shows a quality difference between wrappers. To prove the price advantage, a separate, identical measurement of full trajectories is needed. But after HarnessTax, looking only at the model's tariff is definitely no longer sufficient. Sometimes, it's not the intelligence itself that is expensive, but the road taken to reach the answer.
