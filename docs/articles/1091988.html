I've previously written about Falang (friendly algorithmic language) – a universal solution for building flowcharts. Back then, I had several MVPs for different areas, but now I'm releasing a real product.

Meet FalangFlow – a business process constructor. The code is open-source under the APGL-3 license, and you can install it locally or on your own host.

I believe everyone knows what a business process constructor is. The market for such applications is quite large now, with many solutions available. Therefore, I will focus on the main features.

Key Features of FalangFlow

Strict Node Display Scheme

In editors like n8n, users can place nodes anywhere on the canvas. As a result, diagrams with more than 20 nodes become difficult to read. In FalangFlow, you only control the algorithm; node positioning follows predefined strict rules. Complex algorithms remain readable. Falang allows implementing loops just as you would in real code. You can have any level of nesting. At any level, you can use break and continue to upper levels. The flow lines will accurately indicate where the algorithm is going, leaving no room for misinterpretation. Falang renders even complex diagrams correctly.

TypeScript Instead of a Custom Formula Editor

Block fields are actual TypeScript expressions within the Monaco editor (the same one used in VSCode). The editor knows which variables are visible at that point in the schema. This enables autocompletion for fields and type checking directly within the block. Technically, it works by using Monaco editor's functionality to hide document lines. All type declarations remain in hidden lines, and the client only sees the line where a specific value needs to be entered.

All Information on the Diagram.

Often, business process editors only show an integration icon and a brief description of the action. To see the parameters passed in a request, you need to open the icon's editing form. Falang follows the principle of “Everything should be on the diagram.” When viewing a diagram, you see all the information necessary to understand what is happening at a given node. The diagram can be exported to PDF and printed, and the printed version will display all the essential process information.

Integrations

There are over twenty built-in integrations: Telegram, OpenAI-compatible AI providers, HTTP requests and incoming webhooks, scheduling, PostgreSQL, MySQL, files, media processing via ffmpeg, human-in-the-loop tasks, and Russian services – 1C, Bitrix24, amoCRM, ЮKassa, Diadoc, MoiSklad, Ozon, Wildberries.

To avoid writing a vast number of integrations, I used a small trick: I created an adapter for the integration registry of the open-source ActivePieces engine. Currently, this method integrates an additional 62 services (Slack, Google Sheets, Notion, GitHub, Stripe, and others).

Not all integrations have been thoroughly tested yet, but that's a matter of time.

Selecting Execution Branch with AI

The AI-choice node, inherited from switch, allows you to ask an AI model a question and direct the algorithm's execution to the appropriate branch based on the AI's answer. You can also specify the data type that each branch will add to the context. This is achieved through structured output. The model returns an interface like { action: string, data: T }, and execution proceeds along the correct path.

Editing Diagrams with AI.

Falang has built-in support for an AI agent that modifies diagrams at the core level. This allows you to create and edit diagrams using simple text prompts, similar to how you would with code. You can write a request directly in an empty project, and the agent will create the automation you need.

Dev/Prod

On a dev environment, you can build the project and launch a dev version with test credentials. After publishing to production, all new processes start running on the latest algorithm version. A process that started on an older version will continue to run on that older version.

Backend on Temporal

Temporal is used as the backend (an open-source platform for reliable (durable) code execution that orchestrates distributed workflows and protects applications from failures). The compiler traverses the diagrams and generates two TypeScript modules:

  • workflows.ts – the process itself: branching, loops, function calls, waits. This is deterministic code that Temporal can replay from event history;

  • activities.ts – everything that interacts with the external world: calls to Telegram, HTTP, LLM, databases. Each such action becomes a Temporal activity with its own timeouts and retry policies.

Then, the entire project is type-checked by the TypeScript compiler and bundled by the Temporal bundler. At any moment, you can view the generated code and navigate from a line of code to the specific block it originated from.

Working with Files

FalangFlow supports working with media files. You can create images, videos, and audio using AI, as well as edit them with ffmpeg (a dedicated node is created for ffmpeg). The content of media files is never stored within the runner; instead, a File interface is provided: { id, name, size, mime }. Files are stored in ObjectStorage. When sending a file for processing, for example, to an AI, you pass this interface, and the file is then uploaded from storage and sent to the model. Similarly, when you generate a file using AI, you receive not the file content but an object with a link to the file in object storage.

This example uses two integrations: a Telegram bot and an OpenAI-compatible provider. After creating the integrations and filling in the necessary tokens, the corresponding nodes become available in the diagram. Communication with the user occurs through buttons, which are converted into a switch node on the diagram.

Requests to the AI are handled similarly. The model is provided with the user's question and answer history, and then the model either asks the next question or guesses the personality.

Do Visual Constructors Have a Future?

In the new world of agent development, specialists with lower qualifications can create increasingly complex products. It's already possible to create quite complex projects without looking at the code. This is the inevitable future, but I am convinced that the critical path of a program should be accessible for human review and understanding. And one of the best ways for a non-specialist to understand algorithms is through a flowchart.
