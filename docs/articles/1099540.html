Converting Hugging Face Models -> GGUF

Not all models exist in the ready-made .gguf format. Sometimes you need a model that the community hasn't quantized yet, or you want a specific quantization (Q4_K_M, Q5_K_M, Q8_0) that isn't available in pre-built versions. In such cases, you need to convert it yourself: from raw Hugging Face weights (.safetensors) to GGUF, and then to the desired quantization.

The convert_to_gguf.sh script automates the entire process: from installing dependencies to the final .gguf file, with cleanup of intermediate data.

What to Understand Before Starting

Conversion is always a Python script. Unlike quantization (llama-quantize is a C++ binary), the convert_hf_to_gguf.py converter requires transformers, safetensors, sentencepiece, and torch (CPU version). You can't completely avoid Python, but you can isolate it in a venv to avoid cluttering your system.

The process consists of two steps:

  1. Conversion .safetensors -> .gguf (F16). This is a "translation" of weights from Hugging Face format to llama.cpp format. The file size is approximately equal to the sum of .safetensors (may be slightly larger due to metadata).

  2. Quantization F16 -> Q4_K_M. This is "compression" with loss of precision. The size is reduced by 3–4 times, with minimal quality degradation.

Why the intermediate F16 is needed. llama-quantize works only with GGUF; it cannot read .safetensors. Therefore, the F16 file is a mandatory intermediate step. After quantization, it can be deleted (if other quantizations from the same F16 are not needed).

What the Script Does

The convert_to_gguf.sh script is a "one command, entire pipeline":

  1. Checks system packages (cmake, build-essential, python3-venv, git, curl, jq) via dpkg -s. Installs only if missing.

  2. Builds llama.cpp (if llama-quantize and llama-cli are not yet present).

  3. Creates a venv (if it doesn't exist) and installs dependencies from llama.cpp/requirements/requirements-convert_hf_to_gguf.txt. This is the official file from llama.cpp, which pulls the CPU version of torch (via --extra-index-url https://download.pytorch.org/whl/cpu) — no CUDA drivers required.

  4. Downloads the model via hf download --local-dir hf_model.

  5. Sanity check: verifies that .safetensors are actual weights, not LFS pointers (small text files). After hf download, this is always the case, but the check is inexpensive.

  6. Converts to models/<model>-f16.gguf via convert_hf_to_gguf.py.

  7. Quantizes to models/<model>-Q4_K_M.gguf via llama-quantize.

  8. Checks the Q4 size: if the file is less than 100 MB, it's clearly corrupted, and the script exits with an error.

  9. Cleans up hf_model/ and the intermediate F16 after successful verification.

Everything added to CLEANUP_PATHS is deleted upon exit (success / error / Ctrl+C) via trap cleanup EXIT INT TERM. This ensures that "partially downloaded" gigabytes are not left behind in case of failure. The KEEP_INTERMEDIATE=1 flag disables cleanup for debugging.

Key Points

CPU Version of torch — Critical

requirements-convert_hf_to_gguf.txt already specifies --extra-index-url https://download.pytorch.org/whl/cpu and torch==2.11.0. This ensures that:

  • nvidia-* packages (~2 GB) are not pulled.

  • CUDA drivers are not required.

  • Conversion will run on the CPU (which is normal for convert_hf_to_gguf.py; it doesn't use the GPU).

If you install torch manually without --index-url, pip will fetch the CUDA version from PyPI. This won't break the conversion (the CPU path is still used), but it will take up an extra 2 GB and might require libcuda.so (which is not present).

hf download vs wget vs git clone

The script uses hf download — the official CLI from Hugging Face. It:

  • Does not require git-lfs (downloads via HTTPS).

  • Supports gated models (with a token).

  • Can select specific files (if only part of the repository is needed).

Alternatives:

  • wget/curl — only for a single file via a direct link. For a full repository (with config.json, tokenizer.json, multiple .safetensors shards) — inconvenient.

  • git clone with git-lfs — if you want the git history. But for conversion, this is overkill: git-lfs needs to be installed, and .safetensors will still be downloaded as "large files".

Sanity Check: LFS Pointers

hf download downloads actual weights, but checking for LFS pointers is an inexpensive safeguard:

if grep -ql "git-lfs.github.com/spec" "$HF_DIR"/*.safetensors 2>/dev/null; then 
    echo "[!] LFS pointers found in $HF_DIR instead of weights." >&2 
    exit 1 
fi

What this catches. LFS pointers are small (130 bytes) text files that git creates instead of actual weights if git-lfs is not installed. convert_hf_to_gguf.py will fail on them with an unclear error ("cannot load safetensors"), while the check provides a clear message.

Q4 Size Check

Q4_SIZE=$(stat -c%s "$Q4_GGUF") 
if [ "$Q4_SIZE" -lt $((100 * 1024 * 1024)) ]; then 
    echo "[!] Suspiciously small file: $(du -h "$Q4_GGUF" | cut -f1)" >&2 
    exit 1 
fi

The 100 MB threshold is a generous buffer. Even a tiny 1.5B model in Q4_K_M weighs about 1 GB. If the file is smaller, something went wrong during quantization (e.g., llama-quantize failed but created an empty file). This is an inexpensive check that catches 99% of problems.

Cleanup: CLEANUP_PATHS + trap

CLEANUP_PATHS=() 
# ... 
CLEANUP_PATHS+=("$HF_DIR") 
CLEANUP_PATHS+=("$F16_GGUF") 

cleanup() { 
    local ec=$? 
    trap - EXIT INT TERM 
    set +e 
    # ... 
    for p in "${CLEANUP_PATHS[@]}"; do 
        [ -e "$p" ] && rm -rf "$p" 
    done 
    exit "$ec" 
} 
trap cleanup EXIT INT TERM

Why this is important. hf_model for a large model is 10–20 GB of .safetensors + F16 GGUF is another similar amount. If the script fails midway (e.g., OOM during conversion), 20–40 GB of "junk" will remain without cleanup. trap ensures that intermediate files are deleted under any outcome (success, error, Ctrl+C).

Q4_K_M is not added to CLEANUP_PATHS — it's the final product and should be saved.

KEEP_INTERMEDIATE=1 — for debugging. If the conversion fails, it's useful to see what's in hf_model and -f16.gguf:

KEEP_INTERMEDIATE=1 ./convert_to_gguf.sh Qwen/Qwen3.5-2B

Architectures That "Don't Go"

Not all models convert "out of the box." Real-world cases:

  • KDA / Lissa — convert_hf_to_gguf.py doesn't know the kda architecture. Even installing fla (flash-linear-attention) doesn't help: the script lacks a handler class for it. Solution: wait for support to be merged into llama.cpp master (PR #18381), or use Python inference directly via transformers.

  • Very new architectures (e.g., Mamba hybrids) — may require transformers from git (pip install git+https://github.com/huggingface/transformers.git) if they are not yet in a stable release.

  • Models with custom trust_remote_code — sometimes convert_hf_to_gguf.py requires the --trust-remote-code flag, otherwise it won't load config.json.

How to check in advance. Go to llama.cpp/conversion/ and search for a file with the architecture name:

ls llama.cpp/conversion/ | grep -i <architecture>

For example, grep -i qwen will show qwen.py. If there's no file for your model, conversion will fail without patches.

Usage

Basic run:

./convert_to_gguf.sh Qwen/Qwen3.5-2B

Without arguments — it will prompt interactively:

./convert_to_gguf.sh

convert_to_gguf.sh Code

#!/usr/bin/env bash 
# Converts a Hugging Face model to GGUF (F16) and quantizes to Q4_K_M. 
# Usage: ./convert_to_gguf.sh [USER/REPO] 
# Example:        ./convert_to_gguf.sh Qwen/Qwen3.5-2B 
# 
# The script itself: 
#   - installs missing system packages (via sudo apt); 
#   - creates/activates venv and installs dependencies from llama.cpp/requirements; 
#   - downloads the model via `hf download` if the hf_model directory doesn't exist; 
#   - converts to F16 GGUF, quantizes to Q4_K_M; 
#   - verifies the quant via llama-cli; 
#   - deletes hf_model and the intermediate F16 only after successful verification. 

set -euo pipefail 

# --- 0. Parameters --- 
MODEL_ID="${1:-""}" 
if [ -z "$MODEL_ID" ]; then 
    read -r -p "Enter the model name on Hugging Face (e.g., Qwen/Qwen3.5-2B): " MODEL_ID 
fi 
[ -n "$MODEL_ID" ] || { echo "[!] Model name not specified." >&2; exit 1; } 

# Short name for files (last part after /) 
MODEL_SHORT="${MODEL_ID##*/}" 

# --- 1. Paths --- 
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)" 
LLAMA_DIR="$SCRIPT_DIR/llama.cpp" 
REQ_DIR="$LLAMA_DIR/requirements" 
HF_DIR="$SCRIPT_DIR/hf_model" 
OUT_DIR="$SCRIPT_DIR/models" 
VENV_DIR="$SCRIPT_DIR/venv" 

mkdir -p "$OUT_DIR" 

# --- 1a. Cleanup on exit (trap) --- 
# CLEANUP_PATHS — everything to be deleted on exit. Q4_K_M is NOT added here. 
CLEANUP_PATHS=() 

cleanup() { 
    local ec=$? 
    trap - EXIT INT TERM        # prevent recursion 
    set +e                       # cleanup should not fail 
    echo "" 
    if [ "${KEEP_INTERMEDIATE:-0}" = "1" ]; then 
        echo "[i] KEEP_INTERMEDIATE=1: intermediate files kept." 
        exit "$ec" 
    fi 
    if [ ${#CLEANUP_PATHS[@]} -gt 0 ]; then 
        echo "[*] Cleaning up intermediate files..." 
        for p in "${CLEANUP_PATHS[@]}"; do 
            if [ -e "$p" ]; then 
                echo "    rm -rf $p" 
                rm -rf "$p" 
            fi 
        done 
    fi 
    exit "$ec" 
} 
trap cleanup EXIT INT TERM 

# --- 2. System packages (install only missing ones) --- 
SYS_PKGS=(cmake build-essential libopenblas-dev python3 python3-venv python3-pip git curl wget jq) 
MISSING_SYS=() 
for pkg in "${SYS_PKGS[@]}"; do 
    # dpkg -s: 0 code = installed, otherwise not 
    dpkg -s "$pkg" &>/dev/null || MISSING_SYS+=("$pkg") 
done 

if [ ${#MISSING_SYS[@]} -gt 0 ]; then 
    echo "[*] Installing system packages: ${MISSING_SYS[*]}" 
    sudo apt update -qq 
    sudo apt install -y -qq "${MISSING_SYS[@]}" 
else 
    echo "[*] All system packages are already installed." 
fi 


# --- 3. Build llama.cpp (if needed) --- 
LLAMA_QUANTIZE="$LLAMA_DIR/build/bin/llama-quantize" 
LLAMA_CLI="$LLAMA_DIR/build/bin/llama-cli" 

if [ ! -x "$LLAMA_QUANTIZE" ] || [ ! -x "$LLAMA_CLI" ]; then 
    echo "[*] Building llama.cpp..." 
    if [ ! -d "$LLAMA_DIR/.git" ]; then 
        git clone --depth=1 https://github.com/ggerganov/llama.cpp "$LLAMA_DIR" 
    fi 
    cmake -S "$LLAMA_DIR" -B "$LLAMA_DIR/build" -DCMAKE_BUILD_TYPE=Release -DLLAMA_BUILD_UI=ON 
    cmake --build "$LLAMA_DIR/build" --config Release -j"$(nproc)" 
fi 

# --- 4. venv and converter dependencies --- 
# Use the official requirements file: it pulls the CPU version of torch. 
if [ ! -d "$VENV_DIR" ]; then 
    echo "[*] Creating venv..." 
    python3 -m venv "$VENV_DIR" 
fi 

# activate environment 
source "$VENV_DIR/bin/activate" 

REQ_FILE="$REQ_DIR/requirements-convert_hf_to_gguf.txt" 
[ -f "$REQ_FILE" ] || { echo "[!] $REQ_FILE not found"; exit 1; } 

echo "[*] Installing converter dependencies (CPU-only torch)..." 
# Check "marker" packages from requirements-convert_hf_to_gguf.txt. 
# If at least one is missing, install the whole file (pip will check versions and deliver). 
# This is faster than `pip install -r` with a full set, and more reliable than 
# a manual version list (updates to requirements will be picked up). 
MARKER_PY_PKGS=(torch numpy sentencepiece transformers gguf protobuf huggingface_hub) 
MISSING_PY=() 
for pkg in "${MARKER_PY_PKGS[@]}"; do 
    pip show "$pkg" &>/dev/null || MISSING_PY+=("$pkg") 
done 

# fla is needed for linear attention architectures (KDA/Lissa etc.). 
if [ ${#MISSING_PY[@]} -gt 0 ]; then 
    echo "[*] Python packages missing: ${MISSING_PY[*]}" 
    echo "[*] Installing from $REQ_FILE (CPU-only torch)..." 
    pip install --no-cache-dir -q -r "$REQ_FILE" 
    pip install --no-cache-dir -q huggingface_hub 
else 
    echo "[*] Converter dependencies are already installed." 
fi 


# --- 5. Download model --- 
CLEANUP_PATHS+=("$HF_DIR") 

if [ -d "$HF_DIR" ] && [ -n "$(ls -A "$HF_DIR" 2>/dev/null)" ]; then 
    echo "[*] Directory $HF_DIR already exists, skipping download." 
else 
    echo "[*] Downloading $MODEL_ID to $HF_DIR..." 
    # --local-dir — no intermediate cache, directly into the folder. 
    hf download "$MODEL_ID" --local-dir "$HF_DIR" 
fi 

# --- 5a. Sanity check: weights are not LFS pointers --- 
# After `hf download`, this is always the case, but the check is inexpensive and harmless. 
if grep -ql "git-lfs.github.com/spec" "$HF_DIR"/*.safetensors 2>/dev/null; then 
    echo "[!] LFS pointers found in $HF_DIR instead of weights." >&2 
    exit 1 
fi 

# --- 6. Convert to F16 GGUF --- 
F16_GGUF="$OUT_DIR/${MODEL_SHORT}-f16.gguf" 
CLEANUP_PATHS+=("$F16_GGUF") 

echo "[*] Converting to $F16_GGUF..." 
python3 "$LLAMA_DIR/convert_hf_to_gguf.py" "$HF_DIR" --outfile "$F16_GGUF" 

# Check F16 size (should be comparable to sum of safetensors) 
echo "[*] F16 size: $(du -h "$F16_GGUF" | cut -f1)" 

# --- 7. Quantize to Q4_K_M --- 
Q4_GGUF="$OUT_DIR/${MODEL_SHORT}-Q4_K_M.gguf" 
echo "[*] Quantizing to $Q4_GGUF..." 
"$LLAMA_QUANTIZE" "$F16_GGUF" "$Q4_GGUF" Q4_K_M 


# --- 8. Verify quantized model --- 
# Minimal sanity check: file exists and size is reasonable. 
# Full test — via llama-server manually (or in a separate script). 
if [ ! -f "$Q4_GGUF" ]; then 
    echo "[!] Quantized file not created: $Q4_GGUF" >&2 
    exit 1 
fi 

# Size check: Q4_K_M is usually 1/4..1/5 of F16. If file < 100 MB — clearly corrupted. 
Q4_SIZE=$(stat -c%s "$Q4_GGUF") 
if [ "$Q4_SIZE" -lt $((100 * 1024 * 1024)) ]; then 
    echo "[!] Suspiciously small file: $(du -h "$Q4_GGUF" | cut -f1)" >&2 
    CLEANUP_PATHS+=("$Q4_GGUF") 
    exit 1 
fi 

echo "[*] File created: $Q4_GGUF ($(du -h "$Q4_GGUF" | cut -f1))" 


# --- 9. Cleanup --- 
# Do nothing: cleanup() via trap EXIT/INT/TERM will delete 
# contents of CLEANUP_PATHS (if KEEP_INTERMEDIATE != 1). 

echo "[*] Done: $Q4_GGUF" 

exit 0

ls -lh models/Qwen3.5-2B-Q4_K_M.gguf

Should be ~1–1.5 GB (for 2B in Q4_K_M).

./run_llama_mmap.sh -m Qwen3.5-2B-Q4_K_M

In the log — model loaded, and in the UI — a response to "Hello".
