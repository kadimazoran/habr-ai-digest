Hello! We have news: VkusVill has prepared an MCP server with authorization!

The address is the same, mcp.vkusvill.ru/mcp, and to access the full functionality, please register at https://vkusvill.ru/oauth/registration/ and authorize via the link from your agent. More details below.

In December 2025, we released the first version of the public MCP server and have since received many ideas and suggestions through the feedback form. For example, users suggested adding a tool to identify products by barcode, creating custom response fields for the search tool, and opening links in the mobile app.

However, the main issue was that when opening a link from an agent on the website, some products might be unavailable for order. This happens because the search in the public MCP server scans the entire catalog, while when you open a link on the website, you see the assortment of the store from which delivery will be made.

Passing the store as a parameter to the search tool is not suitable, as for some locations, delivery can be from multiple dark stores – the final choice is determined by an algorithm. And this does not bring us closer to giving the agent personalization capabilities (purchase history, loyalty program) and ordering.

Obviously, access to a personal account is needed. And it must meet information security requirements:

– The agent logs in with their own credentials.

– The agent does not have access to the client's personal data.

– The person chooses what they are willing to delegate to the agent.

– The person can revoke access.

These conditions are met by the OAuth 2.0 protocol, which is also the recommended authorization method in the MCP specification.

So, our solution is based on OAuth 2.0 + PKCE and involves the following process:

Step 1: Registering an OAuth Client

To register an authorization client, go to https://vkusvill.ru/oauth/registration/ and follow the instructions.

Currently, it is only possible to create a personal agent — the OAuth client credentials will be linked to the loyalty card of the creator. This means that the created authorization client will only be able to request access to their personal account.

Soon, we will add the ability to register an OAuth client capable of working for multiple people. And, by the way, we are working on a partnership program. Apply if you want to join the testing.

Redirect URI is the address of a web page or application where the VkusVill OAuth server will redirect the temporary authorization code after the user confirms access. Agent platforms have their own redirect URI. Check the documentation and specify it. At the time of writing, the URI for ChatGPT must be obtained from the plugin creation window, for Claude.ai — https://claude.ai/api/mcp/auth_callback. If your agent is on OpenClaw or Hermes, then most likely you do not have a public address that the agent listens to. In this case, select "My service does not have a public URI."

Result: an authorization client linked to your loyalty card is registered in the VkusVill OAuth server.

Step 2: Connecting to the MCP Server and Transferring Credentials to the Agent

After registration, you will receive an email with credentials. These must be transferred to your agent so that it has access to tools under authorization. How to do this can be found from the agent itself or in the documentation. The main thing is never to write credentials in the chat with the agent or transfer them to third parties/untrusted services, as this is sensitive data that grants access to your personal account.

The email will also contain a link where you can revoke access by deleting the authorization client account. At this stage, access is revoked within 24 hours.

Server address: mcp.vkusvill.ru/mcp.

Result: your agent is connected to the VkusVill MCP server and can request authorization.

Step 3: Agent Authorization

Upon the first request to the MCP server, the agent will request authorization. To do this, it will generate a link that the user must follow to select which actions and data will be available to the agent (scopes). After submitting the form, the user and the authorization code will be sent to the redirect URI (specified in step 1). If it was localhost and your agent is deployed in the cloud, you need to copy and transfer the text from the address bar of the page that opened after submission. The agent will exchange the temporary code for a JWT access token, which is valid for 24 hours. This means that at the moment, after this time expires, you need to repeat this step again.

Result: your agent has a JWT access token with the scopes you approved.

Step 4: Using Tools with Authorization

When calling a tool, the agent also passes the JWT access token. The MCP server checks the token's scopes and executes only what was agreed upon. Thus, the agent will not be able to perform an action that the user did not approve in the previous step.

As of today, an authorized agent with maximum scopes has access to:

– The public MCP server tool;

– A tool for searching the catalog relevant to the address set in the VkusVill personal account;

– A tool for viewing online order history;

– A tool for viewing favorite products;

– A tool for viewing personal discounts ("6 discounts").

We will continue to add tools; the current list can be found on the MCP server page mcp.vkusvill.ru/mcp. And your agent, of course, also has a way to request a list of tools (tools/list).

Result: your personal agent is ready to assemble a suitable basket for you.

Conclusion

This release is the minimum viable increment, taking into account your comments and ideas. Simultaneously with expanding the agent's capabilities, we are working on enhancing the security of the client's personal account. This means we will introduce:

– Instant revocation of access
– Automatic access token renewal
– Loyalty program and ordering tools
– Access management panel.

We look forward to your ideas in the feedback form on how to further improve the agent experience when working with the VkusVill MCP server.

Much more is coming! You can learn about updates on the server page mcp.vkusvill.ru/mcp and on our page on github.
