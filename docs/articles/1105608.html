How We Built an AI Agent That Now Develops Products With Us

Not long ago, deciding which method to use for collection processing could send a developer searching through documentation, Stack Overflow, or Habr discussions. Sometimes the answer was there, other times it led to debates about project architecture, the author's qualifications, and their very suitability for the profession... Somewhere amidst these discussions, the required three lines of code were usually hidden. Then AI chats emerged, acting as an 'advanced search engine': clarifying details, showing code, discussing implementation options. You could even ask for a method name, preventing it from becoming processDataFinalReallyFinal. Later, models became better at larger tasks, and instead of hints, developers started receiving complete files. However, if a request for a small function resulted in a five-thousand-line novel, the saved time was spent deciphering it. A missed check might be flagged by a tester with a message like 'A few remarks' and an attachment the size of a technical specification. Code appeared faster, but so did the load on reviews, testing, and maintenance. The developer also became a courier between the chat and the IDE. Now, it's time for agents that, in addition to generating code, can work with project files, perform checks, and automatically deploy services in cloud environments. In this article, we'll share how we built our own AI agent and gradually expanded its scope of tasks. We'll discuss the reasoning behind adding specific features and how their implementation changed project work. Finally, we'll explore how developer thinking has evolved and what remains for humans when writing code, creating tests, and verifying changes can be delegated.

Why Did We Decide to Integrate an AI Agent into Development?

Neural networks are currently a huge hype, but simply wanting to add 'AI' to a product name wasn't enough for us. It's an excellent efficiency booster if used wisely. Quickly getting code is useful, but that code still needs to be reviewed, integrated into the project, and maintained. We wanted to delegate more work, not just get new tasks for ourselves faster.

We all understand: artificial intelligence is already significantly changing development—the classic approach where all code was written manually is becoming a thing of the past. Our team has always been open to new technologies, but we've always approached them with a degree of criticism, understanding that we shouldn't adopt a technology without fully grasping it and knowing the technical debt we might accumulate from its use. Therefore, we decided to say 'yes' to AI integration, but with a condition: we must clearly understand how what we're implementing works; we wanted to minimize the 'magic' effect. Our own agent is not only a development accelerator but also an opportunity to understand what's happening 'under the hood,' and also to customize the tool specifically for our team's requirements.

Our first 'try' was a plugin for automatic test generation using a language model. We started its development in 2024. It worked directly within the IDE and helped write tests, but it didn't have agent capabilities in its first version.

In the fall of the same year, we added a chat with a language model to the plugin. The necessary foundation already existed, so the ability to discuss tasks directly in the IDE was a logical continuation. And in January 2025, we learned about Windsurf's capabilities and decided to develop our own agent for Jetbrains IDE.

Gradually, it became clear that test generation wasn't the only possibility. Our next decision was to enable the plugin to work with files and perform actions: find the necessary code, make changes, and run checks. It was important for us that every team member could use the agent's capabilities. At the same time, the work had to remain a team effort, because working with artificial intelligence alone is simple. The developer has full context, provides prompts, monitors execution, and remembers which tasks are already completed. However, organizing collaborative work so that everyone can use the agent without losing context and understands what colleagues have already done is a more complex task, although the practice of developing according to specifications existed in our team even before the AI agent was created. Since we are accustomed to working in IntelliJ, we chose this IDE as our platform.

How We Expanded the Agent's Capabilities

Let's start with language models. In our agent, you can work with different LLMs: each has its own advantages and limitations, so we didn't want to tie all tasks to a single model. The agent supports all modern models from OpenAI, Anthropic, Google, DeepSeek, etc. It also includes the ability to add models run locally via ollama. New models are released every month, are added to our own aggregator platform on the day of release, and become available in the plugin. You can select a model manually or use the autopilot mode.
