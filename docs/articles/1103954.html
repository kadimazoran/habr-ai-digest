Hello, Habr! On the Kanban board, everything is green. But the designer has been waiting for approval for five days, the developer has been promised to two projects at once, and the new deadline is already impossible to meet. The manager finds out about this last.

Another planning meeting is unlikely to save this. How can you spot problems you don't even know exist?

I've broken down team work into three levels: task, project, and the unknown. I'll show practical rules using the example of the YouGile project management system and three experiments with ChatGPT, where AI helps find problems that aren't visible on Kanban boards.

Level 1. Task: So assignments don't turn into a quest

The board shows tasks like "Authorization," "Refine," and "Urgent."

To avoid wasting time on endless clarifications, four rules are enough.

1. Name tasks so they don't need to be opened

Not "Authorization problem," but "Fix login error after password reset." The name should explain what needs to be done, not just state the topic.

2. Define the result of the work immediately

Each task must have an assignee, a deadline, and a clear acceptance criterion. For example, for fixing authorization, this would be steps to reproduce the error and a description of how the system should work after the fix.

And to ensure employees don't forget to set deadlines, in YouGile, you can make the "Deadline" sticker mandatory when creating a task. You cannot create a new task without it.

3. Discuss work where the task is assigned

Agreements in external messengers get lost, and with them, context and reasons for decisions. Therefore, either transfer the results of discussions to the task or communicate directly within it.

In YouGile, each task is a chat: you can send messages, files, voice messages with transcription, and screencasts. Found a bug? Record your screen and discuss the fix without leaving the task.

4. Document not only decisions but also their reasons

Developers chose one way to fix a bug and rejected another. Six months later, no one remembers why. And the team repeats old mistakes.

Leave arguments in the discussion, and briefly record the outcome in the description. In YouGile, the log additionally shows who changed the assignee, moved deadlines, and moved the task across the board.

We've dealt with individual tasks. Now we need to organize things at the project level: assign responsibilities for processes, sort out work chats, and update instructions.

Level 2. Project: So there's order not just in individual tasks

1. Assign process owners and keep boards up-to-date

Each process should have an owner who monitors the movement of tasks. Agree on unified formatting rules and work stages: what each status means, when a task moves forward, and who is responsible for it.

Check the boards once a week: are there any tasks without assignees, overdue assignments, or work that hasn't changed status for weeks? If a board doesn't reflect the real situation, it's useless for management.

2. Separate general discussions from task work

Don't turn the general project chat into a dumping ground for assignments. Discuss release dates and priorities at the project level, specific edits within tasks, and personal matters in separate conversations.

The main rule: an agreement must turn into action. Decided in a general chat to fix a bug by Friday? Create a task with an assignee and a deadline. Otherwise, in a week, no one will remember who was responsible for what.

3. Make a knowledge base part of the project, not a graveyard of regulations

It's best to keep the knowledge base close to work tasks. For example, in YouGile, you can place it as the first board of the project. There, employees will find instructions, process descriptions, and materials for newcomers.

To prevent the base from turning into a file dump of "Regulation_final_definitely_new," agree on two things:

  • What to move there. Instructions, standards, and decisions that will be useful repeatedly. One-off discussions remain in tasks.

  • Who is responsible for its relevance. Appoint someone responsible for updating instructions. If a process changes, edit the existing page, don't create a new one. In YouGile, previous versions are saved in the version history.

And so that employees don't search for instructions throughout the project, add links to knowledge base pages directly in task chats.

Level 3. The Unknown: How to find problems you don't know about yet

Even if tasks are in order, a manager cannot check hundreds of conversations daily. And problems often appear long before the first missed deadline. Here's how I suggest finding them with AI.

1. Start managing the project through MCP

Sometimes, a task is in the "In Progress" status, but in reality, everyone is waiting for the manager to approve something. How to find these stalled issues without re-reading dozens of chats? I connected ChatGPT to YouGile via MCP and asked it to check what decisions the team was waiting for from Maria, the manager of the demo project.

The AI found three issues: what quantity of welcome kits to approve, how to organize early shipment, and how long to store personal mockups. It added a link to the task for each.

2. Talk to AI like an analyst, not a search engine

Instead of a list of overdue items, ask it to find conflicts in deadlines and personnel. The main thing is not to conclude that the team is overloaded based solely on the number of tasks.

For example, ChatGPT found that on October 7th, from 2 PM to 6 PM, the team is already busy assembling 80 kits. Meanwhile, a new request for 120 kits came in, which would require another four hours of work from the same employees.

The assistant showed the overlap but didn't claim the team was definitely overloaded: there wasn't enough data on some tasks for a final conclusion.

3. Check the consequences before changing deadlines

The client wants 300 kits instead of the original 100, and by October 9th instead of the 16th. But the branded boxes won't arrive until the 12th. I asked ChatGPT to check if it was possible to speed things up. It suggested replacing the packaging for an additional 5400 rubles, organizing an assembly shift for 6000 rubles, and expediting approvals.

Total – 11,400 rubles in preliminary additional costs, not including potential expenses for urgent printing and delivery. But promising the client October 9th is still premature: the new plan needs to be approved first.

Separately, I checked if ChatGPT could change tasks via MCP. I asked it to move three deadlines – the assistant updated the dates and showed the result. In a working project, such changes should only be made after the new schedule is approved.

AI helps find problems that haven't yet made it into reports. But if agreements remain in personal chats, and no one updates tasks, there will be nothing to find. Therefore, it's best to first organize tasks and projects, and only then ask ChatGPT: "What am I missing right now?"
