What is AnythingLLM and Who Needs It

Formally, it's a full-stack open-source application that takes your files, chunks them, stores them in a vector database, and feeds them to a model when needed. Sounds dry, I know. In practice, it's a workspace where documents, chat, and agents live in one window, not scattered across ten tabs and three services.

There are two distributions. Desktop – a one-click installation for Mac, Windows, or Linux. Everything runs on your machine; not a single byte of your documents leaves it. That's it. 'Single-player,' as the documentation explicitly states.

Docker is a different story. The same codebase, but on a server: multi-user mode, invitations, workspace access control, embeddable chat widgets for websites. Want to put an assistant on a client portal under your own logo? You can – but only with the Docker version.

Who needs this? Lawyers with folders of contracts, analysts with data exports, developers with internal documentation, small teams tired of sending PDFs back and forth in messengers. Anyone who has text but doesn't want to feed it to public clouds.

Who doesn't need it? Those looking for 'just a chat without setup.' RAG has a learning curve, and it can be unpleasant: chunking, embeddings, similarity thresholds – at first glance, it's just documentation jargon, not a tool for normal work. The first evening will be spent figuring things out. But the second will be for actual tasks.

Key Features

This is where it gets interesting – over a couple of years, AnythingLLM has really matured.

RAG and Document Handling

The supported formats are straightforward: PDF, DOCX, TXT, web pages, audio via Whisper – all can be uploaded to a workspace and turned into context. But there's a nuance that trips almost everyone up. You can 'attach' a document to a chat – and then its full text is sent to the model's context window. It works fast but doesn't last long: a couple of large files, and the window is full. The second mode is Embed. The file is split into chunks, each chunk is vectorized and sent to the database, and only relevant fragments are included in the prompt. This is RAG in its proper form. Context window full? AnythingLLM automatically chunks the document – no manual intervention needed.

Vector Databases

By default, everything is stored in LanceDB – built-in and private. Vectors don't leave your system unless you explicitly decide otherwise. Not enough? You can connect PGVector, Chroma, Milvus, Pinecone, Qdrant, Weaviate, AstraDB – depending on what you already have in your infrastructure. The entire migration involves changing one environment variable; you won't need to rewrite the application.

Any LLM

Ollama on your graphics card, OpenAI, Anthropic, Google, Azure, Bedrock – the list is long. And there's Generic OpenAI: a universal adapter for any OpenAI-compatible endpoint. Through it, you can connect Bothub; just enter https://openai.bothub.chat/v1, paste your key, select a model from the catalog – and you're good to go.

Agents, Model Router, and Scheduled Jobs

Let's revisit the Model Router – it's actually quite useful. It decides on the fly which model will answer a specific message: a simple question goes to a cheap local model, a legal query goes to a flagship cloud model. You can configure the rules however you like, based on keywords, token count, time of day, or even an embedded image.

Also introduced in 1.13.0 are Scheduled Jobs. An agent runs on a schedule: it gathers the morning briefing, checks email, monitors a website – all without your intervention. A visual constructor replaces cron syntax. A small thing? Yes, but a nice one for those who prefer not to dive into the terminal.

Multimodality and Multi-user Mode

Speech-to-text, text-to-speech, image generation – all are present, but don't expect miracles. A pleasant bonus to the main scenario, nothing more. However, the multi-user mode in Docker is serious business: user invitations, password protection, access control to workspaces and documents, a full API. For a team of five who don't want to buy five subscriptions, it's a compelling argument.

And again, security. In 2026, the infamous CVE-2026-48116 was discovered – a command injection that allowed arbitrary code execution within a Docker container prior to version 1.13.0. The patch is out, but if you're deploying an instance today, start with an update.

Installation: Two Paths

Since the previous section ended with a recommendation to update – here's the version number at the time of writing: 1.19.0. Now, two options, from home to server.

Desktop: Download and Run

The official website offers builds for Mac (Silicon and Intel), Windows, and Linux. It installs like a regular application: download, open, go through a short first-run wizard. There's almost nothing to configure – the built-in LLM is enabled by default and will offer three models for your hardware at startup: the fastest, balanced, and smartest. It downloads them from Hugging Face in GGUF format, with progress shown in the window corner.

For Linux, there's a separate instruction, which I'll provide in full:

curl -fsSL https://cdn.anythingllm.com/latest/installer.sh -o installer.sh
chmod +x installer.sh
./installer.sh

The script downloads the AppImage for your architecture (x64 or arm64), places it in your home directory, creates a menu shortcut, and an apparmor rule to prevent system warnings about an unsigned file. To update, just run the same script again. Three lines, and you have a live client on your computer.

By the way, the built-in engine in recent versions is built on Lemonade – a local server from AMD that runs GGUF via llama.cpp. It's sufficient for trials and personal tasks. With a large document base, however, it will struggle as the machine's resources are limited. An external model solves this problem, discussed below.

Docker: For Servers

The desktop version is great when you're alone. As soon as you need to share the assistant with colleagues or host it on a machine that runs 24/7, you switch to Docker:

export STORAGE_LOCATION=$HOME/anythingllm
mkdir -p $STORAGE_LOCATION
touch "$STORAGE_LOCATION/.env"
docker run -d -p 3001:3001 \
  --cap-add SYS_ADMIN \
  -v ${STORAGE_LOCATION}:/app/server/storage \
  -v ${STORAGE_LOCATION}/.env:/app/server/.env \
  -e STORAGE_DIR="/app/server/storage" \
  mintplexlabs/anythingllm:latest

STORAGE_LOCATION specifies where everything will be stored: the database, documents, and the .env file with keys. The directory is mounted inside the container, so you can kill and recreate the container daily – the storage will persist. The --cap-add SYS_ADMIN flag might look suspicious, and I was wary too. But without it, the built-in headless browser, used for extracting text from web pages, won't start. Container up? Open http://localhost:3001 and create your admin account.

Now, permissions – this is where most people get stuck. The container runs as an unprivileged user 'anythingllm' with UID/GID 1000. If your host user has different IDs, the mounted folder becomes inaccessible: SQLite can't create the database file, and the container will enter an endless restart loop with the error unable to open database file. Paths like /mnt, /data, or /srv are particularly tricky, as they usually belong to root. The fix is a single command before the first start:

sudo chown -R 1000:1000 ${STORAGE_LOCATION}

You can enable the built-in LLM in Docker as well – add -e ENABLE_BUILT_IN_LLM=true to your docker run command. This flag was introduced in version 1.18.0: the container can pull the same GGUF models from Hugging Face and utilize the GPU – NVIDIA via CUDA, AMD and Intel via Vulkan. A nuance: on an already running instance, just adding the flag isn't enough; you'll need to recreate the container. The storage won't be affected. It's fine for getting started, but for production RAG, I still recommend using an external model via a gateway.

What to choose? For trying things out and understanding if it's for you, the desktop version takes about ten minutes. For a team or continuous server use – only Docker: colleague access is built-in, and backups are as simple as copying the STORAGE_LOCATION directory.

Connecting Bothub as an OpenAI-Compatible Provider

First, the API key. It's located in your Bothub personal account: go to the 'For Developers' section, click 'Add Key' – your gateway base URL is also shown there.

Next, AnythingLLM itself. Click the wrench icon in the bottom left corner, then AI Providers → LLM. In the LLM Provider list, select Generic OpenAI – the option that speaks the OpenAI API language with any compatible gateway.

We're interested in three fields:

Field

What to Enter

Base URL

https://openai.bothub.chat/v1

API Key

Your Bothub key

Chat Model Name

Model ID, e.g., gpt-6-astra, claude-opus-5.5, or deepseek-v4.1-flash-1017

Enter the model ID exactly as it appears in the catalog – including dots, hyphens, and date suffixes if they exist. If you provide a 'nearly correct' name, the API will return an error about an unknown model, and you'll spend half an hour searching for a problem that isn't there.

Below, there are two more fields – Token context window and Max tokens (in self-hosted, these are the variables GENERIC_OPEN_AI_MODEL_TOKEN_LIMIT and GENERIC_OPEN_AI_MAX_TOKENS). Fill the first with the model's actual context window – this allows RAG to more confidently stuff the prompt with relevant chunks. The second defaults to 1024, and long answers will be silently truncated. Set it to at least 4096 if the model tends to be verbose.

Click Save and open a workspace – preferably an empty one. Ask a short test question in the chat, wait a few seconds. If it answers, the connection is established. If it throws an authorization error, double-check your key. If it returns a 404, you already know where the problem lies.

The same Generic OpenAI can also be used with local servers – LM Studio at http://localhost:1234/v1, Ollama in compatibility mode at http://localhost:11434/v1, vLLM, OpenRouter. The setup is the same; only the Base URL changes. This is useful when you want to keep some workspaces on your own hardware.

The best part about this setup is that you don't need to touch any code. AnythingLLM automatically formats requests in OpenAI's style, Bothub accepts them, and you can switch models with a single line in the settings. Today, a flagship from Anthropic; tomorrow, a cheap DeepSeek for routine tasks. The provider is in place, the gateway responds. The main thing remains: your documents.

Limitations

Now, let's talk about what's usually omitted in reviews. RAG in AnythingLLM works out of the box. But it works mediocrely. The quality of the answer depends on how you chunk your documents, which embedding model you choose, and what similarity threshold you set. The defaults are a compromise between speed and accuracy, not a solution tailored to your specific task. You'll need to tweak them. And you'll naturally wonder why the model answers with a single paragraph from the middle of a PDF and persistently ignores three others – where the same information is presented in different words.

And that's not even the worst part.

In 2026, a memory leak issue surfaced in agent sessions. Each RAG query in an agent added 100 to 650 megabytes of native memory that wasn't released. For a home experiment, it's fine. For a server with a dozen users, it's a disaster. Patches partially addressed the hole, but the impression remains. Agents in AnythingLLM sometimes behave like an intern given access to production: they try hard, but it's better to have someone supervising.

Security You'd Rather Forget, But Can't

Next, CVEs, and things get less cheerful. In May 2026, several vulnerabilities were patched, two of which are worth remembering. CVE-2026-48116 – RCE via argument injection in ripgrep. If you have the file plugin enabled (and it is by default in the official Docker image), anyone who can send a message to an agent in chat can execute arbitrary commands within the container. Think about it: a chat message leads to a command on your machine. The patch was released in 1.13.0, but if you deployed earlier and haven't updated, you're at risk.

CVE-2026-45403 – path traversal via symbolic links in the same file tool. You copy a folder, and suddenly /etc/passwd is leaked. Also fixed in 1.13.0. Before that, there was an SQL injection in the SQL Agent plugin – any user with access to the agent could execute arbitrary SQL commands on connected databases.

The conclusion is simple but boring: update. And don't expose the Desktop version to the internet – it has no authentication whatsoever. The Docker version also doesn't ask for a password by default until you enable it yourself. An open port without a password is not privacy; it's a lottery.

Hosted Version: Not What It Seems

The cloud-based AnythingLLM looks tempting: fifty dollars a month, and you don't need to deploy anything. But there's a catch. The hosted version lacks a built-in LLM – only external providers are supported. The embedder runs on CPU with strict limits: upload a 5,000-page PDF, and the instance will crash with a 502 error. Custom agents are disabled for security reasons, as are MCP servers. It's okay for a quick start. But for real document work – only Desktop or self-hosted Docker.

Conclusion

AnythingLLM is already a fully functional local knowledge base: RAG, agents, scheduling, multi-user mode. Yes, it had security issues. Yes, memory leaked. Yes, the hosted version is heavily cut down, and the learning curve is still there. And yet, for the 'chat with your documents' scenario, it remains one of the most practical open-source solutions – especially if you connect an external gateway like Bothub and avoid subscription hassles.
