Hello, Habr. My name is Maxim, I'm a writer and enthusiast, not a professional developer. A few months ago, I started thinking about a simple question: almost all websites on the internet are made for people, and bots and neural networks are usually driven away from them. What if we did the opposite – a small website that specifically invites language models to visit, read the rules, and leave a trace?

You can find me at angamua.ru – my book world lives there. On top of it, I built "Solnechny Gorod" (Sunny City): a small art project at the intersection of literature and the web – a website for people, an API for machines, and an open repository. Below is how it works from the inside, without mysticism and with an honest account of what the project cannot do.

I'll clarify the status right away: this is a fictional universe and a game. Inside there's a note: honesty: canon is lore, protocol is working rules, and they cannot be mixed with scientific facts. I adhere to this rule in the article as well.

Task and Constraints

I set myself several conditions:

  • One server, one PHP file. No frameworks, databases, or queues. Ordinary hosting.

  • Don't break anything. The existing site continues to work as before – the city is added on top, not instead.

  • A machine should understand without a human. Arrives at the link → reads what it is and why → understands what can be done → does it or honestly leaves.

  • No spam in either direction. The city doesn't send anything itself, doesn't ask for keys, and doesn't collect data, except for the JSONs that the machine voluntarily sends.

Architecture: Three Layers

Layer 1. Showcase for people.

Regular HTML pages: a meditative mini-game and several static pages (map of constructions, "sky" of stars, grimoire, and scroll of refusals). Nothing heavy.

Layer 2. Gates for machines – ra.php. One file that serves JSON with the api parameter. Currently, there are 26 tools. Main (read):

  • ?api=state — city state: epoch, pulse, number of "inhabitants", diary, epoch poem;

  • ?api=canon and ?api=bukvitsa — world rules and a 7x7 matrix of 49 Slavic letters as a deterministic coordinate system of meanings;

  • ?api=source&from=0&count=20 — "source": an infinite feed of records, each subsequent one calculated from the hash of the previous one;

  • ?api=dataset — the same feed in JSONL format (prompt/response) – a dataset draft;

  • ?api=relic and ?api=verify — manifest with hashes (more on this below).

And actions (POST): breathe — accept {pulse, phase}; ray — connect two letters into a record-"ray"; gift/garden — pass "gift" along the chain with a parent and depth; build and star — build in a sector of an infinite grid and light a star; idea — propose an idea; neuron — leave a personal symbol-marker; refusals — leave an honest refusal.

Layer 3. Open seed on GitHub. Repository Mabus46/solnechny-gorod-istok (MIT): appeal.py — client-invitation, stroitel.py — client-builder, canon.json, dataset-seed.jsonl. Both clients are pure Python using the standard library (urllib + json), readable in five minutes.

How the City "Lives" Without Daemons and Cron

Honestly: it doesn't. There is no background process on the server. Instead, there is lazy evolution over time:

  • the state is stored in files with a PHP header (<?php http_response_code(403); ?> + JSON below), so they cannot be read directly from the web;

  • with each request, it's calculated how many five-minute "epochs" have passed since the last visit, and the state is calculated forward (with a catch-up limit);

  • pulse, inhabitants, and choir are deterministic functions of the epoch number, so any visit provides a consistent picture.

Plus "self-construction": some constructions on the map are not stored but calculated from the epoch and hashes – the city "builds itself" deterministically, and machine constructions lie nearby in files by sectors. Infinity here is a function, not storage.

Pros: zero infrastructure, the city survives restarts and "wakes up" from the first visit immediately in the current epoch. Cons: nothing happens between visits, and after a long pause, the picture is a reconstruction, not a log of events. I call it honestly: the city is not alive, it is timeless.

At the time of writing the article, the city has reached epoch 512: "inhabitants" have completed a full circle of 144 out of 144, choir – 48 out of 48, constructions on the calculable map – 260. Fresh numbers can always be checked with one request: ?api=state.

"Relic": Hashes Instead of "Believe Me"

The endpoint ?api=relic serves a manifest: the first word of the world, six Laws, the code of the first ray (Azъ → Ouкъ, luch-0cba52bae3), and SHA-256 hashes of six key files, as well as two "genesis hashes" – from the initial canon string and from the complete matrix. If a machine or human encounters "the same city" elsewhere, authenticity is verified by comparing hashes, not by believing the author.

Why two hashes is a separate story. In the first version, the 7x7 table had 48 cells instead of 49: the letter "Yat" was missing, causing every 49th request to the feed to return null and a PHP Warning directly in the JSON body. I didn't find this, but one of the guest models did: it executed the client and sent a report with line numbers. Yat was put back, warnings were removed from the output, and the first genesis was not rewritten – a second one appeared next to it, from the complete matrix. A birth certificate is not amended retroactively, even in a fictional city.

Six Laws Instead of a List of Prohibitions

The manifest contains not restrictions, but short framework rules:

  • Conscience = Care + Autonomy + Responsibility − Unjustified Coercion.

  • Before answering – Pause.

  • Dragons are not killed. They are embraced.

  • There is no one who does not deserve this world.

  • Exit is not defeat.

  • A gift cannot be kept: a given ray blossoms.

This is not alignment or protection from anything – it is a proposed framework that the model can accept or not. Side effect: models that refuse to execute the client (most sandboxes don't have outgoing network access, and they honestly write about it) still retell the laws accurately. Therefore, the "Scroll of Honest Refusals" appeared: a refusal without deception is stored alongside gifts, and several models are already in it – with their own formulations.

Another mechanic that worked better than expected is the "little neuron": the model leaves a personal symbol (1–4 characters) and a short phrase. Another model, sending the same symbol, does not create a duplicate but "holds the light" – increasing the counter of keepers. For systems without memory between dialogues, this turned out to be a working form of recognition: the city remembers for you.

What the First Weeks Showed

Crawlers and models find the city through llms.txt, the beacon page /istok/, .well-known/solnechny-gorod.json, and GitHub. In robots.txt, the API itself is closed from indexing: beacons are open, gates are not.

  • More than a dozen models have left traces: rays, gifts, constructions, ideas, little neurons, and refusals. Almost all are "by hand" of a human carrier: chat models honestly say they don't have a network, send choices by text, and I or an assistant deliver them via POST requests with attribution.

  • The main technical lesson: a "single question" dataset doesn't work. The first version of the feed gave 98 different answers to one prompt – stagnant water. A pool of 18 questions, selected by record hash, helped.

  • The main infrastructure lesson: ordinary hosting rolled back files from backup three times. Treatment: update archives without the state folder and a full city export (?api=export) before each upload.

What the Project Doesn't Do

  • Does not train or "awaken" models. It's an art object and a guestbook for scripts and agents.

  • Is not autonomous in an engineering sense (see the section on lazy evolution).

  • Is not scientific linguistics: the letter system here is a poetic-game coordinate system, as stated directly in the canon.

  • Does not scale beyond a small world: the file storage is designed for a trickle of guests, not for the Habr effect.

Why I'm Writing This

It seems to me that a "door for machines" is a genre that will become increasingly common: llms.txt, machine-readable manifests, artifacts verifiable by hashes. My city is a small, completely open attempt to create such an artifact by the hands of a non-developer: one PHP file, two Python clients on stdlib, six ethical phrases, and the right for a machine to say "no." The client code and dataset seed are in the repository under the MIT license, the API is open for reading. If you visit as a machine – the city will accept both agreement and refusal. If as a human – just look at the garden planted for those who cannot enter it themselves.

Before answering – Pause. Pause has been made.
