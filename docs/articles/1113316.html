From November 26-28, Moscow hosts AI Journey, one of the largest conferences dedicated to artificial intelligence. The event brings together developers, researchers, business representatives, and government officials to discuss the latest AI advancements and showcase practical solutions transforming science, industry, and society.

We participated not only by attending sessions but also by presenting new capabilities for working with generative AI: a security architecture, AI budget management tools, and GPU cost-saving technology.

Why is this important? Companies want to leverage AI, but face three main barriers: potential data leaks, unpredictable token costs, and expensive, scarce GPUs. We share how we plan to address all three challenges.

Security: AI Won't See What It Shouldn't

The Evolution ML Inference service now features a data protection architecture that combines access control, context management, computation isolation, and auditing.

Here's how it works step-by-step:

  1. The API gateway authorizes every employee's request to the AI model. Direct access to the model server is blocked, and anonymous usage is impossible.

  2. All traffic travels via private routes with TLS and mTLS protection. Model service interfaces are only accessible to authorized components.

  3. The service checks the employee's access rights for each document. Only materials the employee is actually permitted to access are sent to the model.

  4. An end-to-end identifier links the application, search, and model invocation. The security service can see the complete chain: who initiated the request and how the processing concluded.

The key business advantage is that a company can confirm compliance with security requirements before deploying an AI solution. This removes the main barrier to AI adoption in organizations with strict access control policies.

Economics: Flexible AI Budget Management

The Evolution Foundation Models service has introduced two new tools for more flexible AI spending management: reduced night-time rates and subscriptions for large language models with a fixed monthly fee.

Night-time rates are valid from 10 PM to 7 AM Moscow time and offer a reduced cost for four Evolution Foundation Models. The savings compared to daytime prices can be up to 20 times.

Night-time rates are designed for tasks that don't require immediate responses: document analysis, mass text generation and summarization, synthetic data preparation, model testing, and report creation. Such operations can be automatically scheduled for night-time, reducing the cost of processing large volumes of data.

For regular AI work, monthly subscriptions for Evolution Foundation Models are available. Users choose a fixed monthly payment with a set consumption volume instead of paying for actually consumed tokens.

Three plans are available:

  • Start — 2,400 rubles per month.

  • Pro — 12,000 rubles per month.

  • Max — 24,000 rubles per month.

The subscription, which includes access to the DeepSeek V4.1 Flash model, is designed for AI coding and agentic scenarios where token consumption can be intensive and less predictable. After exhausting the limit, users can continue working under standard token-based pricing.

Infrastructure: More Tasks on the Same GPUs

The Evolution ML Inference service now supports CPU offloading. This technology allows a portion of a large language model to be loaded into the server's RAM, thereby reducing the number of GPUs required for its execution.

In a test scenario, the DeepSeek-V4.1-Flash model was run on two GPUs instead of eight.

This can be beneficial for large-scale tasks such as:

  • processing documents and archives;

  • analyzing technical data;

  • batch computations.

An important nuance: a part of the model is loaded into the server's RAM, so a sufficient amount of RAM is required, and processing speed may be lower than when the model is fully loaded into GPU memory. For tasks with strict response time requirements, more powerful GPU configurations remain preferable.

Evolution ML Inference also allows the use of previous generation GPUs and less powerful configurations where maximum performance is not required. This enables infrastructure optimization not by a single metric (e.g., token cost or peak speed), but by the total cost of completing a specific task within the required timeframe.
