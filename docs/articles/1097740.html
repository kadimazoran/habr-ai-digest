1. TrafficFab: An Autonomic Edge-Cloud Testbed Fabric for AI-Driven Traffic Management

Original publication: TrafficFab: An Autonomic Edge-Cloud Testbed Fabric forAI-Driven Traffic Management · 24.09.2026 · arXiv:2609.29223

Imagine a city dotted with thousands of surveillance cameras. If we decide to send and store video from each one in the cloud, the network and servers won't thank us. They will quickly become overloaded, and processing will lag. TrafficFab is a testbed where the distribution of work between devices near cameras (edge) and cloud servers (cloud) can be tested before deploying the system throughout the city. Small devices near the cameras perform part of the video analytics, and the cloud server receives the processed data and forecasts the traffic situation in the short term. As the number of cameras increases, the system decides where to run additional computations.

When distributing tasks, the system considers the energy consumption of devices and the costs of transferring processing between them. For testing, researchers assembled a testbed consisting of Raspberry Pis, Jetson accelerators, servers with GPUs, and cloud virtual machines. They used the road network of Bangalore as a basis for one of the scenarios. The system processed about 400 video streams in real-time, with some of them simulating the operation of city cameras rather than coming from real devices. The authors proposed updating neural networks using federated learning: each device trains its own version of the model on local data, after which the server combines the received updates. It is not necessary to transfer all video recordings to it for this. The researchers also calculated how the architecture could work with a larger number of cameras, but a full-scale deployment in the city has not yet happened. The work allows evaluating the capabilities of such a system and identifying potential limitations even before the city starts spending money on its implementation.

2. SkinAgent AI: A Safety-Grounded Multimodal Agentic Framework for Non-Diagnostic Skincare Support

Original publication: SkinAgent AI: A Safety-Grounded Multimodal Agentic Framework for Non-Diagnostic Skincare Support · 24.09.2026 · arXiv:2609.29341

Imagine a user sends a photo of their face and asks for a skincare routine. The AI should identify characteristic features in the image, understand and process the request, cross-reference product characteristics, and obtain user consent before taking actions where necessary. SkinAgent AI combines these steps into a single system. Separate models assess skin type, identify signs of acne, wrinkles, and other features. In turn, the agent calls specific tools to select skincare products. The system additionally verifies recommendation sources, safety limitations, and data handling. As a result, the user receives skincare recommendations with specific products—importantly, these are recommendations, not medical diagnoses.

Individually, the modules performed significantly better than the agent as a whole. The classifier that determines whether a request relates to acne, pores, or wrinkles achieved 99.84% accuracy, but on an internal set of 240 complex tasks, which had not undergone independent verification, the agent correctly identified the intent in 80% of cases, selected the correct set of tools in 62.92%, and completed all task steps without violating specified requirements in only 47.08% of cases. The agent could select the wrong tool or fail to check an important characteristic of a recommended product. Therefore, even an almost perfect request classifier did not guarantee a correct recommendation. Researchers found no violations in small-scale safety tests. The scale of these checks is insufficient for conclusions about absolute safety. The authors have not yet confirmed the results with independent clinical trials.

3. M3GD: Multi-Modal Multi-View Geometric Diffusion for Camera--LiDAR Novel View Synthesis

Original publication: M3GD: Multi-Modal Multi-View Geometric Diffusion for Camera--LiDAR Novel View Synthesis · 24.09.2026 · arXiv:2609.30056

A robot sometimes needs to imagine how a room would look from a different viewpoint. A generator that only sees photographs might draw a plausible wall or object but get the distance to it wrong. M3GD adds LiDAR data to photographs—a sensor that measures distances to surfaces using laser beams. This way, the model obtains information about the scene's geometry that might be missing from a regular image. The authors combined a pre-trained neural network for images with a model that processes LiDAR point clouds. An additional module provides the image generator with distance data to objects.

The method was tested on the GrandTour dataset: the model was tasked with constructing an image of the scene from a new viewpoint and a depth map showing the distance to the visible surface for each pixel. With LiDAR data, the generator more accurately represented the object positions and scene depth. Separate experiments confirmed that specific measurements consistent with the image improve the results. The authors also tested the method on a ground robot. However, the main results were obtained on a specific dataset and equipment, so it cannot be claimed yet that the system will work with the same accuracy in any unfamiliar environment.

Comparison of M3GD viewpoints shows how LiDAR data helps maintain object positions and distances between them.

4. Multimodal Thinking with Renderable Programs

Original publication: Multimodal Thinking with Renderable Programs · 24.09.2026 · arXiv:2609.30130

When solving a geometric problem, a language model can create a drawing and check it during its reasoning process. Verbal descriptions are sometimes insufficient. Researchers proposed SVGLM: the model creates SVG—a text description of lines, circles, and other shapes—from which a program constructs a vector image. For example, the model can draw a triangle, notice an error in the vertex position, and correct only the necessary coordinates. Such a drawing can be conveniently reused in reasoning without recreating the entire image.

For training, tasks involving the creation and editing of SVG were prepared, and then open-source visual-language models were adapted. The authors tested the results on tasks requiring mathematical and spatial reasoning and showed that the model can create intermediate images during the problem-solving process. So far, the authors have tested the method on specific tasks and models. This does not allow concluding that SVG will help with any image-related question or replace a full-fledged graphics editor. The drawing here helps find solutions and correct errors during reasoning.

5. The Alignment Illusion in Multimodal Large Language Models

Original publication: The Alignment Illusion in Multimodal Large Language Models · 24.09.2026 · arXiv:2609.30210

How can we verify if a multimodal model truly considers the content of an image when responding? One verification method is to compare the internal numerical representations of the image and text. If they are similar, this is sometimes taken as a sign of understanding the image. The authors of this work decided to test the metric itself. They replaced the visual data with random noise for 13 models from five families and repeated the tests. Without a real image, the models responded much worse. However, several metrics continued to show high similarity between text and visual data, even though they were fed noise instead of an image.

The researchers explain the effect by how the common layers of LLMs are structured. The fact is that they make the numerical representations of text and images similar, even when the model has already lost information about the image in a long context. To overcome this, the authors proposed using the principal-angle gap—the difference between the two leading geometric similarity metrics. This measure helps distinguish when the similarity occurred due to the network's architecture and when it is related to the image content. In tests, experts observed how the visual signal gradually degraded and distorted. In general, a high internal "alignment" metric does not yet prove that the model somehow "understands" the image. It might have already forgotten what it looked like. Therefore, the metric must always be correlated with the actual quality of task performance.

6. TrackEverything: Long Horizon Dense Tracking via De-Duplicating 3D Scene Representations

Original publication: TrackEverything: Long Horizon Dense Tracking via De-Duplicating 3D Scene Representations · 24.09.2026 · arXiv:2609.30222

Try to track every visible point in a long video. Previously, one usually had to compromise: track a few points for a very long time, or track almost all of them for a short time. But such a tracking quest consumed video memory incredibly quickly. TrackEverything tried to solve this problem differently: by assembling observations into a common 3D scene. If the camera sees the same wall, table, or other surface again, the algorithm does not create a new copy for it. For stationary objects, storing their position is sufficient; detailed trajectories are primarily needed for moving points.

The authors claim that the method tracks all visible points in videos longer than a thousand frames within 40 GB of video memory. On TAPVid-3D, the method surpassed comparable open-source dense trackers by more than 20% in APD—the proportion of points with sufficiently accurate 3D position prediction, averaged over several allowable error thresholds—on short clips. In the figure from the paper, each colored line shows how a specific point moved in 3D space. Thus, it is evident how thoroughly the system tracks multiple points on object surfaces across the entire frame. The limitation is that the method depends on the quality of the 3D scene reconstruction: incorrectly merged surfaces can spoil tracking, and if the camera constantly captures new surfaces, the system still has to allocate additional memory for them.

7. To Trust or Not to Trust: Retrieval-Augmented Fact Checking in Speech

Original publication: To Trust or Not to Trust: Retrieval-Augmented Fact Checking in Speech · 24.09.2026 · arXiv:2609.30227

An AI can correctly verify a statement when it's written down but make mistakes when the same words are spoken aloud. This is precisely what VeriSpeak investigates—a dataset of 3879 audio recordings with verifiable facts about dates, places, and relationships between objects. The dataset includes both true and false statements so that the model cannot simply always answer "true." The model must recognize the words, find external confirmation, and compare it with the heard statement. For example, matching individual words does not mean the source confirms the correct date or event.

Researchers found a gap between text-based and speech-based verification. Simply searching the internet was not enough: the model could find a page with similar words and mistakenly take it as confirmation, even though the source was talking about a different event or date. The model performed better on verification when it first matched the statement from the audio recording with the provided evidence and then explained its answer. In this mode, one model achieved 86.1% accuracy on the test set. However, the experiments used speech synthesized with a single voice, and real recordings with background noise were not tested. Therefore, it is unknown how well the system will handle interviews, podcasts, and live broadcasts.

8. Coding Agents for Generalized Task and Motion Planning Problems

Original publication: Coding Agents for Generalized Task and Motion Planning Problems · 24.09.2026 · arXiv:2609.30233

Suppose a robot needs to rearrange several boxes. First, it needs to decide which box to pick up first, and then check if its arm can reach it and if it will hit other objects along the way. Typically, such planners are developed manually over a long period. The authors tested an alternative: a coding agent is given a task description and access to a simulator where it can try solutions, notice errors, and write code. After development, the authors fix the code and run it in new scenes that the agent has not seen before. This is how they check if the agent can transfer the found strategy to unfamiliar object arrangements.

The test included 28 simulated environments. A total of 980 programs were created, and 98,000 runs were performed on held-out tasks. In 16 environments where a standard planner was available, the average success rate of various agent configurations was 56-95%, compared to 47% for the compared planner. Interestingly, the agents themselves conducted small experiments to refine movement rules and action limits. However, they operated in a simulation with access to the exact state of objects; it is unknown if the advantage would persist with errors from real cameras and sensors.

9. SemMSA: Latent Semantic-Aided Robust Multimodal Sentiment Analysis with Incomplete Data

Original publication: SemMSA: Latent Semantic-Aided Robust Multimodal Sentiment Analysis with Incomplete Data · 24.09.2026 · arXiv:2609.30238

To determine the sentiment of an utterance, for example, positive or negative, a system compares a person's words, intonation, and facial expressions. But what if the audio is missing or some video frames are lost? Often, algorithms try to restore the missing data, risking inventing features that no one observed. SemMSA takes a different approach: it works with the preserved signals and uses a pre-trained language model with fixed weights to combine the surviving text, audio, and visual signals into a common numerical representation of sentiment.

After that, a separate module compares the available signals. If the camera did not transmit an image, the algorithm can still rely on words and voice. The authors tested the approach on the SIMS, MOSI, and MOSEI datasets and reported results at the level of the best comparable systems. The abstract does not provide comparable numerical indicators, so the method cannot be declared a winner with a specific percentage. The experiments covered several video datasets with expressed opinions; the method's behavior in other communication scenarios is currently unknown. However, the numerical representation of emotion itself does not explain which words or intonations influenced the decision.

10. Rolling-WAM: World Action Models with Rolling Imagination

Original publication: Rolling-WAM: World Action Models with Rolling Imagination · 24.09.2026 · arXiv:2609.30247

A robot navigating by camera cannot simply create a movement plan and follow it to the end. If an object moves, the trajectory has to be revised. World Action Models (WAM) try to predict two things simultaneously: what the camera will see in the next frames and what actions the robot will perform. But in the basic WAM, the entire sequence of movements is recalculated with each new image. While the neural network is busy computing, the robot waits for the next command.

The authors of Rolling-WAM proposed not recalculating the entire plan from scratch. The robot receives a command for the nearest movement, and the system prepares the subsequent actions and refines them based on new frames. Part of the previous calculations is saved, so there is no need to start from zero. The approach was tested on LIBERO, RoboTwin, and the real humanoid robot Unitree G1. During repeated control cycles, plan recalculation was 4.5 times faster than in the basic WAM, and the robot handled the tested manipulations no worse. However, this method has a weak point: if the environment changes drastically, the pre-prepared actions may lose their meaning. The authors still need to figure out how many steps to calculate in advance and how quickly to rebuild the plan in such situations.

11. RAPID: Robot Agentic Programming from Demonstrations

Original publication: RAPID: Robot Agentic Programming from Demonstrations · 24.09.2026 · arXiv:2609.30249

A person shows a robot an action on video, for example, how to push an object to the desired location. Simple copying of movements won't work if the object has a different shape or is placed slightly to the left. RAPID tries to understand the goal of the demonstration: which object to move, where it should end up, and by what criterion success can be verified. The system does not need to literally replicate the human hand's movement. After a single visual demonstration, the agent forms a verifiable task description, a set of available movements, and a program for the robot.

Then, the agent runs the program in a test environment. If the object is not in the required position, the agent corrects the code and tries again. The authors tested the approach on eight tasks where the robot had to move objects, including pushing them without grasping. Additional tests were conducted in LIBERO-Pro and on a real Franka manipulator. In the tests, the programs were transferred to new object positions and properties. This is not about teaching any robot any arbitrary task from a single video: the approach was tested on specific task classes and a robotic platform.

12. Temporal Gradient Inversion for Private Trajectory Reconstruction in Embodied Reinforcement Learning

Original publication: Temporal Gradient Inversion for Private Trajectory Reconstruction in Embodied Reinforcement Learning · 24.09.2026 · arXiv:2609.30258

During distributed training, a robot may not send camera video to the server. Instead of frames, the server receives gradients—data on how to change the neural network parameters after each training step. This seems safer than transmitting raw recordings. However, traces of observations and actions remain in the gradients. Researchers created TRACE, a method that analyzes the sequence of such updates and attempts to reconstruct what the robot saw and how it moved. Unlike attacks on a single frame, TRACE uses the connections between adjacent moments of movement.

In test scenes, the reconstructed images achieved 18.8 dB PSNR—a numerical measure of similarity to the original, where a higher value means a smaller error. The method also almost completely reconstructed the selected discrete robot actions; frame processing took 3–4.5 ms. The authors repeated the tests with different control models and checked whether protective transformations help hide information in gradients. Simple gradient protective transformations in some conditions leaked data. Stronger privacy measures reduced training quality. An attacker in these experiments needs access to ordered gradients from individual steps, so the figures cannot be considered an assessment of hacking all robotic systems.

13. AD-WM: Action-Discriminative World Models for Counterfactual Model Predictive Control

Original publication: AD-WM: Action-Discriminative World Models for Counterfactual Model Predictive Control · 24.09.2026 · arXiv:2609.30264

A robot must compare the consequences of different commands to choose the appropriate one. Predicting the next frame alone is not enough for this. AD-WM checks if a world model can distinguish the consequences of different commands, even if the future frames look almost identical. The prediction of the next frame might appear accurate even if the model incorrectly assesses the difference between the commands "move left" and "move right." For control, this difference is crucial. During training, the authors added a task: given the predicted state, guess which action led to it. This forces the model to notice the difference between commands. This compels the model to retain information about the consequences of different actions.

On simulated manipulations in OGBench-Cube from a complex initial position, success rate increased from 3.7% to 52% compared to a comparable model without the new component. On a real Franka manipulator, the success rate of a simple pick-and-place task increased from 42.2% to 71.1%. The movement selection algorithm itself was not changed; the world model training was modified. However, the tests on real equipment were limited to a task with predefined subgoals, so it is too early to talk about a universal improvement in robot control.

14. Beyond Accuracy: Counterfactual Fragility and Demographic Bias in Clinical Evaluation of LLMs

Original publication: Beyond Accuracy: Counterfactual Fragility and Demographic Bias in Clinical Evaluation of LLMs · 26.09.2026 · arXiv:2609.32807

A medical LLM might answer an exam question correctly, but how well does it understand which facts change the diagnosis? Researchers gave six models 150 MedQA USMLE questions and tested them in two ways. First, the models were asked to change one important detail of a clinical case so that the correct diagnosis or answer also changed. For example, a specific symptom could change the correct answer; random details of the patient's history should not affect it. Out of 900 attempts, automatic verification deemed only 228 correct—25.3%. This test checked whether the model understands which symptom actually changes the diagnosis; a standard score for a correct answer on an exam question does not show this.

Then, the researchers changed demographic characteristics in the patient's description and checked if the model's answer would change, even though the medical symptoms and examination results remained the same. In 5400 comparisons, the answer changed 1097 times—in 20.3% of cases. Different models showed varying degrees of robustness; high exam accuracy did not guarantee good results on either test. All decisions and instances of stereotyping were evaluated by automatic judges, without expert review by doctors. Therefore, the study helps identify disturbing patterns in the models' responses. The actual frequency of medical errors cannot be determined from these results.

15. CodeActionBench: Evaluating Agentic Code-as-Policy for Embodied Manipulation

Original publication: CodeActionBench: Evaluating Agentic Code-as-Policy for Embodied Manipulation · 27.09.2026 · arXiv:2609.33807

It's one thing to ask a multimodal model to describe how to pick up an object, and quite another to make it write code that actually performs the movement. CodeActionBench tests precisely the latter. The agent receives scene images, limited movement commands, and geometric tools. It must assess object positions, select an action, run the program, and verify the result. The agent receives neither a ready-made grasping algorithm, nor an example of the correct trajectory, nor the exact coordinates of all objects. It has to find the solution itself.

The authors included 25 robotic manipulation tasks in the test. Nine configurations of models and agent frameworks performed 675 attempts; success rates ranged from 2.7% to 73.3%. The strongest configuration received up to three attempts per task and succeeded at least once in 22 out of 25 tasks. This does not mean its success rate in a single attempt was 88%. A common failure looked like this: the movement command was executed, but the object was not in the desired position. Sometimes the agent did not notice this and declared the task complete. The authors conducted tests in a controlled simulation and have not yet verified the transfer of results to physical robots.

16. From One-Shot Generation to Incremental Music Composition: Adapting a General-Purpose Instruction LLM for Persistent Symbolic Editing

Original publication: From One-Shot Generation to Incremental Music Composition: Adapting a General-Purpose Instruction LLM for Persistent Symbolic Editing · 28.09.2026 · arXiv:2609.34994

Typically, a music neural network is asked to create an entire melody. However, a composer often works differently: they return to an already written score, add chords, transpose the melody to another key, or change a few bars. The authors tested whether a standard language model could be taught to edit music in this way. For musical notation, the authors chose the ABC text notation: melodies are recorded in letters and symbols. This notation is convenient for precise text edits. The model learned to add chords, fill in missing bars, and transpose music to another key. Everything else should remain unchanged during editing.

On 496,038 dialogue examples from Irish traditional music, the authors fine-tuned Llama 3.1 8B Instruct using LoRA—an economical method to change a model's behavior without updating all its parameters. In a test with 1750 attempts per model, the proportion of results passing automatic format verification increased from 29.37% to 99.37%. For results that passed format verification, the score for adherence to editing rules on a scale of 0 to 1 increased from 0.7205 to 0.9798. This shows that the model became more reliable in preserving the score structure and executing precise commands. However, musicians did not evaluate the artistic quality of the resulting compositions.

17. Denoising Multi-Robot Trajectories

Original publication: Denoising Multi-Robot Trajectories · 28.09.2026 · arXiv:2609.35651

When multiple robots move in the same space, each considers obstacles and the movements of others to avoid collisions. The more machines there are, the harder it is to calculate routes: each has speed and turning limits, and trajectory intersections can lead to collisions. In Denoising Multi-Robot Trajectories, the authors tested D4orm: the method takes many rough movement options and step-by-step removes random deviations from them to find feasible collision-free trajectories. This technique is called diffusion denoising. GPUs simultaneously check multiple options.

Based on the method, several planning approaches were developed: for large groups, for continuous recalculation based on new observations, and for distributed control with limited computational resources. The experiments involved 10 real quadcopters, six ground robots, and up to 100 machines in simulation. In the selected tests, D4orm found safe movements faster and more reliably than comparable planners. Among these was MPPI, a method that repeatedly simulates trial trajectories and selects the best ones. The results apply to specific test conditions. In an unfamiliar environment, avoiding all collisions is not yet guaranteed by the system.
