Where this calculation ends

The load profile is mine, not universal. With short sessions, a different chat history, or a different TTL, the proportion of reads and writes may change. Then the volumes need to be plugged back into the formula; there is no basis to promise that the gap will necessarily widen.

For GPT, a short price range was chosen. If actual requests go beyond this range, they should be calculated separately, not by applying the base rate to all tokens. The calculation does not include independent costs for tools and subscriptions, nor additional expenses that may arise from retries or route switching.

The main conclusion of this part is simple: I rank by expected expenses for the same set of tokens — the lower the sum, the higher the rank. LiteAI participates with a clearly indicated package estimate, while other gateways use the sum of expenses for individual categories. For my load, this is more useful than comparing a single input price, but a low calculated cost does not yet mean minimal actual expenses for a completed task.
