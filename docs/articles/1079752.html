❯ It's Never Too Late to Learn

The more tasks an agent has, the longer its system prompt becomes, meaning each call to the model costs more. To avoid wasting tokens, instructions can now be broken down into skills — separate blocks for specific tasks.

Each skill consists of three parts: a name, a description of "when to apply," and the instruction itself. Only a compact index is sent in the request, and the full instruction is pulled if the request matches the condition. How Skills Work →

Getting started is simple: take a repetitive task like report generation, define its conditions, and connect it to one agent or several at once.

❯ 1100 Tokens Instead of 295,000

Documentation should be understandable not only for humans but also for agents. Here's what we've done for that.

Gave Agents Plain Text. We added llms.txt and llms-full.txt to the site, followed by an MD version of all documentation. The files turned out to be too large, so we split them into parts. Now, a page uses about 1100 tokens instead of 295,000.

Removed Mid-Sentence Breaks. We increased rate limits so that a series of quick requests doesn't hit the limit, and configured caching with all the headers agents expect to see. Pages are served from the cache, and the task completes successfully.

Unified HTML and MD to a Single Content. We aligned the markup of both versions: agents read exactly what you see, without discrepancies or outdated parts.

❯ Three Tools Instead of a Catalog

If documentation is a guide, then the MCP server is a tool to view, create, modify, and configure your resources. And the tool should also be convenient to use.

To avoid bloating the context and token usage, we've consolidated all Timeweb Cloud MCP capabilities into three tools:

search_tools — find the right operation by task description

get_tool_definition — get its parameters

execute_tool — execute the operation with these parameters

The agent no longer keeps the entire catalog in memory but searches for what's needed for a specific task. The context remains compact regardless of the number of methods — so we were able to significantly expand the list of available actions. How to Connect MCP Server →

❯ Data Varies — and is Stored Differently

Data in S3 can be different: some are accessed every minute, while others sit in reserve for years. Therefore, we've expanded the number of storage classes in S3 — now, when creating a new bucket, you can choose one of three options.

Premium — with triple replication and enhanced performance. Suitable for data that is constantly read and written.

Standard — for files that are accessed regularly, but high access speed is not critical: user uploads, media, and work exports.

Cold — for archives, backups, and datasets that are accessed infrequently.

Already created buckets operate under the previous conditions — no need to migrate or recalculate anything.

Database, You Have a Cancellation

It's easier than you think to delete a cluster by mistake: while tidying up or executing a command in the wrong window. Cloud servers already have deletion cancellation for such cases, and now it's available for databases too.

With deletion protection enabled, a deleted cluster doesn't disappear immediately: it's stored for another 72 hours, during which it can be restored — with data, backups, and configuration. Restoration is free for all database types and in all regions. Conditions and Restoration Procedure →

The cost is ₽200 per month per database. If protection is not enabled, a one-time recovery costs ₽2000.

It's enabled in the cluster settings → "Backups" → "Deletion Cancellation." For new clusters, it can be enabled immediately upon creation.

❯ One App is Good, Two is Better

Now, an application in App Platform can be cloned just like a cloud server. Select the desired one, click the icon on the right, and check the parameters.

By default, everything is the same as the original application. You can change the branch and commit, configuration with region and tariff, private network, name, comment, and project. Environment variables, directory, and build command are transferred automatically.

Where it might be useful:

Users in another region. Deploy a copy closer to them and reduce latency.

Configuration testing. Set up a clone on different resources and compare it with the original — without touching the working application.

Backup. Keep a copy in another location and switch traffic to it when needed.

❯ Web Server Configuration in the App

A user's request doesn't reach the application immediately — it first encounters the web server. Now, its parameters can be configured directly within the application.

Redirects. Redirecting from one path or domain to another. Useful when changing address structures or migrating to a new domain and you don't want to lose search traffic.

HTTP Headers. Add, modify, and remove headers in web server responses: Cache-Control, CORS, CSP, HSTS. Service headers like Server and X-Powered-By can be hidden instead.

Compression. gzip or zstd: less data is transferred, and the page loads faster for the user.

Handling Non-existent Addresses. For frontend applications only — display the main page, as is common in SPA, or your custom 404 page.

Backend Limits. Maximum request body size in kilobytes and response header timeout in milliseconds: heavy requests and hanging connections won't accumulate.

❯ One More Certificate

In App Platform, in addition to Ministry of Digital Development certificates, a second root certificate has appeared — from the TCI Certification Center.

The logic is the same. Without the root certificate, the application doesn't trust TLS certificates issued by this center, and outgoing requests result in a verification error. Now, the certificate is enabled with a toggle — when creating an application or in the settings of an existing one. After the change, the application undergoes a redeployment. More About Certificates →

Works for backend applications and those deployed from Dockerfile or Docker Compose. The two certificates don't interfere with each other: enable both or just the one you need.

❯ Two Ways to Find Everything

Continuing the AI release parade — the knowledge base search now has two modes.

Classic — as it was before: semantic search precedes each query to the knowledge base, and the found fragments are mixed into the model's context. Predictable and fast.

Agentic — the model itself decides when and what to search for: it can clarify the wording, perform multiple searches in a row, and assemble the answer from different parts of the base. For complex queries like "find all products from list X in category Y," the difference in quality is noticeable.

Knowledge bases connected previously remain in classic mode — you can switch in the agent's settings. For new connections, agentic mode is selected by default.

❯ You Can Now Send Files to an Agent

A screenshot with an error, a CSV export, a log file — all of this can now be sent to an agent in two ways.

In Telegram. The file is sent to the chat along with the request: the agent will summarize the CSV or find the error in the screenshot with logs. Useful for those who already have an agent in their support chat.

Via API. Files API is a separate mechanism for working with files in the agent API, without the previous format and size limitations. The scheme is simple: your service user attached a file in the chat → the service passed it to the agent via API → the agent responded considering the file's content.
