Which AI Talks Were Most Memorable

Out of all the presentations, I particularly highlighted three talks for myself. I liked them primarily because the speakers demonstrated the application of artificial intelligence to solve real problems, not just showcase the capabilities of neural networks.

1. "Chat Instead of Forms: 1C Business Automation Based on AI and MCP Servers" — Vladimir Kharin

An interesting idea is to use AI not only for writing code but also directly for user interaction with the information system.

Instead of the usual forms and tools, a user can interact with the system through chat, and the AI, using an MCP server, can interact with the 1C tools and functions available to it.

This results in a completely different approach to organizing the user interface: a person formulates a task in natural language, and the system performs the necessary actions.

What's interesting to me here is that AI is no longer just a developer's assistant but a tool for automating business processes. Moreover, this approach can potentially be applied to a wide variety of user scenarios where many actions currently require manual execution.

2. "How to Make AI Write Useful Unit Tests for 1C, Not Confident Nonsense" — Artem Kuznetsov

Code generation using neural networks no longer surprises anyone. But automatic test creation is a bit more complicated.

AI can write a test that looks quite convincing and even runs successfully. But this doesn't guarantee that it actually checks what it's supposed to.

The talk addressed issues of context for the model, the quality of generated tests, and verification of the obtained result.

In my opinion, this is one of the important aspects of working with AI: it's not enough to just get ready-made code. You need to know how to set the task correctly, provide the necessary information, and ensure that the result meets expectations.

Especially when it comes to testing, where an error in the test itself can create a false sense that everything is fine with the program.

3. "AI is Everywhere. But Where Exactly? We Built an AI Agent for 1C Code Review and Successfully Integrated It into the Process" — Maxim Kulbarakov

This talk interested me primarily because of the practical application of AI in existing development processes.

The focus of the presentation is the experience of creating an AI agent for 1C code review and its integration into the team's workflow.

I liked the problem statement itself. Instead of using a neural network on a case-by-case basis, you can embed it into a specific development stage and automate some repetitive checks.

This is a completely different level of AI application: not a one-off experiment, but a tool that becomes part of the workflow.

For me, such cases are especially valuable because they show the direction in which one can develop their own tools and company infrastructure.

More about the talk

All three presentations share one idea: artificial intelligence can already be used to solve practical problems, and not just in code development.

Hackathon: When AI Needs to Solve a Real Problem

Another interesting format was the hackathon "Vibe Coders Battle: Who Will Tame the Configuration", organized by Dmitry Kotov.

Participants had to solve a practical problem using "1C:Trade Management 11.5" and AI tools within a limited time. Moreover, the conditions could change during the work.

In this format, it's no longer enough to just ask a neural network to write code. You need to organize work with the tools correctly, consider the configuration limitations, react to changing requirements, and verify the obtained result.

I liked the idea of such a competition: AI capabilities are tested not in ideal demonstration conditions, but on a specific task with time constraints and the need to get a working result.

Such formats well demonstrate that AI can be a serious assistant to a developer, but it doesn't eliminate the need to understand the architecture, logic, and specifics of the system.

Interactive Battle: Optimizing Code Under Time Pressure

In addition to my talk, I conducted an author's activity at the "Infostart Training" booth.

Essence of the interactive: Participants were given a tool with extremely unoptimized and poor code. Their task was to optimize it as much as possible within a limited time, after which the result was compared with my version.

  • Stakes: 1 to 5. If the participant won, they received 5 coins of the conference's internal currency (StartMoney).

  • Win-win situation: Even if the participant lost, they still benefited – I showed my solution and analyzed their mistakes, imparting new knowledge.

The activity caused a real buzz – a whole queue of people wanting to test their skills lined up! Participants' screens were broadcast on large TVs, a crowd of spectators gathered around, enthusiastically cheering, giving hints, and discussing solutions.

For me, this was also an invaluable experience: when participants surpassed my solution, we thoroughly analyzed their code, and I learned alongside them.
