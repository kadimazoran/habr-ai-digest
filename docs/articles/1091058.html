What kind of bot is it and how does it respond

The stack is simple: Python 3.12, aiogram 3 in long-polling mode (the bot itself fetches updates from Telegram, no incoming ports needed), the claude-sonnet-5-5 model via the official SDK, SQLite for user logs. The bot runs in Docker on a small VPS where my other bots also reside, so extra memory and new services were a problem for me.

The corpus of materials is stored in a repository as markdown files. At startup, the bot splits them into "pages" of approximately 4500 characters each, respecting paragraph boundaries (constant TARGET_PAGE_CHARS), and builds an index for full-text SQLite FTS5 search from them. At the time of the last measurement, the index contained 53 materials and 630 pages.

Next, a standard tool-use loop operates. The model doesn't see the entire database; it only has two tools: search_materials(query, k) and read_page(page_id). It formulates the query itself, gets a list of pages, reads those that seem relevant, and responds strictly based on what it read. The system prompt (persona plus material map) is cached by Anthropic via cache_control.

I didn't even try to put everything into the context: after cleaning, the corpus occupies about 2.25 million characters, which is about a million tokens, and even if it fit into the window, I didn't want to pay for it with every response.

A separate note on grounding. Prompt rules alone were not enough: in response to a clarifying question ("so this is normal?"), the model once answered from the chat history without referring to search at all, and missed the expert's caveats. Therefore, the code includes a safeguard: if the model is about to answer without ever calling search_materials, the code discards the answer and restarts the turn with a system message "search the materials first." A forced tool_choice for Sonnet 5.5 rejects this with a 400 error, so the safeguard only nudges the model and guarantees nothing. After implementing the safeguard, in seven test pairs of "question clarification," the number of responses without search dropped from one to zero.

Everything else in the article is about how the search_materials tool finds pages.

First search version and why it didn't work

Initially, I used FTS5. The query is broken down into words, stop words are removed, the rest are joined with OR, and results are ranked by bm25. In a mini-test of eight questions, it all worked: 8 out of 8. Then a complaint came in: a user asked something like "I'm looking through the materials, but nothing is sticking in my head, what should I do?", and the relevant page with the answer wasn't found at all. The page described the process using words like "received, understood, accepted, applied," but these words weren't in the question. FTS5 searches by words, and a conversational question with the author's terminology doesn't match. Changing the model didn't fix this: I tested both Sonnet and Opus, and both failed to retrieve the material because they had nothing to search with.

That first mini-test, as I later realized, was unfair: the questions in it were phrased close to the material titles, something like "Why is product X harmful?" for a file with the same title. Real people don't write like that.

Test stand: how I measured quality

Before changing anything, I built a test stand because without numbers, I wouldn't be able to distinguish search improvement from my own impression. The stand consists of a file with cases and a script that runs them through the selected search mode.

A case is a question, a list of materials where the answer is located, and a type:

  • lexical: the question contains words from the relevant material; FTS5 should handle it; this is a safeguard against regression;

  • semantic: the answer exists in the material but is phrased differently; this is the blind spot;

  • negative: the answer is not in the corpus, and the bot's correct behavior is to refer the user to the expert. Such cases are not counted in the metrics; I only read them visually.

There were 24 cases in total: 8 lexical, 12 semantic, and 4 negative. The main rule for selection: I wrote all questions before looking at the corpus, using conversational language, with typos and slang, and only then searched for where the answer was located.
