What I Calculated

I took a month of typical agent work as a baseline: 492 million new input tokens, 2.3 billion tokens read from cache, 10 million output tokens, and approximately 25,000 requests. Clearly, everyone's consumption model is different; this is an average. But it highlights one thing that's easy to miss: 82% of the total volume is cache. On average, a request weighs about 112,000 tokens, and almost all of it has been sent before.

Here's how I calculated: I multiplied the volume of each token type by the price per million. Cache writes, which Anthropic and OpenAI charge for separately, are not included in the calculation, so for Claude and GPT, the actual amount will be higher. For Opus 5 with a standard five-minute TTL, a quarter surcharge on the input price would add approximately $615. With an hourly TTL, writes cost twice as much as normal input and would add $2,460 (Anthropic documentation on caching).

How Cache Changes Cost

Previously, saving tokens looked like this: shorten the prompt, remove unnecessary parts, some even removed spaces and letters from the prompt. Now, this is not enough. The model remembers nothing between calls, and the harness—Claude Code, OpenCode, Cursor—sends it the system prompt, tool descriptions, and history again at every turn. However, providers offer a significant discount for re-reading the same prompt start. For most Anthropic models, reading from cache costs 0.1 of the input price, and for Fable 5.1, it's 0.025; OpenAI's discount reaches 90% (OpenAI documentation). A large but stable prompt can be cheaper than a small one that constantly changes.

I checked how much the harness sends without our intervention on Claude Code. A just-launched session already occupied about 45,000 tokens: system prompt, tools, memory files. One word "hello" used another 18,000. The cost is determined not by what I typed, but by what the agent actually transmitted. The model itself doesn't store the dialogue: the state lives in the harness, and on the next turn, it sends the current context again—the initial history or its compressed version. If the harness didn't send something, the model doesn't know about it. I wrote separately about why a large context window doesn't solve the memory problem.

Hence, the rules that really save money:

  • Cache works on matching prefixes. If you change something at the beginning, everything after it costs full price again.

  • Do not change the prompt prefix mid-session. Do not reconnect MCP servers or edit rules that are part of the system prompt: Anthropic invalidates the entire cache when tool descriptions change.

  • Connect MCP servers and skills at the project level, not globally. Their descriptions are sent with every call.

  • Monitor TTL. Anthropic API has a standard TTL of five minutes, extended to one hour. In Claude Code with a Pro or Max subscription, within the included limit, user turns and some service requests automatically get an hourly TTL. When switching to usage credits, they revert to five minutes unless you explicitly set promptCacheTtl: 1h (Claude Code documentation). For GPT-5.6 and newer OpenAI models, the minimum TTL is 30 minutes. Cache is still not permanent memory: after a long break, the prompt prefix will have to be written again.

  • Do not blindly cut the stable part of the prompt. The agent will lack context, start reading files, and calling tools, and the final session cost will increase.

Based on my Claude Code statistics, the caching profile is even more pronounced: 98% of all tokens are reads from cache. This is precisely why the numbers diverge so much further down.

With GLM Coding Plan from Z.ai, we can calculate more precisely because the credit formula is published. Our month on GLM-5.3 is approximately 174,000 credits per week during peak hours. Off-peak, credits are debited twice as slowly, and Z.ai's peak coincides with DeepSeek's morning window: 09:00–13:00 Moscow time on weekdays. The Max plan for $168 provides 140,000 credits per week: if working off-peak, one is enough; if only during peak hours, two are needed, i.e., $336. I didn't calculate Ollama Cloud in August because they didn't have figures. Since August 31, they switched to dollar-based credits: Pro for $20 gives $60 of usage per month, Max for $100 gives $300. That is, the subscription provides three times more than it costs.

Claude Code and Codex

The most generous limits are currently with Claude Code. Anthropic does not publish them in tokens, so I can only rely on built-in statistics. I have a Max 20x subscription for $200; the Claude Code usage shown was more than a hundred times the subscription price in API equivalent over the last two months. This is a personal consumption profile, not a tariff promise. Until September 13, there was a promotion: the weekly limit in Claude Code was 50% higher. Since September 14, it remains 25% higher than it was before the promotion.

I wrote separately about my switch from Claude Code to Hermes Agent.

Next in generosity is Codex. OpenAI publishes limits in messages per five hours; there's nothing about tokens, and they themselves state these are estimates, not fixed limits. Therefore, precise calculation is impossible, only estimation. Based on my estimate, our month on GPT-5.6 Sol requires four Pro 5x subscriptions for $100 or one Pro 20x for $200. However, OpenAI temporarily suspended new subscriptions and upgrades to Pro 20x starting September 10. For Luna, a Plus for $20 is sufficient.

The situation with Cursor is different. Third-party models there are charged at API prices, and the amount of usage included in the plan is no longer stated on the official pages. For our volumes, Cursor costs about the same as API, and on Teams plans, an additional $0.25 is added per million tokens.

Why this is not permanent is clear from the same figures. Companies cannot indefinitely sponsor thousands of dollars per month for each user. Prices, promotions, and limits have already changed several times; subscriptions are holding steady for now. At the meetup, I said that limits would gradually decrease and prices would increase.

Benchmarks and Price

I tried to relate price to quality: I took LiveBench, SWE-Bench Pro, and Terminal-Bench 2.1, compared each model with GPT-5.6 Sol, and recalculated the cost using the resulting coefficient. A fair coefficient was not achieved: models were run with different harnesses in Terminal-Bench, some models lack results for one of the tests, and the names in the tables refer to different versions and effort levels. Therefore, I did not publish the "price adjusted for quality." Benchmarks help choose candidates for your own testing, but they do not translate quality into dollars.

How I Choose a Model Now

For everyday work—writing code from a given specification, fixing bugs, debugging—you don't need the smartest model. GPT-5.6 Luna and DeepSeek 4 Flash handle this excellently and cost tens of times less than flagships. Documentation, architecture, and complex analytics are better handled by Opus or Sol. I also use a combination: first, a cheaper model writes a document, then Opus corrects it. In such tasks, the expensive model receives already assembled context instead of starting from scratch.

If paying out of pocket, subscriptions for Claude and Codex for complex tasks and cheap models via API or through OpenCode Go for routine work are currently the most profitable. GLM Coding Plan and Ollama Cloud are also good, especially if most of the work is not done in the morning. Who this won't suit: those who need predictability. Subscription limits are not published and change; prices from Chinese providers depend on the hour, and promotional prices like Sol's will end in November.

Conclusions

  1. A typical month of working with an agent involves billions of tokens, and most of them are repeatedly sent context. Therefore, comparing providers by a single input price is meaningless.

  2. You should monitor the cache hit rate, not the number of tokens. Anything that changes the prompt prefix mid-session costs the full price for all accumulated context.

  3. Sol has become cheaper, DeepSeek introduced peak tariffs, but the gap between the most expensive and cheapest models is still tenfold.

  4. Subscription limits in requests are misleading: they are calculated for light requests. Convert your API usage to dollars and divide by the dollar limit.

  5. Anthropic and OpenAI subscriptions currently offer tens of times more value than they cost, but their limits are not published and may change at any moment.

  6. Do not turn disparate benchmarks into a single "quality coefficient": the accuracy of such a number will be illusory.

  7. The model is chosen based on the task: a cheap one for routine work, an expensive one for tasks where intelligence is truly needed.
