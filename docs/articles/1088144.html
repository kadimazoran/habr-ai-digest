I counted from five weeks of logs which markdown files the agent opened. I call the entry point the means by which the agent is launched for a task: slash command files in .claude/commands and descriptions of sub-agents in .claude/agents. Documents named in the entry point were opened by the agent an average of 12.3 times.

How to count from Claude Code logs which markdown files the agent opened

Logs are stored locally in ~/.claude/projects/ in jsonl format, recording every tool call. Over five weeks, 112 sessions and 472 sub-agent launches were recorded. I will refer to any of these as a launch; there are 584 in total.

The script counts .md file openings via Read and via cat, head, tail, sed in Bash. The path is taken from the repository root so that identically named README.md files from different folders do not merge into a single counter. The list of documents comes from git ls-files. A file is grouped as linked if the entry point mentions its path or name. Another case is a path template like guides/{topic}.md: then all files in the folder go into this group. CLAUDE.md itself is not included in any group; it is loaded without links.

import glob, json, os, re, subprocess
from collections import Counter

REPO = os.getcwd() + "/"
LOGS = os.path.expanduser("~/.claude/projects/" + re.sub(r"[^A-Za-z0-9]", "-", REPO.rstrip("/")))
SHELL_READ = re.compile(r"(?:cat|head|tail|sed -n \S+)(?: -\S+)*\s+\"?([^\s"|;]+\.md)")

reads = Counter()
for path in glob.glob(LOGS + "/**/*.jsonl", recursive=True):
    for line in open(path, errors="ignore"):
        if '"tool_use"' not in line:
            continue
        for b in json.loads(line).get("message", {}).get("content") or []:
            if not isinstance(b, dict) or b.get("type") != "tool_use":
                continue
            args = b.get("input", {})
            files = ([args.get("file_path", "")] if b["name"] == "Read"
                     else SHELL_READ.findall(args.get("command", "")) if b["name"] == "Bash" else [])
            for f in files:
                f = f if f.startswith("/") else REPO + f
                if f.startswith(REPO) and f.endswith(".md"):
                    reads[f[len(REPO):]] += 1

git = ["git", "-c", "core.quotePath=off", "ls-files", "-z", "*.md"]
docs = subprocess.run(git, capture_output=True, text=True).stdout.split("\0")[:-1]
entry = [d for d in docs if d.startswith((".claude/commands/", ".claude/agents/"))]
entry_text = "".join(open(d).read() for d in entry)
templates = re.findall(r"([\w.-]+)/\{[^}]+\}\.md", entry_text)   # guides/{тема}.md

def named_in(d, text):
    return d in text or os.path.basename(d) in text

linked = [d for d in docs if d not in entry + ["CLAUDE.md"] and (named_in(d, entry_text)
          or os.path.basename(os.path.dirname(d)) in templates)]
claude_md = open("CLAUDE.md").read() if os.path.exists("CLAUDE.md") else ""
toc_only = [d for d in docs if d not in entry + linked + ["CLAUDE.md"] and named_in(d, claude_md)]
orphans = [d for d in docs if d not in entry + linked + toc_only + ["CLAUDE.md"]]
for name, group in [("точки входа", entry), ("названы в точке входа", linked),
                    ("только в оглавлении CLAUDE.md", toc_only), ("без ссылки", orphans)]:
    avg = sum(reads[d] for d in group) / len(group) if group else 0
    print(name, len(group), "файлов, в среднем", round(avg, 1))
print("ни разу не открыты:", *[d for d in orphans if reads[d] == 0], sep="\n  ")

Most often, the agent opened documents named in the entry point: there are 53 such files, with an average of 12.3 openings. Files that no one references have an average of 1.2.

A link from the entry point looks like a regular string in a slash command file, for example: Before the visuals stage, read docs/visuals.md. Files named this way account for those 12.3 openings.

README.md in the root was opened 6 times across 584 launches. It is written for a newcomer, but no one showed it to the agent.

Among the files without links, there were exceptions: one was opened 15 times, and two others 11 times each. All three have names directly related to the task. Perhaps the agent found them by name, but this is not visible in the logs.

A human reads a document when it's needed: during onboarding, when debugging a bug. The agent starts each launch with a clean context and only knows about the project what it received in that launch. Therefore, documentation moves from the end of the cycle to the beginning and becomes part of the entry setup: which files the agent will see at the start, which it will receive via a link, and which it will not receive at all.

What Claude Code puts into context itself, without a link

CLAUDE.md is loaded entirely at the beginning of each session; imports via @ come with it. Rules from .claude/rules with the paths: field are pulled when the agent works with relevant files, and only the description of a skill is always visible in the context. The agent reads the rest if it's prompted. Constant loading has a cost: the model's response degrades as the input grows, so an extra file in CLAUDE.md hinders every launch.

Why studies on AGENTS.md differ in assessing usefulness

A study on 10 repositories found that with AGENTS.md, the median task time was 28.64% lower. ETH Zürich on a different set of tasks saw no increase in the proportion of solved tasks, and the inference cost increased by more than 20%. The first study looked at the speed of edits, the second at whether the task was solved. They agree on one thing: the agent executes instructions from the file, but a repository overview does not help it. If AI is used for documentation in the most common way, asking the model to describe the repository, you get exactly such an overview.

How to decide what documentation will be included in the agent's context

  1. Keep CLAUDE.md short: only what the agent will fail without. Anthropic recommends up to 200 lines. Mine grew to about two hundred lines, and I still need to shorten it.

  2. Provide the rest via a link at the moment it's needed: from a slash command, sub-agent description, skill, or rule with paths:. Write the skill description as a trigger condition, as the agent decides whether to call the skill based on it.

  3. Do not delete a file without an incoming link immediately; first, check it in the log. I have three such files opened 15, 11, and 11 times; it's better to link them to a command.

  4. Transfer a rule that must not be forgotten to a hook: it checks every tool call. CLAUDE.md does not guarantee execution.

  5. Run the script above once a month: the last line prints files that the agent has never opened. The month is not chosen randomly: by default, Claude Code stores logs for 30 days, which is the cleanupPeriodDays setting.

  6. Provide documentation for external libraries at the moment of call. Among AI tools for vibe coding, Context7 does this, and the library's website can provide it to the model in llms.txt format.

Why logs from one project don't prove that the link itself works

This is a correlation: files needed for the task are named in the entry point, and part of the difference is explained by this. Counting via Bash doesn't catch all reads; I didn't count grep operations on files. The project is one, and the agent is also one.
