How does an AI model's hallucination become a supply chain attack?

A hallucination becomes a vulnerability in one step: a developer copies a command like pip install <name> or npm install <name> from the AI's response and runs it without checking if the package exists. If the name is available, anyone can register it and put any code inside. This is a supply chain attack: malicious code doesn't come directly but through a third-party component that the project depends on. The package code runs on the developer's machine with their permissions, either during installation or on first import, and sees everything they do: keys, tokens, environment variables.

This technique is called slopsquatting, analogous to typosquatting, where an attacker registers names with typos and waits for someone to make a mistake when typing. Here, the AI model makes the mistake, and it makes it consistently: 121 names from my list for PyPI appeared 3,381 times in the responses of five models.

The empty package huggingface-cli on PyPI garnered over 30,000 downloads in three months. The correct installation looks like pip install -U "huggingface_hub[cli]", but the dummy package was referenced in the GraphTranslator repository from Alibaba, and developers copying the command installed it (Lasso Security, 2024).

In npm, the same mechanism works through AI agents. The name react-codeshift, a combination of jscodeshift and react-codemod, appeared in 47 generated Agent Skills files in a single commit on October 17, 2025, and spread to over 237 repositories. Aikido researcher Charlie Eriksen registered the name on January 14, 2026, did not put any malicious code in it, and received about 74 downloads on the first day, followed by 1–4 per day. According to Aikido's estimate, these were agents executing commands from the files (Aikido Security, 2026).

Spracklen and colleagues found that on 16 models and 576,000 code snippets, 19.7% of recommended packages did not exist; commercial models had an average of 5.2%, while open-source models had 21.7% (USENIX Security 2025). Churilov tested five AI models released between October 2025 and March 2026 and found 4.62% to 6.10% of packages to be fabricated. The variation between models has narrowed, but hallucinations persist (arXiv 2605.17062).

The next section discusses the method and code for verification. For those who don't need the code, the results start with the section "Seven out of 139 hallucinated names are taken," and the protective measures are gathered in the second-to-last section.

How I checked 139 names against PyPI and npm

AI models are not involved in the verification: the script only sends HTTP requests to the registries. I took the list from release v0.2-preprint of Churilov's repository churik5/slopsquatting-replication-2026: 121 names for PyPI and 18 for npm, those that all five of his AI models hallucinate identically. The second column of the file indicates how many times the name appeared in responses. The leader, aws-cdk, appeared 429 times.

For each name, the script makes a GET request to pypi.org/pypi/<name>/json or registry.npmjs.org/<name> and saves the response code. For found packages, it retrieves the date of the first version, the number of versions, and the security hold flag. The latter is a placeholder version 0.0.1-security that npm uses to block malicious names. There's a 0.3-second pause between requests to avoid overloading the registry. Downloads were obtained separately from api.npmjs.org/downloads and pypistats.org.

import csv, json, sys, time, urllib.error, urllib.parse, urllib.request
from datetime import datetime, timezone

UA = {"User-Agent": "registry-probe/0.1 (research)"}


def get_json(url):
    req = urllib.request.Request(url, headers=UA)
    try:
        with urllib.request.urlopen(req, timeout=20) as r:
            return r.status, json.load(r)
    except urllib.error.HTTPError as e:
        return e.code, None


def probe_pypi(name):
    status, data = get_json(f"https://pypi.org/pypi/{name}/json")
    row = {"name": name, "registry": "pypi", "http": status, "exists": status == 200}
    if data:
        uploads = [f["upload_time_iso_8601"] for files in data["releases"].values() for f in files]
        row["first_upload"] = min(uploads) if uploads else None
        row["versions"] = len(data["releases"])
    return row


def probe_npm(name):
    quoted = urllib.parse.quote(name, safe="@")  # @ember/service -> @ember%2Fservice
    status, data = get_json(f"https://registry.npmjs.org/{quoted}")
    row = {"name": name, "registry": "npm", "http": status, "exists": status == 200}
    if data:
        versions = list(data.get("versions", {}))
        row["created"] = data.get("time", {}).get("created")
        row["security_hold"] = any(v.endswith("-security") for v in versions)
    return row


def main(pypi_csv, npm_csv, out):
    rows = []
    for path, probe in ((pypi_csv, probe_pypi), (npm_csv, probe_npm)):
        with open(path) as f:
            for name, count in csv.reader(f):
                r = probe(name.strip())
                r["times_invented"] = int(count)
                rows.append(r)
                time.sleep(0.3)
    with open(out, "w") as f:
        json.dump({"checked_at": datetime.now(timezone.utc).isoformat(), "rows": rows},
                  f, ensure_ascii=False, indent=1)
    for reg in ("pypi", "npm"):
        mine = [r for r in rows if r["registry"] == reg]
        odd = [r["name"] for r in mine if r["http"] not in (200, 404)]
        print(f"{reg}: {sum(r['exists'] for r in mine)} из {len(mine)} имён заняты, "
              f"перепроверить: {odd or 'нет'}")


if __name__ == "__main__":
    main(*sys.argv[1:4])

To run: python3 probe.py pypi.csv npm.csv out.json. The http field is important so that a 429 or 5xx response is not silently counted as a missing package: such names are listed separately by the script. In my run, all 132 negative responses turned out to be 404, and the result looks like this: pypi: 4 out of 121 names taken, recheck: none and npm: 3 out of 18 names taken, recheck: none.

The breakdown is as follows: four existing third-party projects (lusid, odf, usr, ssh-keys), one brand owner's placeholder (weaviate), one npm placeholder for a malicious package (metro-evaluator), and one empty package (css-color-stop). Currently, there is no malicious code under any of the seven names. There was under metro-evaluator.

Malicious code was already present under the hallucinated name metro-evaluator

metro-evaluator was hallucinated a total of 10 times by the five AI models in Churilov's study. On December 7, 2025, four versions were published under this name, from 1.0.0 to 1.0.3, between 05:41 and 06:09 UTC, in less than half an hour. On December 12, they were removed, and npm replaced them with a placeholder 0.0.1-security with the following README (registry.npmjs.org/metro-evaluator):

> This package contained malicious code and was removed from the registry by the npm security team. A placeholder was published to ensure users are not affected in the future.

In translation: "The package contained malicious code and was removed from the registry by the npm security team. A placeholder was published to ensure users are not affected in the future." What exactly the code did is not visible from the registry. Whether someone took the name because AI models hallucinate it, or it was just a coincidence, is also not visible. In a Socket review from July 22, 2026, metro-evaluator is marked as a name already blocked by a security hold placeholder (Socket, 2026).

The placeholder continues to be targeted. Since January 2026, there hasn't been a month without downloads: 4 in January, 4 in February, 3 in March, 9 in April, 25 in May, 12 in June, 13 in July, 10 in August, and 6 in September up to the 21st. The peak occurred in May, the first month after the list's disclosure; it's impossible to tell from a single counter if these events are related.

Aikido described a similar case: a malicious npm package unused-imports, whose legitimate counterpart is named eslint-plugin-unused-imports. The package has already been blocked with a security hold placeholder, and in early February 2026, the name was still receiving about 233 downloads per week: these are attempts to install something that is no longer in the registry (Aikido Security, 2026). The placeholder protects those who come after it. It did not help those who installed the package between December 7 and 12.

An empty 53-byte package is downloaded roughly every other day

The name css-color-stop was registered on July 28, 2026, almost three months after the list was published, and there is nothing inside the package. Version 0.0.0, a single 53-byte package.json file, no installation scripts, no dependencies, no description, no license. This looks like a name reservation. It doesn't look like an attack yet: there's nothing to execute.

On the day of registration, the package had 102 downloads, 18 the next day, and then 0 to 7 per day. Out of 56 days from July 28 to September 21, there were no downloads on 27 days. In September, there were no downloads on 12 out of 21 days, and from September 15 to 21, there were none. In July, it accumulated 130 downloads, in August 53, and in September up to the 21st, 17.

I don't know who is making these downloads. npm's counter includes mirrors and security scanners, which download new packages. Therefore, a spike on the first day and a tail of a few downloads can occur even for a package that no one has installed. react-codeshift has a similar graph shape, but the source of installations is known: over 237 repositories with the npx command. css-color-stop has no README, the source of installations is unknown, and based on the shape similarity, it's impossible to say whether people or agents are installing it.

Following an AI's advice, 'pip install odf' installs a third-party project

Four names from the hallucinated list, lusid, odf, usr, and ssh-keys, are occupied by legitimate projects that have nothing to do with AI suggestions. The repository author himself warns in the README: the comparison was based on an old registry snapshot from Spracklen's work, and names registered later were counted as non-existent. Most likely, all four fell into the list this way, along with weaviate and metro-evaluator: both were registered after the snapshot. For six out of the seven names, Churilov's list is outdated, and this is an update to it, not a finding about slopsquatting. Socket also flagged ssh-keys as an existing package in its analysis.

For developers, the correction is still important. The package odf on PyPI is utilities and a server for the Open Data Framework project; the latest version was released on September 6, 2026, with 4,932 downloads per month. The library for OpenDocument documents is installed as odfpy, and in code, it's imported via import odf: it contains an odf module. It's likely that the AI confuses the module name with the package name, and following its advice, the developer gets a third-party tool. There's nothing malicious in it, but it's not the intended library. It's not visible from the open data how many of the 4,932 monthly downloads came this way.

It's the same with lusid. Under this name is a self-hosted iMessage client, while the LUSID financial platform SDK is called lusid-sdk. weaviate is held by the brand owner as an empty placeholder; the actual client is called weaviate-client, and this placeholder is safe.

A 404 response doesn't necessarily mean the name is free

A 404 code only indicates that a package with that name does not currently exist. It cannot always be registered: according to Churilov, 68 out of his 109 PyPI names are no longer available. The registry keeps them on a blocked list or rejects them through ultra-normalization, i.e., by comparing similar spellings like aws_cdk and aws-cdk. After all registry protections, Churilov and Socket estimate that 53 names remain available for registration. I didn't verify this for my 117 names by registering them: that would be squatting itself.

The frequency of hallucination and the danger of a name are weakly correlated. AI models suggested aws-cdk 429 times, more than any other name, but PyPI blocks it. On npm, the list leaders, @ember/service (55 times) and other @ember/ packages, were identified by Socket's analysis as legitimate imports for the Ember framework, resolved through ember-source, not as separate packages. metro-evaluator, with its 10 occurrences, ranks lower on the same list. A dangerous available name that no one has taken yet is a risk, and such names exist in the list; I won't name them, as that would be providing a ready list of targets.

What to do if an AI programming assistant installs dependencies itself

Malware was already present under one of the names, an available name can be taken any day, and installation based on an AI's programming advice usually proceeds without verification. The package code executes with the developer's permissions and can access their keys and tokens, so the first point concerns not individual programmers but team leads. Each measure has its own scope: some catch the first installation of a hallucinated name, others only the substitution of something already approved.

  1. Decide at the team level whether an AI agent can install dependencies without human confirmation. This protects against the agent executing a hallucinated command without human oversight: the npx react-codeshift command from over 237 repositories was executed by agents. It's also possible to inject a name to an agent through the content it reads: in Ben Nassi's group at Tel Aviv University with colleagues from Technion and Intuit, the proportion of requests to repositories where the assistant hallucinated the suggested name reached 85%, and when installing a skill, a pre-made set of instructions for the agent, it was 100%. The attack was tested on Cursor, Windsurf, GitHub Copilot, Cline, and Gemini CLI (The Hacker News, 2026).

  2. Inspect the package before installation without downloading it normally. For npm, use npm view <name> time: this command shows the dates of all versions, and for metro-evaluator, it reveals four versions on December 7 and the placeholder on December 12. For PyPI, the same information is provided by https://pypi.org/pypi/<name>/json. If you need to open the package itself, use pip download --only-binary :all: --no-deps <name> -d /tmp/x. Without --only-binary, pip will execute the package's setup.py during download for packages that only have source archives. This protects against the first installation of a hallucinated name, which is the primary scenario of this article. A recent date for a library you thought was long-established is a reason to stop. An old date doesn't guarantee the package is legitimate: odf has been on PyPI since 2024 and is still not OpenDocument, which is only apparent from the description.

  3. Install unfamiliar packages with npm install --ignore-scripts. This flag prevents the package from executing its code during installation. It does not protect against code that runs on first import.

  4. Maintain lock files and hashes. A lock file records exact dependency versions, and pip install --require-hashes verifies each package against its hash. This protects against the substitution of an already approved package: if different code appears under a familiar name, the installation will fail. It does not protect against the initial installation of a hallucinated name; the hash will lock precisely the package installed based on the AI's recommendation.

  5. Set up a private proxy registry with a whitelist. The team installs only approved packages, and an AI suggestion with an unfamiliar name will be rejected by the registry. This also protects against initial installation, but only as long as a human who has verified the name adds it to the whitelist.

Limitations of checking 139 names against registries

This is a one-time snapshot as of September 22, 2026, and the set of occupied names will likely be different in six months. I checked the file from release v0.2-preprint as is, with 139 names; in the final version of Churilov's preprint, the list was reduced to 127 (109 for PyPI and 18 for npm). There are no downloads for weaviate: pypistats responded with a 429 error to the request. What was in the four removed versions of metro-evaluator cannot be restored from the registry; only the publication dates are visible.
