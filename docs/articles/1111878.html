On November 23, Z.ai released GLM-5.4. This is its first flagship model based on the Loop Transformer architecture: some layers with shared weights are executed twice in one pass. This is how developers are trying to make the model "deeper" without increasing the number of parameters. It's hard to verify if it worked yet, as the flagship lacks a benchmark table, public API, and weights.

What is known

The official blog of Z.ai did not open for me. Therefore, I am relying on those who cite it.

  • The model was not trained from scratch: it was fine-tuned from the GLM-5 base. According to MarkTechPost, 28 layers are run twice, and the entire model weighs about 750B. DataCamp clarifies that Z.ai has not confirmed these figures.

  • The second pass reuses the sparse KV cache (saved attention keys and values) from the first pass, and its own cache stores only within a sliding window. Therefore, the additional round occupies one cache window, not a full cache for 1M tokens.

  • Z.ai claims a model scale of 2–3 trillion parameters. Only ablation results on a 30B model have been published: approximately +10% compute for training, AIME25 increased from 19.17 to 30.42, GPQA-Diamond from 47.58 to 56.26, and answers became 2–15% shorter.

Pricing and Access

The model is only available in the GLM Coding Plan (Lite tariff from $18 per month), in the ZCode desktop agent, and in Z.ai Chat. Pay-as-you-go API is marked as "Coming Soon", weights are promised "after safety hardening", no dates. Credit quotas remain the same, but GLM-5.4 tokens deduct about 1.5 times fewer credits than GLM-5.3 (Fello AI). Simon Willison connected to the model via a Coding Plan key on an OpenAI-compatible endpoint api.z.ai/api/v1.

GLM-5.4 took 7th place out of 19 and first place among open models. It spent about 1.04 million tokens on reasoning, while Neon used about 70 thousand. There are caveats: scores were set by Gemini 4 Neon, GLM-5.4 evaluated a couple of tasks itself, and the reasoning mode used for the run is still debated.

Z.ai itself admits that the model is prone to "marathon thinking". In High and Max modes, it hit the 180-second timeout without finishing its reasoning.

My opinion

From an architectural standpoint, the release is interesting because it uses a loop instead of new parameters, and there's a cool trick with the cache. But releasing a flagship without benchmarks, API, and weights is strange, especially when the model thinks many times longer than its competitors. The 1.5x credit saving will disappear if the answers become twice as long. For now, it's a reason for those already paying for Coding Plan to try the model. We await the flagship's benchmark table and API.
